# CLPM P0 原型 5 分钟演示脚本

日期：2026-06-16
阶段：阶段性交付 v0.4

## 演示目标

证明 CLPM 首版不是报表工具，而是能从低性能识别走到证据解释、人工审核、安全实施、复评和证据包归档的治理闭环原型。

## 演示路径

| 时间 | 路由 | 讲解重点 | 验收句 |
|---:|---|---|---|
| 0:00-0:40 | `/` | 工程首页三栏工作台：优先回路、证据摘要、动作待办 | 10 秒内知道先处理 demo-data 主回路 |
| 0:40-1:20 | `/samples/readiness` | 样本可用但 partial：当前 24 回路为开发 smoke 数据，P0 目标仍按 50-100/72 回路口径保留 | 数据不足不是错误 |
| 1:20-2:00 | `/performance/ranking` | 低效排行按评分与风险定位问题回路 | 排行能解释为什么优先处理 |
| 2:00-2:50 | `/diagnosis/loop/TIC-1115` | PV/SP/OP 趋势、规则命中、事件线共同构成证据链 | 诊断可解释、可追溯 |
| 2:50-3:40 | `/closure/review` | 工艺、仪表、安全多角色意见与人工实施边界 | 平台不写 DCS |
| 3:40-4:20 | `/evidence` | EvidencePackage manifest-first，引用契约对象而非截图堆叠 | 证据包可审计 |
| 4:20-5:00 | `/sponsor` | Sponsor 第一屏：可信度、闭环率、风险、代表样例 | 管理层能判断是否可汇报 |

## 必须明确的边界

- P0 只做治理闭环验证，不扩大到完整项目交付。
- 可信整定只展示 demo-data `tuning_candidate` 单条样例，不承诺批量整定。
- 平台只读 DCS，不自动下发 P/I/D。
- P1/P2/P3 入口只做结构展示，必须保留版本标签。

## 演示通过标准

| 项目 | 标准 |
|---|---|
| 主链 | 首页 → 证据链 → 审核 → 证据包可走通 |
| 状态 | partial / success / risk / safety 边界均有文案 |
| 响应式 | desktop 与 mobile smoke 均通过 |
| 可审计 | EvidencePackage 展示 manifest 与版本引用 |
| 安全 | 安全边界页面明确“不写 DCS、人工实施、审计留痕” |
