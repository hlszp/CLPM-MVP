# 招标需求对 PRS v0.2 的补充评估

日期：2026-06-16
评估对象：`product-requirements-specification-v0.2-2026-06-16.md`
新增输入：用户正式招标需求 `1.1.1 PID性能评估与整定系统`

## 1. 总体结论

当前 PRS v0.2 的方向和主体框架仍然成立，尤其在标准口径、指标体系、台账、诊断、变更、报表、安全边界方面已经比较完整。但正式招标需求把项目从“平台产品能力”进一步拉到了“可交付项目能力”，因此 PRS 还需要补充和优化。

最关键的新增约束有 7 类：

- 明确项目实施范围：11 类装置、共 `1200` 个控制回路。
- 明确交付内容：软件部署、培训、PID 参数专家整定服务。
- 明确查询要求：授权 WEB 访问，查询项目实施后 `5 年内` 任意时间段、任意单元、任意回路。
- 明确整定分析输出：回路辨识模型、整定结果可信度、闭环阶跃响应曲线、数据激励指数、闭环频域响应分析。
- 明确历史数据不足场景：迁移学习、交互式整定、专家经验库、趋势线法、特征点法、迭代优化。
- 明确故障类型：过程扰动、分布式振荡、非线性程度、阀门幅值、粘滞状况等。
- 明确项目验收目标：装置自控率 `>=95%`，仪表阀门异常和工艺原因除外。

建议升级为 PRS v0.3。v0.3 不应推翻 v0.2，而应新增“招标项目实施与专家整定服务能力”“整定仿真与可信度分析”“交互式整定与迁移学习”“5 年 WEB 查询与项目验收指标”四个方向。

| 招标要求 | PRS v0.2 覆盖情况 |

| 自控率、平稳率实时监控 | 已覆盖，`FR-201` 到 `FR-204` |
| 日、周、月、年、自定义报告 | 已覆盖，`FR-603` |
| 性能评分、性能级别 | 已覆盖，`FR-214`、`FR-215` |
| 优、良、中、差、开环评级映射 | 已覆盖，`FR-215` |
| 振荡率、饱和率、粘滞系数 | 已覆盖，`FR-309`、`FR-310`、`FR-311` |
| 回路耦合 | 已覆盖，`FR-306` |
| PID 参数优化建议 | 已覆盖，`FR-401` 到 `FR-413` |
| 不自动下写 DCS、安全审核 | 已覆盖，`FR-408`、`FR-501` 到 `FR-508` |
| 远程 WEB 访问的基础页面 | 部分覆盖，页面需求已有，但需强化授权 WEB 查询要求 |

## 3. 部分覆盖但需要增强

### 3.1 项目范围和交付边界

招标明确范围为：

`气化、变换及热回收、低温甲醇洗、液氮洗、氨合成、PSA 制氢、CO 分离及压缩、硫回收制酸、冷冻站、甲醇装置、醋酸装置，共 1200 个控制回路`

PRS v0.2 目前只有“单企业支持 >=10,000 回路”的容量描述，但没有项目实施范围、装置清单、回路数量、项目交付内容。

建议新增：

| 建议编号 | 需求 |
|---|---|
| `FR-901` | 系统应支持按招标装置清单建立项目实施范围，至少覆盖 11 类装置和 1200 个控制回路。 |
| `FR-902` | 系统应支持项目实施进度管理，跟踪每个装置的部署、点位确认、台账校核、评估、整定、培训和验收状态。 |
| `FR-903` | 系统应支持控制回路交付清单，记录每个回路是否完成数据接入、性能评估、专家整定、复评和验收。 |

### 3.2 5 年 WEB 查询

招标要求：

`能够在授权计算机上查询项目实施后 5 年内任意时间段、任意单元、任意回路的自控率、控制平稳率，并能够排序和评比。`

PRS v0.2 目前：

- 数据留存：5 年，已覆盖。
- 在线历史查询：近 3 年，`FR-612` 和 `NFR-010`。

这是一个明确不一致点。应按招标改为 5 年在线查询。

建议调整：

| 原编号 | 调整 |
|---|---|
| `FR-612` | 从“近三年历史查询”改为“项目实施后 5 年内任意时间段历史查询”。 |
| `NFR-010` | 从“近三年评估指标在线查询”改为“5 年评估指标在线查询”。 |
| 新增 `FR-613` | 支持任意时间段、任意装置/单元/回路的自控率、平稳率查询、排序和评比。 |

### 3.3 报警次数和操作频次

招标把 `报警次数、操作频次` 列入目标中的实时统计数据。PRS v0.2 已有 `FR-219`，但优先级是 P1。

建议调整：

| 原编号 | 调整 |
|---|---|
| `FR-219` | 从 P1 调整为 P0，验收标准增加“实时统计、历史查询、排序和报表输出”。 |

### 3.4 单回路详细报告

招标要求回路详细评估报告和维护建议，并明确雷达图、闭环频域响应等展示。PRS v0.2 中 `FR-609` 是 P1。

建议调整：

| 原编号 | 调整 |
|---|---|
| `FR-609` | 从 P1 调整为 P0。单回路高级报告是招标明确要求，不宜放到后续版本。 |
| 新增 `FR-614` | 单回路报告应输出维护建议，包括可能原因、建议处理方式、是否建议仪表/阀门检查、是否建议 PID 参数整定。 |

## 4. 当前 PRS 缺失内容

### 4.1 过程模型辨识

招标明确要求：

`基于 PID 回路运行数据，采用辨识算法获得 PID 回路的过程模型。`

PRS v0.2 有“识别对象模型”，但没有把模型辨识作为独立能力定义，也没有说明模型类型、模型质量、模型版本和可视化输出。

建议新增：

| 建议编号 | 需求 |
|---|---|
| `FR-414` | 系统应支持基于历史和实时数据的过程模型辨识，输出模型类型、模型参数、拟合度和适用工况。 |
| `FR-415` | 系统应支持模型质量评价，包括数据质量、数据激励充分性、模型残差、拟合优度和可信度。 |
| `FR-416` | 系统应支持模型版本管理，同一回路可保留多个工况或时间段的辨识模型。 |

### 4.2 闭环响应仿真和整定可信度

招标明确要求：

`根据回路辨识模型及优化得出的 PID 控制器参数，对 PID 回路进行闭环响应仿真，给出整定结果可信度，闭环阶跃响应曲线，数据激励指数，闭环频域响应分析等仿真和分析结果。`

PRS v0.2 只有 `FR-407` 整定前验证，优先级 P1，描述过粗。

建议新增并提升为 P0：

| 建议编号 | 需求 |
|---|---|
| `FR-417` | 系统应支持基于辨识模型和建议 PID 参数的闭环响应仿真。 |
| `FR-418` | 系统应输出闭环阶跃响应曲线，至少展示超调量、调节时间、稳态误差、响应速度。 |
| `FR-419` | 系统应输出闭环频域响应分析，至少展示稳定裕度或频域性能评价指标。 |
| `FR-420` | 系统应输出数据激励指数，用于判断历史数据是否足以支撑可靠辨识和整定。 |
| `FR-421` | 系统应输出整定结果可信度，综合考虑数据质量、激励充分性、模型质量、仿真结果和工况匹配。 |
| `FR-422` | 系统应支持整定前后仿真结果对比，作为专家审核依据。 |

同时建议将 `FR-407` 从 P1 调整为 P0，并改名为“整定仿真验证”。

### 4.3 交互式 PID 整定

招标明确要求：

`交互式整定应用于回路历史数据不足或者激励不够、辨识效果不佳的情况下，通过软件内置专家经验库以及趋势线法和特征点法两种交互式整定算法，经过软件计算和用户对回路的特征评价给出新的 PID 优化参数，通过几次迭代进一步提升回路性能。`

PRS v0.2 未覆盖“交互式整定”的具体机制。

建议新增：

| 建议编号 | 需求 |
|---|---|
| `FR-423` | 系统应支持交互式 PID 整定，用于历史数据不足、激励不足或辨识效果不佳的回路。 |
| `FR-424` | 系统应内置专家经验库，支持按回路类型、对象特性、控制目标推荐整定策略。 |
| `FR-425` | 系统应支持趋势线法交互式整定。 |
| `FR-426` | 系统应支持特征点法交互式整定。 |
| `FR-427` | 系统应支持用户对回路特征进行交互评价，并把评价作为参数计算输入。 |
| `FR-428` | 系统应支持多轮迭代整定，记录每轮参数、仿真结果、专家意见和性能变化。 |

### 4.4 迁移学习

招标明确要求：

`针对缺少有效历史数据的回路，采用基于数据和模型驱动的迁移学习和交互式整定策略。`

PRS v0.2 没有迁移学习能力描述。考虑到这是招标原文，不能忽略，但需要谨慎定义，避免变成不可验收的泛 AI 口号。

建议新增为 P1 或可选增强项：

| 建议编号 | 需求 |
|---|---|
| `FR-429` | 系统宜支持基于相似回路、相似工况或历史模型库的迁移学习整定建议。 |
| `FR-430` | 迁移学习建议必须输出相似性依据、适用边界、可信度和人工确认要求。 |
| `FR-431` | 迁移学习结果不得自动下写 DCS，只能作为专家整定建议输入。 |

建议优先级：

- 如果投标响应必须逐条满足，列为 P0 可选模块。
- 如果产品规划，列为 P1，先用“相似回路模型库 + 专家规则 + 可信度说明”实现，不宜承诺黑盒大模型。

### 4.5 普通整定中的搜索算法

招标明确要求：

`普通整定主要基于实时和历史数据，采用基于智能控制算法及系统期望闭环响应的搜索算法两种方式给出控制器参数。`

PRS v0.2 有整定方法库，但没有“期望闭环响应搜索算法”。

建议新增：

| 建议编号 | 需求 |
|---|---|
| `FR-432` | 系统应支持基于期望闭环响应的 PID 参数搜索算法。 |
| `FR-433` | 用户应可配置期望闭环响应目标，包括响应速度、超调约束、稳态误差、鲁棒性偏好等。 |
| `FR-434` | 系统应输出候选参数集排序，并说明各候选参数的性能、风险和可信度。 |

### 4.6 故障检测类型

招标明确要求故障包括：

- 阀门粘滞
- 过程扰动
- 回路耦合
- 分布式振荡

PRS v0.2 覆盖阀门粘滞和回路耦合，但“过程扰动”和“分布式振荡”不够明确。

建议新增：

| 建议编号 | 需求 |
|---|---|
| `FR-317` | 系统应识别过程扰动，并区分设定值变化、负荷扰动、外部周期扰动等来源。 |
| `FR-318` | 系统应识别分布式振荡，支持跨回路振荡传播、同频振荡和源头回路分析。 |

### 4.7 性能指标细化

招标列出的指标比 PRS 更细：

`控制性能指标、参考时间、振荡状况、振荡周期、振荡幅值、非线性程度、阀门幅值、粘滞状况、粘滞系数`

PRS v0.2 已覆盖部分，但还应补齐字段化输出。

建议新增：

| 建议编号 | 需求 |
|---|---|
| `FR-220` | 系统应输出控制性能指标和参考时间。 |
| `FR-221` | 系统应输出振荡状况、振荡周期和振荡幅值。 |
| `FR-222` | 系统应输出非线性程度和阀门幅值。 |
| `FR-223` | 系统应输出粘滞状况和粘滞系数。 |

### 4.8 专家整定服务和培训

招标范围明确包括：

`完成软件部署、培训及 PID 参数专家整定服务。`

PRS v0.2 只有第三方运维服务商角色和培训接口预留，没有把“专家整定服务”作为项目交付模块。

建议新增：

| 建议编号 | 需求 |
|---|---|
| `FR-904` | 系统应支持专家整定服务工作台，按装置和回路跟踪评估、诊断、整定、审核、实施、复评状态。 |
| `FR-905` | 系统应支持专家整定服务报告，包含服务范围、回路清单、问题分类、整定建议、实施记录、优化效果。 |
| `FR-906` | 系统应支持培训交付记录，记录培训对象、内容、时间、资料、签到和考核情况。 |
| `FR-907` | 系统应支持项目验收包导出，包含部署记录、培训记录、回路评估报告、整定服务报告、验收指标结果。 |

| 编号 | 验收指标 |
|---|---|

| `AC-002` | 项目实施后可查询 5 年内任意时间段、任意单元、任意回路的自控率和平稳率。 |

| `AC-005` | PID 整定输出包含辨识模型、建议参数、整定可信度、数据激励指数、闭环阶跃响应曲线和闭环频域响应分析。 |

## 7. 是否需要修改 PRS

需要。建议形成 `product-requirements-specification-v0.3`，重点新增以下章节或小节：

- `项目实施范围与交付`
- `专家整定服务`
- `模型辨识与整定仿真`
- `交互式整定与迁移学习`
- `招标验收指标`

同时调整以下现有章节：

- `3.3 成功指标`：加入 1200 回路、装置自控率 >=95%、培训和专家整定服务交付。
- `5.1 首版范围`：加入专家整定服务、闭环仿真、5 年任意时间查询。
- `6.3 指标计算`：加入控制性能指标、参考时间、非线性程度、阀门幅值、粘滞状况字段化输出。
- `6.4 问题诊断`：加入过程扰动、分布式振荡。
- `6.5 PID 参数优化`：加入模型辨识、闭环仿真、可信度、数据激励指数、期望闭环响应搜索、交互式整定、迁移学习。
- `6.7 报表与看板`：把单回路高级报告提升为 P0，并补维护建议。
- `7 非功能需求`：5 年在线查询替代近三年在线查询。
- `11 验收标准`：加入招标验收指标。

## 8. 建议产品边界判断

招标需求中有几个偏“投标响应/项目交付”的内容，不一定都应该变成长期平台核心能力，但必须在项目版 PRS 里体现：

- `1200 回路、11 类装置`：属于项目实施范围，不是通用产品限制。
- `软件部署、培训、专家整定服务`：属于交付服务能力，应进入项目交付章节。
- `迁移学习`：建议产品化为“相似回路模型库 + 专家规则 + 可信度说明”，避免承诺不可解释的黑盒算法。
- `闭环仿真、可信度、数据激励指数`：这是本次招标的核心差异点，应作为 P0。

最终建议：

- 通用产品 PRS 保持 v0.2 的合规平台定位。
- 针对此招标，新增 v0.3 或“投标响应版 PRS”，把模型辨识、整定仿真、专家服务和 5 年查询补齐。
