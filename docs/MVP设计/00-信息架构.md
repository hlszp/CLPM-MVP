## 关键依赖关系

- **导航顺序**：驾驶舱 → 运维工作台 → 监控 → 评估 → 诊断 → 整定 → 处置 → 报告 → 配置 → 系统（按 `order` -1~8；驾驶舱 order=-1 为方案 11 号文落地，工作台 2026-08-25 v2.0 挂 order=0〔2026-10-04 更名运维工作台〕，报告 order=6 为 2026-08-23 IA 优化 P0~P4 产物，2026-08-24 显示名“统计报告”改为“报告”）。
- **工作台规整（2026-10-04 用户裁决 D1~D4，方案：`docs/设计文档/工作台规整方案-2026-10-04.md`）**：
  - D1 权限以回路工作台剖面为准：诊断/整定操作角色统一四角色 ADMIN/IC/PE/EXPERT（后端 `_DIAGNOSIS_TRIGGER_ROLES` + EXPERT、tuning require_roles + PE），模块内查看类页面统一全 5 角色；SPONSOR 仍只读。
  - D2 诊断工作台并入不保留：单回路发起/结论让位回路工作台诊断剖面；`/diagnosis/workbench` redirect（带 loopId → 回路工作台；无 → 诊断概览）；「仅可诊断」过滤与预检徽标筛选迁入诊断概览。
  - D3 整定工作台转型「整定总览」（`/tuning/overview`）：保留总览表 + 在途建议，四锚点流程移回路工作台整定剖面；`/tuning/workbench` redirect。
  - D4 全局工作台更名「运维工作台」。
  - 回路工作台新增 `?section=` 直达协议（assess|diagnosis|tuning|handling，一次性消费后从 URL 清除），作为模块页 → 单回路操作台的统一跳转通道。
- **总览三屏收敛（2026-09-29 用户裁决）**：全站总览类页面收敛为**驾驶舱 `/cockpit`（管理者）+ 工作台 `/workbench`（工程任务台，定位=聚合+下钻薄层）+ 性能总览 `/metric/pid-dashboard`（评估看板）**三屏；装置总览 `/dashboard/workbench` 与管理总览 `/reports/overview` 下线（页面删除，后端 /reports/overview 端点保留待 P3 报表做实恢复），旧书签经 redirect 落回路监视 / 绩效报告。
- **驾驶舱 / 工作台 v2.0 分工（2026-09-24 定稿：两者都保留，互不替代）**：
  | 维度 | 驾驶舱 `/cockpit` | 工作台 v2.0 `/workbench` |
  |---|---|---|
  | 定位 | 管理视角「现在怎么样」 | 工程视角「现在该做什么」 |
  | 形态 | 满屏只读（noBasicLayout），独立深/浅主题 | 后台单页 5 Tab，随全局主题 |
  | 写操作 | 无（Poka-Yoke，仅弹窗/联动） | 有（发起诊断/整定、记录处置） |
  | 入口 | 菜单首项 + IC/PE/SPONSOR 登录默认落地；顶栏「管理后台」互通 | 菜单次项 + ADMIN/EXPERT 默认落地 |
  | 数据口径 | 只读聚合（cockpit 服务） | workbench/aggregate + 各域 BFF |
  两者共享同一 KPI 口径（kpi_snapshot_hourly / diagnosis_run），不接受"同一指标两个数"。
- **监控默认首页分流（0929 更新）**：EXPERT 角色进「回路工作台」，其余角色进「回路监视」（装置总览已下线）。
- **关注队列排序与导出（2026-09-24 设计）**：
  - **排序必须服务端做**：该页按「回路组」服务端分页，客户端 sorter 只能排当前页，
    会造成"全局有序"的错觉。故 `GET /monitor/attention` 新增
    `sortBy=priority|updatedAt|itemCount|overdue` + `sortOrder=asc|desc`，
    在**分页之前**对分组排序；非法值静默回退默认（不 400）。
    优先级语义：priority asc=紧急在前、updatedAt desc=最近更新在前、
    itemCount desc=问题项多在前、overdue asc=超期优先。
  - **全量导出另立端点**：`GET /monitor/attention/export`（CSV，UTF-8 BOM）与列表
    共用同一过滤/排序口径但不分页（上限 2000 组，超出在首行注明），
    文件首行写入口径（生成时间/生成人/筛选/排序/条数）以便材料自证；
    页面内导出若只导当前页，提示必须写明"当前页 N 条（共 M 条）"。
    一行=一个「问题回路组」（与主表一致），附关注项明细标题前 5 条。
- **隐藏项（不占导航但路由有效）**：
  - 监控：回路实时表格 `/loop/monitor`、回路实时表格（旧版）、旧书签兼容 `/dashboard` 与 `/dashboard/workbench` → `/monitor/loops`（0929 装置总览下线）
  - 诊断：`/diagnosis/workbench` redirect（2026-10-04 D2：带 loopId → `/loop/workbench360?loopId=&section=diagnosis`，无 → `/diagnosis/overview`）
  - 整定：`/tuning/workbench` redirect → `/tuning/overview`（2026-10-04 D3，query 透传）
  - 评估：`/metric/kpi-report` 旧路径 redirect（→ `/reports/performance`）
  - 处置：处置工作台 `/handling/workbench`、处置报告 `/handling/statistics`（报告已迁 `/reports/handling`）
  - 报告：`/reports/overview` → `/reports/performance`（0929 管理总览下线）
  - 配置：回路台账、PID 结构模板
  - 系统：订阅配置 `/system/reports` redirect（→ `/reports/subscription`）、算法参数配置 `/system/algorithm-params` redirect（→ `/config/metric`）
  - 预警：`/alert/events`、`/alert/rules`（预警事件归监控、预警规则归配置后的旧路径兼容）
  - 各类 `legacy redirect`（链路/测点/回路/工厂模型/数据管理/指标配置/诊断配置/预警规则等旧路径兼容）

## 角色权限要点

| 角色 | 权限范围 |
|------|----------|
| ADMIN | 全部菜单 |
| IC_ENGINEER | 监控/评估/诊断/整定/处置/报告/配置（链路/指标/诊断/预警规则配置除外）+ 系统查看 |
| PE_ENGINEER | 监控/评估/诊断/整定/处置/报告查看 + 部分配置查看（链路/指标/诊断/预警规则不可见） |
| SPONSOR | 监控/评估/诊断/整定/处置/报告查看，无配置/无系统 |
| EXPERT | 监控/诊断/整定/处置/报告，无评估/无配置菜单 |

> 工作台角色口径：`/workbench` 全角色可见（ADMIN/EXPERT/IC_ENGINEER/PE_ENGINEER/SPONSOR），为跨模块总览入口，不设 meta.module、不参与模块热插拔过滤。
> 操作角色口径（2026-10-04 D1，以回路工作台剖面为准）：诊断/整定的发起与执行 = ADMIN/IC_ENGINEER/PE_ENGINEER/EXPERT 四角色（后端常量同步），SPONSOR 全线只读；诊断/整定模块内查看类页面（概览/记录/任务/总览/验证）统一全 5 角色。
> 评估角色口径：性能总览/指标分析/回路性能全角色可见（EXPERT 除外，EXPERT 无评估菜单）；评估记录/评估任务仅 ADMIN/IC_ENGINEER。
> 报告角色口径：父菜单全角色可见；绩效/收益报告不含 EXPERT；订阅配置仅 ADMIN（见 `reports.ts` authority）。
