# 01 - MVP 精简总体方案

## 1. MVP 目标

将 CLPM v6.2（6 模块 + 1 门户）精简为生产环境最小可用版，只保留**监控、评估、配置、系统**四个模块的核心功能，彻底移除诊断、整定模块及相关的流程闭环内容。

### 保留模块

| 模块 | 核心功能 |
|---|---|
| 监控 | 系统概览、回路工作台、关注队列、预警事件 |
| 评估 | 性能总览、回路性能、评估任务、KPI 报表 |
| 配置 | 回路配置、数据源配置、指标配置、预警规则配置、DCS 配置等 |
| 系统 | 用户管理、审计日志、报表管理等 |

### 屏蔽模块

| 模块 | 说明 |
|---|---|
| 诊断中心 | 诊断触发、诊断分析、Action Tracker、诊断验证、诊断配置、LLM 配置 |
| 回路整定 | 模型辨识、PID 整定、闭环仿真、整定知识库、整定统计 |
| AAS/OPC UA 同步 | AAS tag 位号同步任务 |
| 流程闭环 | 诊断→整定→验证的闭环状态机、Tracker 时间线、生命周期管理 |

## 2. 当前改造状态（第一轮：注释屏蔽）

第一轮改造已完成，采用"注释屏蔽 + 条件隐藏"策略：

### 已完成的前端屏蔽

| 文件 | 改造方式 |
|---|---|
| `router/routes/modules/diagnosis.ts` | 导出空数组 `routes: RouteRecordRaw[] = []` |
| `router/routes/modules/tuning.ts` | 导出空数组 |
| `router/routes/modules/config.ts` | 注释"诊断配置"路由项 |
| `router/routes/modules/system.ts` | 注释"LLM 配置"路由项 |
| `views/monitor/attention.vue` | 客户端过滤 TRACKER/VERIFICATION 来源项 |
| `views/loop/workbench.vue` | `MVP_DISABLE_DIAGNOSIS_TUNING = true` 开关，条件隐藏诊断/整定/验证区 |

### 已完成的后端屏蔽

| 文件 | 改造方式 |
|---|---|
| `app/main.py` | 注释 diagnosis/tuning/aas/llm_config/diagnosis_trigger_config 的路由注册；lifespan 跳过诊断预载 |
| `app/tasks/celery_app.py` | 从 include 移除 diagnosis_engine/tuning/tracker_verification/aas_sync |

### 第一轮改造的局限

- 代码仍保留在文件中，只是被注释或条件隐藏
- 诊断/整定的 API 文件、组件文件、页面文件、服务文件全部存在
- 部分保留模块的页面仍有诊断/整定的交叉引用（如 dashboard.py 引用 DiagnosisResult）
- 后续需要彻底删除这些代码

## 3. 端口隔离方案

MVP 项目与原项目在同一台机器上并行运行，端口全部在原端口基础上加 10000（首位前加 1）：

| 服务 | 原项目 | MVP |
|---|---|---|
| 前端 dev | 5666 | **15666** |
| 后端 API | 7101 | **17101** |
| PostgreSQL | 7102 | **17102** |
| Redis | 7103 | **17103** |
| TDengine | 7104/7115 | **17104/17115** |

### Docker 隔离

| 资源 | 原项目 | MVP |
|---|---|---|
| 容器名前缀 | `clpm-` | `clpm-mvp-` |

## 6. 数据库策略

**不改动数据库 schema**：ORM 模型和 Alembic 迁移脚本保持原样。

- 诊断/整定/tracker 表保留在数据库中，但不再有新数据写入
- 种子数据中的诊断/整定配置保留（不影响功能）
- 避免数据迁移风险，保持与原项目的兼容性
