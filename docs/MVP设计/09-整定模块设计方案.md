## 1. 背景与目标

### 1.1 动机

MVP 已打通「监控 → 评估 → 诊断 → 处置」链路，诊断 8 类原因中的**参数问题（TUNING）**对应的处置措施是 PID 参数整定。处置模块（08 文档决策 #4）当前对 TUNING 类型采用**记录式闭环**（人工填写调整前后 P/I/D），并预留 `tuning_record_id` 关联位，明确"未来整定模块开放后无缝挂接"。

本模块将整定恢复为**一级模块**，为参数问题提供"建议生成 + 效果验证"的专业工具链：

```
诊断发现参数问题 → 整定（辨识→整定矩阵→仿真对比→保存方案）
    → 线下实施（处置模块记录 P/I/D 前后值，关联 tuning_record_id）
    → 效果验证（前后窗曲线对比，整定/检修两类场景通用）
```

## 2. 产品定位与范围

### 2.1 定位

整定 = 回路 PID 参数优化的**建议生成器 + 效果验证工具**。平台只输出建议、证据与仿真对比，不执行任何 DCS 操作（安全红线不变）。

### 2.2 范围内

- 过程辨识：历史数据自动辨识（主路径）+ 阶跃实验辨识（兜底路径），输出 FOPDT/SOPDT/IPDT 模型参数 + 拟合度 + 可信度
- 参数整定：全算法矩阵（5 算法并列）+ 算法参数微调 + 当前 PID 对照
- 回路仿真：当前 PID（DCS 实际值）+ 1~2 组推荐参数的阶跃响应曲线对比 + 量化指标（超调量/调节时间/IAE）
- 方案保存：生成整定记录（含模型/算法/推荐参数/仿真快照），供处置挂接与历史追溯
- 效果验证：前后窗 SP/PV/OP 趋势对比 + PV/OP X-Y 轨迹对比（整定独立页 + 处置 VERIFYING 嵌入）
- 诊断联动：诊断 TUNING 类建议「去整定」带回路上下文进入工作台

### 2.3 范围外（非目标）

| 项 | 说明 |
|---|---|
| DCS 参数下写 | 平台安全边界不变，永久红线 |
| 整定知识库 / 效果统计页 | 后端端点保留不删，首版不做页面入口（Phase 4 候选） |
| 多变量/MIMO 辨识 | 原 Phase 3+ 范围，不做 |
| 继电器反馈法等主动实验 | 与"历史数据自动辨识"目标相悖，不做 |
| 自动整定触发 | 整定始终由人发起，不做评分阈值自动触发 |

## 3. 总体流程

```
┌─ 整定工作台（单页 4 锚点）─────────────────────────────────┐
│ ① 过程辨识        ② 整定矩阵        ③ 仿真对比      ④ 方案确认 │
│  选回路+时间窗  →  5 算法并列    →  当前 vs 推荐  →  保存方案  │
│  历史/阶跃双路径   勾选 1~2 组      曲线+指标对比    落 tuning_record │
└──────────────────────────────────────────────────────────┘
        ↓ 保存方案（显式）                    ↓ 去整定（带 loopId）
┌─ 整定记录页 ──────────────┐    ┌─ 诊断详情弹窗（TUNING 类建议）─┐
│ 列表 + 详情抽屉 + 去验证    │    └───────────────────────────────┘
└──────────────────────────┘
        ↓ 去验证（带 loopId + 时点）
┌─ 效果验证页 ──────────────┐    ┌─ 处置详情抽屉（VERIFYING）─────┐
│ 回路+时点+窗口 → 趋势对比   │ ←→ │ 验证区嵌入同一曲线对比组件        │
│ + X-Y 轨迹对比            │    └───────────────────────────────┘
└──────────────────────────┘
```

## 4. 功能设计

### 4.1 过程辨识

**双路径**（复用原实现，均已有端点）：

| 路径 | 端点 | 执行方式 | 适用场景 |
|---|---|---|---|
| 历史数据自动辨识 | `POST /tuning/identify/history` + `POST /tuning/identify/segments` | **Celery 异步**（数据量大） | 主路径：正常运行的历史 OP/PV 数据，无需人工实验 |
| 阶跃实验辨识 | `POST /tuning/identify` | 同步 | 兜底：用户指定阶跃段（检修后试车、新建回路） |

- 历史辨识内部流程：DataPlanner 统一取数（8 步预处理）→ 激励检测 → 非参数粗估 → ARX/ARMAX/IV 参数化辨识 → 阶次选择（AIC/BIC）→ 离散转连续 → ConfidenceEvaluator 可信度评级
- 输出：模型类型（FOPDT/SOPDT/IPDT）+ 模型参数（K/θ/τ，SOPDT 含 τ2）+ 拟合度（fittingScore）+ 可信度等级（A/B/C/D/E）
- **可信度门禁**：D/E 级结果醒目标注"不建议用于整定"，允许查看但仿真对比区置灰提示（防呆，对齐平台"可信数据"红线）

### 4.2 参数整定（全算法矩阵）

- **一次全算**：选定模型后，后端对 IMC / Lambda / Z-N / Cohen-Coon / SIMC 5 种算法分别计算推荐 PID（纯内存计算，毫秒级，同步）
- **新增端点** `POST /tuning/tune/matrix`：请求同 `TuneRequest` 去掉 `algorithm` 单值字段，返回 5 组 `TuneResult`；内部循环调用现有 5 个 `tune_*` 函数，改动极小
- **矩阵表格**：每算法一行 —— 算法名 | P | I | D | 算法特性备注（如"IMC 偏平缓，λ 可调"、"Z-N 偏激进，1/4 衰减比"）| 操作（勾选进仿真）
- **算法参数微调**：每行可展开调整算法参数（如 IMC 的 λ 档位 0.5θ 激进 / 1θ 标准 / 2θ 平缓；Lambda 法 λ 倍数），调整后单行重算（调现有 `POST /tuning/tune` 单算法端点）
- **当前 PID 对照**：矩阵首行固定展示当前 DCS PID（从回路关联 PID_P/PID_I/PID_D tag 实时值读取，优先 Redis 实时缓存，口径同监控模块），作为对照基准
- **PID 口径转换**：DCS 厂商 PID 形式（比例带/积分时间等）与平台标准形式（Kp/Ti/Td）的转换复用 `pid_conversion.py` 服务，按回路配置的 DCS 型号自动适配

### 4.3 回路仿真

- 复用 `POST /tuning/compare`（`SimulateRequest.pidCandidates` 多组候选，原 Phase 2 已实现）
- 对比曲线：**当前 PID**（必选基准）+ 矩阵勾选的 **1~2 组推荐参数**，同一辨识模型上做 SP 阶跃响应仿真（RK4 + 增量式 PID）
- 展示：阶跃响应曲线叠加图（3 色：当前=灰 / 推荐1=蓝 / 推荐2=橙）+ 量化指标列（上升时间 / 超调量 / 调节时间 / ITAE，每参数组一行）
- 仿真参数（时长/步长/阶跃幅值）给默认值（600s/1s/1 个工程量单位），高级用户可改

#### 仿真性能指标说明（IAE vs ITAE）

| 维度 | IAE（绝对误差积分） | **ITAE（时间加权绝对误差积分，本系统采用）** |
|---|---|---|
| 定义 | ∫\|e(t)\|dt | ∫ t·\|e(t)\|dt |
| 权重 | 全程等权：每 1 秒偏差贡献相同 | 权重随时间线性增长：越晚的偏差惩罚越重 |
| 对初期偏差 | 与后期同等计入（纯滞后 θ 造成的初期偏差不可避免，也全额计入） | t≈0 时权重≈0，初期偏差基本不计 |
| 工程语义 | "窗口内的总偏差量"——反映累计偏离程度 | "回路多久能稳住"——长尾/缓爬/持续振荡被显著放大 |
| 整定对比区分度 | 各候选共享同一 θ，初期大面积误差相同，等权计入稀释尾部差异 | 尾部差异主导数值，候选间区分明显 |
| 典型取向 | IAE 最优参数偏圆润保守 | ITAE 最优参数调节时间更短，可容忍略大的初期超调 |

**选型结论**：本功能目标是"比较当前 vs 推荐参数的阶跃响应稳定质量"，ITAE 区分度更高，代码 `_extract_metrics` 采用 ITAE（Σ t·\|e\|·dt）作为排名与改善幅度（improvement）指标。IAE 语义直观（总偏差量，与产品质量累计偏差更贴近），后续如需可在指标列并列展示——同一响应序列零成本补算，本期不纳入。

### 4.4 方案确认与保存（决策 #6：显式保存才落记录）

- 仿真对比区下方为方案确认区：用户从仿真组中**选定 1 组最终方案**，确认后点击「保存方案」
- 保存内容（写 `tuning_record`）：回路、模型类型+参数、算法、推荐 PID、当前 PID、拟合度、仿真结果快照、状态 `SIMULATED`、创建人/时间
- 保存后引导：提示"请线下实施后在处置模块记录闭环"，提供「创建处置项」快捷入口（跳转处置，预填 TUNING 类型 + 关联 `tuning_record_id` + `pidBefore`=当前 PID + 建议 `pidAfter`=推荐 PID）
- 未保存的辨识/整定/仿真中间结果不落库，离开页面即丢弃（用户决策明确）

### 4.5 效果验证（新增能力）

**输入**：回路 + 对比时点 + 窗口（1h / 2h / 24h 预设三档）

**时点来源**（决策 #5：记录带出 + 可改）：
- 从整定记录「去验证」进入：带出该回路关联处置项（TUNING 类型）的 `submitted_at`；无关联处置时带出整定记录创建时间，用户改
- 从处置 VERIFYING 嵌入：固定带 `submitted_at`（处置实施完成时间），可改
- 独立进入：用户手选

**输出**（实时拉取，不落库）：
1. **前后窗趋势对比**：前窗 `[时点−窗口, 时点]` 与后窗 `[时点, 时点+窗口]` 上下分区同轴展示 SP/PV/OP 趋势（上前窗、下后窗，Y 轴量纲对齐）；后窗不足完整窗口按实际数据展示并标注
2. **PV/OP X-Y 轨迹对比**：前窗/后窗双色叠加（前窗=灰、后窗=蓝），直观看阀门回差/粘滞改善、操作模式变化
3. **前后窗 KPI 摘要条**（复用处置模块口径）：评分 + 六率各取窗口内最新快照，涨跌箭头标示

**数据口径**：复用 waveform/trend 服务拉取本地 TDengine 数据（计算全本地红线）；时间参数 naive UTC 传输、前端补 Z 转本地（同诊断模块口径）。

### 6.2 整定工作台（单页 4 锚点）

- **锚点 ① 过程辨识**：时间窗选择 + 辨识路径 tabs（历史数据辨识=默认 / 阶跃实验辨识）→ 辨识结果卡（模型类型/参数/拟合度/可信度等级徽标；D/E 级警示）；历史辨识异步进度条（细粒度）
- **锚点 ② 整定矩阵**：当前 PID 对照行（灰底固定首行）+ 5 算法行（P/I/D/特性备注/复选框）；行内展开算法参数微调（λ 档位等）+ 单行重算
- **锚点 ③ 仿真对比**：阶跃响应曲线叠加图（当前=灰/推荐1=蓝/推荐2=橙）+ 指标表（超调量/调节时间/IAE）
- **锚点 ④ 方案确认**：选定最终方案（radio）→ 「保存方案」→ 成功提示 + 「创建处置项」快捷入口
- 锚点间数据流：辨识结果 → 矩阵计算 → 勾选进仿真 → 确认保存，顺序解锁（前序未完成后续置灰，Poka-Yoke）

### 6.3 整定记录页

- 顶部统计卡：总任务数 / 已实施（APPLIED+VERIFIED）/ 平均拟合度 / 近 7 天新增
- 表格：回路位号 | 模型类型 | 算法 | 推荐 P/I/D | 拟合度（三档色阶 ≥80 绿/≥60 黄/<60 红）| 状态 tag（SIMULATED=蓝/APPLIED=青/VERIFIED=绿）| 创建人/时间 | 操作（详情/去验证）
- 详情抽屉：完整模型参数 + 仿真快照图 + 关联处置项（`tuning_record_id` 反查，跳转处置详情）

### 6.4 效果验证页（共享组件）

- 查询区：回路选择 + 对比时点（记录带出可改）+ 窗口档（1h/2h/24h）+ 「对比」按钮
- 结果区：`TuningVerifyCompare` 组件 —— 前后窗趋势对比（上下分区）+ PV/OP X-Y 对比（双色轨迹）+ KPI 摘要条
- **组件共享**：处置详情抽屉 VERIFYING 环节嵌入同一组件（props 带入 `loopId` + `pointTime=submitted_at`），处置 KPI 对比卡之上新增「曲线对比」折叠块

### 6.5 诊断联动

诊断详情弹窗处置建议 Tab 中 `category=TUNING` 的建议行，操作列增加「去整定」：跳 `/tuning/workbench?loopId=xx&from=diagnosis`，工作台预填回路并显示诊断来源 Alert。
