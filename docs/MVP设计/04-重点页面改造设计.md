# 04 - 重点页面改造设计

本文档详述保留模块中受诊断/整定/闭环影响的核心页面改造方案。

## 1. 回路工作台（views/loop/workbench.vue）⚠️核心

### 1.1 页面定位

回路工作台是监控模块的主入口（`/monitor/loop-workbench`），单回路四区工作台，原设计包含：
- R1：回路基本信息 + 实时数据
- R2：评估摘要
- R3：KPI 指标条
- R4：六维雷达图
- R5：证据卡区（评估卡 + 诊断卡 + 整定卡 + 验证卡）
- R6：验证前后对比条
- 右侧：闭环时间线（含 Tracker 节点）
- 弹窗：诊断触发/整定触发/调参/仿真结果

### 1.2 当前改造状态

已使用 `MVP_DISABLE_DIAGNOSIS_TUNING = true` 开关条件隐藏：
- `loadDiagnosis()` / `loadTuning()` 函数短路
- 阶段数组过滤掉 DIAGNOSE / TUNE / VERIFY
- R5 中的诊断卡/整定卡/验证卡条件隐藏
- R6 验证前后对比条条件隐藏
- 右侧闭环时间线 Tracker 节点条件隐藏
- 4 个弹窗条件隐藏

### 1.3 彻底改造方案

#### 删除的内容

| 区域 | 删除内容 | 原因 |
|---|---|---|
| import | `DiagnosisTriggerModal` / `TuningTriggerModal` / `TuneParamModal` / `SimulateResultModal` 组件导入 | 诊断/整定弹窗 |
| import | `diagnosisApi` / `tuningApi` 相关 API 导入 | 诊断/整定数据请求 |
| 数据函数 | `loadDiagnosis()` / `loadTuning()` / `loadVerification()` 函数 | 诊断/整定数据加载 |
| 阶段定义 | `DIAGNOSE` / `TUNE` / `VERIFY` 阶段 | 闭环流程阶段 |
| R5 证据卡区 | 诊断卡、整定卡、验证卡 | 仅保留评估卡 |
| R6 | 验证前后对比条整个区域 | 整定效果对比 |
| 右侧时间线 | Tracker 节点、诊断/整定/验证节点 | 闭环时间线 |
| 弹窗 | 4 个弹窗的 `<component>` 标签和触发按钮 | 诊断/整定弹窗 |
| MVP 开关 | `MVP_DISABLE_DIAGNOSIS_TUNING` 常量及所有 `v-if` 条件 | 清理开关代码 |

#### 保留的内容

| 区域 | 保留内容 | 说明 |
|---|---|---|
| R1 | 回路基本信息 + 实时数据 | 监控核心 |
| R2 | 评估摘要 | 评估核心 |
| R3 | KPI 指标条 | 评估核心 |
| R4 | 六维雷达图 | 评估核心 |
| R5 | 评估卡 | 评估核心 |
| 右侧时间线 | 评估节点 | 仅保留评估相关节点 |
| 通用组件 | KPI 指标卡、评分趋势图、PID 结构抽屉、数据完整性报告 | 评估相关 |

#### 改造后的页面结构

```
回路工作台
├── R1: 回路基本信息 + 实时数据
├── R2: 评估摘要
├── R3: KPI 指标条
├── R4: 六维雷达图
├── R5: 证据卡区（仅评估卡）
├── 右侧: 时间线（仅评估节点 + 活跃关注列表）
└── 弹窗: 评估触发弹窗（保留）
```

## 2. 关注队列（views/monitor/attention.vue）

### 2.1 页面定位

关注队列（`/monitor/attention`）聚合五类来源的当前行动项：ALERT / DEGRADATION / DATA_QUALITY / TRACKER / VERIFICATION。

### 2.2 当前改造状态

客户端过滤 `TRACKER` 和 `VERIFICATION` 来源项：
- `DIAGNOSIS_SOURCES = new Set(['TRACKER', 'VERIFICATION'])`
- `loadData` 中过滤 `res.items`
- `SOURCE_ORDER` 数组注释掉 TRACKER 和 VERIFICATION

### 2.3 彻底改造方案

| 改造项 | 说明 |
|---|---|
| 删除 `DIAGNOSIS_SOURCES` 过滤逻辑 | 改为后端不返回 TRACKER/VERIFICATION 来源 |
| 删除 `SOURCE_ORDER` 中的 TRACKER/VERIFICATION | 仅保留 ALERT/DEGRADATION/DATA_QUALITY |
| 删除相关类型定义 | `AttentionSource` 类型移除 TRACKER/VERIFICATION |
| 删除相关文案 | 来源标签、筛选选项等 |

### 2.4 后端配合改造

`endpoints/monitor.py`：
- `_VALID_SOURCES` 移除 TRACKER/VERIFICATION
- `list_attention` 服务不再聚合 Tracker 和验证超期来源

## 3. 系统概览（views/dashboard/workbench.vue）

### 3.1 页面定位

系统概览（`/dashboard/workbench`）是监控模块的首页，展示全厂 KPI 概览、帕累托图、工厂模型树等。

### 3.2 需删除的内容

| 区域 | 删除内容 | 数据来源 |
|---|---|---|
| 统计卡 | Tracker 计数（trackerCount/pendingCount） | `dashboard.py` L999-1096 |
| 统计卡 | 诊断建议分布（diagnosisDistribution） | `dashboard.py` L1118-1142 |
| 问题回路 | Tracker 相关的问题回路标记 | `dashboard.py` L1080-1087 |

### 3.3 后端配合改造

`endpoints/dashboard.py`：
- 删除 `DiagnosisResult` 导入和所有查询
- 删除 `ActionTracker` 导入和所有查询
- `trackerCount` / `pendingCount` / `pendingTrackerCount` 返回 0
- `diagnosisDistribution` 返回空字典

## 4. 监控上下文改造（composables/use-monitor-context.ts）

### 4.1 WorkbenchSection 类型

```typescript
// 改造前
export type WorkbenchSection =
  | 'assessment'
  | 'diagnosis'
  | 'overview'
  | 'tuning'
  | 'verification';

// 改造后
export type WorkbenchSection = 'assessment' | 'overview';
```

### 4.2 VALID_SECTIONS 集合

```typescript
// 改造前
const VALID_SECTIONS = new Set<WorkbenchSection>([
  'assessment', 'diagnosis', 'overview', 'tuning', 'verification',
]);

// 改造后
const VALID_SECTIONS = new Set<WorkbenchSection>(['assessment', 'overview']);
```

### 4.3 trackerId 字段

删除 `trackerId` 字段及所有相关逻辑：
- `MonitorContext` 接口中的 `trackerId` 字段
- `CONTEXT_KEYS` 数组中的 `'trackerId'`
- `context` computed 中的 `trackerId: parseStr(route.query.trackerId)`
- `trackerId` computed
- `navigateWithMonitorContext` 中的 `if (current.trackerId) carry.trackerId = current.trackerId`
- 返回对象中的 `trackerId`

## 5. 生命周期条改造（components/monitor/workbench-lifecycle-bar.vue）

### 5.1 当前状态

展示回路闭环生命周期：评估 → 诊断 → 整定 → 验证。

### 5.2 改造方案

仅保留评估阶段节点，删除诊断/整定/验证阶段节点。

## 6. AI 洞察改造（endpoints/ai_insight.py + services/ai_insight/scenes/）

### 6.1 场景策略

| 场景 | 处理方式 |
|---|---|
| `diagnosis` | 删除 `scenes/diagnosis.py`，从 SCENE_LIST 移除 |
| `tuning` | 删除 `scenes/tuning.py`，从 SCENE_LIST 移除 |
| `performance` | 保留 |

- 删除 `POST /diagnosis/{loopId}/interpret` 兼容代理说明
