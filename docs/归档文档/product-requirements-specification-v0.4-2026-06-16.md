## 2. 产品定位

本产品定位为：**面向危化企业安全生产和工艺平稳性的控制回路绩效治理与优化闭环平台**。

它回答四个问题：

1. 哪些回路正在拖累装置稳定性。
2. 为什么拖累，是 PID 参数、阀门仪表、工艺扰动、耦合、数据质量还是长期手动。
3. 下一步该由谁处理，处理动作是什么。
4. 处理后是否真的变好，证据是什么。

本产品**不是**：

- 单机版 PID 调参软件。
- 自动向 DCS 批量下写参数的闭环自整定系统。
- APC、RTO、SIS、DCS 的替代系统。

本产品**是**：

`可信数据 -> 可解释诊断 -> 可验证整定 -> 安全闭环 -> 规模化交付`

## 3. 产品目标

### 3.1 业务目标

- 支撑危化企业落实工艺平稳性和控制回路性能评估要求。
- 建立企业级、装置级、回路组、回路级控制绩效指标体系。
- 将低性能回路从“感觉不好”变为“可排序、可归因、可审核、可复评”的治理对象。
- 将参数优化从专家经验动作变为“有数据、有仿真、有可信度、有回退”的受控流程。
- 支撑后续 `1200` 回路项目交付、专家服务、培训和验收。

### 3.2 产品目标

- 建立 DCS/BPCS 回路台账治理和只读数据接入能力。
- 建立 KPI、诊断、证据链、审核、实施、复评的闭环工作流。
- 建立“能不能整定、该不该采纳”的可信整定能力，但不在 P0 批量承诺。
- 建立版本化、审计化、可追溯的数据与规则体系。

## 4. 产品护城河

| 护城河层 | 核心能力 | 产品要求 |
|---|---|---|
| 可信数据 | OPC 接入、质量码、点位映射、台账版本、统计口径 | 每个结论都能追到数据窗口、台账版本、质量规则 |
| 可解释诊断 | KPI、异常诊断、证据链、建议动作 | 每个低性能结论可展开趋势、事件、规则、阈值 |
| 可验证整定 | 数据激励、模型质量、仿真、可信度、回退 | 先判断“能不能整定”，再给建议 |
| 安全闭环 | 审核、人工实施、观察期、复评、审计 | 平台不直接修改 DCS 的 P/I/D 参数 |
| 规模化交付 | 样板验证、项目模板、培训验收、证据包 | 从 P0 验证包逐步扩展到 P2 项目化交付 |

## 5. 用户与入口

### 5.1 用户角色

| 角色 | 第一关注 | 首要入口 |
|---|---|---|
| 仪表控制工程师 / 控制回路专家 | 今天先处理哪条回路，为什么，怎么处理 | 工程师工作台 |
| 工艺管理 / 生产技术 / sponsor | 本轮样本是否可信，闭环是否跑通，结论是否可汇报 | sponsor 证据视图 |
| 安全管理 / OT 运维 | 边界、安全、权限、审计、部署 | 系统与审计入口 |
| 专家服务团队 | 诊断复核、整定样例、实施后复评 | 专家分析入口（P1/P2） |

### 5.2 双入口信息架构

P0 必须显式采用双入口，不允许一个首页同时承载工程师工作流和 sponsor 汇报工作。

| 入口 | 第一屏先看什么 | 第一问题 |
|---|---|---|
| 工程师工作台 | 低性能清单、数据雷达、待复评事项 | 今天先处理哪条回路 |
| sponsor 证据视图 | 样本验证仪表盘、证据包摘要、关键风险与结论 | 这次验证是否可信 |

### 5.3 第一用户最小闭环

P0 的第一可证明闭环为：

`单装置 50-100 回路 -> 样本验证仪表盘 -> 低性能清单 -> 单回路证据链 -> 审核/实施/复评 -> 验收证据包`

说明：

- P0 允许 `1` 个专家确认的整定可信度样例。
- P0 不承诺批量可信整定。
- P0 不承诺 `1200` 回路完整交付流程。

## 6. 版本范围

### 6.1 版本边界总表

| 版本 | 目标 | 核心范围 | 明确不做 |
|---|---|---|---|
| P0 治理闭环验证版 | 证明产品不是报表工具，而是治理闭环 | 样本接入、台账治理、核心 KPI、低性能清单、证据链、审核/实施/复评、样本验证仪表盘、数据雷达、验收证据包、`1` 个整定样例 | 自动下写 DCS、批量整定、迁移学习、完整专家服务台、`5` 年任意查询性能、完整项目交付驾驶舱 |
| P1 可信整定产品化版 | 把“能不能整定、该不该采纳”做成产品工作台 | 模型辨识、数据激励指数、模型质量、可信整定工作台、仿真对比、专家复核、交互式整定 | 无审核在线自整定、迁移学习泛化承诺 |
| P2 企业平台与项目交付版 | 支撑 `1200` 回路项目和长期运维 | `5` 年历史查询、冷热分层、异步报表、项目交付驾驶舱、专家服务工作台、培训验收包 | 替代 DCS/SIS/APC/RTO |
| P3 知识资产与差异化智能版 | 沉淀跨项目知识资产 | 相似回路知识库、多工况模型库、迁移学习建议、行业模板、集团驾驶舱 | 不可解释黑盒整定 |

### 6.2 P0/P1/P2/P3 细项边界

| PRS 主题 | P0 | P1-P3 |
|---|---|---|
| OPC DA/UA 接入 | 支持一个真实或模拟源，或历史导入 | P1/P2 扩展冗余、诊断、多源模板 |
| OPC AE 事件 | 可使用导入或简化事件 | P1 产品化实时事件采集 |
| KPI 计算 | 样本窗口 KPI 与版本口径 | P1/P2 扩展企业口径、全量指标库 |
| 低性能排行 | 必做 | 持续优化排序规则 |
| 证据链 | 必做 `3` 个典型样例 | P1 扩展诊断类型和校准 |
| 模型辨识 | 仅 `1` 个样例 | P1 工作台化 |
| 频域分析 | 样例级或可选 | P1/P2 批量化 |
| 交互式整定 | 不进入 P0 主链 | P1/P2 |
| 迁移学习 | 不进入 P0 | P3 |
| 专家服务工作台 | 不进入 P0 | P2 |
| `5` 年任意查询 | 仅定义边界和留存策略 | P2 实现 |
| 完整验收包 | 不进入 P0 | P2 |

## 7. 安全边界

| 边界 | 规则 |
|---|---|
| DCS 写入 | 平台不直接修改 DCS 的 P/I/D 参数 |
| 控制方式 | 平台不切换 AUTO/CAS/REMOTE/APC 等模式 |
| 主动激励 | 平台不主动执行阶跃、脉冲、继电反馈试验 |
| 参数实施 | 必须由授权人员在 DCS 中人工实施 |
| 记录 | 所有建议、审核、实施、复评都必须留痕 |
| 回退 | 每次建议必须包含回退参数和回退说明 |

## 8. P0 成功口径与数据门槛

### 8.1 P0 验证阈值

| 区域 | 阈值 |
|---|---:|
| 样本规模 | `50-100` 回路 |
| 核心点位映射 | `>=95%` 回路具备 `PV/SP/OP/MODE` |
| 台账完整率 | 人工修正后 `>=99%` |
| 好值率 | KPI 窗口 `>=90%`，低于阈值必须显式标注 |
| 低性能样本 | 至少识别 `10` 条低性能回路，或明确说明“样本过于健康” |
| 证据链样例 | 至少 `3` 条：PID 疑似、阀门/仪表疑似、数据/工况问题 |
| 专家诊断认可率 | `>=70%` |
| 闭环记录 | 至少 `3` 条审核/实施/复评记录，可为桌面评审模拟流程 |
| 整定样例 | `1` 条专家确认可整定回路，含模型、仿真、可信度、风险、回退 |

### 8.2 数据就绪门

在 P0 被视为可执行前，必须明确：

| 项目 | 最低要求 |
|---|---|
| 数据来源 | 真实 OPC、historian 导出、CSV 或模拟数据，来源必须命名 |
| 时间窗口 | 足以支撑 KPI 窗口和 `3` 条证据链 |
| 必备点位 | `PV/SP/OP/MODE`；PID 参数只要求整定样例具备 |
| 事件 | 报警、操作、MODE 事件可用、可导入或明确模拟 |
| 质量标记 | 有质量码，或有人工质量规则 |
| 专家资源 | 至少 `1` 位具名专家可完成诊断复核和整定样例确认 |
| 降级策略 | 数据不足时，P0 仍可证明台账/KPI/证据链外壳，但算法结论必须标注“未验证” |

## 9. P0 契约主干

P0 虽按层铺开，但必须围绕统一契约主干建设，不允许各层各自定义不可拼接的结果。

字段级、状态级、接口级规格详见：`p0-contract-backbone-design-v0.1-2026-06-16.md`。

### 9.1 契约对象

| 对象 | 作用 | 关键版本引用 |
|---|---|---|
| `EvidencePackage` | 最终证据包 manifest，不是大对象导出 | 引用全部版本和快照 |
| `SampleBatch` | 定义样本范围、来源、时间窗 | `source_version`、`import_run_id` |
| `TimeWindow` | 定义 KPI/诊断/证据窗口 | `window_id` |
| `SignalSeries` | `PV/SP/OP/MODE` 窗口数据或其引用 | `source`、降采样规则 |
| `QualityMask` | good/bad/missing/frozen 质量叠层 | `quality_rule_version` |
| `ModeSegment` | AUTO/manual/APC/unknown 状态段 | `mode_mapping_version` |
| `LoopLedger` | 回路身份、映射、层级、类型 | `ledger_version`、`mapping_version` |
| `KpiResult` | KPI 值和状态 | `formula_version`、`threshold_version` |
| `DiagnosisFinding` | 问题、置信度、证据、建议动作 | `rule_version`、`evidence_window_id` |
| `ExceptionRecord` | 排除原因和审批记录 | 审批人、有效窗口、影响指标 |
| `ReviewRecord` | 决策、角色、原因、置信度覆盖 | 审计轨迹 |
| `Reevaluation` | 前后对比 | 前后窗口和 KPI 版本 |
| `TuningCase` | P0 单个整定样例附件 | 不进入治理闭环主依赖 |

### 9.2 版本化规则

任何结论必须可追溯到：

- `ledger_version`
- `mapping_version`
- `formula_version`
- `threshold_version`
- `quality_rule_version`
- `mode_mapping_version`
- `rule_version`

生成结果必须支持：

| 字段 | 用途 |
|---|---|
| `validity_status` | 当前结果是否仍有效 |
| `superseded_by` | 被哪个新结果替代 |
| `generated_by_run` | 对应 CalculationRun / JobRun |

## 10. 用户视角功能信息架构

完整产品一级/二级菜单和首期原型展示深度详见：`full-product-menu-ia-v0.1-2026-06-16.md`。该文档作为用户视角信息架构补充，不改变 P0 交付边界。

### 10.1 P0 页面骨架

| 页面 | 第一价值 | 页面骨架 |
|---|---|---|
| 工程师工作台 | 决定今天先处理哪条回路 | 低性能清单 + 数据雷达 + 待复评事项 |
| 单回路证据链 | 判断为什么是它、下一步做什么 | 趋势/状态带/事件 + 规则与阈值 + 动作建议 |
| 审核/实施/复评 | 把动作闭环跑通 | 审核意见 + 实施记录 + 前后对比 |
| sponsor 证据视图 | 快速判断样本验证是否可信 | 样本验证仪表盘 + 证据包摘要 + 风险与结论 |
| 验收证据包 | 形成可汇报、可交付的证据对象 | 摘要优先，完整证据二级展开或导出 |

### 10.2 工作台化约束

P0 明确禁止“卡片拼盘式仪表盘”作为主要页面结构。

推荐布局：

```text
工程师工作台（桌面）
+-------------------+---------------------------+----------------------+
| 低性能清单        | 单回路证据/趋势/事件      | 动作与复评           |
| 优先级、状态      | MODE带、规则、阈值        | 审核、实施、回退     |
+-------------------+---------------------------+----------------------+

Sponsor 证据视图（桌面）
+-------------------------+---------------------------+
| 样本验证仪表盘          | 证据包摘要 / 关键样例     |
| 样本数、映射率、闭环率  | 风险说明、结论、导出      |
+-------------------------+---------------------------+
```

### 10.3 样本验证仪表盘

样本验证仪表盘对客户可见，但只显示客户应看到的验证结果与可信度，不暴露内部调试字段。

必须包含：

| 字段 | 说明 |
|---|---|
| 样本范围 | 装置、回路数、时间范围 |
| 映射完整率 | `PV/SP/OP/MODE` 映射完成情况 |
| 数据可信度 | 好值率、数据不足比例 |
| 低性能识别结果 | 识别数量、分类分布 |
| 闭环完成率 | 审核/实施/复评完成情况 |
| 风险说明 | 当前样本不能证明什么 |

### 10.4 sponsor 证据视图

sponsor 页面采用**摘要优先**：

- 第一屏展示样本范围、可信度、闭环完成率、关键风险、结论、导出入口。
- 完整证据包不在第一屏全量直出，只在二级展开或导出文件中查看。

## 12. 用户旅程与情绪路径

| 步骤 | 用户动作 | 用户感受 | 产品支持 |
|---|---|---|---|
| 1 | 打开工程师工作台 | 想立刻知道先处理谁 | 先显示低性能清单，而不是大盘卡片 |
| 2 | 看数据雷达 | 想确认这些结论靠不靠谱 | 显示数据可信、数据不足、可整定状态 |
| 3 | 展开单回路证据链 | 想判断“为什么是它” | 趋势、MODE、事件、规则、阈值、建议动作 |
| 4 | 进入审核/实施记录 | 想知道该由谁做、风险是什么 | 审核意见、风险、回退、观察期 |
| 5 | 查看复评 | 想知道处理后有没有改善 | 前后 KPI、振荡、报警、操作频次对比 |
| 6 | sponsor 打开证据视图 | 想知道样本验证是否可信 | 仪表盘 + 证据包摘要 + 风险与结论 |

## 13. 响应式与无障碍

### 13.1 响应式

| 视口 | 布局规则 |
|---|---|
| Desktop | 三栏工作台：清单 / 证据 / 动作 |
| Tablet | 上下两层：清单在上，证据与动作在下 |

### 13.2 无障碍

| 领域 | 规则 |
|---|---|
| 键盘 | 审核流必须支持纯键盘完成 |
| 触控 | 关键动作触控区域 `>=44px` |
| 对比度 | 状态颜色不能仅靠颜色区分，必须带文字标签 |
| 屏幕阅读器 | 双入口、清单区、证据区、动作区有明确 landmark 和 section label |
| 图表 | 趋势图旁必须有文字摘要，不能只靠图表表达 |

## 15. EvidencePackage 设计

EvidencePackage 不是“导出汇总文档”，而是一个**manifest**，负责引用和固化本次验证所依赖的全部结果。

| 字段 | 含义 |
|---|---|
| `sample_batch_id` | 对应样本批次 |
| `ledger_version` | 台账版本 |
| `mapping_version` | 映射版本 |
| `formula_version` | KPI 公式版本 |
| `threshold_version` | KPI 阈值版本 |
| `quality_rule_version` | 质量规则版本 |
| `included_kpi_results` | 纳入的 KPI 结果引用 |
| `included_findings` | 纳入的诊断结论引用 |
| `included_reviews` | 纳入的审核/实施/复评记录引用 |
| `included_exceptions` | 纳入的排除记录引用 |
| `package_status` | 草稿、完整、过期、需重算 |

规则：

- 证据包默认读取结果快照，不直接扫描长时序原始数据。
- 证据包不得 silently 包含被 `superseded` 的结果。
- 证据包支持“桌面评审版/模拟版/完整闭环版”三种状态标识。

## 16. 契约测试矩阵

当前项目尚无代码测试框架，但实现阶段必须把下表转成验收级契约测试。

| 契约对象 | Happy | Empty | Error | Partial |
|---|---|---|---|---|
| `SampleBatch` | `50-100` 回路样本导入成功 | `0` 回路样本 | 来源解析失败 | 样本数不足 |
| `LoopLedger` | 正常映射并生成新版本 | 无可映射回路 | 单位/方向异常 | 部分回路缺点位 |
| `KpiResult` | 正常计算并带版本 | 样本过于健康 | 口径未固化 | 仅部分回路可算 |
| `DiagnosisFinding` | `3` 类典型证据链 | 无低性能回路 | 证据窗口失效 | 某类证据缺失 |
| `ReviewRecord` | 专家决策完整 | 无需审核记录 | 审核对象缺失 | 专家暂缺 |
| `EvidencePackage` | 摘要与导出可用 | 无完整闭环 | 结果过期 | 缺实施或复评，仅桌面评审版 |

## 17. 性能与查询边界

### 17.1 P0

P0 只允许：

- 样本窗口查询
- 结果快照查询
- 小范围趋势渲染
- 证据包摘要导出

P0 不允许承诺：

- `1200` 回路 `5` 年任意查询性能
- 原始长时序直接读取渲染

### 17.2 P2

P2 实现：

- 冷热分层
- 预聚合
- 异步查询任务
- 结果缓存
- 大跨度历史查询性能优化

## 18. 风险与应对

| 风险 | 影响 | v0.4 应对 |
|---|---|---|
| P0 再次膨胀 | 首版失焦 | 用版本边界表锁定范围 |
| 证据包最后才拼装 | 集成返工 | 采用 manifest-first 反向驱动 |
| 数据不足被误解为系统失效 | 信任下降 | 把“数据不足/不可判定”做成一等状态 |
| 工程师与 sponsor 混在一个首页 | 层级混乱 | 双入口 |
| 页面落成 generic dashboard | 像报表工具 | 工作台骨架约束 |
| 趋势渲染过重 | 页面卡顿 | 小窗口、降采样、点数上限 |
| `5` 年查询提前吞掉 P0 | 变成平台工程 | P0/P2 性能隔离 |

## 20. 术语统一

| 主术语 | 别名 | 本版规则 |
|---|---|---|
| SP | SV、设定值 | 首次出现写作 `SP/SV（设定值）`，后续统一用 SP |
| OP | MV、输出值 | 首次出现写作 `OP/MV（输出值）`，后续统一用 OP |
| 平稳率 | 稳定率 | 页面统一用平稳率 |
| 可信整定 | PID 优化、参数整定 | 产品主线统一称可信整定 |
| 证据包 | 验收包摘要、验证证据包 | P0 用证据包，P2 扩展为完整验收包 |

## 21. 当前最高优先级决策

| 决策 | 当前口径 |
|---|---|
| 产品定位 | 控制回路绩效治理与优化闭环平台，不是单机 PID 调参工具 |
| 首版主线 | P0 治理闭环验证包 |
| 首版样本 | `50-100` 回路 |
| P0 入口 | 工程师工作台 + sponsor 证据视图 |
| P0 关键新增制品 | 样本验证仪表盘、数据可用性与可整定性雷达、验收证据包 |
| 工程主约束 | 契约主干 + EvidencePackage manifest-first |
| 性能边界 | `5` 年任意查询后置至 P2 |
| 安全边界 | 不写 DCS，只建议、审核、人工实施、复评 |
