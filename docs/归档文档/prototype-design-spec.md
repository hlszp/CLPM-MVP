# CLPM 高保真原型设计说明与交付标准

## 1. 目标与范围
本原型设计的目的是将 PRD 与 FDS 中的抽象业务逻辑，转化为可交互、可验证的前端高保真产物，主要用于：
1. **需求验证**：在投入真实后端开发前，验证业务链路（尤其是状态机流转）的逻辑自洽性。
2. **用户测试**：提供给 Sponsor 与工艺专家，进行真实场景下的可用性测试。

## 2. 核心演示链路 (P0 范围)
本次高保真原型重点覆盖以下 6 个核心页面与链路：
1. **工程师首页工作台**：待办任务聚合、高优问题回路提醒。
2. **样本导入与就绪校验**：CSV/接口数据导入模拟、数据质量雷达图展示。
3. **低效排行与指标总览**：全局 KPI 监控与回路低效排行表格。
4. **单回路证据中心**：回路诊断结果、PID 趋势图对比如下、参数调整建议。
5. **审核/实施/复评联动页**：模拟工单流转的时间线交互。
6. **Sponsor 汇报与证据包**：全局绩效改善的对比视图与 Partial 状态检查。

## 3. 技术选型与实现标准
- **架构**：采用单文件 Inline React 架构（结合 Babel 实时编译）进行极速演示，或基于现有的 `prototype/` 目录（Vite + React）进行组件化重构。
- **数据模拟**：
  - 不依赖真实后端，通过前端 `Context` 或全局 `State` 模拟数据流转。
  - 核心状态机（如 `SampleBatch` 的 `draft -> validating -> ready -> frozen`）必须在内存中真实流转，不可写死静态页面。
- **交付形态**：
  - **多视角平铺演示**：将不同角色的视图（如工程师 vs. Sponsor）并排展示，方便横向对比与汇报。
  - **独立交互测试**：确保所有主按钮（如“驳回”、“批准”、“导出证据包”）具备真实的点击反馈。

## 4. 下一步开发支撑
- 后续开发团队可直接复用原型中的 CSS Tokens（色彩、字号、间距）与组件 DOM 结构。
- 前端路由与权限守卫逻辑可直接参考原型中的角色切换模拟器。
