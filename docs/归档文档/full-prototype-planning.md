# CLPM 全流程高保真原型设计实施计划 (Prototype Implementation Plan)

> **目标**: 基于 PRD (v2.1) 和 UI/UX 规范 (v2.0)，系统性地开发一套覆盖项目所有模块的完整高保真可交互原型系统。原型将采用 React + Vite 技术栈，支持真实的路由跳转、状态分支切换及端到端流程演示，作为后续研发与测试的唯一视觉与交互基准。

## 1. 原型页面清单与状态分支梳理

原型系统将划分为 5 大业务模块，覆盖 MVP 与 二期 的全量核心页面。

### 模块 A: 基础框架与通用状态 (Layout & Commons)
- **页面/组件**: 全局侧边栏导航、顶部状态栏、角色切换器。
- **状态分支**:
  - `Loading State`: 全局数据加载骨架屏。
  - `Empty State`: 暂无数据的缺省占位符。
  - `403 Forbidden`: 越权访问拦截页。
  - `404 Not Found`: 路由丢失兜底页。

### 模块 B: 工厂模型与配置 (Config)
- **页面 B1: 工厂层级与回路台账**
  - 功能：左侧树状结构，右侧回路列表。
  - 状态：新增回路弹窗、映射配置表单、数据校验缺失时的 `Partial` 红框警告状态。
- **页面 B2: 算法与指标管理**
  - 功能：指标权重配置与诊断阈值参数面板。

### 模块 C: 性能评估与看板 (Evaluation) [已初步 Demo]
- **页面 C1: 厂级/装置级全局性能看板**
  - 功能：KPI 指标卡片、平稳率趋势图、Top 差等生排行表。
  - 状态：数据缺失时的 `Inconclusive` 置灰状态。
- **页面 C2: 自动报表中心**
  - 功能：历史周期报表列表、PDF 下载预览弹窗。

### 模块 D: 诊断中心与追踪验证 (Diagnostics & Tracking) [已初步 Demo]
- **页面 D1: 单回路诊断详情与轻量追踪**
  - 功能：高频波形渲染、散点图特征、自动预诊结论卡片、右侧状态操作轴。
  - 状态：`待处理`、`处理中`、`已实施` 状态切换联动时间线。
- **页面 D2: A/B 效果对比视图**
  - 功能：实施后的 KPI 与波形前后对比弹窗。

### 模块 E: 回路整定与仿真 (Tuning - 二期模块)
- **页面 E1: 模型辨识与参数整定**
  - 功能：阶跃响应测试数据录入、FOPDT/SOPDT 模型辨识结果展示。
  - 状态：不同整定算法（IMC/Lambda）的推荐参数表格。
- **页面 E2: 闭环仿真对比**
  - 功能：双波形对比面板（当前参数 vs 推荐参数的阶跃抗扰动响应）。

## 2. 视觉与交互规范约束
- **色彩与排版**: 严格调用 `:root` 中的 `--bg-app`, `--color-info`, `--color-danger` 等变量；数值强制使用等宽字体 `var(--font-mono)`。
- **交互动效**: 侧边栏抽屉平滑滑出 (`transform: translateX`)，状态更新时提供轻量全局 Toast 提示 (`Fade-in-out`)。
- **路由逻辑**: 使用 React Router 进行 SPA 路由控制，确保浏览器前进/后退可用。

---

## 3. 实施排期与里程碑节点 (Milestones)

为确保有序交付，原型开发将分为 4 个里程碑节点：

* **[M1] 框架搭建与规范注入**
  * 初始化 Vite + React 工程，或者直接在现有原型代码库（`docs/设计文档/prototype/`）中进行重构升级。
  * 配置全局 CSS Tokens、基础 Layout、Router 结构。
* **[M2] MVP 核心业务链开发**
  * 完成模块 B (工厂配置)、模块 C (性能看板)、模块 D (诊断与轻量追踪)。
  * 打通从“查看看板 -> 点击异常回路 -> 诊断详情 -> 标记已实施”的端到端交互链路。
* **[M3] 进阶配置与二期模块开发**
  * 补齐模块 E (整定与仿真) 的参数推荐与双波形对比交互。
  * 补齐全局异常状态 (Empty/403/404) 的渲染逻辑。
* **[M4] 内部联调与交付物整理**
  * 全局自检路由死胡同与样式错位。
  * 编写《原型演示路径指南》，部署本地 HTTP Server，输出评审链接。
