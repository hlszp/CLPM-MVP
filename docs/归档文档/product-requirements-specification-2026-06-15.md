# 危化企业控制回路性能评估与优化平台产品需求规格书

日期：2026-06-15
版本：v0.1
依据：`GB/T 44693.1-2024`、`GB/T 44693.2-2024`、`DB32/T 4822-2024`、应急管理部“工业互联网+危化安全生产”试点建设方案、`AQ 3064.1—2025`

## 1. 产品定位

本产品定位为“危化企业控制回路性能评估与优化平台”，面向已采用 `DCS` 实施连续生产过程控制的危化、化工、石化、煤化工等企业，提供控制回路台账治理、性能评估、问题诊断、PID 参数优化建议、审核闭环、报表考核和安全风险联动能力。

本产品不定位为单机版 PID 调参软件，也不在首版定位为自动向 DCS 批量下写参数的闭环控制系统。首版应坚持旁路只读、专家审核、人工确认更新、审计留痕。

## 2. 建设目标

### 2.1 业务目标

- 支撑危化企业落实工艺平稳性和控制回路性能评估要求。
- 建立装置级、回路级控制绩效指标体系。
- 识别自控率低、平稳率低、振荡、阀门异常、仪表异常、回路耦合等问题。
- 形成可审核、可追踪、可复盘的 PID 参数优化流程。
- 将控制回路优化能力纳入企业安全风险智能化管控平台。

### 2.2 产品目标

- 建立 DCS 回路自动识别与台账治理能力。
- 原生计算 `DB32/T 4822-2024` 中的关键指标：装置自控率、装置平稳率、装置周期自控率、装置周期平稳率、回路自控率、回路平稳率。
- 支持不计入统计回路管理、评估周期管理和装置级考核报表。
- 支持离线和在线 PID 参数优化建议。
- 支持参数变更的工艺、仪表、安全多角色审核。

### 2.3 成功指标

- 回路自动识别准确率：首版目标 `>=90%`，人工修正后台账完整率 `>=99%`。
- 指标计算可追溯性：每个 KPI 可追溯到采样数据、统计周期、排除规则和计算公式。
- 报告生成效率：装置月度评估报告可在 `10 分钟` 内生成。
- 优化闭环率：可优化回路中完成审核、实施、复评的比例可统计。
- 安全策略：首版默认不向 DCS 自动下写 PID 参数。

## 3. 用户与场景

### 3.1 用户角色

| 角色 | 核心关注 | 典型操作 |
|---|---|---|
| 工艺工程师 | 工况稳定、质量波动、负荷扰动 | 查看平稳率、确认优化建议是否符合工艺约束 |
| 仪表控制工程师 | 回路性能、PID 参数、阀门/仪表问题 | 配置回路、分析振荡、生成整定建议、实施参数变更 |
| 生产运行人员 | 当前装置状态、报警与波动 | 查看异常回路、确认操作影响 |
| 安全管理人员 | 工艺平稳性、安全风险前移识别 | 查看关键回路异常、整改闭环、审计记录 |
| 信息化/OT 运维人员 | 数据接入、网络隔离、系统可用性 | 配置 OPC、权限、存储、备份、接口 |
| 企业管理层 | 装置考核、整改进度、经济影响 | 查看装置排行、趋势、月报、整改率 |
| 第三方运维服务商 | 持续服务、专家诊断、优化复评 | 批量诊断、出具服务报告、跟踪实施效果 |

### 3.2 核心场景

1. 月度工艺平稳性评估

企业按装置统计自控率、平稳率和周期指标，识别不达标装置和重点回路，形成整改清单。

2. 回路异常诊断

仪表控制工程师从低平稳率、低自控率、振荡、高切手动频次等维度筛选回路，系统给出可能原因和证据。

3. PID 参数优化

系统基于历史数据或在线数据识别对象特性，生成 PID 参数建议，经工艺和仪表人员确认后，由仪表控制工程师手动更新到 DCS。

4. 安全风险联动

关键回路持续失稳、长时间手动、执行机构饱和等情况进入企业安全风险智能化管控平台，联动报警优化、设备完整性和隐患整改。

## 4. 范围

### 4.1 首版范围

- DCS 数据只读接入。
- OPC DA、OPC AE 接入。
- 回路台账自动识别与人工校核。
- 装置/单元/回路层级管理。
- 回路评估指标计算。
- 异常诊断和优先级排序。
- PID 参数整定建议。
- 审核、实施记录、复评闭环。
- 报表与数据导出。
- 角色权限与审计日志。

### 4.2 首版不做

- 自动批量下写 DCS 参数。
- 无人工审核的在线闭环自整定。
- 全量 APC、RTO、MPC 建模平台。
- 替代 DCS、SIS、报警管理系统。
- 面向离散制造的通用控制优化。

### 4.3 后续扩展

- OPC UA、PI、PHD、实时数据库和工业数据湖接口。
- 阀门定位器、智能仪表、设备完整性系统接入。
- 报警优化模块联动。
- 18 种重点监管危险化工工艺模板库。
- 多工况参数库和推荐策略。
- 仿真回放与变更前风险评估。
- 边缘计算节点和跨厂区集团驾驶舱。

### 7.2 指标口径

| 指标 | 口径 |
|---|---|
| 装置自控率 | 装置实际投用自控回路数 / 参与统计的在用回路数 |
| 装置平稳率 | 满足平稳状态的控制回路数 / 参与统计的控制回路数 |
| 回路自控率 | 评估时段内回路处于自控状态的总时长 / 投用总时长 |
| 回路平稳率 | 评估时段内回路处于平稳状态的总时长 / 投用总时长 |
| 装置周期自控率 | 周期内回路自控率达到阈值的回路数 / 参与统计回路数 |
| 装置周期平稳率 | 周期内回路平稳率达到阈值的回路数 / 参与统计回路数 |

默认达标阈值为 `95%`，应允许企业按制度调整，但报告中必须显示实际采用阈值。

## 8. 关键流程

### 8.1 系统部署流程

1. 确认网络分区、DCS 类型、OPC Server、点位范围。
2. 部署数据采集服务、时序库、应用服务和前端。
3. 配置 OPC DA、OPC AE 接入。
4. 自动扫描回路组态。
5. 人工校核回路台账和统计范围。
6. 启动试运行评估。
7. 固化统计周期、阈值、报告模板和权限。

### 8.2 月度评估流程

1. 系统按周期生成装置和回路 KPI。
2. 自动识别低自控率、低平稳率和异常回路。
3. 仪表控制工程师确认诊断结论。
4. 工艺工程师确认工艺约束和优先级。
5. 系统生成评估报告和整改清单。
6. 安全管理人员跟踪整改闭环。

### 8.3 参数优化流程

1. 选择可优化回路。
2. 选择数据窗口和整定策略。
3. 系统识别对象模型并生成参数建议。
4. 系统给出预期效果、风险提示和回退参数。
5. 工艺、仪表、安全角色审核。
6. 仪表控制工程师在 DCS 中人工更新参数。
7. 系统进入观察期并自动复评。
8. 形成优化效果报告。

| 装置详情 | 装置自控率、平稳率、周期指标、回路列表、排行 |
| 回路详情 | PV/SP/MV 趋势、模式、PID 参数、KPI、诊断、建议 |
| 回路台账 | 自动识别结果、人工校核、不参与统计、关键回路标记 |
| 诊断中心 | 异常分类、严重度、证据、批量筛选、优先级 |
| 参数优化 | 数据窗口、模型识别、建议参数、风险和回退 |
| 审核中心 | 待审建议、审核意见、实施记录、复评结果 |
| 报表中心 | 月报、季报、明细表、导出、模板配置 |
| 系统管理 | 数据源、权限、阈值、规则、审计、备份 |

## 10. 验收标准

### 10.1 功能验收

- 能接入至少一个真实或模拟 DCS/OPC 数据源。
- 能自动识别一批 PID 回路并完成人工校核。
- 能按配置周期计算装置和回路 KPI。
- 能识别低自控率、低平稳率、振荡、执行机构异常等问题。
- 能生成 PID 参数建议并走完审核、实施记录、复评流程。
- 能生成周期评估报告和明细表。

### 10.2 合规验收

- 报表指标口径与 `DB32/T 4822-2024` 关键定义一致。
- 不参与统计回路必须有原因、有效期和记录。
- 参数优化建议不得默认自动下写 DCS。
- 审核和实施记录必须可追溯。
- 数据留存策略满足至少 `5 年` 要求。

### 10.3 安全验收

- 默认部署不具备 DCS 写入权限。
- 关键配置修改需要授权并留痕。
- 账号权限遵循最小权限原则。
- 数据导出和报告下载可审计。
- 网络分区和防火墙策略有实施说明。

## 11. 版本路线

| 阶段 | 时间 | 目标 |
|---|---|---|
| PoC | 1-2 个月 | 接入单装置数据，完成 KPI 计算、台账、基础诊断和报表 |
| MVP | 3-4 个月 | 支持多装置、参数建议、审核闭环、月报和审计 |
| V1.0 | 6-9 个月 | 支持企业级部署、稳定运维、诊断增强、复评闭环和平台接口 |
| V2.0 | 12 个月以上 | 支持多工况参数库、报警/设备联动、集团驾驶舱、行业模板 |

## 12. 风险与约束

| 风险 | 影响 | 应对 |
|---|---|---|
| DCS 组态差异大 | 自动识别准确率不足 | 建立厂商适配模板和人工校核流程 |
| 历史数据质量差 | KPI 和整定结果不可信 | 引入质量位、缺失标记、数据窗口评分 |
| 企业担心控制安全 | 产品上线受阻 | 默认只读部署，不自动下写，提供安全评审材料 |
| 工艺工况频繁变化 | 单一参数建议失效 | 引入工况识别、多工况参数库 |
| 诊断结论不可解释 | 工程师不采纳 | 每条建议必须展示证据和边界 |
| 标准持续更新 | 合规口径变化 | 指标公式、报告模板、术语字典可版本化 |
