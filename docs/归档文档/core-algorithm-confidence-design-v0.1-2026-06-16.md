# 核心算法与可信度体系设计说明

日期：2026-06-16
版本：v0.1
关联 PRS：`product-requirements-specification-v0.3-2026-06-16.md`
文档定位：PRS 补充材料，面向算法设计、产品原型、专家评审和招标技术响应

## 1. 设计结论

本平台在工程现场采用严格只读边界：

- 不向 DCS 写入设定值。
- 不向 DCS 写入 P/I/D 参数。
- 不切换控制方式。
- 不主动执行阶跃、脉冲、继电反馈等激励试验。
- 不执行无人值守在线闭环自整定。

因此，本产品不应承诺“自动修改控制器参数”的传统在线自整定，而应定义为：

> 基于只读运行数据的 PID 参数智能整定建议系统。

系统可以自动完成数据窗口挖掘、可整定性判定、模型辨识、参数计算、闭环仿真、可信度评价、诊断证据生成和复评分析；但参数实施必须由授权仪控工程师在 DCS 中人工完成，并经过工艺、仪表、安全等角色审核。

核心技术链路为：

`只读采集 -> 数据治理 -> 可整定性判定 -> 有效数据窗口挖掘 -> 闭环数据辨识 -> 模型质量评价 -> 参数候选计算 -> 闭环仿真 -> 可信度评分 -> 专家审核 -> 人工实施 -> 实施后复评`

## 3. 核心设计原则

### 3.1 只读安全原则

算法只能读取 `PV`、`SP/SV`、`OP/MV`、`MODE`、报警事件、操作事件、PID 参数和相关工况数据。所有主动控制动作均由 DCS 操作员或仪控工程师在既有制度下执行。

系统输出的是“建议”和“证据”，不是“执行指令”。

### 3.2 先诊断后整定

不是所有低性能回路都应该调 PID。系统必须先判断问题来源：

- 阀门粘滞、饱和、死区、内漏。
- 仪表漂移、噪声、断线、冻结。
- 工艺扰动或频繁负荷切换。
- 上下游回路耦合或分布式振荡。
- PID 参数不匹配。

只有当主要问题可以通过参数优化改善时，才进入整定建议流程。

### 3.3 无可信度不建议实施

每组 PID 参数建议必须附带可信度、风险、适用边界和回退方案。低可信建议只能进入“专家参考”状态，不能直接进入实施审核。

### 3.4 可解释优先

诊断结论、模型质量、整定建议和可信度评分必须能够展开证据，包括趋势、频谱、事件、数据窗口、模型拟合、残差、仿真结果和规则命中情况。

### 3.5 人机协同

历史数据不足、自然扰动不足或模型质量不足时，系统不强行给出高可信参数，而是进入交互式整定：由工程师或专家输入趋势线、特征点、对象特性、现场经验和工艺约束。

## 5. 回路可整定性判定

### 5.1 判定目标

可整定性判定回答三个问题：

1. 这条回路当前是否适合做 PID 参数优化？
2. 当前低性能是否主要由 PID 参数导致？
3. 系统是否具备足够数据给出可信建议？

### 5.2 判定状态

| 状态 | 含义 | 后续动作 |
|---|---|---|
| 可自动建议 | 数据质量好、激励充分、模型质量达标 | 进入模型辨识和参数候选计算 |
| 可专家整定 | 数据可用但存在边界条件或不确定性 | 进入专家审核增强流程 |
| 需交互整定 | 历史数据不足、激励不足或辨识质量不足 | 进入趋势线法、特征点法或经验库流程 |
| 需现场核实 | 疑似阀门、仪表、工艺扰动等问题 | 输出维护建议，不直接建议调参 |
| 不建议整定 | 数据异常、工况不稳定、回路未投自动或风险过高 | 暂停整定，进入整改或观察 |

### 5.3 判定输入

| 输入 | 说明 |
|---|---|
| 投用状态 | `MODE` 是否处于自动、串级、远程或 APC 有效控制状态 |
| 数据质量 | 好值率、缺失率、冻结率、质量码可信度 |
| 输出状态 | OP 是否饱和、是否长期无动作、是否频繁动作 |
| 扰动状态 | 是否存在开停车、负荷切换、外部大扰动 |
| 诊断结果 | 阀门、仪表、耦合、振荡、过程扰动等诊断结论 |
| 数据激励 | SP、OP、PV 是否有足够可观测变化 |
| 工况一致性 | 数据窗口内工况是否相对稳定 |

## 6. 数据窗口挖掘

### 6.1 设计目标

在不能主动做阶跃测试的前提下，系统必须从历史运行数据中自动寻找可用于辨识的自然扰动窗口。

可辨识窗口不是任意一段历史数据，而是同时满足以下条件的数据片段：

- 数据质量可信。
- 回路处于有效自动或可解释的闭环状态。
- OP、SP 或扰动变量存在足够变化。
- PV 对输入变化存在可观测响应。
- 工况没有明显切换。
- 无明显阀门饱和、仪表冻结、通信异常。

### 6.2 窗口来源

| 窗口类型 | 来源 | 适用场景 |
|---|---|---|
| 自然 SP 变化 | 操作员正常调整设定值 | 可用于闭环响应辨识 |
| 自然 OP 变化 | 控制器正常调节输出 | 可用于闭环模型估计 |
| 负荷扰动 | 上游负荷、流量、压力变化 | 可用于扰动响应分析 |
| 操作事件 | 班组操作、工艺切换 | 可作为窗口边界或剔除条件 |
| 报警事件 | 报警触发前后 | 可用于诊断，不一定适合整定 |
| 专家标注窗口 | 工程师选择典型时段 | 用于交互式整定和复核 |

### 6.3 窗口评分

建议将窗口评分拆为五个维度：

| 维度 | 说明 |
|---|---|
| 数据质量分 | 好值率、缺失率、冻结率、时间戳连续性 |
| 激励充分分 | SP/OP/PV 变化幅度、变化持续时间、信噪比 |
| 工况稳定分 | 负荷、产品牌号、工艺约束是否稳定 |
| 控制有效分 | MODE、OP 饱和、手自动切换、控制作用有效性 |
| 干扰可解释分 | 是否存在可标记扰动，是否能区分主扰动和外部扰动 |

窗口评分低于阈值时，不应进入高可信自动建议，只能进入专家参考或交互式整定。

## 7. 数据激励指数

### 7.1 定义

数据激励指数用于回答：

> 这段历史数据是否足以支撑可靠的模型辨识和 PID 参数整定？

建议采用 `0-100` 分制，并输出等级。

| 等级 | 分值 | 含义 |
|---|---:|---|
| A | 80-100 | 激励充分，可支撑模型辨识和整定建议 |
| B | 60-79 | 激励基本可用，建议专家复核 |
| C | 40-59 | 激励不足，只能低可信参考 |
| D | 0-39 | 不适合辨识和整定 |

### 7.2 评分因子

| 因子 | 示例口径 |
|---|---|
| 输入变化幅度 | SP 或 OP 变化相对量程、噪声水平的倍数 |
| 响应可观测性 | PV 是否有明显、连续、方向一致的响应 |
| 信噪比 | 响应幅度与过程噪声的比例 |
| 动态覆盖 | 数据是否覆盖滞后、上升、接近稳态等阶段 |
| 多样性 | 是否包含多个有效扰动或多个操作区间 |
| 干扰可分离性 | 是否能区分主输入变化和外部扰动 |

### 7.3 产品表达

系统界面不应只显示一个分数，还应显示原因：

- 激励不足原因。
- 使用的数据窗口。
- 主要输入变化。
- 主要 PV 响应。
- 是否建议人工补充试验或交互式整定。

## 8. 过程模型辨识

### 8.1 模型类型

首版建议支持工程可解释模型，而不是优先使用黑盒模型。

| 模型类型 | 适用对象 |
|---|---|
| 一阶惯性加纯滞后模型 | 大部分温度、压力、流量、液位调节回路 |
| 二阶模型 | 响应存在明显二阶动态或滞后叠加的回路 |
| 积分对象模型 | 液位、库存类非自衡对象 |
| 反向作用模型 | 输出增加导致 PV 下降的对象 |
| 多工况模型 | 同一回路在不同负荷或操作区间表现不同 |

### 8.2 闭环辨识约束

由于系统不能主动激励，只能利用闭环运行数据。闭环辨识必须处理以下问题：

- 输入和输出受控制器反馈影响，不是开环独立数据。
- SP、OP、PV 的变化可能由外部扰动共同驱动。
- 控制器参数、限幅、死区会影响可观测响应。
- 阀门粘滞和输出饱和会污染模型。

因此模型辨识前必须先执行窗口筛选、故障诊断和数据激励评价。

### 8.3 模型质量评价

模型质量不只看拟合曲线是否接近，还应综合评价：

| 指标 | 含义 |
|---|---|
| 拟合优度 | 模型输出与实际 PV 的贴合程度 |
| 残差结构 | 残差是否接近随机，是否存在周期性或趋势性 |
| 参数合理性 | 增益、时间常数、滞后时间是否符合工程常识 |
| 工况一致性 | 模型对应的数据窗口是否属于同一工况 |
| 抗扰鲁棒性 | 模型在相邻窗口或复评窗口上是否仍可解释 |
| 专家认可度 | 专家是否确认模型方向、时滞、响应速度合理 |

### 8.4 模型状态

| 状态 | 含义 |
|---|---|
| 已验证 | 数据、拟合、残差、专家复核均通过 |
| 可用 | 自动评价通过，但尚未专家确认 |
| 待复核 | 存在不确定性，需要专家检查 |
| 低可信 | 只能作为参考，不建议直接用于参数实施 |
| 失效 | 工况变化或复评失败，不再用于建议 |

## 9. 参数候选计算

### 9.1 参数输出方式

系统不应只输出唯一一组 PID 参数，而应输出候选参数集。

| 参数类型 | 设计目标 |
|---|---|
| 保守型 | 优先稳定性和鲁棒性，适合安全关键或扰动频繁回路 |
| 平衡型 | 在响应速度、稳定性和阀门动作之间折中 |
| 快速型 | 提高响应速度，适合对跟踪性能要求高的回路 |
| 低动作型 | 降低 OP 频繁动作和阀门磨损 |
| 专家型 | 基于专家约束或交互输入生成 |

### 9.2 参数计算输入

| 输入 | 说明 |
|---|---|
| 过程模型 | 模型类型、增益、时间常数、滞后、积分特性 |
| 当前 PID 参数 | 当前 P/I/D、控制方向、单位、算法形式 |
| 控制目标 | 响应速度、超调约束、稳态误差、鲁棒性 |
| 工艺约束 | 输出限幅、设定值范围、安全边界、质量约束 |
| 设备约束 | 阀门动作频率、执行机构限位、死区、粘滞 |
| 风险偏好 | 保守、平衡、快速、低动作 |

### 9.3 参数建议边界

系统必须识别并提示：

- 当前 DCS 的 PID 算法形式和参数单位。
- 正反作用方向。
- 比例、积分、微分的允许范围。
- 积分单位差异，例如秒、分钟、重复次数。
- 输出上下限和抗积分饱和策略。
- 微分作用是否启用以及是否适合当前测量噪声。

## 10. 闭环仿真验证

### 10.1 仿真目的

闭环仿真不是为了替代现场验证，而是为了在人工实施前降低风险，回答：

- 建议参数是否稳定？
- 相比当前参数是否有改善？
- 是否存在明显超调或振荡风险？
- 输出动作是否过大？
- 是否满足工艺约束？

### 10.2 仿真输出

| 输出 | 说明 |
|---|---|
| 闭环阶跃响应 | 当前参数和建议参数的响应曲线 |
| 超调量 | PV 超过目标值的幅度 |
| 调节时间 | PV 进入并保持在允许误差带内的时间 |
| 稳态误差 | 达稳态后的偏差 |
| 输出动作幅度 | OP 最大变化和累计动作 |
| 频域稳定裕度 | 稳定裕度或频域风险等级 |
| 鲁棒性评价 | 模型参数扰动下是否仍稳定 |

### 10.3 风险分级

| 风险等级 | 判定逻辑 |
|---|---|
| 低风险 | 仿真稳定，超调小，输出动作合理，鲁棒性良好 |
| 中风险 | 仿真改善但存在超调、输出动作或工况边界不确定性 |
| 高风险 | 接近不稳定、输出动作过大或模型可信度不足 |
| 不建议实施 | 仿真不稳定、模型低可信或安全约束不满足 |

## 11. 整定可信度体系

### 11.1 可信度定义

整定可信度用于评价：

> 这组 PID 参数建议是否足以进入人工审核和现场实施？

可信度不是单一算法输出，而是综合评分：

`整定可信度 = 数据可信度 * 0.20 + 激励充分度 * 0.20 + 模型可信度 * 0.25 + 仿真可信度 * 0.20 + 工况匹配度 * 0.10 + 专家确认度 * 0.05`

权重应可配置并版本化。首版可采用上述默认权重，后续根据项目复评效果调整。

### 11.2 评分维度

| 维度 | 权重 | 说明 |
|---|---:|---|
| 数据可信度 | 20% | 好值率、缺失率、冻结率、时间戳、质量码 |
| 激励充分度 | 20% | 数据激励指数、响应可观测性、信噪比 |
| 模型可信度 | 25% | 拟合、残差、参数合理性、工况一致性 |
| 仿真可信度 | 20% | 稳定性、超调、调节时间、频域裕度、鲁棒性 |
| 工况匹配度 | 10% | 建议参数适用工况与当前生产工况一致性 |
| 专家确认度 | 5% | 专家是否确认诊断、模型和建议参数 |

### 11.3 可信度等级

| 等级 | 分值 | 系统处理 |
|---|---:|---|
| 高可信 | 80-100 | 可提交正式审核，建议实施前仍需人工确认 |
| 中可信 | 60-79 | 可提交专家审核，但需明确风险和适用边界 |
| 低可信 | 40-59 | 仅作参考，不建议直接实施 |
| 不可信 | 0-39 | 不输出实施建议，转交互式整定或现场核实 |

### 11.4 可信度解释

每次可信度评分必须输出：

- 总分和等级。
- 各维度得分。
- 扣分原因。
- 关键证据。
- 是否建议实施。
- 必要的现场确认事项。
- 推荐回退参数。

## 12. 故障诊断证据链

### 12.1 诊断输出结构

每条诊断结论应采用统一结构：

| 字段 | 说明 |
|---|---|
| 问题类型 | 偏差、振荡、阀门、仪表、扰动、耦合、数据质量、PID 参数 |
| 严重度 | 高、中、低 |
| 置信度 | 诊断规则和证据支持程度 |
| 证据 | 趋势、频谱、事件、统计指标、规则命中 |
| 可能原因 | 工艺、仪表、阀门、控制参数、操作、外部扰动 |
| 建议动作 | 现场核实、维护检查、参数整定、继续观察 |
| 是否可整定 | 是、否、待确认 |

### 12.2 典型诊断逻辑

| 诊断类型 | 关键证据 | 建议动作 |
|---|---|---|
| PID 参数不当 | 振荡、超调、调节时间长，阀门和仪表未见明显异常 | 进入模型辨识和整定建议 |
| 阀门粘滞 | OP 存在黏滑、PV 呈周期波动、粘滞系数高 | 建议阀门检查，调参仅作辅助 |
| 输出饱和 | OP 长时间处于上限或下限 | 检查工艺能力、阀门容量、设定值合理性 |
| 仪表异常 | PV 冻结、噪声突变、质量位异常、漂移 | 建议仪表核查，暂停整定 |
| 过程扰动 | 多回路同时受负荷或上游变量影响 | 识别扰动源，避免误判为 PID 问题 |
| 分布式振荡 | 多回路同频振荡，存在传播链路 | 定位源头回路，优先处理源头 |
| 回路耦合 | 变量相关性高且存在滞后传播 | 提示耦合风险，必要时建议 APC 或解耦策略 |

## 13. 交互式整定

### 13.1 触发条件

满足任一条件时进入交互式整定：

- 数据激励指数低。
- 模型拟合差或残差不合格。
- 回路长期平稳但参数明显保守，缺少有效扰动。
- 回路长期手动或自动时间不足。
- 专家认为历史数据不能代表当前工况。
- 招标或服务项目要求对特定回路给出专家建议。

### 13.2 交互方式

| 方式 | 输入 | 输出 |
|---|---|---|
| 趋势线法 | 用户选择趋势区间、响应起点、终点、稳态趋势 | 估计过程增益、时间常数、滞后和参数建议 |
| 特征点法 | 用户标注关键时间点和响应特征点 | 估计模型参数和候选 PID |
| 专家经验库 | 回路类型、对象特性、控制目标、行业经验 | 推荐整定策略和参数范围 |
| 相似回路迁移 | 相似回路、相似工况、历史模型和参数 | 给出候选参数、相似性依据和可信度 |

### 13.3 交互整定输出

交互式整定必须输出：

- 用户输入和标注记录。
- 计算出的对象特性。
- 建议参数和参数范围。
- 闭环仿真结果。
- 可信度等级。
- 专家意见。
- 是否建议进入实施审核。

## 14. 迁移学习建议

### 14.1 产品化定义

首版不应把迁移学习设计成不可解释的黑盒模型，而应产品化为：

> 相似回路模型库 + 相似工况匹配 + 专家规则 + 可信度说明。

### 14.2 相似性维度

| 维度 | 说明 |
|---|---|
| 回路类型 | 温度、压力、流量、液位、成分等 |
| 过程对象 | 自衡、非自衡、积分、纯滞后、反向作用 |
| 工况区间 | 负荷、产品、操作条件 |
| 模型参数 | 增益、时间常数、滞后、噪声水平 |
| 控制目标 | 稳定优先、快速跟踪、低输出动作 |
| 设备特性 | 阀门类型、执行机构、量程、死区 |

### 14.3 输出约束

迁移建议必须输出：

- 来源回路。
- 相似性依据。
- 差异风险。
- 适用边界。
- 建议参数范围。
- 可信度。
- 不自动下写 DCS 声明。

## 15. 人工审核与实施边界

### 15.1 审核前置条件

进入人工审核前必须满足：

- 回路台账和点位映射已确认。
- 数据窗口和模型版本已固化。
- 诊断结论已生成。
- 建议参数、仿真结果、可信度和回退参数已生成。
- 风险和适用边界已明确。
- 若存在阀门、仪表或工艺异常，必须有专家确认意见。

### 15.2 实施记录

系统只记录实施，不执行实施。实施记录应包含：

- 实施人。
- 实施时间。
- DCS 原参数。
- DCS 新参数。
- 实施窗口。
- 生产工况。
- 审核意见。
- 回退方案。
- 观察期。

### 15.3 实施后复评

复评至少比较：

- 自控率。
- 有效自控率。
- 平稳率。
- 性能评分。
- 偏差均值和波动。
- 振荡状况。
- 报警次数。
- 操作频次。
- OP 饱和率和输出行程。
- 是否引入新风险。

## 18. 原型验证方案

### 18.1 离线数据集验证

使用历史数据构建验证集：

- 已知优化有效的回路。
- 已知阀门粘滞回路。
- 已知仪表异常回路。
- 已知扰动主导回路。
- 数据激励充分和不足的对照样本。

验证目标：

- 可整定性判定是否合理。
- 故障诊断是否命中。
- 模型辨识结果是否符合专家判断。
- 可信度评分是否能区分高风险和低风险建议。

### 18.2 专家盲评

让专家在不看系统结论的情况下独立判断：

- 问题类型。
- 是否适合整定。
- 合理模型类型。
- 参数调整方向。
- 实施风险。

然后与系统结论对比，形成一致性指标。

### 18.3 影子模式验证

系统上线初期只做影子运行：

- 不参与实际参数变更决策。
- 持续生成整定建议和可信度。
- 与人工专家建议对照。
- 与后续实际整定效果对照。

通过影子模式验证后，再进入专家审核辅助流程。

### 18.4 实施后复评

每次人工实施后，系统自动评价：

- 是否改善。
- 改善幅度。
- 是否产生副作用。
- 可信度评分与实际效果是否一致。

这些结果应反向用于修正评分权重和专家规则。

## 19. 验收标准

### 19.1 算法功能验收

- 能从历史数据中自动挖掘可辨识窗口。
- 能输出数据激励指数和原因说明。
- 能对至少一类可解释模型完成辨识并输出模型质量。
- 能输出至少三类候选参数：保守型、平衡型、快速型。
- 能完成当前参数和建议参数的闭环仿真对比。
- 能输出整定可信度、风险等级、适用边界和回退参数。
- 能在数据不足时进入交互式整定流程。
- 能对阀门粘滞、过程扰动、回路耦合、分布式振荡给出诊断证据。

### 19.2 工程安全验收

- 算法模块无任何 DCS 写入能力。
- 所有建议参数必须经过人工审核才可进入实施记录。
- 所有参数实施均由人员在 DCS 中完成，系统只记录和复评。
- 低可信建议不得进入自动实施或默认实施状态。
- 每条建议均保留原参数和回退方案。

### 19.3 可解释性验收

- 每个诊断结论能展开证据链。
- 每个模型能查看数据窗口、模型参数、拟合和残差。
- 每个可信度评分能查看分项得分和扣分原因。
- 每个参数建议能查看仿真曲线、风险提示和适用边界。

## 21. 关键风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 历史数据激励不足 | 模型辨识不可靠 | 数据激励指数、交互式整定、专家经验库 |
| 阀门或仪表问题误判为 PID 问题 | 参数建议无效或引入风险 | 先诊断后整定，维护建议优先 |
| 闭环数据辨识偏差 | 模型不代表真实过程 | 多窗口验证、残差检验、专家复核 |
| 可信度评分失真 | 高风险建议被误认为可实施 | 影子模式、实施后复评、权重校准 |
| 迁移建议不可解释 | 用户不采纳或验收困难 | 明确相似性依据、适用边界和风险 |
| 用户误解为自动改参数 | 安全风险和责任边界不清 | 产品文案、权限、流程均强调只读和人工实施 |
