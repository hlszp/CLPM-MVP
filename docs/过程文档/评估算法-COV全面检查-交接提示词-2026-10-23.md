## 4. 本轮已发现但尚未修复的问题

### A. 已复现：除 PV 外的角色质量码在取数链丢失

- `logical_wide_builder.py` 约 531–532、588–599 行只收集并返回 `pv_quality`。
- `tdengine_provider.py` 约 219、233 行继续只透传 `pv_quality`。
- 前一代理内存端到端复现：PV 为 Good，其余六角色全 Bad，结果 `quality_keys=['pv_quality']`，7 角色 validity 全为 10/10，回路有效率 1、可信度 A。
- 原始复现脚本未归档，接手后须自行重现并写有意义的回归，不能仅把代理报告当修复验收。
- 候选修复：7 角色质量与值使用相同因果状态、同步 ZOH；provider 通用透传；pipeline 已有按角色质量识别机制可复用。缺失质量不能编造 Good。
- 注意现行文档说“数据质量主要针对 PV”；此次需核实各算子实际依赖，不能把 7 角色简单全部 AND 成新的统一硬门禁。缺少未使用 PID 不应使普通评估无法计算。

### B. 已复现：状态锚点的 coverage_until 被丢弃

- `backend/app/models/point_history.py` 约 254–255 行规定 `PointStateAnchor.coverage_until` 是半开有效终点。
- builder 约 417–424 行将 anchor 变成虚拟事件时丢掉此字段，`_PointStream.state_at` 随后无限保持。
- 前一代理复现：anchor 时刻 -10 秒、coverage_until=3 秒，无后续事件，查询 0..9 秒，却得到 10 个 known；按有效终点应仅 0/1/2 秒可用。
- 接手后重现；修复时区分“普通 COV 事件合法持续保持”与“有明确有效上界的锚点”，保证后续真实事件可恢复，不能回退到更旧状态越过到期边界。

### C. 待复现：数值有效性掩码可能忽略 UNKNOWN/gap

- `preprocessing/validity_mask.py` 的 `apply_mask/_evaluate_mask` 只读 DataBlock.validity。
- builder 为审计保留 gap 内的 Good 数值；pipeline 另在 coverage/连续段中标未知，因此部分普通 mask 可能仍把未知槽送进 A/S/统计或动态算子。
- 需要按真实 Pipeline → Assembler → Calculator 链复现，区分已正确使用时间视图/连续段的指标和确实漏掉的指标。
- 核对删除坏槽后拼接时间序列是否制造假阶跃、假连续、假振荡。不得未经验证直接全局改 mask。

### D. 已知需解释的 QUALITY_HF 口径

- QUALITY_HF 只有 `pv_quality`，共享 PV/OP 核心集合为空，故组级 valid_rate=0/conf=E；好值率仍可能从质量摘要返回 100。
- 已独立验证：该组 E 不会单独阻断 composite，综合评分仅检查 R/A/F/S。
- 全面审查时可检查该可信度表达是否应改，但不能误判为本次空分根因，也不能强行把无依据状态改成 A。

## 5. 全面检查范围与完成标准

建立“角色/指标 → 输入来源 → ZOH/质量/coverage → 算法 → 输出/可信度 → 测试证据”矩阵。至少覆盖：

1. **7 角色数据链**：UUID 映射、当前与历史绑定、窗前初值、空窗有初值、完全无初值、稀疏及常量、质量变化但值不变、Bad/Unknown、None/NaN/Inf、子秒/乱序/重复时间、锚点有效期、真实 gap 和恢复、改绑、量程/单位边界。
2. **预处理与时间口径**：ZOH 因果性，不未来回填、不线性插值；各角色按语义使用量程和离散域；PID/MODE 不误套 PV 范围；UNKNOWN、validity、连续段和 metric mask 一致；采样间隔与实际网格一致。
3. **所有评估计算器**：准确率、快速率、平稳/稳定率、有效自控率、自控率、饱和率、好值率、振荡、整定时间、时间常数、阀门/粘滞、输出行程、统计等，按当前注册表枚举，不只看主评分。检查分母、缺失依赖、最少数据、异常输入、恒值、有效零值、浮点边界、动态时间连续性和参数单位。
4. **综合评分与可信度**：R/A/F/S 缺失或 E 的传播；合法 0 与 NULL 区分；权重和归一化；指标依赖质量不能被组级可信度掩盖。保持用户已有业务口径，不为“有分”降低真实数据保护。
5. **所有正式入口**：定时、backfill、custom 都只查本地 TDengine，正确使用同一 ZOH 和参数快照；缓存版本/键/派生组正确；无静默截断、远端降级、异常吞成空或伪正常。
6. **持久化与消费**：hourly/custom、结果记录、任务状态、覆盖重算、并发/幂等和聚合一致；不能只看 Celery SUCCESS，须看业务结果；评分缺失及低分前后端传递正确。计算使用全量时序，不混用趋势 LTTB 展示数据。
