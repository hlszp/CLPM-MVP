## 1. 冻结结论

当前设计已经具备启动原型系统开发的条件。

原型系统定位为：**正式产品全景导航 + P0 主链高保真可点击原型**。

本原型不是正式后端系统，不直接接入 DCS，不实现真实算法计算，不承诺 P1/P2/P3 全量能力。P1/P2/P3 在首期原型中只做结构展示和版本标注。

## 3. 技术栈冻结

| 层级 | 冻结选择 | 理由 |
|---|---|---|
| 前端框架 | React + Vite + TypeScript | 快速开发、组件化、后续可扩展为正式前端 |
| 路由 | React Router | 支持完整菜单、深链接、可点击演示路径 |
| 图表 | Apache ECharts | 适合趋势、状态带、雷达、分布、对比等工业数据图表 |
| 图标 | lucide-react | 轻量、统一、适合工作台和管理界面 |
| 样式 | 原生 CSS + design tokens | 保持可控，不引入重型设计系统依赖 |
| 数据 | 本地 TypeScript/JSON mock data | 支撑离线演示，不依赖后端 |
| 测试 | Playwright smoke test | 验证关键页面可打开、主链可点击、桌面和窄屏不崩 |
| 运行 | `npm install` + `npm run dev` | 本地启动门槛低 |

不采用：

| 技术 | 暂不采用原因 |
|---|---|
| 后端服务 | 首期原型只验证用户视角和交互，不需要真实 API |
| 数据库 | 样例数据足以支撑验证 |
| Tailwind / UI 套件 | 当前需要工业产品定制界面，避免套件味过重 |
| 真实 OPC / historian 接入 | 属于工程实现，不进入原型阶段 |

## 4. 原型开发任务

### 4.1 目标

原型必须让评审人员在浏览器中看清：

1. 完整产品未来有哪些一级/二级模块。
2. 首期 P0 主链如何从样本验证走到证据包。
3. 数据不足、不可判定、需现场核实不是系统失败，而是可信结论。
4. 平台只读 DCS，只输出建议、证据、风险和回退。
5. P1/P2/P3 能力存在规划入口，但不形成 P0 交付承诺。

### 4.2 首期必须走通的主链

```text
工程首页
  -> 样本批次 / 数据导入 / 就绪校验
  -> 回路清单 / 点位映射 / 台账校核
  -> 指标总览 / 低效排行
  -> 诊断清单 / 回路证据
  -> 建议审核 / 实施记录 / 观察复评
  -> 证据包 / 样本报告
  -> 管理首页
```

### 4.3 非目标

| 非目标 | 说明 |
|---|---|
| 真实后端 | 不开发 API 服务 |
| 真实算法 | 不实现模型辨识、PID 整定算法、诊断算法 |
| 真实 DCS 接入 | 不接 OPC，不写 DCS |
| 5 年查询 | 只做结构展示 |
| 批量整定 | 只做 1 个可信整定样例 |
| 项目交付全流程 | 只做 P2 规划入口 |

## 7. 原型验收标准

| 验收项 | 标准 |
|---|---|
| 主导航 | 11 个一级菜单可见，P1/P2/P3 有版本标签 |
| P0 主链 | 从工程首页到证据包能连续点击走通 |
| 双入口 | 工程首页和管理首页信息层级明显不同 |
| 数据可信表达 | 数据不足、不可判定、需现场核实有明确状态和原因 |
| 证据链 | 至少 3 条典型诊断样例可展开 |
| 整定样例 | 仅 1 条样例，明确不代表批量整定 |
| 安全边界 | 页面明确显示不写 DCS、人工实施、审计留痕 |
| 响应式 | 桌面可用，窄屏不重叠、不截断关键内容 |
| 浏览器验证 | 本地启动后用浏览器打开核心页面并截图检查 |
