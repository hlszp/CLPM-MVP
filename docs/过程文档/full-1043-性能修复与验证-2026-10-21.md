## 修复与行为差异

| 落点 / 关键函数 | 原问题 | 本批行为 |
|---|---|---|
| `diagnosis_orchestrator.py` / `run_diagnosis_for_loop` | 同回路同窗的历史 SUCCESS 被独立新任务复用，新任务查不到自己的结果 | 成功复用限制在同一 task_id；两次独立复诊分别保留配置、证据及结果 |
| `outlier_detection.py` / `detect_all` | 多种检测反复转换和逐点扫描同一数组 | 一次数值转换，向量化范围、跳变、尖峰及无效值判断；保留阈值、原因顺序与输入不可变性 |
| `data_quality_assessor.py`、`pipeline.py` | 多信号重复检查时间轴、重复分配掩码 | 共享时间异常结果，复用数组，数值及质量结论等价 |
| `logical_wide_builder.py` | 历史事件与窗口初始状态串行；缓存保留了上次查询步长的放大值 | 两类独立读取并发且异常时等待收尾；缓存原始配置，每次按当前步长计算有效值 |
| `tdengine_provider.py` | 网格组装重复构造缺省数组及排序复制 | 缺省数组单次构造；单段已排序、长度一致的网格走直接组装路径，其余保持通用合并 |
| `point_history_repository.py` / `read_events` | 跨点分页边界时间相同，严格大于游标可能漏行 | 边界包含同时间戳并按点去重；保留页数上限与无进展显式报错 |
| `core/tdengine_native.py` | 长读取可占满共享线程，写入只能等待 | 保留 8 个读线程，独立 2 个写线程；SQL 写操作与有效写入量查询使用写池 |
| `celery_app.py` / `AsyncTask.apply_async` | 父类先注入默认 9，使继承开关无法保留人工任务级别 | 默认注入前继承父请求真实优先级；调用者显式指定优先级时仍以指定值为准 |
| `kpi_calc.py` / 自定义批量评估 | 整批预热完成前首个回路不能计算，且可能重复读取/预处理 | 走已有有界 DataPlanner 按需加载路径，移除整批预热屏障 |
| `views/task/list.vue` | 诊断中间进度刷新间隔较长，缺少自动刷新回归 | 诊断 3 秒轮询，其他任务仍为 5 秒；增加可访问进度值，并验证自动更新、终态绿色和固定计时 |

未调整质量码映射、诊断阈值、指标公式、COV 因果填充或数据门禁。
没有新增 Worker/Beat、模块级 asyncio 锁或数据库迁移；head 仍为 `p703report01`。
原有历史导入一小时分片及有界并发保持，不以盲目增大并发换取不确定吞吐。

## TDengine 原生能力核查

| 用途 | 当前实现 | 核查结果 |
|---|---|---|
| 窗口初始状态 | `LAST_ROW`，按点查询并排除 NULL 值 | 真实 3.3.6.6 验证 NULL 不盖掉有效种子；Bad 有值状态仍保留 |
| 趋势分桶 | `LAST`、`PARTITION BY point_id`、`INTERVAL`、`FILL(PREV)` | 已在数据库内分桶，真实库验证了桶值与前值填充 |
| 导入与实时写入 | 点仓储批量 INSERT 每块 500 行；历史直导每块 5000 行，同子表同 ts UPSERT | 重复写入后 COUNT 物理行数不增长；实时冲突策略由仓储控制，历史直导不执行前置 DELETE，导入窗口保留 5 分钟保护 |
| 诊断 / 评估原始输入 | 本地 TDengine 原始事件，加质量、缺口、因果填充及掩码 | 原始波形和坏点位置参与算法，不能直接统一替换成 AVG 或粗粒度聚合 |
| 已落地指标汇总 | PostgreSQL 中的 KPI / 诊断快照聚合 | 避免报表重复扫描原始波形；不需要为了使用 TDengine 而迁移所有业务汇总 |

文件名虽为 `tdengine_native.py`，连接器实际使用 taosrest HTTP REST；原生 SQL 函数和 libtaos 原生协议是不同概念。
本批没有未经测量地切换连接驱动。原生聚合可减少返回量，但不能消除 Python 重复处理、整批预热或 Celery 排队。
诊断数值语义要求读取原始数据；本次优先优化已经确认的处理与调度问题。
