## 四、为什么归档量远小于预期（2026-09-26 实测）

本次尝试批量归档时，用"单次扫描收集被引用的文件名"做安全检查，结果：

- 顶层 81 个 `.md` 中，**22 个文件名被其它文件引用**（含互相引用），只有 **1 个**满足"零引用"条件；
- 其余多为**中文/主题命名**的工程记录（宽表、诊断、断点续传、IA 优化等），它们之间有大量交叉引用，
  贸然移动会造成链接失效、追溯链断裂。

**结论**：本目录的"降噪"不能靠移动实现，需二选一（待决策）：
1. **移动 + 同步改引用**（把所有引用路径一起改，改动面较大，但可一次性整理干净）；
2. **只登记不移动**（沿用 `docs/过程文档/stale-docs.md` 的既有口径：标注失效/归档状态，不挪文件）。

本次采用最小动作：只移动了 1 个真正无引用的文件，并建立本索引，避免制造断链。
