## 0. 结论速览（先读这一节）

| # | 问题 | 判定 | 一句话结论 |
|---|---|---|---|
| 1 | 能否"一键"从回路直接拿到粗推荐 P/I/D？ | **否，但已接近（深链进入仅需 1 次点击）** | 唯一必需的人工动作是点一次「开始辨识」；辨识成功后**矩阵自动全算 5 套 P/I/D**，无需人工选算法。但**没有任何不跑辨识就出数的路径**。 |
| 2 | 后端是否有"默认推荐"逻辑（查表 / Z-N / 知识库）？ | **否** | 所有出数端点都强制 `modelSource` + 服务端已验证模型（`authorize_tuning_model`）。知识库 `tuning_knowledge` 只读、不回流、前端页面已删、当前 0 条。 |
| 3 | 四步流程哪几步对"粗推荐"必要？ | **①必要、②自动、③④可跳过** | ① 过程辨识 = 硬前提（不可跳过）；② 整定矩阵 = 出数步但**自动触发**；③ 闭环仿真 与 ④ 方案保存 = 仅"落库/验证"需要，对"看到粗推荐"不必要。 |
| 4 | 仿真是同步还是异步？ | **同步 HTTP** | `POST /tuning/compare` 同步返回曲线+指标；虽实现了异步版 `tune_and_simulate_task`，但**无任何调用方**（死链路）。 |
| 5 | 适用性门禁是否让用户"看不到入口也不知道为什么"？ | **入口可见、原因可见，但存在静默放行** | L0/L1 按钮 disabled + Tooltip + Toast 三级提示（文案含等级与原因标签）；但 `loadFitness` 失败即降级为"未评定"并**放行**。另有 1 处 UI 文案与现行裁决相矛盾。 |

**一句话总评**：链路是"**选回路 → 点一次开始辨识 → 自动出 5 套 P/I/D**"，已接近"低门槛"，但仍**必须跑完整过程辨识（异步 Celery，默认候选含 SOPDT）**，且**不告诉用户该选哪一套**；同时"从评估/诊断结论直接发起"只做到"深链预选回路"，未做到"带着诊断结论一键出参"。

### 2.1 点击计数（实测口径）

| 进入方式 | 人工点击次数（到屏幕上出现 P/I/D） | 说明 |
|---|---|---|
| 深链进入（E2/E3/E4/E5/E6，带 `?loopId=`） | **1 次**（点「开始辨识」）+ 等待 | 时间窗已有默认值 |
| 菜单进入（E1） | **2 次**（点回路行 → 点「开始辨识」）+ 等待 | — |
| 命中 C 级可信度 | **+1 次**（风险确认弹窗 `composable:395-417`） | 后端 `ERR_TUNING_RISK_CONFIRMATION_REQUIRED` |

### 2.2 关键结论

- **可以"一次点击出 5 套粗推荐"**（辨识成功后矩阵自动触发），这是现状最接近用户诉求的地方。
- **不能"零辨识出数"**：`authorize_tuning_model` 在 `model_source is None` 时直接 400（`backend/app/services/tuning.py:120-125`），`tune_pid` 无 `source_context` 时直接 400（`:1356-1361`）。
- "算法矩阵"这一环**已从用户负担中移除**（自动跑 5 算法），但**"选哪一套"的负担仍然留给用户**（矩阵 5 行全部 `checked: false`，`composable:447,458`；无排序、无评分、无默认勾选）。
- 人工修改模型入口（`identify-section.vue:246-253`「手动修改模型」）**只在已有辨识结果后出现**（`v-if="outcome"` `:228`），因此**不存在"从零手填模型直接出参数"的路径**。

### 3.3 是否存在"默认推荐"（不选算法矩阵也能出结果）？

| 候选机制 | 是否存在 | 证据 |
|---|---|---|
| 基于回路类型查表（loop_type → P/I/D） | **不存在** | 全仓 grep 无 `粗推荐/一键` 命中；`tuning_knowledge.py` 无查表结构 |
| Z-N 经验默认（不跑辨识） | **不存在** | ZN 只是 5 算法之一，且必须传入已验证 FOPDT（`services/tuning.py:1416-1419`） |
| 知识库回流推荐 | **不存在** | `tuning_knowledge.py:76-176` 仅在 ActionTracker 验证完成时聚合快照；`recommend_similar`（`:279-316`）只返回 `pidBefore/pidAfter` 供人看，**从未被 tune_pid 消费** |
| 算法默认（不选算法） | **部分存在** | `/tune/matrix` 固定 5 算法全算（`endpoints/tuning.py:353`）；异步任务默认 `["IMC"]`（`tasks/tuning.py:683`） |
| 免算法的同步串联端点 | **存在但需完整入参** | `POST /api/v1/algorithms/tuning/calculate`（`endpoints/algorithms.py:377-521`）一次串联 `identify_model → tune_pid → run_simulation`，但入参需 `identificationParams.dataSegment` 起止时间 + `tuningParams.method`，**且前端无任何调用方**（grep `tuning/calculate` 于 `frontend/apps/web-antd/src` 零命中） |

**判定**：**不存在**任何"给定 loopId 直接返回粗推荐 P/I/D"的接口。最小入参 = 一个**服务端已验证的 FOPDT 模型**（`K/tau/theta` + `sourceRecordId` 或 `modelSource=MANUAL + riskConfirmed`）。

## 5. 必答问题 5：适用性门禁（L0~L4）现状

### 5.1 规则（代码为准）

| 等级 | 语义（`backend/app/services/loop_fitness.py:6-11`） | 整定是否放行 | 证据 |
|---|---|---|---|
| L0 | 不可评估（数据严重不足） | **阻断 400** `ERR_TUNING_FITNESS_INSUFFICIENT` | `endpoints/tuning.py:122-138` |
| L1 | 仅可监视（手动主导/自控率极低） | **阻断 400** | 同上 |
| L2 | 条件异常（OP 饱和 / SP-PV 偏离） | **放行**（2026-10-01 裁决，原为阻断） | `endpoints/tuning.py:110-113,122`（`BLOCK_LEVELS={"L0","L1"}`） |
| L3 | 待激励（无激励/响应极弱） | **放行**，仅前端前置提示 | `loop_fitness.py:9,13-14` |
| L4 / 未评定(null) | 可优化 / 尚未评定 | 放行 | `loop_fitness.py:11`；`endpoints/tuning.py:120-121` |

- 门禁挂载点：`/identify`（:171）、`/identify/history`（:210）、`/tune`（:290）、`/tune/matrix`（:342，T4 补齐）；异步任务内二次兜底 `tasks/tuning.py:205`、`:470`。
- **fail-open 两处**：fitness 记录缺失 → 放行（`endpoints/tuning.py:120-121`）；查询异常 → 放行（`:117-118`）。
- 后端注释漂移：`:170`/`:209`/`:289` 仍写「L3 以下阻断」，与实现（L2 已放开）不符。

### 5.2 前端门禁（三级提示，**入口不隐藏**）

| 机制 | 位置 |
|---|---|
| `tuningDisabled = (level === 'L0' \|\| level === 'L1')` | `composable/use-tuning-workbench.ts:138-143` |

3. 菜单可见但路由不可达：整定菜单 authority 含 `PE_ENGINEER/SPONSOR`（`router/routes/modules/tuning.ts:22-27`），但 `/tuning/workbench` 仅 `ADMIN/IC_ENGINEER/EXPERT`（`:33`）→ VIEW 角色点菜单落到 403。

### 7.4 给需求的直接回答

> **"对于需要参数整定的，可以直接发起整定、仿真，计算粗推荐的整定参数"**

- **"直接发起"**：✅ 已具备（6 类入口，深链预选回路；1 次点击「开始辨识」）。
- **"仿真"**：✅ 已具备（同步、秒级、曲线+指标），但**不是出参必经步骤**。
- **"粗推荐参数"**：⚠️ 已具备但**门槛高于"粗推荐"预期**——必须跑完整过程辨识（异步、≤120s、依赖本地历史数据激励），且默认候选含 SOPDT 有全矩阵失败风险（G3），出参后还需用户自选（G5），并且**没有任何"零辨识/查表/知识库"的兜底默认**（G1/G4）。
- **最小改造方向**（供决策，不在本次核验范围）：① 给 `tune_and_simulate_task` 补一个"回路 ID → 辨识 + 全算法 + 仿真"的单一端点（G2 能力已就绪）；② 辨识候选强制 `FOPDT` 或补齐 SOPDT 整定公式（G3）；③ 矩阵加"推荐度排序 + 默认勾选"（G5）。
