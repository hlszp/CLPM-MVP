§A框架层 · index.vue + HeaderBar

工作台外框与跨 Tab 全局组件。优化目标：腾出垂直空间、统一状态色语义、工具栏分组。

A1tabbar 48px 偏高index.vue
现状

tabbar 高度 48px，5 个 tab 按钮单行排列

问题

工业 SCADA 单行 tab 通常 32-36px；48px 浪费 12px 垂直空间，挤压 816px 内容区

方向

压到 36px，腾出的 12px 给内容区；tab 按钮内边距同步收紧

AGENTS.md 视觉偏好：空间紧凑、去冗余
A2ModuleStatusDot 状态点语义未对齐index.vue + ModuleStatusDot.vue
现状

5 tab 各带状态点，颜色含义未明确，无图例

问题

用户不知道圆点颜色指什么（运行？告警？数据缺失？），Glanceability 不足

方向

状态点统一映射 7 色约定；statusbar 右侧加固定图例；hover 显文字 tooltip

绿 运行 蓝 启动 橙 停止 黄 待命 红 维护 灰 禁用 青 检查中
AGENTS.md 状态色约定
A3HeaderBar 工具未分组HeaderBar.vue L78-181
现状

范围选择器、时间胶囊、可信徽章、铃铛 flex gap-3 混排

问题

四类语义混排，视觉无分组；时间胶囊 24h/7d/30d 三按钮占位宽

方向

按"范围 / 时间 / 质量 / 通知"四组分隔符竖线区隔；时间胶囊改 segmented control 更紧凑

现状 [范围▾] [24h][7d][30d] [✓可信] [🔔]
优化后 [范围▾]│[24h|7d|30d]│[✓可信]│[🔔]
AGENTS.md 视觉偏好：工具栏右对齐、空间紧凑
A4StatusBar 28px 底部固定index.vue
现状

底部固定 28px，符合工业 SCADA 习惯

问题

当前可能仅摆设，未承载关键运行时信息

方向

承载：数据源（SignalR/TDengine）+ 当前范围 + 时间窗 + 最后刷新时间戳（细粒度进度反馈）

AGENTS.md 偏好：进度细粒度（按小时窗口）、计算类全本地 TDengine
A5v-show 常驻 5 路 WS 风险index.vue
现状

5 tab 组件 v-show 不卸载，常驻内存

问题

监控类实时连接可能并存 5 路 WebSocket，浪费带宽、易重复消费

方向

非活跃 tab 暂停 WS 节流；仅监控 PV/SP/OP 走 WS，其余手动刷新

AGENTS.md 偏好：PV/SP/OP/MODE/P/I/D 走 WS，其余手动刷新；禁止多 Worker 并存

§BTab1 系统总览 · overview.vue（重点）

12 列非等宽网格 3 行 9 区块。优化目标：data-ink 最大化、Glanceability 优先级、统一图表语言。

B1KPI 卡片 chartjunkoverview.vue Row1
现状

Row1 KPI 卡片行，可能有边框/阴影/大图标

问题

装饰元素降低 data-ink 比例，违背工业 Calm UI 原则

方向

去边框去阴影，1px 细分隔线；数字优先大号、标签次号字、单位灰显

AGENTS.md 偏好：1px 细分隔线、去冗余标签符号、data-ink 最大化
B2KPI 时间窗未跟随全局overview.vue Row1
现状

KPI 可能各自为政，与 HeaderBar 全局 24h/7d/30d 不联动

问题

同一页面时间窗不一致，认知负担大

方向

KPI 全部跟随 HeaderBar 全局时间窗；每张卡角标微型柱状趋势（无动画）

AGENTS.md 偏好：微型柱状图不要动画、时间窗统一
B3Row2 三维度图表语言不统一overview.vue Row2
现状

模块健康/数据流/装置风险 并排，图表类型各异

问题

环图/表格/矩阵三种异构，视觉跳跃

方向

统一"微型条形+状态色"语言；模块健康改饼图（无引线只 hover 框）

AGENTS.md 偏好：饼图优于环图、饼图无引线只显示悬浮框
B4Row3 趋势/事件/漏斗异构overview.vue Row3
现状

评分趋势折线 + 预警事件列表 + 处置漏斗

问题

垂直漏斗 data-ink 低；事件列表行高可能不紧凑

方向

趋势保留折线；事件列表紧凑单行 28px；漏斗改横向条形

AGENTS.md 偏好：树/列表 28px 单行、data-ink 最大化
B5缺全局健康带（Glanceability）overview.vue 顶部
现状

9 区块平铺，无优先级层级

问题

用户无法"一眼可知系统是否正常"，违背 Glanceability 原则

方向

顶部加"全局健康带"：5 模块状态色 + 在线/告警计数，下方再展开细节

现状（无健康带） ┌─ KPI 卡片行 ─────────────┐
│ 模块健康 │ 数据流 │ 装置风险│
│ 评分趋势 │ 预警事件 │ 处置漏斗│
优化后（顶部健康带） ┌─ ●监控 ●评估 ●诊断 ●整定 ●处置 · 在线 4/告警 1 ─┐
│ KPI 卡片行 │
│ 模块健康 │ 数据流 │ 装置风险│
│ 评分趋势 │ 预警事件 │ 处置漏斗│
AGENTS.md 偏好：Glanceability、状态色约定

§CTab2-5 · 评估 / 诊断 / 整定 / 处置

未逐个读源码（方案层）。基于已知模块形态给方向。

C1性能评估 L0~L4 适用性tabs/assessment
现状

L0~L4 适用性评估，等级横幅

问题

等级横幅 Glanceability 可能不足；L0/L1 阻止 L2 是否显式阻断

方向

等级横幅强化色：L0/L1 红、L2~L3 黄、L4 绿；Poka-Yoke 阻断动作显式禁用而非隐藏

AGENTS.md 偏好：Poka-Yoke、状态色、工具栏灰显不隐藏
C2回路诊断两页式tabs/diagnosis
现状

两页式（列表页 + 详情页）

问题

详情页布局可能未用左右分栏；筛选区与页内 tab 可能重复

方向

详情页左右分栏（左回路树 8px/级 28px 行高，右诊断证据）；筛选区与页内 tab 合并同行右侧

AGENTS.md 偏好：树结构 8px/级 28px 单行 flex 防换行、筛选区与 Tab 同行右侧
C3参数整定三页式tabs/tuning
现状

三页式（列表 / 整定 / 验证）

问题

各页工具栏可能不统一；PID 参数是否只读未明确

方向

各页统一符号栏、上下文灰显；整定页 PID 参数只读（AAS 模型决策：平台不直接改 DCS）

AGENTS.md 决策：安全边界——平台只输出建议/证据/风险/回退，参数由授权人员人工实施
C4问题处置 v2.0 双实体tabs/handling
现状

loop_action_item + handling_order 双实体

问题

双实体关系可能未用左右分栏呈现；处置动作缺证据链

方向

左右分栏列表+详情；处置走"建议+证据+风险+回退"四段式

AGENTS.md 决策：安全边界——建议/证据/风险/回退方案

§D横切问题 · 5 Tab 共性

跨 Tab 的统一性约束。

D1工具栏层级重复index.vue + 各 tab
现状

每个 tab 内可能还有自己的工具栏/筛选区，与 HeaderBar 重复

问题

跨 tab 全局筛选 vs tab 专属动作边界不清

方向

HeaderBar 承载全局（范围/时间）；tab 内只放专属动作，工具栏统一在页面标题栏右侧

AGENTS.md 偏好：工具栏固定标题栏右侧、筛选区与 Tab 同行右侧
D2中英文混用全工作台
现状

PV/SP/OP/MODE 等英文指标名散落

问题

大量英文指标名降低中文用户可读性

方向

PV/SP/OP 保留（行业术语）；栏目标题、操作按钮、状态提示一律中文

AGENTS.md 偏好：大量英文指标名时用中文描述/提示
D3工具栏图标彩色约定全工作台
现状

各 tab 工具栏图标样式可能不统一

问题

无统一符号库；无权限项可能直接隐藏

方向

统一符号库；默认原色、无权限灰显但占位保留

AGENTS.md 偏好：工具栏图标彩色、原色默认/灰显不隐藏
D4实时 vs 统计刷新策略全工作台
现状

监控类实时数据刷新策略未明确区分

问题

统计数据可能误用 WS 实时推送，浪费带宽

方向

PV/SP/OP/MODE/P/I/D 走 WS；评估/诊断/整定/处置统计指标手动刷新；非活跃 tab 暂停 WS

AGENTS.md 偏好：PV/SP/OP/MODE/P/I/D 走 WS、其余手动刷新

  • A4 StatusBar 承载运行时信息
