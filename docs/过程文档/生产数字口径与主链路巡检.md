## 一、数字口径（业务方核对用）

| 数字 | 正确含义 | 常见误读 | 核对点 |
|---|---|---|---|
| **回路总数 1209** | 回路配置台账全量（含监控禁止） | 当成可评估数 | 仅回路配置页可含禁止回路 |
| **可统计 961** | `is_active=监控中` 且 `include_in_evaluation=true` | 当成全厂回路 | 其他页面统计/列表/评分均应为 961 口径 |
| **禁止 248** | `is_active=false`（监控禁止） | 当成删除 | 除回路配置外不显示、不计算 |
| **回路评估「全部」** | 窗口内有最新快照的可统计回路数 | 等于 961 | 无快照回路不进评估分布 |
| **等级 1~5 + 不确定** | 必须 = 「全部」 | 五档加总就等于全部 | 「不确定」= 最新快照 `score=NULL`（数据不足/可信度 E），不是准入门槛 |
| **自控率** | MODE∈{AUTO,CAS,REMOTE,APC} 时长 / 窗口总时长 ×100% | 等于有效自控率 | 有效自控率还扣 OP 饱和/大偏差 |
| **自控率中位数 100%** | 榜单样本（默认最差 100 条）的中位数 | 全厂真实中位数 | 样本全 100% 时属数据事实；见 §二 对账 SQL |
| **装置×单元综合评分** | 该节点子树参评回路窗口加权均分 | 平均所有回路 | `evaluated_loops=0` → 空值「—」，不是 0 分 |

**评分入册条件（CAL-06）**：`is_active` + `status=READY` + `include_in_evaluation`，且窗口内有评估快照。

## 二、3~5 条代表回路对账（DB → 页面）

现场 Linux root 逐条执行；再在页面回路评估/工作台对同一时间窗看分。

```bash
# A. 台账与可统计数（期望 1209 / 961 / 248）
docker exec clpm-postgres psql -U clpm -d clpm -c "SELECT COUNT(*) AS total, COUNT(*) FILTER (WHERE is_active) AS active, COUNT(*) FILTER (WHERE NOT is_active) AS disabled FROM loop_ledger;"
```

```bash
# B. 指定位号：快照有无、分、自控率、监控/参评
docker exec clpm-postgres psql -U clpm -d clpm -c "SELECT l.tag_name, l.is_active, l.include_in_evaluation, s.ts_start, s.score, s.auto_mode_rate, s.status FROM loop_ledger l LEFT JOIN LATERAL (SELECT ts_start, score, auto_mode_rate, status FROM kpi_snapshot_hourly k WHERE k.loop_id=l.id ORDER BY ts_start DESC LIMIT 1) s ON true WHERE l.tag_name IN ('01TV_06003_PID','01PV_06004_PID','80LIC31601_PIDA','41FIC20134_PIDA','41TIC40422_PIDA') ORDER BY l.tag_name;"
```

```bash
# C. 自控率分布（解释「中位数 100%」：是否全体 100）
docker exec clpm-postgres psql -U clpm -d clpm -c "SELECT width_bucket(auto_mode_rate,0,100,10) AS bkt, COUNT(*) FROM (SELECT DISTINCT ON (loop_id) loop_id, auto_mode_rate FROM kpi_snapshot_hourly WHERE ts_start >= now() - interval '1 day' AND auto_mode_rate IS NOT NULL ORDER BY loop_id, ts_start DESC) t GROUP BY 1 ORDER BY 1;"
```

```bash
# D. 单元分：UNIT 预计算 vs 节点树 source_node_id
docker exec clpm-postgres psql -U clpm -d clpm -c "SELECT scope_id, score, loop_count, status FROM workbench_window_summary WHERE scope_type='UNIT' AND window='24h' ORDER BY window_end DESC LIMIT 10;"
```

**页面对齐标准**：B 中 `score` 与页面该回路综合评分一致（允许 UI 四舍五入）；C 若几乎全在 100% 桶，则中位数 100% 为真值而非筛掉手动回路。

## 三、主链路巡检（每条业务链 1 个真实回路）

| 链 | 操作 | 通过标准 | 记录 |
|---|---|---|---|
| 评估 | 回路评估页/任务发起 1 回路，窗口 24h | 任务 SUCCESS，进度到 100%，列表该回路有分 | task_id、回路、耗时 |
| 诊断 | 诊断任务或工作台诊断剖面 1 回路 | 出结论；全未命中显示「**正常**」 | run_id、主分类 |
| 整定 | 工作台整定：辨识→矩阵 | 矩阵出多行；失败时文案含 `ERR_` 码 | 回路、算法行 ok 数 |
| 处置 | 由整定/诊断建处置单 1 单 | 状态可流转 | order_id |
| 批量诊断 | 勾 0→2 回路→清空→全选>50 | 默认 0、已选 2、超限提示且不发请求 | 截图/日志 |
| 进度条 | 24h 全算子诊断 1 回路 | 中途有百分比/阶段，非只看终态绿 | task_id、排队/执行耗时 |
