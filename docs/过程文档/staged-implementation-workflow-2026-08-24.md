# 分阶段实施工作流（阶段任务提示词骨架）

> 日期：2026-08-24
> 状态：生效（最小持久 owner，源自 IA 优化 P0–P4 五次重复程序的沉淀）
> Owner：AGENTS.md「分阶段实施工作流」小节路由到本文档

## 1. 背景与来源

IA 优化 P0–P4（2026-08-22~23）构成 5 个可比 episode，每次都重复同一带验证关卡的程序：

1. 读取实施方案对应阶段章节；
2. 手工生成该阶段的任务提示词（含必读清单、阶段范围、验收口径）；
3. 单独启动新任务执行；
4. 完成度核验通过后才进入下一阶段。

期间暴露两类共性摩擦：**提示词超长需精简**、**中途暂停/恢复缺状态锚点**。
本文档是该程序的持久化骨架：每次新阶段启动时按 §3 模板填空生成任务提示词，不再从零手写。

**适用边界**：本骨架适用于"有书面实施方案、阶段划分清晰、每阶段有验收清单"的阶段型任务（如 IA 优化类重构）。一次性小任务、无方案文档的探索性工作不适用。

## 2. 触发、产物与验证器

| 项 | 内容 |
|---|---|
| 触发 | 新阶段启动（用户显式启动为人工决策点，见 §8.4 类"人工决策点"约定） |
| 产物 | 按 §3 模板生成的阶段任务提示词（建议 ≤60 行，超长即精简为引用） |
| 验证器 | 阶段完成度核验清单（§3 第 4 节 + 实施方案对应"验收标准"章节逐项核对） |
| 晋级条件 | 核验清单全绿 + 门禁命令通过，才允许启动下一阶段 |

## 3. 阶段任务提示词骨架模板

生成新阶段提示词时，按以下五节填空。**引用实施方案章节号，不复制正文**（防超长）：

```markdown
## 阶段：{方案名} {阶段编号}（如 IA 优化 P1）

### 1. 必读清单（按序阅读，禁止跳读）
- 实施方案：docs/设计文档/{方案目录}/{方案文件}.md
  重点章节：§{阶段划分表}、§{本阶段详细任务}、§{本阶段验收标准}、§{文件影响范围}、§{风险与控制}
- AGENTS.md：MVP 覆盖说明 + 关键注意事项（行为红线）+ 提交前本地检查
- 上一阶段的完成结论与遗留项（实施方案"修订记录"最新一行）

### 2. 阶段范围（做什么 / 不做什么）
- 本阶段任务清单：方案 §{本阶段详细任务}（逐条列出任务编号，如 P1-1 ~ P1-15）
- 文件影响范围：方案 §{文件影响范围}（标注 Owner 归属，跨 Owner 只提需求不动手）
- 明确不做：{列出相邻阶段内容，防止越界}（如"权限矩阵动态化留 P1，P0 不改"）
- 依赖确认：本阶段依赖的 {前置阶段} 已验收通过

### 3. 执行纪律
- 提交/推送/CI 仅在用户显式要求时执行（AGENTS.md Git 纪律）
- DB 迁移与 ORM 改动同批；alembic check 退出码 0
- 提示词超长时：以"引用方案章节号"替代复制正文
- 暂停/恢复：阶段进度以实施方案"修订记录"为状态锚点，恢复时先读最新修订行

### 4. 完成度核验问题（逐项回答，全部通过才算完成）
- [ ] 方案 §{本阶段验收标准} 的每一项是否逐条核对并有证据（截图/命令输出/测试结果）？
- [ ] 门禁命令是否全部通过？（ruff / pytest / check:type / eslint / alembic check，按 AGENTS.md"提交前本地检查"）
- [ ] 是否引入了下阶段范围外的改动？（越界检查）
- [ ] 实施方案"修订记录"是否已追加本阶段完成同步行？
- [ ] 是否有验收中发现的 bug 需在进入下阶段前修复？

### 5. 人工决策点（出现即暂停等待用户）
阶段验收结论 / 路由契约变更 / 阈值设定 / DB 迁移审查 / 冲突仲裁 / 合并 main
```

## 4. 使用步骤

1. 确认实施方案已含阶段划分表、各阶段详细任务、验收标准、文件影响范围四要素；缺要素先补方案再启动阶段。
2. 复制 §3 模板，替换 `{}` 占位符，生成阶段任务提示词。
3. 新开会话/任务执行，提示词作为首条指令。
4. 阶段收尾按 §3 第 4 节核验清单逐项过；全绿后在实施方案"修订记录"追加完成同步行，再启动下一阶段。

## 5. 升级路径

本骨架当前为文档级 owner（AGENTS.md 路由引用，人工触发）。若后续阶段型任务再次重复（≥2 次）且希望自动路由，可经用户显式授权升级为项目级 Skill/Command；**未经确认不创建新资产**。
