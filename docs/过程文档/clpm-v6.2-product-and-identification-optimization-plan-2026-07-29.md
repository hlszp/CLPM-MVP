> 文档状态：规划评审稿 v1.0

> - `docs/预研文档/基于HiaMonitor工程实践的CLPM产品方案建议.md`

## 1. 执行结论

两份预研文档提供了有价值的竞品能力清单和在线辨识演进方向，但**不能直接作为 CLPM 新版本实施规格**。

建议将下一版本定义为：

> **CLPM v6.2：可信辨识与一体化工作流**

它不是一次模块扩张，而是一次“真实性、安全性、连续工作流和认知减负”改造：

1. **先修正确性，再谈在线化。** 当前历史辨识存在错误模型类型、固定纯滞后、闭环 IV 名不副实、无效阶跃兜底被标成成功、低可信模型仍可进入整定等问题。继续叠加滑窗、RLS、漂移检测会把错误放大。
2. **保留 6 模块 + 1 门户和模块化单体。** 不采用 13 个能力中心、11 个微服务和 6 张指标资产表的扩张方案。
3. **不增加顶级导航模块。** 诊断、辨识、仿真、整定、整改是一个有分支的业务闭环，不是五个独立“中心”。
4. **不触碰 DCS 参数下写。** CLPM 继续只提供建议、证据、风险、回退方案和人工实施留痕。
5. **模型版本是唯一可能合理的新业务实体。** v6.2 前半程先复用现有 `tuning_record`；只有通过独立生命周期、复用、审计和漂移管理门禁后，才允许以 ADR 批准最小化的不可变 `process_model_version`，不同时创建“模型、模型版本、模型审批、模型工况”等表族。
6. **页面做减法。** 优先消除工作台/装置性能重复入口，将诊断任务与记录合为 Tabs，将整定的模型→算法→仿真收敛为一个可恢复步骤流。

### 1.1 建议采纳比例

| 预研材料 | 可直接采纳 | 需改写后采纳 | 延后验证 | 不采纳 |
|---|---|---|---|---|
| HiaMonitor 产品方案建议 | 现有能力的工程化检查项 | 业务闭环、DCS 适配、参数继承、指标语义清理 | 外部指标发布、批次、报警、AI 辅助 | 13 中心、11 微服务、DCS 写入、6 表指标资产、新总分与混合状态机 |
| 在线过程辨识建议 | 数据筛选、可辨识性门禁、候选模型、留出验证、模型置信度、影子运行 | 相关/频域、闭环辨识、动态指纹、模型版本 | Laguerre/Kautz、RLS、多工况、漂移自动更新 | 把互相关峰值直接当纯滞后、把闭环谱估计当无偏、未经校准的乘法评分直接做门禁 |

## 2. 评审范围、方法与事实源

### 2.1 两条权威链

不能用一条线性优先级同时判断“产品应该怎样”和“系统现在怎样”：

**产品目标与安全边界权威链**

1. PRD v6.1：产品定位、用户价值和范围；
2. 实现契约 v2.2：经确认的目标 IA、权限、状态机和 KPI 口径；
3. UIUX v6.1：工业交互与“只建议、不下写”等安全表达。

**当前运行行为权威链**

1. 已应用的 ORM/Alembic、后端与前端代码；
2. 实际 OpenAPI/路由；
3. 能证明生产路径行为的自动化测试；
4. 设计文档只作为待校正说明，不能反向覆盖已经验证的实现。

当两条链冲突时，先记录为事实漂移：产品边界不因代码偶然实现而自动改变；运行现状也不因过期文档描述而被假定存在。两份预研文档仅是待验证的竞品输入，不属于任何权威链。

### 2.2 检查方法

- 对建议逐项标记：`已实现 / 接受 / 改写接受 / 条件接受 / 延后 / 拒绝`。
- 从实体、页面、状态机、服务、算法和接口六个层次与现行实现对照。
- 对算法声明检查“接口承诺—生产路径—测试覆盖”是否一致。
- 对所有新增能力先执行“勿增实体”门禁。
- 工作量采用“熟悉现有代码的 3 人跨职能小组”粗估，包含开发、自测、评审、文档和回归，不包含外部系统联调等待。

### 4.1 三项必须改写的产品主张

#### A. 业务闭环不是一条直线

预研稿的“诊断→辨识→整定→整改”只适用于 PID 参数问题。目标流程应为：

```text
诊断结果
  ├─ PID 候选问题 ─→ 辨识 ─→ 仿真 ─→ 建议 ─→ 人工实施 ─→ A/B 验证
  ├─ 阀门/仪表问题 ─→ 检修建议 ─────────→ 人工实施 ─→ A/B 验证
  └─ 工艺/外扰/数据 ─→ 协同处置 ─────────→ 人工实施 ─→ A/B 验证
                         │
                         └──────── 全部分支统一进入 Action Tracker
```

#### B. “审批后写 DCS”必须改成“人工实施前检查”

CLPM 不提供自动或审批后参数下写。允许的能力是：

- 读取并标准化当前 PID 参数；
- 按 DCS 厂家/型号展示单位与结构转换；
- 给出建议、证据、风险和回退值；
- 导出人工实施清单；
- 记录 MOC、执行人、实施时间和验证结果。

#### C. 不建立第二套综合评分

继续使用实现契约的 3+1+8：

```text
P = (A·a + F·f + S·s) / (a + f + s) × R
```

饱和、质量、手动、故障通过扩展指标、可信度、INCONCLUSIVE 和诊断标签表达，不再叠加另一组乘法惩罚因子。

## 5. 在线过程辨识建议的科学性评估

### 5.1 建议保留的方向

- 先做可辨识性和数据质量门禁，再辨识；
- 以被动历史数据为主、受控阶跃为兜底；
- 事件切片而非整窗盲算；
- 同时比较低阶工程模型和动态指纹；
- 时间顺序训练/验证/测试，不能只看训练窗口 R²；
- 分离“候选模型”和“当前有效模型”；
- 低可信模型只展示趋势，不触发整定；
- 连续在线能力先影子运行，再人工审批发布；
- 漂移判断必须基于跨窗口一致性和不确定度，而不是单点参数变化。

### 5.2 必须修正的科学边界

| 原建议 | 问题 | 修正口径 |
|---|---|---|
| OP–PV 互相关峰值近似纯滞后 | 峰值包含对象动态和输入自相关展宽 | 只作为延迟候选；先预白化，再做延迟网格和留出集验证 |
| `Syu/Suu` 得到对象频响 | AUTO 闭环下输入与扰动相关，会产生反馈偏差 | 仅作指纹/筛选；对象模型需要闭环一致估计或受控实验 |
| 高相干说明模型可信 | 相干只说明线性相关强，不证明因果方向或结构正确 | 与工况、闭环结构、残差、留出仿真联合判断 |
| `K=Σg(k)Ts` | 与文中离散卷积约定不一致 | 明确脉冲响应离散化单位；若 `y=Σgᵢu(k-i)`，DC 增益为 `Σgᵢ` |
| 动态矩适用于全部对象 | 积分过程不可绝对求和，反向响应分母可能接近零 | 仅用于满足稳定、可和、非病态条件的响应 |
| 正交基天然稳定且不易过拟合 | 稳定性依赖基极点，RLS 仍会漂移 | 增加基极点选择、投影、遗忘因子、协方差重置和激励门禁 |
| 六因子乘法评分与 50/70/85 阈值 | 未定义归一化、标定数据和误差代价 | 作为待校准假设，不直接写入生产门禁 |

闭环 IV 的关键困难是控制量与扰动相关，工具变量必须与回归量相关且与误差独立；当前实现不满足该条件。该判断与闭环 IV 文献一致：[Gilson & Van den Hof, 2005](https://www.sciencedirect.com/science/article/pii/S0005109804002845)。残差—输入互相关也不能单独证明模型有效，需结合噪声模型和更完整验证：[Douma et al., 2008](https://www.sciencedirect.com/science/article/abs/pii/S0005109807004311)。闭环非参数频响存在反馈偏差：[Heath, 2001](https://www.sciencedirect.com/science/article/abs/pii/S0005109801001054)。模型结构选择应引入时间顺序交叉验证或 PRESS 类留出证据：[Wang & Cluett, 1996](https://www.sciencedirect.com/science/article/pii/0005109896000039)。

## 7. “如非必要，勿增实体”门禁

### 7.1 新实体准入规则

一个新实体必须同时满足：

1. 有区别于现有对象的独立生命周期；
2. 有明确的业务所有者和权限边界；
3. 需要独立查询、审计或版本不可变性；
4. 至少有两个独立消费者，而不是单页面临时展示；
5. 不能用现有实体字段、JSON 证据、标签、视图或派生结果表达而不丢失语义；
6. 已有真实生产场景和样本，不仅是竞品功能或未来想象；
7. 提供迁移、回滚、保留期和唯一真相源设计。

任一项不满足，默认不建表、不建状态机、不建顶级页面。

### 7.2 候选实体裁决

| 候选 | v6.2 决策 | 最小替代方案 | 重新评审条件 |
|---|---|---|---|
| `loop_relation` | 不新增 | 复用 complex group/role，关系仅做只读推导 | 至少 2 个真实选择器/前馈场景进入算法，且需有效条件和版本 |
| 六张 metric asset 表 | 不新增 | v6.2 先做指标语义清单 + 现有配置/快照/血缘 | 出现外部多消费者和独立指标版本生命周期后，v6.3 再评估只读发布 API |
| 七级 plant hierarchy | 不新增 | 现有三级树 + 标签/聚合视图 | 多站点权限和报告无法无损表达 |
| operational loop state | 不新增 | MODE、质量、诊断标签和工况分别表达 | 不允许把正交事实压成互斥状态 |
| data quality state | 不新增 | 现有状态 + A–E + reason code | 无 |

### 7.3 模型实体的 ADR 决策点

在 v6.2 Phase 2 结束时召开一次 ADR 评审。若门禁通过，仅允许新增一个 `process_model_version` 聚合：

- `loop_id`、不可变 `version`、`status=CANDIDATE/CURRENT/RETIRED`；
- 数据窗口、数据快照哈希、工况摘要；
- 算法及版本、模型类型、参数、延迟、采样周期；
- train/validation/test 指标、残差检验、不确定度；
- 发布人、发布时间、替代版本和失效原因。

整定记录引用该版本。首版不再创建 `process_model` 主表，因为 Loop 已是模型所有者；也不创建独立审批表、工况表、误差表。

## 8. 页面与交互减法方案

### 8.1 设计原则

- 导航表达用户任务域，算法步骤在页面内表达。
- 同一对象操作保持 Loop 上下文，不要求用户重复选回路和时间窗。
- 默认展示“结论—可信度—原因—下一步”，专业证据按层次展开。
- 无数据使用“未计算/不可用”，不得用 0 代替未知。
- 危险动作和不可执行建议必须有明确门禁；专业性来自证据而非页面数量。
- 旧 URL 至少兼容一个版本，先遥测再删除。

### 8.2 目标可见导航

| 模块 | 当前主要问题 | v6.2 目标 |
|---|---|---|
| 工作台 | 与装置性能重复 | 真正的跨模块待办门户；装置绩效只在性能评估出现 |
| 回路管理 | 入口较多但职责基本清楚 | 保持；DCS/PID 结构继续内聚在数据接入 Tabs |
| 性能评估 | 装置与门户重复 | 保留装置绩效、回路绩效、任务、配置、报告 |
| 诊断中心 | Overview、Analysis、Tasks、Records、Tracker、Config 共 6 个 | Overview、诊断任务、Tracker、Config；Analysis 作为对象上下文动作/隐藏深链 |
| 回路整定 | Workbench、Model、Algorithm、Simulation、Stats 共 5 个 | 整定工作台、整定记录/效果；中间步骤作为工作台 stepper |
| 系统管理 | 高级算法参数与业务配置重叠 | 高级参数降为管理员隐藏入口，配置逐项回归业务模块 |

每一步保存草稿状态，刷新和深链后可恢复；旧 `/tuning/model`、`/algorithm`、`/simulation` 先保留为隐藏兼容路由。

### 8.4 统一 Loop 上下文壳

不做大爆炸式 canonical route 重写。复用现有 URL，在以下页面共享一个轻量上下文头：

- 回路名称、Tag、装置、控制类型、MODE、数据时间窗；
- 最新数据质量/可信度；
- “查看性能 / 查看诊断 / 发起整定 / 创建整改”上下文动作；

这样可降低重复选择成本，又避免一次性重写 `/loop/detail`、`/diagnosis/detail`、Tracker 和 tuning 路由。

### 10.1 最小验证指标

- 数据：有效率、插值率、MODE 占比、饱和占比、激励强度、条件数；
- 拟合：train/validation/test 自由仿真 NRMSE；
- 结构：BIC、FOPDT 与 SOPDT 增益、复杂度提升是否显著；
- 残差：白噪声检验、残差—输入/设定值关系，明确其局限；
- 物理：有限参数、稳定性、增益符号、时间常数、纯滞后、采样比；
- 稳定性：跨片段参数离散度；
- 不确定度：bootstrap 或近似置信区间；
- 可追溯：算法版本、数据窗口、快照哈希和所有门禁 reason code。

## 11. 分阶段实施计划

### Phase 0：Truth First 安全与事实收口（1–2 周，必须先做）

目标：停止产生或展示“看起来成功、实际上不可信”的模型和指标。

| 任务 | 内容 | 验收 |
|---|---|---|
| T0.1 | 禁止无有效阶跃的 AUTO fallback | 噪声、常值、漂移、多阶跃均 INCONCLUSIVE |
| T0.2 | 历史 IPDT 暂时下线 | API/UI/契约一致拒绝，不静默返回 SOPDT |
| T0.3 | 收容固定 `theta=2Ts` 风险 | API 不再宣称自动估计；未显式给 θ 时标为 `HEURISTIC_2TS`、可信度最高 C 且不得直接进入整定 |
| T0.4 | A–E 放行门禁 | A/B 放行、C 确认、D/E 禁止 |
| T0.5 | 移除伪 0 风险 KPI | 未计算显示未知，不显示 0 |
| T0.6 | 给现有 IV 降级标识 | 不宣称闭环无偏，不作为版本化 CURRENT 的发布依据 |
| T0.7 | 建立回归数据集 | 覆盖常值、噪声、慢漂移、单/多阶跃、闭环 SP 激励、IPDT |
| T0.8 | 固化整定状态机和历史兼容映射 | 代码、数据库、API、UI、统计、设计文档使用同一语义 |
| T0.9 | 校正六份设计事实源 | PRD/FDS/ADS/DDS/IDS/实现契约与 OpenAPI、ORM、路由一致 |
| T0.10 | 修复生产 bootstrap 与 fresh-install | Phase 0 保持 `01_schema.sql → stamp head` 现行路径，将 DDL 补齐至 37 张 ORM 表；空 PostgreSQL 实测建库、seed、head 和 `alembic check`。Alembic 唯一建库源作为后续 ADR |

Go/No-Go：上述 P0 必须完成“根治或安全收容”，否则不得开启自动滑窗或后台在线辨识；状态机和 schema 真相源未固化，不得新增模型实体或迁移。`HEURISTIC_2TS` 只有在 Phase 2 完成自动延迟搜索后才能取消限制。

目标：让算法吃到正确数据，让用户沿一个流程完成任务。

| 任务 | 内容 | 主要影响面 |
|---|---|---|
| T1.1 | PV/OP/SP/MODE 同轴，修复 bundle 顺序与异采样率 | DataPlanner 接缝、tuning service、测试 |
| T1.2 | 真实片段切分与 reason code | tuning identification、preview API/UI |
| T1.3 | 激励归一化和单位缩放不变性 | excitation、配置与测试 |
| T1.4 | 修复逐点 datetime 热路径 | tuning service、性能测试 |
| T1.5 | 工作台/装置性能去重 | 路由、权限、E2E、文档 |
| T1.6 | 诊断任务/记录合并 Tabs | 路由、页面、E2E |
| T1.7 | 整定步骤流第一版，旧路由隐藏兼容 | 5 个整定页面、草稿状态、E2E |
| T1.8 | typed response、枚举和状态语义统一 | API、前端类型、兼容层 |
| T1.9 | 用现有 DCS PID 结构实现标准参数转换 | PB/Kp、秒/分钟、结构和微分滤波往返性质测试 |

Go/No-Go：不同采样率和乱序 bundle 的集成测试全通过；用户不再需要在 3 个顶级菜单之间手工搬运模型参数。

### Phase 2：可信候选模型（3–4 周）

目标：从“能算出参数”升级为“有证据地选择模型”。

| 任务 | 内容 | 验收 |
|---|---|---|
| T2.1 | 延迟候选网格搜索 | θ=0、2、5、20、60 Ts 均在不传真值时验证 |
| T2.2 | AIC/BIC/CV 接入主 pipeline | 不再固定一/二阶后只按训练 R² 排名 |
| T2.3 | 合格闭环 IV/OE/PEM 方案 | Monte Carlo 下相对 ARX 偏差显著下降 |
| T2.4 | IPDT 独立辨识路径 | 液位斜坡数据模型类型、积分增益和延迟正确 |
| T2.5 | 物理参数与转换门禁 | 复极点、负根、不稳定模型不会伪装成工程模型 |
| T2.6 | 拟合、残差、留出和区间证据 | API/UI 能完整复核模型选择 |
| T2.7 | 20+ 回路人工标注集 | 覆盖流量、压力、温度、液位和典型异常 |

Go/No-Go：没有留出证据、物理门禁或数据快照的模型，不得进入整定。

### Phase 3：模型生命周期与整改闭环（2–3 周）

目标：决定模型是否值得成为独立版本实体，并连通“人工选择时间窗所得模型”的发布、实施和验证；不包含在线影子候选发布。

| 任务 | 内容 | 验收 |
|---|---|---|
| T3.1 | 执行模型实体 ADR | 按第 7 节七项准入规则逐项给证据 |
| T3.2 | 若通过，仅建最小 `process_model_version` | 一个聚合完成候选/当前/退役和不可变证据；只有人工窗口模型可审批为 CURRENT |
| T3.3 | 整定记录引用模型版本 | 不再用 `algorithm=IMC` 占位表示纯辨识；ADR 不通过则只保留单次证据快照 |
| T3.4 | 人工实施清单与回退值 | 无 DCS 下写入口，MOC 与执行人完整 |
| T3.5 | Tracker A/B 效果验证 | 调参前后口径、时间窗和置信度可追溯 |

Go/No-Go：若独立模型复用和漂移管理需求不成立，Phase 3 不建新表，继续用 `tuning_record`。

### Phase 4：在线影子运行（4 周观测，不自动发布）

目标：验证连续在线能力的收益和误报成本。

- 每日/每周滑窗扫描，但只生成候选；
- 事件触发重辨识；
- 当前模型与新候选漂移对比；
- 独立低优先队列、限流、超时、能力开关和任务监控；
- 试点复核队列与分层评估报表；
- 在线影子候选不更新 CURRENT、不触发 PID 推荐；人工窗口模型既有流程不受影响；
- 20+ 回路、至少 4 周人工复核；
- 统计可辨识率、误报率、拒绝原因、参数误差、工况切换影响和人工审阅时间。

只有试点达到验收阈值，才在 v6.3 开放“人工审批后发布模型”。

### 条件性 v6.3 能力

以下不进入 v6.2 承诺：

- Laguerre/Kautz + RLS；
- 多工况模型和漂移自动检测；
- 批次/MES 和报警关联；
- 证据型 AI 助手；
- 复杂回路关系实体；
- 外部指标语义发布；
- 在线候选的人工审批发布。

### 14.3 产品验收

- 可见导航数减少，且没有新增顶级模块；
- 诊断任务/历史可在一个页面完成；
- 整定模型、算法、仿真不再要求用户手工复制参数；
- 刷新、返回、深链后 Loop 与时间窗上下文不丢；
- 未计算数据绝不显示为 0；
- D/E/INCONCLUSIVE 不存在“使用此模型整定”入口；
- 所有建议均显示证据、可信度、风险和人工实施边界；
- 旧 URL 在兼容期内可正确跳转。

### 14.4 算法验收

- 不传真实 θ 的黄金测试；
- 历史 IPDT 不再静默返回 SOPDT；
- 无有效阶跃的 fallback 假阳性为 0；
- 闭环算法有 Monte Carlo 偏差/方差报告和弱工具门禁；
- 模型选择使用留出自由仿真，而非只看训练一步预测 R²；
- 所有发布候选具有数据快照、算法版本、残差、物理门禁和不确定度；
- 现场试点按流量、压力、温度、液位分层报告，不用一个总平均掩盖弱项。

## 15. 发布、兼容与回退

1. 使用能力开关区分 `history_identification_v2`、`tuning_stepper_v2`、`shadow_identification`。
2. Phase 0 门禁修复直接进入主链，但保留旧记录只读展示。
3. Phase 1 路由先隐藏并重定向，不立即删除组件。
4. Phase 2 新旧辨识双算抽样，只允许新算法生成候选；旧模型不被自动替换。
5. Phase 3 若新增模型版本，采用“一次性回填 → 影子读比对 → 切换读路径 → 停止旧参数新写”的迁移。`process_model_version` 是切换后的唯一写所有者；`tuning_record` 只保留外键和迁移前遗留快照的只读兼容。若因发布窗口必须短期双写，需限定最长一版、每次写入做一致性断言，并预先定义切断日期和回滚脚本。
6. Phase 4 影子任务使用独立队列/限流，不影响 KPI、诊断和实时数据任务。
7. 任一阶段出现错误模型、任务拥塞或统计漂移，可关闭对应能力开关，回退到人工时间窗 + 人工参数输入，不回退安全门禁。
