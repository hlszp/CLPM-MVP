### 菜单显示顺序与规则

- 当前角色无权限的菜单项隐藏（不置灰，避免噪音）
- 隐藏路由（详情页 `:loopId`）通过列表行点击进入，不在菜单中显示
- Phase 2 整定模块在 Phase 1 保留原型页面（可点击查看结构与交互），算法实现标注"Phase 2 规划中"
- Sponsor 角色默认首页为 `/performance`（全局看板），且不可见诊断中心与回路整定模块
- 外部专家默认首页为 `/diagnosis`，仅可见诊断中心与回路整定模块

### 元数据（pageLevel / stage / depth 等）

（文档未明确给出 pageLevel / stage / depth 等元数据字段定义；但通过页面结构模式与分期可以推断）
- **页面结构模式**（4 类）：工作台页 / 数据表页 / 配置页 / 审计页
- **分期**：Phase 1 / Phase 2（原型 Phase 1）
- **目标角色**：全角色 / 系统管理员 / 仪控工程师 / 外部专家

## 7. 状态机定义

### 7.1 回路就绪状态

```
Partial（Tag 关联字段缺失，标红） → 就绪（PV/SP/OP/MODE 完整校验通过）
```

### 7.2 回路评估状态（`kpi_snapshot_hourly.status`，v5.0 更新：可信度联动）

| 状态值 | 颜色 | 文本 | 图标 | 触发条件 |
|---|---|---|---|---|
| `SUCCESS` | `--status-ok` 青绿 | 正常 | ✓ | 正常计算（输出评分，标注可信度 A/B/C/D 等级） |
| `INCONCLUSIVE` | `--status-neutral` 冷灰 | 数据不足 | ? | valid_rate < 0.20（可信度 E 级），不计算评分、不参与聚合、灰色虚线保留连线 |
| `PARTIAL` | `--status-warning` 琥珀 | 部分计算 | ⚠ | 部分字段缺失，黄色横幅 |

**转换规则**：
- 可信度等级由 `valid_rate` 自动判定（A/B/C/D/E）
- 可信度 E 级强制 `status=INCONCLUSIVE`，评分数值留空显示"—"
- 可信度 C/D 级评分正常展示，但附加角标提示

### 7.3 Action Tracker 处理状态（`action_tracker.action_status`，v5.0 更新）

**v5.0 状态枚举变更**：从 PENDING/IN_PROGRESS/IGNORED/IMPLEMENTED 变更为 ACTIVE/RESOLVED/SUPPRESSED

**注**：§7.2.2 与 §8.2.3 在文档中存在不一致：
- §7.2.2 仍使用旧枚举（PENDING/IN_PROGRESS/IGNORED/IMPLEMENTED）
- §8.2.3 使用新枚举（ACTIVE/RESOLVED/SUPPRESSED）

**§7.2.2 旧枚举**（保留供参考）：

| 值 | 颜色 | 文本 | 图标 |
|---|---|---|---|
| `PENDING` | `--status-danger` 警示红 | 待处理 | ⏳ |
| `IN_PROGRESS` | `--status-info` 深蓝 | 处理中 | ⟳ |
| `IGNORED` | `--status-neutral` 冷灰 | 已忽略 | — |
| `IMPLEMENTED` | `--status-ok` 青绿 | 已实施 | ✓ |

**§8.2.3 新枚举**（v5.0 更新）：

```
ACTIVE（活跃） → RESOLVED（已处理，触发 A/B 对比采集）
ACTIVE → SUPPRESSED（人工抑制，需注明抑制原因与到期时间）
SUPPRESSED → ACTIVE（重新激活）
```

- 每次变更记录 `updated_by` + `updated_at` + severity（INFO/WARN/ERROR/CRITICAL）
- 标记 RESOLVED 后截取 `[T-7天,T]` vs `[T,T+7天]` 窗口
- 状态变更记录审计日志，不支持 RESOLVED/SUPPRESSED 回退至 ACTIVE
- SUPPRESSED 需注明抑制原因与到期时间

### 7.4 诊断标签（`diagnosis_label`，v4.1 更新，8 类枚举对齐 C6）

| 标签值 | 中文名 | 颜色 | 图标 | 检测方法 |
|---|---|---|---|---|
| `OSCILLATION` | 振荡 | `--status-warning` 琥珀 | 〰 | FFT/自相关检测，振荡周期/频率特征命中 |
| `VALVE_STICTION` | 阀门粘滞 | `--status-danger` 警示红 | ⚠ | PV-OP 散点拟合命中椭圆/平行四边形 |
| `OVERAGGRESSIVE` | 参数过激 | `--status-danger` 警示红 | ⚡ | PID 增益分析，增益偏差/振荡指数超阈值 |
| `OVERCONSERVATIVE` | 参数过保守 | `--status-info` 深蓝 | 🐢 | PID 增益分析，响应时间/settling time 超阈值 |
| `EXTERNAL_DISTURBANCE` | 外扰频繁 | `--status-warning` 琥珀 | ↯ | 频谱分析，扰动指数/频率集中度超阈值 |
| `QUALITY_ABNORMAL` | PV 质量异常 | `--status-neutral` 冷灰 | ? | 质量码统计，Bad/Uncertain 占比超阈值 |
| `OUTPUT_SATURATION` | 输出饱和 | `--status-warning` 琥珀 | ⛔ | OP 范围统计，饱和时长占比超阈值 |

**说明**：多标签可共存（如同时存在振荡+阀门粘滞），通过 Dempster-Shafer 证据理论融合置信度（`fusedConfidence`）

### 7.5 PV 数据质量状态（v5.0 更新：灰色虚线保留连线）

| 质量码 | PV 线表现 | pvValid | 标签表现 | 参与计算 |
|---|---|---|---|---|
| `Good` | 实线正常显示（青绿或主色） | `true` | 绿色"Good"徽章 ✓ | 参与 KPI 计算 |
| `Bad` | **PV 灰色虚线保留连线**（v5.0 变更：不再断线） | `false` | 红色"Bad"徽章 ✖ | 不计入好值率 |
| `Uncertain` | PV 琥珀色虚线保留连线 | `false` | 琥珀"Uncertain"徽章 ? | 按权重折算 |

**规则**：
- SP/OP 线始终正常显示，不受 PV 质量码影响
- 对齐 KEEP_ALL_WITH_VALIDITY 策略：Bad/Uncertain 数据点保留在时间序列中，不删除
- 各指标通过 Metric Validity Mask 决定有效点

### 7.7 指标可信度标签（v5.0 新增，`confidence_level`）

| 值 | 颜色 | 文本 | 图标 | 触发条件 | UI 处理 |
|---|---|---|---|---|---|
| `A` | `--status-ok` 青绿 | 高可信 | ✓ | valid_rate ≥ 0.95 | 正常展示，无额外提示 |
| `B` | `--status-info` 深蓝 | 较高可信 | ✓ | 0.80 ≤ valid_rate < 0.95 | 正常展示 + 可信度角标 |
| `C` | `--status-warning` 琥珀 | 中等可信 | ⚠ | 0.60 ≤ valid_rate < 0.80 | 显著标注 + tooltip "建议复核" |
| `D` | `--status-danger` 警示红 | 低可信 | ⚠ | 0.20 ≤ valid_rate < 0.60 | 警告提示 + tooltip "数据有效率低，谨慎使用" |

**展示规则**：
- 角标形式：`[评分值] [可信度等级徽章]`，如 `78.5 [B]`
- 可信度 E 级时：评分区域显示 `INCONCLUSIVE —`，评分数值不展示
- 综合评分可信度 = min(A 可信度, F 可信度, S 可信度)，取最低等级
- 与计算状态标签联动：可信度 E 级时强制 `status=INCONCLUSIVE`

## 9. 视觉规范

### 9.1 色彩使用规则

- 所有颜色必须从 CSS 变量引用，**不允许页面散落写死 hex**
- 风险色优先用于标签、边线、状态点，**不大面积铺底**
- 单一工业蓝作 accent（`--accent-blue`），仅用于主操作；**不使用大面积装饰性渐变**（紫/霓虹）
- 评分色块动态映射，阈值由算法配置决定，UI 需支持动态读取
- PV 质量码分段渲染：Good 实线、Bad 灰色虚线保留连线、Uncertain 琥珀虚线保留连线
- 状态标签必须颜色+文本+图标三维组合，**绝不仅靠颜色传递信息**

### 9.2 字体使用规则

- 通用界面文字使用 `--font-sans`
- 数字、规则 ID、tag 位号、版本号、PID 参数使用 `--font-mono`（等宽强制规则）
- 页面层级由大小、粗细、间距共同表达，不只靠颜色
- 高密度表格正文可降至 13px

### 9.3 间距使用规则

- 采用 4px/8px spacing scale
- 一级区块上下间距（`--space-6` 至 `--space-8`）大于区块内元素间距（`--space-2` 至 `--space-4`）
- 列表和工作台页面优先高密度紧凑布局，不做营销站式大留白

### 9.4 圆角与阴影规则

- 控件圆角 `--radius-sm` (4px)，克制使用
- 面板圆角 `--radius-md` (8px)
- 标签/徽章 `--radius-pill` (999px)
- 阴影只做层级分离，不做悬浮装饰，**坚决不使用大面积重阴影**
- **不使用圆角卡片 + 左彩色 border accent**（2020-2024 Material/Tailwind 烂大街组合），改用诚实边框分隔

## 11. 组件标准

### 11.1 表格标准（§7.1）

- 工业场景下所有台账、清单、排行优先使用紧凑型表格，**不允许用卡片代替批量信息浏览**
- 必须具备：多维联合筛选、列头排序、固定表头与首列（回路位号列固定）、状态颜色高亮（行级或单元格级）、行级快捷动作、批量选择、空状态、Partial 状态提示
- 性能要求：单页 100 条以上回路表格 FPS ≥ 40；超 500 条启用虚拟滚动
- **筛选栏统一布局**：`[关键词搜索] [装置/单元过滤] [状态过滤] [风险过滤] [排序入口] [批量操作]`

### 11.2 状态标签标准（§7.2）

- 统一标签体系，必须是"**颜色 + 文本 + 语义图标**"三维组合
- **绝不能仅靠颜色传递信息**
- 6 类子标签：计算状态 / 处理状态 / 控制模式 / PV 数据质量 / 诊断标签（8 类枚举）/ 指标可信度（A/B/C/D/E 五级）

### 11.3 筛选栏标准

- 所有列表页统一布局：`[关键词搜索] [装置/单元过滤] [状态过滤] [风险过滤] [排序入口] [批量操作]`
- 默认值：排行榜 `limit`=10（可选 10/20/50）；排行榜 `timeWindow`=`today`（枚举 today/yesterday/last_7_days）；工作台统计粒度=`day`；工作台趋势粒度=`day`；波形 `downsample`=`true`（LTTB 算法）；波形 `maxPoints`=2000；波形时间窗上限 30 天（超限 `ERR_TS_001`）；表格排序=`score` 升序（低效优先）；表格分页默认 10/页（超 500 条虚拟滚动）

### 11.4 时间线标准

（文档未明确给出独立"时间线"组件标准；但在异常跟踪抽屉中提及"显示时间线、状态、操作人"，每次状态变更生成处理时间线节点，记录 `updated_by` + `updated_at`）

### 11.5 对比组件标准（A/B 对比）

- Before/After 双柱对比
- 提升标绿、下降标红
- 标注 delta 数值
- 标记"已实施"后自动截取 `[T-7天, T]` 与 `[T, T+7天]` 两窗口 KPI 数据
- 实施后数据不足 24h 时提示"评估数据采集中，请稍后查看"

### 11.6 空状态标准（§7.9）

- **空状态 (Empty)**：必须说明原因 + 提供动作入口。如"暂无计算数据，请检查数据接入配置"、"当前时间窗无低效回路"
- **Partial 状态**：明确"缺什么、还能继续做什么、下一步去哪"。批次 Partial 黄色警告横幅，列出 Inconclusive 回路数量与影响
- **Inconclusive 状态**（v5.0：对齐可信度 E 级，数据不足是一等公民，不是错误）：灰色标签"数据不足" + 可信度角标"E"；波形区灰色虚线保留连线；评分区显示"—"而非 0（**严禁以 0 分掩盖数据缺失**）；tooltip"可信度 E 级（有效数据率 < 20%），无法计算"
- **Error 状态**：计算超时/内存溢出（中断批次+记录日志+触发管理员告警）；越权操作（全局 Toast"无权限"）；网络异常（标准错误态+重试按钮）

### 11.7 Tag 关联选择器（§7.7）

- 左侧 AAS 同步 tag 列表（搜索/筛选/数据质量徽章/关联状态）
- 右侧 7 槽位关联区（PV/SP/OP/MODE/PID_P/PID_I/PID_D）
- 拖拽与下拉两种交互方式
- 槽位标签：必填项标注红色 `*`，可选项标注灰色 `(可选)`
- 已关联 tag：等宽字体显示 tag 名 + 数据质量徽章
- 缺失槽位：红色虚线边框 + "未关联"占位文本
- 必填槽位（PV/SP/OP/MODE）缺失时标红 + tooltip

### 11.8 配置变更确认对话框（§7.8）

- 标题：确认 [配置名称] 变更
- 变更摘要：列出本次变更的字段与新旧值对比
- 变更说明输入框（必填）：填写变更原因/说明
- 操作按钮：[取消] [确认变更]
- 确认后调用对应 API，记录审计日志（操作人/操作类型/变更内容/变更说明/时间戳）
- 成功后全局 Toast"配置已保存，变更已记录审计日志"

## 12. 文案规范

### 12.1 文案语言要求

- **视觉语气**：稳重、审计化、任务驱动。这是工业治理平台，不是通用 SaaS 控制台，也不是概念展示网站
- 信息密度高，但层级清晰
- 优先展示状态、风险、下一步动作
- 文案以业务动作和结论为中心，**避免营销化表达**
- 首屏必须先回答"现在该做什么"，再解释"为什么"
- **中文为主**，技术术语保留英文（如 KPI/PID/Tag/STABLE 等）

### 12.2 文案句式要求

（文档未明确给出句式模板清单；但从示例可归纳）
- Toast 反馈："配置已保存，变更已记录审计日志"、"状态已更新为：处理中"、"无权限执行此操作"
- 错误提示："请缩小查询时间范围"、"PV tag 必填"、"该层级下已存在同名节点"
- 确认弹窗："删除后该节点下所有回路将失去归属，确认删除？"、"确认保存 Tag 关联？变更将影响该回路的数据采集与性能评估。"
- 数据不足提示："评估数据采集中，请稍后查看"
- 文件名规范：`CLPM-诊断建议书-[回路位号]-[日期].pdf`、`CLPM-报表-[周期]-[日期].pdf`

### 12.3 反 AI Slop 文案禁忌（§2.2）

| 禁忌 | 替代方案 |
|---|---|
| 装饰性渐变文案 | 单一工业蓝作 accent，中性底色 |
| Emoji 作功能图标 | 语义化 SVG 图标库（Lucide） |
| 编造 stats/quotes 装饰 | 留白或真实数据 |
| 营销化表达 | 业务动作和结论为中心 |

## 13. 验收标准

### 13.1 原型验收标准（Phase 1，§12.5）

- 25 个页面可运行（含回路整定模块 5 个原型页面）
- 角色切换器驱动菜单与页面可见态
- 至少 1 条闭环链路可跑通（工作台→低效排行→诊断详情→异常跟踪标记已实施→A/B 对比）
- Tag 关联管理支持拖拽与下拉两种交互
- 配置页保存弹确认弹窗，填写变更说明
- 波形图正确处理 PV 质量码（Good 实线/Bad 灰色虚线保留连线/Uncertain 琥珀虚线保留连线）
- 所有主按钮有真实结果
- 所有列表页支持筛选、排序
- `npm run dev` 与 `npm run build` 通过

### 13.2 反 AI Slop 验收（§2.2）

- 不使用大面积装饰性渐变（紫/霓虹）
- 不使用 Emoji 作功能图标
- 不使用圆角卡片 + 左彩色 border accent
- 不使用卡片瀑布流代替工作台
- 不画 SVG 人脸/场景/物品
- 不每处都配装饰性 icon
- 不编造 stats/quotes 装饰

### 13.3 信息密度验收（§2.3）

- 每屏需至少 3 处可见的产品差异化信息（非装饰性数据、状态推断、上下文关联）
- 装饰性 icon 仍然忌讳——加的是有内容的密度，不是装饰
- 列表和工作台页面优先高密度紧凑布局

### 13.4 无障碍验收（§11.3）

| 领域 | 规则 |
|---|---|
| 键盘 | 状态变更、导出、Tag 关联拖拽等操作必须可 Tab 完整操作（拖拽需提供下拉选择替代方案） |
| 触达 | 可点击元素最小 44px |
| 色彩 | 状态标签必须颜色+文本+图标，绝不仅靠颜色 |
| 对比度 | 满足 WCAG AA 标准 |
| 等宽 | 数字、回路位号、tag 名、ID 等宽字体确保对齐 |

### 13.5 性能验收

- 单页 100 条以上回路表格 FPS ≥ 40
- 超 500 条启用虚拟滚动
- 波形 LTTB 降采样 maxPoints=2000
- 波形时间窗最大跨度 30 天

### 13.6 页面状态矩阵验收（§8.1）

所有列表/详情页统一遵循状态表达：Loading / Empty / Error / Success / Partial/Inconclusive（详见 §8.1 页面状态矩阵表）
