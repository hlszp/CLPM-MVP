## 2. 术语差距

### 差距 3: "快速率"术语与 FDS v5.1 "快速响应率"不一致
- **来源文档**：PRD §5.1.1 A 表
- **差距类型**：术语
- **当前值**：PRD 使用"快速率 (Fast Rate)"，公式代号 F，metric_code `FAST_RATE`，定义为"衡量回路从扰动到恢复稳态的响应速度，基于 ARMA 模型辨识和 Green 函数计算"
- **基准值**：FDS v5.1 §1.3 使用"快速响应率 (Fast Response Rate)"，对应 metric_code 应为 `FAST_RESPONSE_RATE`
- **修复方案**：将 §5.1.1 A 表第 2 行"快速率 (Fast Rate)"更正为"快速响应率 (Fast Response Rate)"，metric_code 同步更正；并更新 §5.1.2 综合评分公式变量说明中 F 的描述

### 差距 4: "稳定率" vs "平稳率"术语混用
- **来源文档**：PRD §5.1.1 A 表、§4.1 工作台、§4.3.4 全局看板
- **差距类型**：术语
- **当前值**：PRD §5.1.1 A 表第 3 行使用"稳定率 (Stability Rate)"，但 §4.1 工作台、§4.3.4 全局看板、§4.3.5 统计报表使用"平稳率"；§0 v3.1 变更记录也使用"平稳率"
- **基准值**：FDS v5.1 / DDS v4.1 / 实现契约 v1.0 统一使用"平稳率"，DDS v4.1 §3.7 明确：loop-level 字段名为 `steady_rate`，unit-level 聚合字段名为 `stability_rate`
- **修复方案**：将 §5.1.1 A 表第 3 行"稳定率 (Stability Rate)"更正为"平稳率 (Steady Rate)"，metric_code 由 `STABILITY_RATE` 更正为 `STEADY_RATE`（loop-level）；在 §5.1.2 公式变量说明中补充"unit-level 聚合字段为 `stability_rate`"

### 差距 5: "自控率" vs "有效自控率"术语不一致
- **来源文档**：PRD §5.1.1 B 表
- **差距类型**：术语
- **当前值**：PRD §5.1.1 B 表第 4 行使用"自控率 (Auto Mode Rate)"，公式代号 R，metric_code `AUTO_MODE_RATE`
- **基准值**：FDS v5.1 §1.3 使用"有效自控率 (Effective Auto Mode Rate)"作为折扣因子 R
- **修复方案**：将 §5.1.1 B 表"自控率 (Auto Mode Rate)"更正为"有效自控率 (Effective Auto Mode Rate)"；保留 `AUTO_MODE_RATE` 作为基础统计指标，并新增 `EFFECTIVE_AUTO_MODE_RATE` 作为折扣因子 R 的派生指标

## 3. 模块清单差距

### 差距 6: PRD 模块清单缺少 Tag 管理独立入口
- **来源文档**：PRD §4.0 模块总览
- **差距类型**：模块
- **当前值**：PRD §4.0 模块总览列出 6 模块 + 1 门户（工作台门户 / 回路管理 / 性能评估 / 诊断中心 / 回路整定 / 系统管理），未明确 Tag 管理路由
- **基准值**：实现契约 v1.0 §4.2 路由清单包含 `/tag/list`（Tag 管理）；UIUX v5.3 §2.4 页面清单包含 Tag 管理 1 页
- **修复方案**：在 §4.2 回路管理模块下补充"4.2.6 Tag 管理子页"，描述 AAS Tag 列表查看、筛选、状态展示功能，路由 `/tag/list`

### 差距 7: PRD 任务管理归属描述与 FDS v5.1 一致但需明确
- **来源文档**：PRD §4.3.7 任务管理
- **差距类型**：模块
- **当前值**：PRD §4.3.7 将任务管理作为性能评估模块的子节（4.3.7），描述标准评估任务与自定义评估任务
- **基准值**：实现契约 v1.0 §4.2 路由清单包含 `/metric/tasks`、`/metric/task-strategy`；FDS v5.1 §5.3.11 任务管理非独立模块，是性能评估子节；UIUX v5.3 §2.4 任务管理 1 页
- **修复方案**：维持任务管理作为性能评估子模块的口径，但在 §4.0 模块总览中明确"任务管理为性能评估子模块，路由 `/metric/tasks`"

## 4. 功能项差距

### 差距 8: PRD 缺少性能定级功能描述
- **来源文档**：PRD §4.3 性能评估、§5.1 性能评估指标池
- **差距类型**：功能
- **当前值**：PRD 未描述 5 级性能定级（EXCELLENT/GOOD/FAIR/WARNING/POOR）功能
- **基准值**：FDS v5.1 §1.3 明确 5 级性能定级；DDS v4.1 §3.6 提到 `metric_config` 新增 `grading_thresholds`（5 级性能定级）字段
- **修复方案**：在 §4.3.1 性能指标配置中补充"性能定级配置"子项，描述 5 级定级（EXCELLENT/GOOD/FAIR/WARNING/POOR）阈值配置功能；在 §5.1 中补充"5.1.5 性能定级"小节

### 差距 9: PRD 缺少权重模板功能描述
- **来源文档**：PRD §4.3.1 性能指标配置、§5.1.2 综合评分模型
- **差距类型**：功能
- **当前值**：PRD §5.1.2 仅提到"权重按控制类型（STABLE/SLOW/FAST/LOGIC）默认配置，用户可自助调整"
- **基准值**：FDS v5.1 §1.3 明确 4 类权重模板（STABLE/SLOW/FAST/LOGIC）作为独立功能项
- **修复方案**：在 §4.3.1 中补充"权重模板管理"子项，描述 4 类控制类型权重模板的创建、编辑、应用、复制功能

### 差距 10: PRD 缺少指标数据需求配置功能
- **来源文档**：PRD §4.3.1 性能指标配置、§8 数据架构需求
- **差距类型**：功能
- **当前值**：PRD §8.3 描述了 tagGroup 分组，但未将"指标数据需求配置"作为独立功能项描述
- **基准值**：DDS v4.1 §3.2 包含 `clpm_metric_data_requirement` 表（指标数据需求），FDS v5.1 应有对应功能描述
- **修复方案**：在 §4.3.1 中补充"指标数据需求配置"子项，描述每个指标声明的依赖 tagGroup、采样频率、数据窗口配置功能，对应 `clpm_metric_data_requirement` 表

### 差距 11: PRD 工作台门户缺少"聚合工作台"设计口径
- **来源文档**：PRD §4.1 工作台（门户）
- **差距类型**：功能
- **当前值**：PRD §4.1 描述工作台包含顶部筛选栏、KPI 卡片区、低效回路列表、回路趋势摘要、组合趋势图 5 个区块
- **基准值**：实现契约 v1.0 §4.2 提到"页面组织已从旧版 25 页面清单调整为'聚合工作台 + 隐藏详情页 + 专项配置页'"
- **修复方案**：在 §4.1 中补充"聚合工作台"设计原则说明，明确工作台为多模块数据聚合入口，详情页通过路由跳转而非内嵌展示

## 5. 数据模型差距

### 差距 12: PRD 快照表名与 DDS v4.1 不一致
- **来源文档**：PRD §4.3.7 任务管理
- **差距类型**：数据模型
- **当前值**：PRD §4.3.7 A 标准评估任务"结果写入**标准快照表** (`standard_snapshot`)"；B 自定义评估任务"结果写入**自定义快照表** (`custom_snapshot`)"
- **基准值**：DDS v4.1 §3.2 表清单为 `kpi_snapshot_hourly`（KPI 小时快照）与 `kpi_snapshot_custom`（KPI 自定义快照）
- **修复方案**：将 §4.3.7 A 中 `standard_snapshot` 更正为 `kpi_snapshot_hourly`；将 B 中 `custom_snapshot` 更正为 `kpi_snapshot_custom`

### 差距 13: PRD 缺少 17 张表的完整数据模型描述
- **来源文档**：PRD §5 核心算法与指标范围约束、§8 数据架构需求
- **差距类型**：数据模型
- **当前值**：PRD 仅描述了指标体系、数据架构组件（DataPlanner/DataBlock/tagGroup），未列出完整数据表清单
- **基准值**：DDS v4.1 §3.2 定义 17 张 PostgreSQL 表（loop_ledger / tag_registry / loop_tag_mapping / plant_node / metric_config / kpi_snapshot_hourly / kpi_snapshot_custom / unit_kpi_summary / clpm_metric_data_requirement / action_tracker / tuning_record / report_record / sys_user / sys_role / sys_user_role / sys_audit_log / report_schedule）+ 1 个 TDengine 超级表 `st_loop_data`
- **修复方案**：PRD 作为上位约束可不列完整表清单，但应在 §8 数据架构需求中补充"数据模型对齐 DDS v4.1，共 17 张 PostgreSQL 表 + 1 个 TDengine 超级表"的引用说明

### 差距 14: PRD 数据血缘字段描述与 DDS v4.1 不一致
- **来源文档**：PRD §5.4.1 数据血缘追溯
- **差距类型**：数据模型
- **当前值**：PRD §5.4.1 列出 6 项数据血缘信息：采样频率、质量策略、数据分组 (tagGroup)、有效数据率、数据窗口、算法版本
- **基准值**：DDS v4.1 §3.5 明确 `kpi_snapshot_hourly` 与 `kpi_snapshot_custom` 均包含 5 个独立字段（`sampling_freq`、`quality_policy`、`valid_rate`、`confidence_level`、`data_lineage`），其中 `data_lineage`（JSONB）内部包含 6 个子字段
- **修复方案**：将 §5.4.1 重构为"5 个独立血缘字段 + `data_lineage` JSONB 内 6 个子字段"结构，明确字段名与数据库列名对齐

### 差距 15: PRD 缺少 DDS v4.1 新增字段描述
- **来源文档**：PRD §4.2 回路管理、§5.1 性能指标配置
- **差距类型**：数据模型
- **当前值**：PRD 未描述 `loop_ledger.control_type` / `importance_level` / `include_in_evaluation`、`metric_config.grading_thresholds`、`unit_kpi_summary.excluded_loops` / `status` 等 v4.1 新增字段
- **基准值**：DDS v4.1 §3.6 列出 v4.1 主要新增字段
- **修复方案**：在 §4.2.3 回路台账管理中补充"控制类型 / 重要性等级 / 是否纳入评估"配置项；在 §4.3.1 中补充"性能定级阈值"配置项；在 §4.3.3 多维层级评估中补充"装置级汇总排除回路与状态"描述

## 6. KPI 指标差距

### 差距 16: PRD §5.1 指标体系为 3+1+7，与 FDS v5.1 的 3+1+8 不一致
- **来源文档**：PRD §5.1.1 指标体系结构
- **差距类型**：KPI
- **当前值**：PRD §5.1.1 标题为"3+1+7 指标体系结构"，C 表列出 7 项辅助诊断指标（好值率 / 振荡率 / 饱和率 / 粘滞系数 / 行程指数 / 稳态时间 / 理想稳态时间），共 11 项指标
- **基准值**：FDS v5.1 §1.3 为"3+1+8 体系（3 核心 + 1 折扣 + 8 扩展）= 12 项指标计算器"
- **修复方案**：将 §5.1.1 标题更正为"3+1+8 指标体系结构"；核对 FDS v5.1 的 8 项扩展指标清单，补充缺失的第 8 项扩展指标；将 §5.1 开头"3+1+7 指标体系结构"更正为"3+1+8"

### 差距 17: PRD 内部 KPI 体系口径自相矛盾
- **来源文档**：PRD §4.1 工作台、§4.3.1 性能指标配置、§4.3.4 全局看板 vs §5.1.1 指标体系结构
- **差距类型**：KPI
- **当前值**：PRD §4.1 / §4.3.1 / §4.3.4 描述"基于 3+1+8 指标体系，管理 12 项指标"，但 §5.1.1 实际定义为"3+1+7 指标体系结构，11 项指标"
- **基准值**：FDS v5.1 统一为 3+1+8 = 12 项
- **修复方案**：将 §5.1.1 的 3+1+7 修正为 3+1+8，与 §4.1 / §4.3.1 / §4.3.4 内部口径统一

### 差距 18: PRD 综合评分公式变量 F 定义与 FDS v5.1 不一致
- **来源文档**：PRD §5.1.2 综合评分模型
- **差距类型**：KPI
- **当前值**：PRD §5.1.2 公式 `P = (A·a + F·f + S·s) / (a + f + s) × R`，F 定义为"快速率的归一化值"
- **基准值**：FDS v5.1 的 F 应为"快速响应率 (Fast Response Rate)"的归一化值
- **修复方案**：将 §5.1.2 公式变量说明中"`F`：快速率的归一化值"更正为"`F`：快速响应率的归一化值"

### 差距 19: PRD 装置级 KPI 描述与 FDS v5.1 不一致
- **来源文档**：PRD §4.3.3 多维层级评估、§4.3.4 全局看板
- **差距类型**：KPI
- **当前值**：PRD §4.3.3 仅提到"自动聚合生成单元级、装置级评分"，未明确装置级 KPI 清单
- **基准值**：FDS v5.1 §1.3 明确"装置级三大 KPI（自控率 / 好值率 / 平稳率）"
- **修复方案**：在 §4.3.3 中补充"装置级 KPI 包含自控率、好值率、平稳率三项核心指标"的明确描述

### 差距 20: PRD 可信度分级 D 级阈值与 FDS v5.1 不一致
- **来源文档**：PRD §5.4.2 指标可信度分级
- **差距类型**：KPI
- **当前值**：PRD §5.4.2 表格：A ≥ 95% / B 80%~95% / C 60%~80% / D 40%~60% / E < 40%
- **基准值**：FDS v5.1 §1.3 与基准摘要 §1.3 明确"valid_rate 阈值 95/80/60/20%"，即 D 级为 20%~60%，E 级为 < 20%
- **修复方案**：将 §5.4.2 表格 D 级阈值由"40% ~ 60%"更正为"20% ~ 60%"，E 级由"< 40%"更正为"< 20%"

## 7. 状态机差距

### 差距 21: PRD 诊断标签状态使用 RESOLVED，与实现契约 v1.0 冲突
- **来源文档**：PRD §5.6.2 标签状态管理
- **差距类型**：状态机
- **当前值**：PRD §5.6.2 诊断标签状态为"活跃 (ACTIVE) / 已处理 (RESOLVED) / 已抑制 (SUPPRESSED)"
- **基准值**：实现契约 v1.0 §4.6 明确"历史文档中的 `RESOLVED` 统一视为旧命名；当前代码与后续文档使用 `IMPLEMENTED`"
- **修复方案**：将 §5.6.2 中"已处理 (RESOLVED)"更正为"已实施 (IMPLEMENTED)"，与 Action Tracker 状态枚举对齐

### 差距 22: PRD 缺少 Loop 状态机完整枚举
- **来源文档**：PRD §4.2.4 Tag 关联管理
- **差距类型**：状态机
- **当前值**：PRD §4.2.4 仅提到"缺失时回路状态为 `Partial`"，未给出 Loop 完整状态枚举
- **基准值**：实现契约 v1.0 §4.6 明确 Loop 状态为 `READY` / `PARTIAL` / `INACTIVE`（就绪 / 部分配置 / 已停用）；并明确"历史文档中的 `ACTIVE`/`PAUSED`/`DECOMMISSIONED` 统一视为旧命名"
- **修复方案**：在 §4.2 回路管理章节中补充"4.2.0 回路状态机"小节，明确 Loop 状态枚举为 READY/PARTIAL/INACTIVE，并标注中文显示名

### 差距 23: PRD 缺少 KPI 快照状态机描述
- **来源文档**：PRD §4.3.7 任务管理、§5.4.3 INCONCLUSIVE 处理
- **差距类型**：状态机
- **当前值**：PRD §5.4.3 提到"INCONCLUSIVE 快照"但未明确 KPI 快照状态枚举；§4.3.7 C 任务状态机为 PENDING/RUNNING/SUCCESS/FAILED/CANCELLED（这是任务状态，非快照状态）
- **基准值**：实现契约 v1.0 §4.6 明确 KPI 快照状态为 `SUCCESS` / `PARTIAL` / `INCONCLUSIVE`（成功 / 部分有效 / 数据不足）
- **修复方案**：在 §4.3.7 或 §5.4 中补充"KPI 快照状态机"小节，明确快照状态枚举为 SUCCESS/PARTIAL/INCONCLUSIVE

### 差距 24: PRD 缺少 Tuning 状态机描述
- **来源文档**：PRD §4.5 回路整定
- **差距类型**：状态机
- **当前值**：PRD §4.5 未描述整定记录状态机
- **基准值**：实现契约 v1.0 §4.6 明确 Tuning 状态为 `DRAFT` / `RUNNING` / `COMPLETED` / `ROLLED_BACK`（草稿 / 运行中 / 已完成 / 已回退）
- **修复方案**：在 §4.5 回路整定章节中补充"4.5.0 整定记录状态机"小节，明确 Tuning 状态枚举

### 差距 25: PRD 任务状态机与实现契约 v1.0 KPI 快照状态概念混淆
- **来源文档**：PRD §4.3.7 C 任务状态查询
- **差距类型**：状态机
