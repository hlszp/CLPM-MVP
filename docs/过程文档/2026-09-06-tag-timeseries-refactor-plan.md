## 1. 交付目标与完成标准

物理历史改为每测点一张 TDengine 子表，按来源事件保存值、时间与质量；统一适配层按历史绑定、质量和覆盖依据生成 1 秒逻辑宽表。现有性能评估、诊断、整定继续调用原取数接口，算法数学与业务逻辑不变。

完成必须同时满足：新事件可恢复地写入；合法 COV 常值能够保持、真实缺口不可伪装完整；新旧历史按明确边界可读；活跃取数入口全部接通；算法等价性、真实数据库行为、容量与回退证据通过。仅新表建成、Provider 单测通过或前端能看到曲线，均不足以完成。

用户已经确定目标结构，无需实施者重新争论宽表/子表选择。现有算法发现独立问题可登记证据，不借本任务调整公式、评分、门禁和阈值。SignalR 库替换、永久秒级宽表双存、旧表退役与删除历史均不属于本轮。

6. **P0-6** 记录冷/热取数时延、SQL 次数、内存和现有算法结果基线，冻结 §5 测量口径。此阶段不改业务逻辑或生产数据。

2. **P1-2** 实现稳定点身份与绑定历史，初始化只覆盖可信当前时刻；当前映射更新与历史同 PG 事务，读时检查历史区间不重叠。

### P2：实时与历史统一写点表

依赖：P1 仓储与元数据接口。Owner：B；A 支持底层写入。

任务：

1. **P2-1** 新建 PointHistoryWriter；接收事件保留点/源时间/质量，队列按事件组织，显示缓存继续合并最新值。复用已修复的租约、超时、故障隔离，不另写一套领导者机制。
2. **P2-2** 实现有界批量、重试、未确认批次、取消和进程恢复；旧时间事件进入历史而不回退最新显示；队列满/租约失效/写入失败形成可见缺口与告警计数。
3. **P2-3** 将 data_import 暂存与替换下沉至点级；保留参数、任务状态及外部计数单位，新增内部物理计数；共享点并发、部分成功、响应丢失、空响应、取消都能恢复。
4. **P2-4** 分离原始历史与远端重建样本，保留质量原码及窗口初值；skip、now−5min 与 gap 默认关闭/600s 门槛不变；远端调用只在 data_import 内。
5. **P2-5** 在隔离环境/明确样本集合启用 shadow 写入；同一输入事实进入两路，不启动两个订阅者；记录影子范围、结束条件和旧写覆盖边界。

交付：新写链路、导入适配、计数对账、状态恢复报告；每个内部队列/缓存有容量及生命周期说明。

晋级：实时、导入、重试的规范化事实集合对账一致；共享点只存一份；质量变化不丢、同 tick 多事件不丢；进程退出边界的未确认区间可定位；Redis 故障不导致领导者失控或 TD 成功水位越界。

### 5.2 算法等价性门槛

1. 独立密集参考输入同一套现有 Pipeline/算法；另一条路径将该参考正确 COV 编码后写点表，再通过生产 Provider 重建。参考生成不得调用待测 builder 充当自身预期。
2. timestamps、角色集合、数组长度、MODE 整数/枚举语义、质量码、validity、consecutive_segments 和状态/原因码必须一致。因数据身份而不同的 ID、耗时、生成时间可在 P0 明确排除；不得临时排除评分、采样频率或可信度。
3. 使用相同数值精度输入时，重建前后数值应相同；算法浮点结果采用现有数值测试容差和固定种子/依赖版本。若旧 FLOAT 落盘参考与新 DOUBLE 对照，单列可量化的精度差异及容差依据，不能把任意 1% 变化认作等价。
4. 覆盖性能指标、综合评分、诊断状态/证据和实际已启用辨识/整定方法；迭代/随机算法固定种子并复用其现有收敛判据。不得只测一个均值指标代表全部算法。
5. 新质量/缺口契约会纠正原输入错误，这类结果可能由成功变为 INCONCLUSIVE；必须单列输入与预期解释，不能要求复制旧错值，也不能将所有差异笼统归为“数据更准确”。

### 5.3 性能与容量验收

以下为方案提出的测试负载及门槛，**尚无本轮实测结果**。P0 记录 CPU/内存、容器限制、TD/Redis 持久化、网络、点数/角色共享与消息大小；固定同一硬件比较。硬件不足列为容量阻塞，不能静默缩小规模后宣称达标。

| 项目 | 目标 / 方法 |
|---|---|
| 稳态写入 | 隔离回放 9,000 测点事件/s 持续 60min；另用真实 COV 分布做 8h 长稳态。未解释丢失/重复事实为 0；队列无持续增长；源到 TD 确认延迟 p95≤2s、p99≤5s，测量扣除回放原事件年代造成的假延迟 |
| 短时突发 | 18,000 事件/s 持续 60s，再回 9,000；120s 内回到稳态队列/延迟。若容量不足必须可观察退化和准确缺口，不能声称无损达标 |
| 查询 | 相同可信 1s 数据、同窗同角色及同缓存状态比较；单回路 1h 取数/组装 p95≤基线 1.2 倍；SQL 次数不随网格点数增长，无每点查询 |
| 全站评估 | 按 9,000 点的实际回路映射跑完整评估批次，含全部既有指标；完成时间不超过基线 1.2 倍，无新远端调用、无遗漏回路；若基线已有超期另列待解决项 |
| 长窗口 | 验证当前 API 真正允许的最大趋势及计算窗口；趋势保留 30 天和 2,000 点输出契约。记录最终列表、组装与序列化峰值，不能以 SQL 分块或最终点少证明内存已受控 |
| 内存/连接/缓存 | 队列、批次、L1/L2/L3、元数据缓冲有配置上限；进程总 RSS 有基于部署限额的预算。8h 稳态峰值在预算内，无持续爬升；取消/重连后连接和任务回到稳定范围 |
| 源端压力 | 点表转换和计算都在本地；不因多子表增加 AAS 订阅副本/历史请求。历史导入沿用已配置并发限流，不在本轮提升源端压力预算 |

出现超预算优先优化批量、查询合并、数据表示、缓存和热点；不通过更改计算窗口、少算角色、LTTB 喂算法或降低采样率通过测试。预算确需调整时先提供瓶颈证据及影响供主审/用户判断。

## 7. 合并阻断项

出现任一项，主审不合并为完成版：

- 算法公式/阈值/评分/诊断整定门禁被改以适应新表，或接口改动迫使消费者逐一迁移。
- 常值按事件稀疏判缺失，或断线/BAD/无初值被统一 ffill 为正常。
- 源时间被 flush/接收时间替代；质量只留 Redis；同 ts 不同事实静默覆盖。
- 旧历史被猜测转换成原始事实、旧表被删、停止旧写后回退覆盖不足却未披露。
- 计算路径调用远端历史，或将 LTTB/展示降采样结果传给算法。
- 新表/旧表混用无明确时间边界，活跃后台入口仍遗漏，导入后缓存不一致。
- TD 部分成功、恢复、共享点更正、改绑与质量码只经 fake 验证；真实数据库证据缺失。
- 受保护的其他任务改动被覆盖，或最终 HEAD 与验证版本不一致。
