## 一、总体评价

### 1.1 优势分析

| 优势项 | 说明 |
|---|---|
| **模块边界清晰** | 6模块+1门户的IA架构符合"配置→运行→分析"三态自包含原则，工作台/回路管理/性能评估/诊断中心/回路整定/系统管理的划分逻辑清晰 |
| **状态机完整** | Action Tracker（待处理→处理中→已实施/已忽略）、KPI可信度（A/B/C/D/E）、整定流程（DRAFT→RUNNING→IDENTIFIED→SIMULATED→COMPLETED）等核心状态机定义完备 |
| **工业设计原则落地** | Calm UI/Poka-Yoke/Glanceability/数据墨水比四大原则在设计规范中有明确定义，整定模块"只读建议·人工实施·需留痕"安全提示到位 |
| **角色权限分层** | ADMIN/IC_ENGINEER/PE_ENGINEER/EXPERT/SPONSOR五角色权限模型清晰，菜单按角色过滤隐藏而非置灰，减少视觉噪音 |
| **安全边界明确** | "不直接修改DCS参数，只输出建议、证据、风险与回退方案"的红线在代码层（静态扫描测试）和UI层（整定页黄色警告条）双重守护 |
| **待办聚合门户** | 工作台改造为"诊断待处理/异常跟踪待办/评估待执行/整定任务"跨模块待办聚合，符合仪控工程师上班先看待办的工作习惯 |

### 1.2 关键问题识别（按严重程度排序）

| 严重度 | 问题类别 | 核心问题 |
|---|---|---|
| **P0 阻断** | 闭环流程断点 | **评估→诊断→整定→验证闭环断裂**：工作台/性能看板发现问题回路后，缺乏直接跳转到诊断/整定的"一键处置"入口；异常跟踪列表缺少关键诊断信息（标签类型、严重度、发现时间），无法快速判断优先级 |
| **P0 阻断** | 信息架构(IA)问题 | **Tag测点→回路→监控→评估的数据链路路径不直观**：仪控工程师首次使用时，难以理解"先配置链路→同步Tag→创建回路→关联Tag→才能看到数据"的配置顺序，配置入口分散（链路配置仅ADMIN可见，与实际运维需求矛盾） |
| **P1 严重** | 认知负担 | **术语不一致与专业术语缺失**：UI中"测点配置"对应设计文档的"Tag管理"，"回路配置"合并了原"工厂层级+回路台账+Tag关联"三个概念；工业现场常用术语如"位号"、"控制回路"、"PID参数"、"手动/自动/串级"在关键位置缺乏解释或显示不完整 |
| **P1 严重** | 数据展示 | **表格列宽严重不足导致信息截断**：回路台账、异常跟踪列表等核心页面的装置名、回路描述等关键列被截断（如"脱甲烷精饣"），严重影响扫视效率；异常跟踪列表仅3列（回路位号/装置/操作），缺少诊断标签、严重度、发现时间、可信度等核心决策信息 |
| **P2 中等** | 指导辅助 | **新手引导与上下文帮助缺失**：关键配置页面缺少操作引导（如"7槽位Tag关联"无图解说明），无空状态引导（"暂无数据"时不提示下一步该做什么），KPI指标（准确率/快速率/平稳率）缺少专业解释Tooltip |
| **P2 中等** | 交互体验 | **可视化选型与布局问题**：性能看板KPI卡片使用横向滚动仪表盘，不符合Glanceability原则；X轴时间标签倾斜45°可读性差；右侧悬浮蓝色齿轮按钮遮挡内容；每页都有"刷新"按钮但无全局自动刷新状态指示 |
| **P3 轻微** | 细节打磨 | **微交互与状态反馈不足**：批量操作按钮（批量设置/分组/删除）默认禁用但无提示原因；双"导入"按钮并存造成混淆；状态颜色语义在部分区域不一致 |

## 二、维度一：认知负担优化分析

### 2.1 符合专业认知习惯的设计

1. **状态色彩语义体系完整**：绿(正常)/蓝(进行中)/黄(警告)/红(危险)/灰(中性/不足)的五色语义体系符合工业HMI惯例，可信度A-E颜色编码逻辑清晰
2. **等宽字体用于位号/数值**：设计规范要求位号、KPI值、时间戳使用等宽字体，符合仪控工程师快速扫视数值对齐的习惯
3. **整定安全提示前置**：整定工作台顶部黄色警告条"只读建议·人工实施·需留痕"第一时间告知安全边界，避免误解

### 2.2 导致认知负担的问题

#### 问题1：模块命名与菜单结构认知错位

| 设计规范命名 | 实际UI命名 | 认知问题 |
|---|---|---|
| AAS Tag同步/链路配置 | 链路配置（仅ADMIN可见） | ic_engineer看不到数据源配置入口，但实际运维中仪控工程师经常需要检查数据链路状态 |
| Tag管理 | 测点配置 | "测点"是工业术语，但菜单图标是普通list图标，缺乏"数据流/信号"语义 |
| 回路台账+工厂层级+Tag关联 | 回路配置（合并为一页） | 左树右表布局把三个概念塞在一页，但操作流程不明确——先建工厂树？先建回路？还是先关联Tag？ |
| 性能评估→指标配置 | 指标配置（仅ADMIN可见） | KPI阈值、权重、诊断规则等配置项全部收口到ADMIN，但仪控工程师作为主要使用者无法根据装置特性微调阈值 |

**整改建议**：
- 将"链路配置"从ADMIN专属改为IC_ENGINEER可查看（仅配置保存保留ADMIN权限），增加"数据链路健康状态"卡片在工作台常驻显示
- 菜单增加图标语义区分：测点配置用"信号/数据流"图标，回路配置用"回路/网络"图标
- 回路配置页增加**配置向导进度条**：「步骤1: 配置工厂层级 → 步骤2: 同步测点 → 步骤3: 创建回路 → 步骤4: 关联Tag」，首次进入时引导完成

#### 问题2：数据展示信息密度失衡

**问题表现**：
- 诊断总览页：4张统计卡片竖向堆叠（异常回路数/待处理/已闭环/平均闭环时长），仅占屏幕上部约30%空间，下部大片空白，数据墨水比低
- 异常跟踪列表：仅3列可见，关键诊断信息（什么异常？什么时候发现的？严重程度？可信度？）全部隐藏在"详情"点击后，违反Glanceability原则
- 装置性能看板：KPI卡片采用横向滚动仪表盘设计，8个指标需要横向滚动才能看完，首屏只能看到4个；"回路状态统计"区域数据未加载完成显示大绿点占位，造成困惑

**整改建议**：
- **异常跟踪列表扩充为工业级高密度表格**，列建议：

| 列名 | 说明 | 宽度 |
|---|---|---|
| 回路位号 | 等宽字体，超链接到诊断详情 | 140px |
| 装置/单元 | 完整显示不截断 | 120px |
| 诊断标签 | 振荡/粘滞/外扰/参数问题等，带颜色标签 | 100px |
| 严重度 | 高/中/低，颜色编码 | 60px |
| 可信度 | A/B/C/D/E小徽章 | 50px |
| 发现时间 | 等宽字体 | 140px |
| 状态 | 待处理/处理中/已实施/已忽略 | 80px |
| 处理人 | - | 80px |
| 操作 | 详情/更新状态/A-B对比/导出PDF | 200px |

- **性能看板KPI卡片改为网格布局**（2行×4列），首屏展示全部8个指标，禁用横向滚动；仪表盘径向图缩小尺寸，数值使用大号等宽字体（≥28px/700weight）突出
- 所有列表页启用**列宽自适应+用户可拖拽调整+列显示/隐藏配置**，默认列配置按最常用场景预设

#### 问题3：术语缺乏专业解释

**问题表现**：
- "准确率"、"快速率"、"稳定率"三个核心KPI名称对新用户不直观——准确率是指什么的准确率？快速率响应什么？
- "可信度A/B/C/D/E"只有颜色没有解释——C级是什么意思？能不能用于整定？
- 诊断标签"人工复核"、"振荡"、"PV质量异常"、"外扰频繁"缺少判断依据说明

**整改建议**：
- 所有专业术语旁增加**信息图标(i)**，Hover显示专业解释Tooltip：
  - 准确率（A）："反映设定值(SP)跟踪过程值(PV)的精度，基于IAE/ISE误差指标计算"
  - 可信度C："数据有效率60%-80%，结果可供参考，建议复核数据质量"
  - 振荡："检测到PV/OP周期性波动，可能原因：参数整定过激、阀门粘滞、外扰"
- 诊断标签在列表中Hover时显示**触发阈值与诊断依据摘要**
- 首次登录增加**术语Quick Start引导卡片**（可关闭），用一页图解说明核心概念

## 三、维度二：指导辅助有效性分析

### 3.1 已有的有效指导

1. **整定安全边界提示**：黄色警告条清晰醒目，在所有整定页面常驻
2. **状态流转可视化**：异常跟踪页「待处理 → 处理中 → 已实施 / 已忽略」状态流转图直观展示流程
3. **危险操作二次确认**：设计规范要求高危操作使用ClpmDangerConfirmModal（输入确认码+变更原因），符合Poka-Yoke原则

### 3.2 指导辅助缺失的问题

#### 问题1：空状态无引导

**问题表现**：
- 首次进入系统，无回路、无数据时，页面仅显示"暂无数据"，不告诉用户下一步该做什么
- 评估任务列表为空时，不提示"系统会在整点自动触发评估，您也可以手动创建自定义评估任务"
- 整定任务列表为空时，不引导"从诊断中心的异常回路进入整定流程"

**整改建议**：
所有空状态采用**引导式空状态设计**，而非单纯"暂无数据"：

| 页面 | 空状态引导文案+操作 |
|---|---|
| 回路配置（无回路） | "尚未配置任何控制回路。请先完成：①检查数据链路配置 → ②同步测点 → ③创建第一个回路" + 按钮「开始配置」 |
| 异常跟踪（待处理为0） | "🎉 太棒了！当前没有待处理的异常回路。系统每小时自动体检，有新异常会在这里提醒您。" |
| 整定工作台（无任务） | "尚未创建整定任务。建议从「诊断中心→异常跟踪」选择需要整定的回路，点击「进入整定」开始。" + 按钮「查看待整定回路」 |
| 数据管理（无数据） | "本地暂无历史数据。请先配置远端API接口，然后导入历史数据开始评估。" + 按钮「配置数据源」 |

#### 问题2：关键操作节点缺少上下文帮助

**问题表现**：
- 创建回路时，"控制类型"（STABLE/SLOW/FAST/LOGIC）选择没有解释——我怎么知道这个回路是哪种类型？选错了有什么影响？
- "重要等级"（1/2/3级）没有说明——1级最重要？3级最重要？对什么有影响？
- "是否参与评估"开关，切换时弹窗提示过于技术化，不说明业务影响
- Tag关联7个槽位（PV/SP/OP/MODE/PID_P/PID_I/PID_D），对于不熟悉CLPM数据模型的仪控工程师，不知道哪些必填、哪些可选、OP和MODE分别是什么

**整改建议**：
- 在表单字段旁增加**"这是什么？"帮助链接**，点击展开小型帮助面板：
  - 控制类型："STABLE=稳定型（如液位、压力，平稳率权重高）；SLOW=慢速型（如温度，准确率权重高）；FAST=快速型（如流量，快速率权重高）；LOGIC=逻辑开关回路。系统将根据类型自动套用默认权重模板。"
  - 重要等级："1级=关键回路（聚合权重×3）；2级=一般回路（权重×2）；3级=辅助回路（权重×1）。影响装置级KPI聚合计算。"
- Tag关联页面增加**7槽位可视化图解**，用小图标+颜色区分必填(红)与可选(灰)，Hover每个槽位显示说明：
  - PV(红)：过程测量值 - 必填
  - SP(红)：设定值 - 必填
  - OP(红)：控制器输出 - 必填
  - MODE(红)：控制模式(手动/自动/串级) - 必填
  - PID_P(灰)：比例增益 - 可选（用于整定对比）
  - PID_I(灰)：积分时间 - 可选
  - PID_D(灰)：微分时间 - 可选
- 所有配置项保存后增加**Toast提示变更影响范围**："已保存。该变更将在下一次评估任务（约xx分钟后）生效。"

#### 问题3：无全局新手引导与操作手册入口

**问题表现**：
- 首次登录无Onboarding Tour引导
- 顶部无"帮助/文档"入口
- 没有"快速入门" checklist

**整改建议**：
- 增加**顶部状态栏帮助入口**（问号图标），包含：
  - 快速入门（3-5步完成首个回路配置与评估）
  - 术语表
  - 操作视频/图解
  - 常见问题
- 首次登录（或新用户首次登录）弹出**5步引导Tour**：
  1. 工作台待办说明
  2. 回路配置流程说明
  3. 如何查看性能评估
  4. 异常处理闭环流程
  5. 整定安全边界说明
- 用户菜单中增加「引导教程重播」选项

## 四、维度三：工作流程契合度分析

### 4.1 仪控工程师典型工作日流程

根据工业现场调研，仪控工程师典型日工作流程：

```
8:00  上班 → 打开工作台 → 查看待办异常/夜班问题
8:15  → 按优先级逐个处理异常：
        ① 查看异常回路诊断结果与波形证据
        ② 判断问题根因（参数问题/设备问题/工艺问题）
        ③ 如需要整定 → 进入整定模块辨识模型→仿真对比
        ④ 现场实施/或忽略/或提工单
        ⑤ 更新处理状态、记录备注
10:00 → 监控关键回路实时趋势
14:00 → 周/月度：查看装置绩效统计，整改效果验证(A/B对比)
16:00 → 新回路投用：配置Tag→关联回路→验证数据→启用评估
```

### 4.2 当前系统流程断点分析

#### 断点1：发现问题 → 诊断问题 跳转断裂

**问题**：
- 工作台低效回路列表只有"查看全部"，点击回路行无直接跳转诊断入口（当前右侧只有"进入装置性能"按钮）
- 性能看板/回路性能页面发现评分低的回路，需要手动切换到诊断中心菜单，再搜索该回路位号——平均多5次点击
- 实时监控页面发现PV异常波动，无"发起诊断"快捷按钮

**整改建议**：
建立**"问题发现→诊断→处置"一键跳转链路**：
1. 所有出现回路位号的地方（工作台列表/性能排行/监控列表/异常列表），位号均为超链接
2. 右键/行末"更多"菜单增加快捷操作：
   - 📊 查看性能趋势
   - 🔍 进入诊断详情
   - ⚙️ 进入整定（需诊断已完成）
   - 📝 创建跟踪记录
3. 工作台低效回路列表选中行右侧，将"进入装置性能"改为**操作按钮组**：
   [查看诊断] [查看趋势] [加入整定]

#### 断点2：诊断 → 整定 上下文丢失

**问题**：
- 诊断中心发现振荡/参数过激问题，点击"整定"需要跳转到整定工作台，但**当前诊断上下文（回路ID、诊断结果标签、当前PID参数）不传递**
- 整定工作台选择回路时需要重新搜索，没有"从诊断中心待整定列表进入"的快捷路径
- 整定流程完成后，返回诊断中心时不保留原位置

**整改建议**：
1. 诊断详情页增加**「基于此诊断发起整定」按钮**，点击后跳转整定流程并自动带入：
   - 选中的回路
   - 诊断标签（预选择整定方向：振荡→减小增益/加大积分；粘滞→建议检修阀门）
   - 当前PID参数作为基线
2. 整定工作台增加**「待整定回路」列表**，自动聚合诊断中心中"建议整定"状态的回路
3. 所有跨模块跳转使用**"来源页"面包屑/返回按钮**，确保可一键返回上下文

#### 断点3：整定实施 → 效果验证(A/B对比) 流程不闭环

**问题**：
- 整定输出建议参数后，仪控工程师现场实施，但系统没有"实施记录"入口——当前"已实施"状态只在Action Tracker中标记，没有记录"什么时候改的、改成了什么值、谁改的、MOC单号"
- A/B对比功能隐藏在异常跟踪的操作列中，没有从"已实施"状态自动引导进入对比验证
- 验证周期配置（默认24h）在后端实现了，但UI没有明确提示"我们将在24小时后自动对比整改效果"

**整改建议**：
1. Action Tracker更新状态为"已实施"时，弹出**实施记录表单**（强制填写，符合Poka-Yoke）：
   - 实施时间（默认当前时间）
   - 实施人（默认当前用户）
   - 新PID参数（P/I/D，必填）
   - MOC单号（可选，但需说明不填原因）
   - 实施备注
2. 状态流转图增加"验证中"状态：「待处理 → 处理中 → 已实施 → **验证中** → 已闭环/重新打开」
3. 标记"已实施"后，明确提示："已记录。系统将在24小时后自动抓取整改后数据进行A/B对比，您也可以随时手动查看对比结果。" + 按钮[查看验证计划]

#### 断点4：新回路配置 流程路径不清

**问题**：
- 仪控工程师新投用一个回路，不知道第一步该点哪里：
  - 先"链路配置"？（ic_engineer看不到）
  - 先"测点配置"同步Tag？
  - 先"回路配置"建回路？
- 当前左树右表布局没有明显的"下一步"引导
- Tag关联需要到独立页面操作，与回路创建割裂

**整改建议**：
1. 回路配置页增加**配置向导模式**，顶部进度条引导：
   ```
   [1.链路检查] → [2.同步测点] → [3.创建回路] → [4.关联Tag] → [5.启用评估] ✅
   ```
   每步完成后自动引导下一步，未完成步骤显示"待完成"黄色警告
2. 将Tag关联功能**内嵌到回路编辑抽屉**：回路创建/编辑时，直接在同一抽屉内完成7槽位Tag选择，无需跳转独立页面
3. 配置完成后增加**验证环节**：「检查数据连通性」按钮，点击后拉取最近5分钟PV/SP/OP实时值显示波形，确认数据正常后再"启用评估"

## 五、维度四：闭环管理实现分析

### 5.1 闭环模型评估

CLPM目标闭环：`配置 → 监控 → 评估 → 诊断 → 整定 → 验证 → 持续优化`

| 环节 | 当前实现成熟度 | 主要问题 |
|---|---|---|
| **配置** | ⭐⭐⭐ | 链路配置仅ADMIN可见；配置流程无引导；Tag关联割裂 |
| **监控** | ⭐⭐⭐⭐ | 回路监控列表存在，但缺少实时异常高亮；实时数据刷新状态不明确 |
| **评估** | ⭐⭐⭐⭐ | 3+1+8 KPI体系完整；自动整点+自定义任务双轨；可信度评级落地 |
| **诊断** | ⭐⭐⭐ | 8类诊断+D-S证据融合算法落地；但诊断结果展示不直观；标签触发阈值不透明 |
| **整定** | ⭐⭐⭐ | Phase 2算法栈已实现（ARX/ARMAX/IV+5种算法+仿真）；但从诊断进入整定的链路断裂；安全提示到位 |
| **Action跟踪** | ⭐⭐ | 状态机只有4态，缺"验证中"；列表信息严重不足；MOC校验已实现但UI引导不够 |
| **效果验证** | ⭐⭐ | A/B对比接口存在但入口深；无自动验证计划提示；整改有效率统计卡片存在但不在主流程 |
| **持续优化** | ⭐ | 缺少"从验证结果反馈到参数模板/阈值优化"的闭环；无整定知识库积累 |

### 5.2 闭环衔接关键缺失

#### 缺失1：异常处置全链路时间线不透明

当前每个异常的处理历史分散，没有单回路的完整处置时间线：
- 什么时候发现的（诊断任务时间）？
- 什么时候认领的？
- 诊断结论是什么？
- 什么时候开始整定？
- 整定建议参数是什么？
- 什么时候实施的？谁实施的？改了什么？
- 验证结果怎么样？改善了还是恶化了？

**整改建议**：
在单回路诊断详情页增加**「异常处置时间线」Tab**，纵向时间轴展示全链路事件：

```
● 2026-08-01 14:00  系统自动诊断发现「振荡」问题，可信度B
│  标签：振荡(中)；建议：检查PID参数，考虑减小Kp
┃
● 2026-08-02 09:15  张工 认领，状态改为「处理中」
│  备注：已确认PV振荡，准备重新整定
┃
● 2026-08-02 10:30  整定完成，模型拟合度82%，可信度B
│  建议参数：Kp: 1.2→0.8, Ti: 3min→4min；仿真预测振荡消除
┃
● 2026-08-02 14:00  李工 现场实施，MOC-20260802-003
│  参数变更：Kp=0.8, Ti=4min
┃
● 2026-08-03 14:00  系统自动A/B对比验证完成
   结果：改善 ✅ 振荡率从32%降至5%，综合评分从52→78
```

#### 缺失2：诊断标签与整定建议的因果链不明确

当前诊断只说"有振荡"，但不直接告诉仪控工程师：
- 振荡的可能原因有哪些？概率各多少？
- 建议首先排查什么？
- 如果是参数问题，建议往哪个方向调（增益大了还是小了？积分太快还是太慢？）
- 预期改善效果大概多少？

**整改建议**：
诊断结果卡片采用**结构化诊断报告**格式：

```
┌─────────────────────────────────────────┐
│ 🔴 振荡检测                              │
│ 置信度：85% (B级)                        │
├─────────────────────────────────────────┤
│ 可能原因排序：                            │
│  1. PID参数过激 (Kp过大) - 概率65%        │
│  2. 阀门粘滞 - 概率25%                    │
│  3. 周期性外扰 - 概率10%                  │
├─────────────────────────────────────────┤
│ 建议下一步：                              │
│ ▶ 优先检查：查看OP输出波形是否有粘滞特征  │
│ ▶ 若确认参数问题：[进入整定] 预估可改善~60% │
│ ▶ 若确认阀门问题：[生成检修建议单]         │
└─────────────────────────────────────────┘
```

#### 缺失3：整定知识库与最佳实践未积累

当前每次整定都是独立的，没有积累"什么类型的回路、什么问题、用什么算法、调到什么参数效果好"的知识库。

**整改建议**（可作为Phase 3功能，但架构应预留）：
- 每次整定验证完成后，自动记录「问题类型→模型类型→算法选择→参数变化→改善幅度」
- 整定工作台为新回路推荐参数时，优先展示"相似回路的成功整定案例"
- 增加「整定知识库」页面，按控制类型/问题类型分类查询历史最佳实践

## 七、总结

CLPM v6.1在**架构设计、状态机定义、安全边界、算法落地**方面已经打下了非常扎实的基础，"配置→监控→评估→诊断→整定"的技术闭环已基本贯通，工业设计原则（Calm UI/Poka-Yoke/Glanceability/数据墨水比）在规范层面定义完整。

当前主要短板集中在**"最后一公里"的用户体验层**：技术闭环已通，但**用户操作闭环还存在断点**——仪控工程师发现问题后不能顺畅到达处置入口，关键决策信息（是什么问题、多严重、该先做什么）不能在第一屏看到，配置流程缺乏引导导致新手上手困难。

按P0→P1→P2优先级路线图整改后，预期可实现：
- 仪控工程师日常异常处置效率提升 **50%以上**（减少点击、信息前置、一键跳转）
- 新用户首次完成回路配置的时间从 **>2小时** 缩短至 **<20分钟**（向导+引导）
- 异常闭环率（发现→处置→验证）从当前约 **40%** 提升至 **>90%**（补齐验证环节+时间线追溯）
- 系统从"技术功能可演示"升级为"工业现场工程师日常愿意用、离不开"的生产力工具
