# 数据导入优化与本地验证（2026-10-20）

范围：参数配置 → 数据导入；工作区基线 `d282eb14559d20fb28eaa7471eca38894b5f850e`。
本报告记录修复阶段的本地验证；后续提交和打包以 `releases/部署指令-1041-ToDesk人工.md` 为准。
同批另有诊断性能及进度修复，不属于本报告的导入性能数据。现场部署由用户手工执行。

## 行为变化

| 文件 | 关键入口 | 变化 |
| --- | --- | --- |
| `backend/app/services/data_import.py` | `import_history_data` | 配置查询在数据库会话关闭前完成；运行进度保留收尾空间；缓存刷新和 KPI 回算提交后再发布终态；部分失败不再显示成功 |
| 同上 | `_import_single_loop` | 并行分块共用一个批次；实际写入完成后登记测点覆盖；正确换算本地窗口到 UTC；部分写入计数保留用于缓存失效；等待所有分块退出后收口 |
| 同上 | `_write_points_bulk` | 时间戳毫秒值和 SQL 字符串跨角色复用；保留质量码、COV 去重和 payload hash；批次边界检查取消并上报真实写入进展 |
| 同上 | `cancel_import_task` / `delete_import_task` | 取消改为协作退出，不强杀 Worker；取消后删除记录仍保留有 TTL 的取消标志 |
| 同上 | `list_import_tasks` | 分批检查有效任务索引，只读取当前页详情；保留过期任务清理和准确总数 |
| `backend/app/services/data_source/remote_api_provider.py` | `ensure_remote_concurrency` | 首次配置可生效；原位扩缩容，保留在途请求计数；不因换闸短时超限 |
| `backend/app/services/cache/invalidation.py` | `invalidate_loops` | 一次游标遍历删除本批次涉及回路的 L1/L2/L3 缓存，替代每回路重复遍历 |
| `backend/app/schemas/loop_data.py` / `frontend/apps/web-antd/src/api/loop-data.ts` | `ImportTaskResponse` / `ImportTask` | 新增 `currentStage` |
| `frontend/apps/web-antd/src/views/loop/data.vue` | 任务表、翻页、发起导入 | 显示阶段、耗时、成功/失败数及错误；失败进度不显示绿色成功；翻页后恢复活跃任务轮询；新任务回到第一页；默认截止时间避开最近 5 分钟 |

取消不能撤回已经完成的 TDengine 写入。运行中的远端请求会等返回或超时后检查取消；
正在执行的单批写入会结束后退出，后续批次不再写入，已写数据正常收尾。
并发限制仍是进程内限制，跨 Worker/进程容量需要按部署规模配置。

## 性能对比

同一台机器，对比基线和修改后的 `_write_points_bulk`。输入为 24 小时等量数据、
7 个角色、1 秒采样，按 8 个 3 小时块构造，每组重复 3 次取中位数。
数据库执行替换为内存接收器，固定接收时间后逐条 SQL 汇总 SHA-256；
两版的 SQL 摘要、行数和批次数完全一致。

| 输入 | 修改前 | 修改后 | 写入准备耗时下降 | 行数 / SQL 批次数 |
| --- | ---: | ---: | ---: | ---: |
| PV/OP 变化，其余 5 个角色恒定 | 0.8852 s | 0.6314 s | 28.7% | 172840 / 88 |
| 7 个角色均变化 | 2.5485 s | 1.4944 s | 41.4% | 604800 / 168 |

这里只测 Python 数据处理与 SQL 准备，不含真实网络、TDengine 或 PostgreSQL IO，
不能换算成现场总耗时下降比例。新增分块日志包含 `task`、`loop`、`chunk`、
`fetch_ms`、`write_ms`，用于现场定位剩余耗时。

任务分页回归：1000 个任务索引含 2 个过期项，第二页 10 条结果只读取 10 个 Hash；
EXISTS 使用 2 次批量管道，详情使用 1 次批量管道，总数准确为 998。
有效总数仍需遍历索引，未将其宣称为常数时间查询。
