# 10 分钟预计算：影子验证

本阶段实现原始事件块的预备与完整窗口对照，**正式评估不消费新缓存**。诊断、整定、数据导入的算法与发布路径不变；不创建 TDengine Stream/TSMA，不升级数据库。现场 961 回路的性能改善尚须复测，不能用本机耗时推算。

## 实现与边界

| 事项 | 当前行为 |
|---|---|
| 开关 | PG `sys_config.kpi.shadow.config`，缺省关闭；启用必须指定 1~24 个有效回路 UUID |
| 预备 | 既有 Beat 每 10 分钟触发；取至少结束 5 分钟的闭合 UTC 10 分钟块；只存原始事件 |
| 自动 / 人工 | 标准批量、单回路、自定义单回路/批量评估完成后派发；源任务身份和窗口随独立报告保存 |
| 窗口 | 影子验证接受不超过 1 小时的精确请求；不支持的长窗明确 `UNSUPPORTED_WINDOW`，不截断 |
| 算法 | 完整窗口统一恢复初值、锚点、改绑、覆盖、COV；再运行原 DataPlanner、质量预处理、门禁和全部 KPI 算法 |
| 正式结果 | `result_writer` 只捕获完整语义；影子主会话 `SET TRANSACTION READ ONLY`；不写 KPI / latest / 结果账本 / 输入包 |
| 消息与进程 | 复用现有 Worker/Beat，所有影子消息显式 priority=9，准备触发 120 秒过期 |
| 并发 | 全局仅一条 cohort，逐回路投递；一个 Redis 执行租约，15 秒续租、60 秒租期；单回路最多 180 秒 |
| 等待与恢复 | 后续步骤排队超过 900 秒作废；重复步骤检查 cohort+cursor；失锁立即取消；旧 token 不释放后继锁 |
| 缓存预算 | 最多 256 块，每块压缩后含 base64 至多 128 KiB，值合计最多 32 MiB；超限显式失败，不截断数据 |
| 报告 | 独立共享卷；原子写入；14 天 / 最多 1000 份；CLI 可导出完整单份报告 |

默认关闭时，正式任务只增加一次开关查询，不执行影子 TD 查询或算法。派发检查有 6 秒等待上限；配置或 Redis/消息故障记录日志，不改变已完成的正式结果。消息优先级不能抢占已运行任务，影子试验会增加读取负载，应从 1 个回路启用，再逐步扩大白名单。

影子开始时单独固定当前五层参数、指标契约、权重、门禁及质量配置，三遍使用同一份配置。源任务 ID 仅用于追踪；**不把源任务以前算出的旧结果当作本次基线**，也不修改原任务记录或 custom/标准结果归属。

## 一致性和补数失效

1. 用新鲜 TD 数据运行完整窗口基线，记录原始事件内容指纹。
2. 以 point + UTC 块边界 + 完整内容 SHA256 寻址。匹配才命中；缺块独立回源并核对指纹；损坏块删除后重建。
3. 首尾不足 10 分钟部分精确回源，包含式尾点单独保留，块内部半开拼接避免重复。
4. 再次权威回读完整窗口，并重新核对配置。比较全部输入数组字节、dtype、质量原因、完整 SeriesContext、maskedIndices，以及分值、状态、confidence、known/unknown、分母、fitness 等完整结果语义。只排除计时字段，浮点不放宽容差。

| 结果 | 含义 |
|---|---|
| `PREPARED` | 原始事件块已准备，不代表算法验证通过 |
| `EQUAL` | 稳定输入下三遍输入/结果完全一致，且正式算法给出 SUCCESS |
| `INVALIDATED` | 补数、改绑、缺口或配置变化；本次不能作一致性结论 |
| `MISMATCH` | 稳定基线下候选输入或完整语义不同，保留三份结果供定位 |
| `INSUFFICIENT_DATA` | 无数据或非 SUCCESS，不能据此晋级正式消费 |
| `ERROR` / `DISABLED` | 执行失败或运行时停用，不能视为通过 |
| `BUSY` / `STALE` | 已有一轮或排队过期，不再堆积额外任务 |
| cohort `FINISHED` | 流程结束；逐项状态仍可能不通过，不等于整批 PASS |
| `observedStatus=STALLED` | 报告显示排队，但活跃身份已过期/消失；重新发起，不伪装仍在运行或已完成 |

失效不依赖导入末尾的 best-effort 删除，也不以 TTL 当作源版本。补数新事件、同时间戳值/质量变化会得到不同内容键；初值、锚点、改绑和缺口每遍仍走原权威读取。每次都回读两遍是影子阶段的正确性成本，**尚未实现正式消费所需的持久 dirty/outbox、跨任务发布代际 fencing 或全厂流式增量计算**。

工作进程崩溃可重投同一 cursor；已推进的旧步骤不重复执行。若崩溃发生在状态推进与下一条消息投递之间，报告保持未完成，租期后释放占用并可重新发起；本阶段不声称已有可自动恢复的持久 outbox。

## 运维入口

生产先按 full-1044 部署说明挂载 `clpm-shadow-reports` 到 backend/worker 的 `/app/shadow-reports`，环境变量 `CLPM_KPI_SHADOW_REPORT_DIR` 只配置报告路径，不充当业务开关。原评分输入包目录不变。复制到宿主机或外部归档后再做长期留存。

只读查看配置与活跃状态：

```bash
docker exec clpm-backend python -m scripts.ten_minute_shadow status
```

只读查询一个明确位号的 UUID：

```bash
docker exec clpm-backend python -m scripts.ten_minute_shadow loops --tags 80LIC32103_PIDA
```

用查得的真实 UUID 启用（替换 `<loop-uuid>`）：

```bash
docker exec clpm-backend python -m scripts.ten_minute_shadow configure --enabled true --loop-ids '<loop-uuid>'
```

手动影子验证示例（UTC 窗口须有已导入的本地数据）：

```bash
docker exec clpm-backend python -m scripts.ten_minute_shadow run --start 2026-10-21T01:00:00Z --end 2026-10-21T02:00:00Z
```

只读查看最近报告（显示 shown/total；单份 `reports --id <uuid>` 可导出全部明细）：

```bash
docker exec clpm-backend python -m scripts.ten_minute_shadow reports --limit 10
```

停止新任务及后续步骤（运行项结束时重新检查开关，不能继续报告一致通过）：

```bash
docker exec clpm-backend python -m scripts.ten_minute_shadow configure --enabled false
```

## 本机验证与未完成验收

- 边界回归覆盖常值、跳变、Bad/Unknown、跨块冻结/振荡、改绑/缺口：完整输入与原质量预处理结果相等；覆盖非整点起止、包含式尾点、时区、补数/质量变更、缓存损坏、缓存预算及取消收束。
- 真实本机 PG+TDengine+Redis 的一个 SUCCESS 小时窗口：冷/暖两轮三遍完整输入和结果哈希均一致；暖缓存命中 24 块，仅 4 次事件尾点查询。见[证据摘要](验收证据/shadow-1044-local.json)。该回路不是 24 个代表回路验收，也不是 961 回路压测。
- 真实隔离 TDengine 验证迟到补点；真实 Redis Lua 验证缓存上限、互斥、cursor 重投、取消、租约被接管时拒绝 EQUAL 且保留后继 token。
- 全量门禁结果随交付清单记录。没有修改算法 golden、评分函数或预处理阈值，没有新迁移。
- **待现场**：从 1 个回路逐步扩大到 24 个代表回路；导入/诊断/评估混合负载下记录排队、执行、提交、实时 gap、导入吞吐和人工等待。影子阶段不自动升级为正式缓存消费。
