| 项目 | 说明 |
|------|------|
| 文档版本 | v1.0 |
| 创建日期 | 2026-06-23 |
| 文档性质 | 底层数据接口开发规范（交付底层开发团队实施） |
| 上层消费方 | CLPM 控制回路性能管理系统 |

---

## 1. 概述

### 1.1 背景

CLPM 系统需要对全厂控制回路进行性能评估、诊断分析和 PID 整定。底层数据来源于 DCS 控制系统，经过程数据平台汇总后向 CLPM 提供数据服务。

**数据组织方式**：
- 底层按**位号（Tag）**存储原始时序数据，不按回路组织
- CLPM 系统负责回路配置——将回路编号与 PV/SP/OP/MODE/PID 等位号关联
- CLPM 调用底层接口时，按**位号列表**查询数据，在上层组装为回路数据

底层需提供两个接口：
1. **历史数据查询接口**（HTTP REST）— 按位号列表 + 时间范围 + 采样频率获取历史数据
2. **实时数据推送接口**（WebSocket）— 订阅位号后，实时推送数据变化

### 1.2 读者对象

底层过程数据平台开发工程师。

### 1.3 术语约定

| 术语 | 说明 |
|------|------|
| 位号（Tag） | DCS 中测点的唯一标识，如 `01TV_06003_PID_PV` |
| 回路编号 | 控制回路的唯一标识，如 `01TV_06003_PID`，由 CLPM 系统管理 |
| 采样频率 | 历史数据查询的降采样间隔，如 `10s`、`1m`、`1h` |

### 1.4 回路与位号的关系

一个控制回路关联 7 个位号：

| 角色 | 位号后缀 | 说明 | 变化频率 |
|------|---------|------|---------|
| PV | `_PV` | 过程变量测量值 | 高频 |
| SP | `_SP` | 设定值 | 低频 |
| OP | `_OUT` | 控制器输出值 0-100 | 高频 |
| MODE | `_MODE` | 控制模式 | 低频 |
| PID_P | `_KP` | 比例参数 | 低频 |
| PID_I | `_TI` | 积分参数 | 低频 |
| PID_D | `_TD` | 微分参数 | 低频 |

**示例**：回路 `01TV_06003_PID` 关联的 7 个位号：

```
01TV_06003_PID_PV       — 过程变量
01TV_06003_PID_SP       — 设定值
01TV_06003_PID_OUT      — 控制器输出
01TV_06003_PID_MODE     — 控制模式
01TV_06003_PID_KP       — 比例参数
01TV_06003_PID_TI       — 积分参数
01TV_06003_PID_TD       — 微分参数
```

CLPM 根据实际分析需要，查询任意位号组合的数据。例如：波形分析可能只需 PV/SP/OP，PID 整定可能需要 PV/OP/PID 参数，性能评估可能只需 PV/SP。底层接口按位号、时间范围、采样频率返回数据，不关心位号属于哪个回路。

## 2. 底层数据存储说明

### 2.1 存储原则

- 底层按**位号**存储原始时序数据，每个位号一条时间序列
- 底层**不按回路组织数据**，不创建回路维度的子表
- 回路与位号的关联关系由 CLPM 系统维护

### 2.2 存储建议

底层可采用以下任一存储方案（由底层团队决定）：

**方案 A：TDengine 超级表（按位号）**

```sql
-- 一个超级表，每个位号一张子表
CREATE STABLE st_tag_data (
    ts          TIMESTAMP,   -- 采样时间戳
    val         FLOAT,       -- 位号值
    quality     TINYINT      -- 数据质量码：0=Bad, 1=Good, 2=Uncertain
) TAGS (
    tag_name    BINARY(128)  -- 位号名
);

-- 每个位号创建一张子表
CREATE TABLE t_01tv_06003_pid_pv USING st_tag_data TAGS ('01TV_06003_PID_PV');
```

**方案 B：单表（所有位号共用）**

```sql
CREATE TABLE tag_history (
    ts          TIMESTAMP,
    tag_name    VARCHAR(128),
    val         FLOAT,
    quality     TINYINT
);
```

> 存储方案由底层团队根据现有系统架构决定，CLPM 不做约束。CLPM 只通过接口消费数据。

### 2.3 数据质量码

| 值 | 含义 | 说明 |
|----|------|------|
| 0 | Bad（坏） | 数据不可信，上层会将值置为 null |
| 1 | Good（好） | 数据正常 |
| 2 | Uncertain（不确定） | 数据存疑 |

> 所有位号均应返回质量码。若某些位号（如 PID 参数）无质量码，统一返回 1（Good）。

### 2.4 控制模式枚举值

MODE 位号的值定义：

| 值 | 含义 |
|----|------|
| 0 | 手动模式（Manual） |
| 1 | 自动模式（Auto） |
| 2 | 串级模式（Cascade） |

## 3. 接口 1：历史数据查询（HTTP REST）

### 3.1 接口定义

| 项目 | 说明 |
|------|------|
| 方法 | `POST` |
| 路径 | `/process-data/history/query` |
| Content-Type | `application/json` |
| 认证 | Bearer Token（API Key） |

### 3.2 请求参数

```json
{
  "tagNames": [
    "01TV_06003_PID_PV",
    "01TV_06003_PID_SP",
    "01TV_06003_PID_OUT",
    "01TV_06003_PID_MODE",
    "01TV_06003_PID_KP",
    "01TV_06003_PID_TI",
    "01TV_06003_PID_TD"
  ],
  "startTime": "2026-06-22T00:00:00Z",
  "endTime": "2026-06-23T00:00:00Z",
  "sampleInterval": "10s"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tagNames` | string[] | 是 | 位号列表，一次可查询多个位号 |
| `startTime` | string | 是 | 起始时间，ISO 8601 格式 |
| `endTime` | string | 是 | 结束时间，ISO 8601 格式 |
| `sampleInterval` | string | 是 | 采样间隔，支持 `1s`/`10s`/`1m`/`10m`/`1h` |

### 3.3 响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "sampleInterval": "10s",
    "timeRange": {
      "startTime": "2026-06-22T00:00:00Z",
      "endTime": "2026-06-23T00:00:00Z"
    },
    "timestamps": [
      "2026-06-22T00:00:00Z",
      "2026-06-22T00:00:10Z",
      "2026-06-22T00:00:20Z"
    ],
    "series": {
      "01TV_06003_PID_PV": {
        "values": [382.11, 381.95, 381.88],
        "qualities": [1, 1, 1]
      },
      "01TV_06003_PID_SP": {
        "values": [380.0, 380.0, 380.0],
        "qualities": [1, 1, 1]
      },
      "01TV_06003_PID_OUT": {
        "values": [55.3, 55.5, 55.4],
        "qualities": [1, 1, 1]
      },
      "01TV_06003_PID_MODE": {
        "values": [1, 1, 1],
        "qualities": [1, 1, 1]
      },
      "01TV_06003_PID_KP": {
        "values": [0.5, 0.5, 0.5],
        "qualities": [1, 1, 1]
      },
      "01TV_06003_PID_TI": {
        "values": [120.0, 120.0, 120.0],
        "qualities": [1, 1, 1]
      },
      "01TV_06003_PID_TD": {
        "values": [0.0, 0.0, 0.0],
        "qualities": [1, 1, 1]
      }
    }
  }
}
```

### 3.4 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 0=成功，非 0=失败（见错误码表） |
| `message` | string | 结果描述 |
| `data.sampleInterval` | string | 实际使用的采样间隔 |
| `data.timeRange` | object | 实际查询的时间范围 |
| `data.timestamps` | string[] | 统一时间戳数组，ISO 8601 格式，所有位号共用 |
| `data.series` | object | 按位号组织的数据，key 为位号名 |
| `data.series[tag].values` | number[] | 该位号的值数组，与 timestamps 一一对应 |
| `data.series[tag].qualities` | int[] | 该位号的质量码数组，与 timestamps 一一对应 |

**关键约定**：
- 所有位号共用同一组 `timestamps`，按 `sampleInterval` 对齐
- 每个位号的 `values` 和 `qualities` 数组长度与 `timestamps` 一致
- 某时刻无数据时，`values` 对应位置为 `null`，`qualities` 对应位置为 `0`（Bad）
- 请求中的位号在响应中全部出现（即使无数据，返回全 null 数组）

### 3.5 采样间隔支持

| 值 | 说明 | 典型场景 |
|----|------|---------|
| `1s` | 1 秒 | 短时波形分析（≤2 小时） |
| `10s` | 10 秒 | 常规波形分析、诊断（≤7 天） |
| `1m` | 1 分钟 | 趋势分析（≤30 天） |
| `10m` | 10 分钟 | 长期趋势（≤90 天） |
| `1h` | 1 小时 | KPI 聚合（≤1 年） |

### 3.6 降采样策略建议

底层在实现降采样时，建议按以下策略聚合：

| 数据类型 | 聚合方式 | 说明 |
|---------|---------|------|
| PV / SP / OP | `AVG`（平均值） | 过程值取平均，反映区间整体水平 |
| MODE | `LAST`（末值） | 模式为状态量，取区间最后一个值 |
| PID_P / PID_I / PID_D | `LAST`（末值） | PID 参数为状态量，取区间最后一个值 |
| quality | `LAST`（末值） | 质量码取区间最后一个值 |

### 3.7 错误码

| code | HTTP Status | 说明 |
|------|-------------|------|
| 0 | 200 | 成功 |
| 1001 | 400 | 参数缺失或格式错误 |
| 1002 | 400 | 位号不存在 |
| 1003 | 400 | 时间范围非法（startTime >= endTime） |
| 1004 | 400 | 不支持的 `sampleInterval` 值 |
| 1005 | 400 | 时间范围超过限制（>365 天） |
| 1006 | 400 | 位号数量超过限制（>100） |
| 2001 | 401 | 认证失败 |
| 2002 | 403 | 无权限访问该位号 |
| 5001 | 500 | 数据库查询失败 |
| 5002 | 500 | 内部服务异常 |

**错误响应示例**：

```json
{
  "code": 1002,
  "message": "位号不存在: 01TV_06003_PID_PV",
  "data": null
}
```

### 3.8 调用示例

**cURL**：

```bash
curl -X POST http://data-server:8080/process-data/history/query \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \

    "startTime": "2026-06-22T00:00:00Z",
    "endTime": "2026-06-23T00:00:00Z",
    "sampleInterval": "10s"
  }'
```

**Python**：

```python
import httpx

resp = httpx.post(
    "http://data-server:8080/process-data/history/query",
    json={
        "tagNames": [
            "01TV_06003_PID_PV",
            "01TV_06003_PID_SP",
            "01TV_06003_PID_OUT",

```

## 4. 接口 2：实时数据推送（WebSocket）

### 4.1 接口定义

| 项目 | 说明 |
|------|------|
| 协议 | WebSocket |
| 路径 | `/process-data/realtime/stream` |
| 认证 | Query 参数 `token` |

### 4.2 建立连接

```
ws://data-server:8080/process-data/realtime/stream?tagNames=01TV_06003_PID_PV,01TV_06003_PID_SP,01TV_06003_PID_OUT&token=<token>
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tagNames` | string | 是 | 订阅的位号列表，逗号分隔 |
| `token` | string | 是 | 认证 Token |

**连接成功后，服务端返回确认消息**：

```json
{
  "type": "connected",
  "ts": "2026-06-23T15:42:00Z",
  "subscribedTags": ["01TV_06003_PID_PV", "01TV_06003_PID_SP", "01TV_06003_PID_OUT"]
}
```

### 4.3 动态订阅管理

客户端可通过消息动态增减订阅位号：

**增加订阅**：

```json
{
  "action": "subscribe",
  "tagNames": ["01TV_06003_PID_MODE", "01TV_06003_PID_KP"]
}
```

**取消订阅**：

```json
{
  "action": "unsubscribe",
  "tagNames": ["01TV_06003_PID_SP"]
}
```

**服务端确认**：

```json
{
  "type": "subscribed",
  "tagNames": ["01TV_06003_PID_MODE", "01TV_06003_PID_KP"]
}
```

```json
{
  "type": "unsubscribed",
  "tagNames": ["01TV_06003_PID_SP"]
}
```

### 4.4 数据推送格式

服务端检测到位号数据变化时，推送更新消息。**每次推送一个位号的变化**：

```json
{
  "tagName": "01TV_06003_PID_PV",
  "ts": "2026-06-23T15:42:00Z",
  "value": 382.11,
  "quality": 1
}
```

```json
{
  "tagName": "01TV_06003_PID_SP",
  "ts": "2026-06-23T16:00:00Z",
  "value": 381.0,
  "quality": 1
}
```

```json
{
  "tagName": "01TV_06003_PID_MODE",
  "ts": "2026-06-23T17:30:00Z",
  "value": 0,
  "quality": 1
}
```

**推送字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `tagName` | string | 位号名 |
| `ts` | string | 数据时间戳，ISO 8601 格式 |
| `value` | number | 位号当前值 |
| `quality` | int | 数据质量码（0=Bad, 1=Good, 2=Uncertain） |

**推送规则**：
- 事件驱动：位号数据变化时立即推送，不按固定频率轮询
- 单位号推送：每条消息只包含一个位号的变化
- 多位号复用：一条 WebSocket 连接可订阅多个位号，通过 `tagName` 区分

### 4.5 心跳保活

**服务端心跳**（每 30 秒发送一次）：

```json
{
  "type": "heartbeat",
  "ts": "2026-06-23T15:42:30Z"
}
```

**客户端心跳**（建议每 30 秒发送一次）：

```json
{
  "action": "ping"
}
```

**服务端响应**：

```json
{
  "type": "pong",
  "ts": "2026-06-23T15:42:30Z"
}
```

### 4.6 断线重连

客户端检测到连接断开后应自动重连。重连成功后，服务端推送一次**全量快照**（所有订阅位号的当前值）：

```json
{
  "type": "snapshot",
  "tagName": "01TV_06003_PID_PV",
  "ts": "2026-06-23T15:43:00Z",
  "value": 382.50,
  "quality": 1
}
```

```json
{
  "type": "snapshot",
  "tagName": "01TV_06003_PID_SP",
  "ts": "2026-06-23T15:43:00Z",
  "value": 380.0,
  "quality": 1
}
```

> 快照消息逐个位号推送，每个位号一条消息，`type` 字段为 `snapshot`。

### 4.7 错误消息

```json
{
  "type": "error",
  "code": 2002,
  "message": "无权限访问位号: 01TV_06003_PID_PV"
}
```

| code | 说明 |
|------|------|
| 2001 | 认证失败 |
| 2002 | 无权限访问该位号 |
| 1002 | 位号不存在 |
| 5001 | 内部服务异常 |

### 4.8 消息类型汇总

| type | 方向 | 说明 |
|------|------|------|
| `connected` | 服务端→客户端 | 连接成功确认 |
| `subscribed` | 服务端→客户端 | 订阅成功确认 |
| `unsubscribed` | 服务端→客户端 | 取消订阅确认 |
| 数据推送（无 type 字段） | 服务端→客户端 | 实时数据变化推送 |
| `snapshot` | 服务端→客户端 | 重连后的全量快照 |
| `heartbeat` | 服务端→客户端 | 心跳保活 |
| `pong` | 服务端→客户端 | 响应客户端 ping |
| `error` | 服务端→客户端 | 错误消息 |
| `subscribe` | 客户端→服务端 | 增加订阅 |
| `unsubscribe` | 客户端→服务端 | 取消订阅 |
| `ping` | 客户端→服务端 | 客户端心跳 |

## 5. 回路清单格式

CLPM 系统通过回路清单配置回路与位号的关联关系。回路清单为 Excel 文件（`.xlsx`），结构如下：

| 列序 | 列名 | 说明 | 示例 |
|------|------|------|------|
| 1 | 自控回路编号 | 回路唯一标识 | `01TV_06003_PID` |
| 2 | 自控回路名称 | 回路描述 | `减温水气动调节` |
| 3 | 设定值位号 | SP 位号 | `01TV_06003_PID_SP` |
| 4 | 测量值位号 | PV 位号 | `01TV_06003_PID_PV` |
| 5 | 输出值位号 | OP 位号 | `01TV_06003_PID_OUT` |
| 6 | 控制方式位号 | MODE 位号 | `01TV_06003_PID_MODE` |
| 7 | 所属区域编号 | 工艺单元代码 | `UT` |
| 8 | 是否启用 | 启用状态 | `是`/`否` |
| 9 | 比例带 | PID_P 位号 | `01TV_06003_PID_KP` |
| 10 | 积分时间 | PID_I 位号 | `01TV_06003_PID_TI` |
| 11 | 微分时间 | PID_D 位号 | `01TV_06003_PID_TD` |

> 此清单由 CLPM 系统导入，用于在 CLPM 中建立回路与位号的关联。底层不需要根据此清单建表，只需确保清单中出现的位号在底层数据库中有对应的数据。

## 6. 接口实现要求

### 6.1 性能要求

| 指标 | 要求 |
|------|------|
| 历史查询响应时间 | ≤2 秒（7 个位号、7 天、10s 采样，约 60480 点/位号） |
| 实时推送延迟 | ≤1 秒（从数据变化到推送到达客户端） |
| WebSocket 并发连接 | ≥100 个客户端 |
| 单连接订阅位号数 | ≤500 个 |
| 单次历史查询位号数 | ≤100 个 |
| 历史查询时间范围上限 | ≤365 天 |

### 6.2 可用性要求

| 指标 | 要求 |
|------|------|
| 接口可用率 | ≥99.5% |
| 断线自动重连 | 客户端重连后推送全量快照 |
| 心跳超时 | 90 秒无心跳判定连接断开（3 个心跳周期） |

### 6.3 安全要求

| 项目 | 要求 |
|------|------|
| 认证 | Bearer Token（API Key） |
| 传输 | 生产环境必须使用 HTTPS / WSS |
| 位号权限 | 按用户角色限制可访问的位号 |
| 输入校验 | 校验 `tagNames` 格式、时间格式、`sampleInterval` 枚举值 |

## 7. 附录

### 7.1 完整调用流程示例

```
1. CLPM 导入回路清单 → 建立回路与位号的关联关系
2. CLPM 根据分析需要，选择相关位号调用历史接口
   （传入位号列表 + 时间范围 + 采样频率）
   → 底层返回每个位号的时序数据
   → CLPM 将数据按时间戳对齐，组装为回路数据
   → 用于波形分析、诊断、KPI 计算
3. 用户打开监控页面
   → CLPM 建立 WebSocket 连接（订阅相关位号）
   → 底层实时推送位号变化数据
   → CLPM 按回路组织后转发给前端页面
4. 用户关闭监控页面
   → CLPM 断开 WebSocket 连接
```

### 7.2 时间格式约定

- 所有时间字段使用 ISO 8601 格式
- 带时区标识：`2026-06-23T15:42:00Z`（UTC）或 `2026-06-23T23:42:00+08:00`（东八区）
- 毫秒精度：`2026-06-23T15:42:00.123Z`

### 7.3 数据为空的约定

- 历史查询中某时刻无数据：`values` 对应位置为 `null`，`qualities` 对应位置为 `0`
- 历史查询中位号完全无数据：`values` 和 `qualities` 返回全 `null` / 全 `0` 的数组（长度与 `timestamps` 一致）
- 实时推送中位号无数据：不推送该位号

### 7.4 位号命名规范

位号名由 DCS 系统决定，通常遵循以下格式：

```
<区域代码><设备类型><编号>_<功能>_<角色>
```

**示例**：`01TV_06003_PID_PV`

| 部分 | 含义 |
|------|------|
| `01` | 区域编号 |
| `TV` | 设备类型（调节阀） |
| `06003` | 设备编号 |
| `PID` | 功能模块（PID 控制） |
| `PV` | 角色（过程变量） |

> 位号命名规范由 DCS 系统决定，底层接口只需按位号名原样查询，不做解析。
