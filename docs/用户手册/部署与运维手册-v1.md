## 2. 新装（双路径口径）

### 路径 A（生产推荐）：引导 SQL + stamp head

```bash
# 1. 建库后依次执行引导 SQL（可重放，幂等）
psql "$DATABASE_URL" -f db/postgresql/01_schema.sql
psql "$DATABASE_URL" -f db/postgresql/02_seed_data.sql
# 2. 登记迁移版本（引导 SQL 与迁移链 head 同批同内容，零漂移）
cd backend && uv run alembic stamp head
# 3. 零漂移门禁（退出码必须为 0）
uv run alembic check
```

实测（P7-03 scratch 库）：bootstrap 重放幂等、`stamp head` rc=0、`alembic check` rc=0、
目录 127 码/五角色矩阵/账本 [SEED+EXT×3] 与代码常量三方一致
（`tests/integration/test_p4_01_real_pg.py::TestFreshInstallPath` 6 passed，2026-10-16）。

### 路径 B：空库 alembic upgrade head —— **不可用（实测）**

老迁移链 init schema 历史断裂：空库 `upgrade head` 在早期 `ALTER TABLE loop_ledger ADD COLUMN`
处报 `UndefinedTableError: relation "loop_ledger" does not exist`（rc=1，P7-03 演练步骤 A 实测）。
**生产口径：一律按路径 A 引导起步**；存量库升级见 §3。

## 3. 存量升级

存量库 = 历史版本引导 SQL 打出的库（迁移前版本已在库中）：

```bash
cd backend && uv run alembic upgrade head   # 逐迁移前进至 head
uv run alembic check                        # 零漂移门禁，rc 必须为 0
```

实测口径（`tests/integration/test_p4_01_real_pg.py::TestUpgradePath`）：
git 基线引导 SQL（p204engtpl01 同批 commit `2d29235a`）→ `stamp p204engtpl01` →
造 2 存量用户 → `upgrade head` rc=0 → `check` rc=0 → 矩阵/目录/存量用户 scope=ALL 与新装路径完全一致。
**注意**：存量升级测试的"旧版 bootstrap"取自 git 基线（P7-03 修复），不得用"当前 01_schema.sql 剥段"近似——
后续批次建表插在 §9 标记之前，剥离结果不等于基线（p308arele01 撞 already exists 的教训）。

提交前本地门禁（lefthook pre-push 同款）：`ruff check . && ruff format --check .`、
`pytest -x -q`、`alembic check`（schema 漂移即失败）。

## 4. 回退（兼容与回退演练）

回退原则（方案 §6）：**生产数据已写入后不以盲目 downgrade/drop 为回退手段**，先备份并评估前向修复；
回退应用版本时仍能读兼容字段；授权回退保留至少一个管理员；配置回退生成新 revision。

隔离库回退演练（P7-03 实测，2026-10-16，scratch 自建自清、共享库零写入）：

```bash
# 前置：bootstrap 01+02 → stamp head（同 §2 路径 A）
uv run alembic downgrade -3     # head(p702perm01) 回退三步 -> p504srvflt01
uv run alembic upgrade head     # 重升级回 head
uv run alembic check            # rc=0
```

实测记录（两轮全周期幂等 PASS）：

| 步骤 | 命令 | rc | 关键 diff |
|---|---|---|---|
| 引导+stamp | bootstrap 01+02 + `stamp head` | 0 | 83 表；目录 127 码；账本 4 行 |
| downgrade -3 | 跨 `p702perm01`/`p605invest01`/`p605person01` | 0 | 79 表：-loop_investigation/-user_loop_follow/-user_workspace_preference/-user_work_resume；目录 127→124；账本 4→3；矩阵 358→350 |
| upgrade head | 重升级 | 0 | 四表恢复；目录/账本/矩阵全量复原 |
| 二轮 downgrade -3 + upgrade head | 幂等复演 | 0 | 与首轮终态完全一致；`alembic check` rc=0 |

复演工具：`backend/scripts/p703_rollback_drill.py`（自建 scratch 库、finally 全 DROP；
需环境变量 `CLPM_BOOTSTRAP_TEST_ADMIN_DSN` 指向 loopback 管理库）。
注意：`p702perm01` 的 CATALOG_EXTENSION 账本行=系统基线变更，其 downgrade 删增量行后重升级会重播种，
但**运行期已产生的 ROLE_GRANT/ROLLBACK 账本是业务数据**——生产库回退前必须先备份评估，不得直接照搬演练。

## 5. 巡检口径

| 项 | 命令/入口 | 判读 |
|---|---|---|
| 服务健康 | `GET /health`（17101） | ok；后端 lifespan 自动拉起 Celery Worker/Beat，**严禁手工再启动**（重复消费/双触发） |

| 诚实化红线 | 统计卡/看板无静默截断/降级/恒真徽章 | 发现即产品事故处理 |
