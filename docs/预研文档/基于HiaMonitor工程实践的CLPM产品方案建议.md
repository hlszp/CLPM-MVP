# 基于 HiaMonitor 工程实践的 CLPM/PDS 产品方案建议

**文档版本：** V1.0  
**适用对象：** 产品经理、控制工程师、算法团队、软件架构师、实施与交付团队  
**参考对象：** HiaMonitor V3.1.0 过程控制性能监控与评估系统  
**文档用途：** 将竞品中成熟、可借鉴的工程设计转化为我方 CLPM/PDS 产品的可落地方案

---

## 1. 总体判断

HiaMonitor 的突出价值不只在于计算平稳率、自控率、振荡率等指标，而在于它已经形成了一套较完整的工程化体系：

- 基于工业数据底座部署
- 回路资产与区域树管理
- 多厂家 PID 结构模板
- 简单回路和复杂回路建模
- 评价阈值与算法参数配置
- 指标结果点位化
- 实时评估、历史评估和综合评估
- 仪表故障、开环和有效自控状态识别
- 振荡、阀门黏滞、非线性、饱和等诊断指标
- 批量导入导出和实施校验

对我方产品而言，最合理的策略不是复制其页面和公式，而是：

> 借鉴其“工程化配置与资产管理体系”，并在在线过程辨识、PID 整定、仿真验证、问题闭环、批次工况和 AI 诊断方面形成明显增强。

---

## 2. 产品重新定位

建议将产品定位由单一“控制回路性能评估软件”升级为：

> **面向流程工业的控制回路健康管理、诊断与优化平台。**

完整业务链路应为：

```mermaid
flowchart LR
    A[数据接入] --> B[回路资产建模]
    B --> C[性能监测与评估]
    C --> D[故障诊断]
    D --> E[在线过程辨识]
    E --> F[PID整定与仿真]
    F --> G[整改任务]
    G --> H[效果复盘]
    H --> I[经验与知识沉淀]
```

产品核心不应停留在“哪些回路差”，而应回答：

1. 哪个回路存在问题？
2. 问题发生在什么工况？
3. 为什么控制不好？
4. 是 PID、阀门、仪表、扰动还是结构问题？
5. 是否需要整定？
6. 推荐参数是否安全？
7. 处理后是否真正改善？

## 6. 重点借鉴三：PID 厂家结构模板中心

这是产品工程化和跨 DCS 整定的关键基础。

## 6.1 模板内容

| 配置项 | 说明 |
|---|---|
| 厂家/产品版本 | 和利时、中控、横河、DeltaV、Honeywell、Siemens 等 |
| 控制器结构 | 并联式、串联式、ISA 标准式、厂商特定形式 |
| 比例形式 | 增益 Kp 或比例带 PB |
| 积分形式 | Ti、Ki、重复率等 |
| 积分单位 | 秒、分钟 |
| 微分形式 | Td、Kd |
| 微分滤波 | 系数或时间常数 |
| 滤波因子方向 | 乘法或除法 |
| 正反作用 | Direct/Reverse |
| MODE 映射 | MAN、AUTO、CAS、RCAS、外给定等 |
| 参数读写方式 | 常量、测点读、接口读、审批后写 |

## 6.2 需要进一步增强的能力

相比 HiaMonitor，我方应增加：

- PID 参数标准化转换
- 厂商参数到内部统一模型的双向换算
- 参数换算单元测试
- 参数写入前安全校验
- 版本差异管理
- 用户自定义厂商模板审核
- 模板变更审计

## 6.3 内部标准形式

建议内部统一采用一种标准 PID 表达，例如：

\[
C(s)=K_c\left(1+\frac{1}{T_i s}+
\frac{T_d s}{1+T_d s/N}\right)
\]

所有厂商参数先转换为内部标准形式，完成整定后再转换回目标 DCS 格式。

## 9. 重点借鉴六：有效自控率与状态机

普通自控率只看 MODE，容易形成“假自动”。

建议定义三类指标：

### 9.1 模式自控率

仅按 MAN/AUTO/CAS 等状态统计。

### 9.2 有效自控率

满足：

- MODE 为自动类状态
- OP 未长期饱和
- 数据质量正常
- PV 对控制作用存在有效响应
- 回路不处于停用、检修和异常工况

### 9.3 真实自控率

在有效自控率基础上，进一步扣除：

- 长期偏差未消除
- 高频人工修改 SP
- 自动状态下 OP 固定
- 长期受约束
- 频繁自动/手动切换
- 控制器输出有动作但 PV 无响应

## 9.4 回路状态机

```text
NOT_EVALUATED
MANUAL
AUTO_VALID
AUTO_INEFFECTIVE
SATURATED
INSTRUMENT_FAULT
COMMUNICATION_FAULT
MAINTENANCE
STARTUP_SHUTDOWN
```

## 10. 重点借鉴七：振荡识别算法

HiaMonitor 使用正负半波面积和持续时间相似性判断规律振荡，具有较强工程解释性。

我方建议采用多算法融合：

### 10.1 半波特征

对去趋势偏差序列，提取：

- 正半波面积
- 正半波持续时间
- 负半波面积
- 负半波持续时间

计算各序列的稳定中心和相似率，判断波形规律性。

### 10.2 自相关验证

用于估计周期和确认周期性。

### 10.3 频谱验证

计算主频和主频能量占比。

### 10.4 PV-OP 联合判断

用于区分：

- PID 参数过激
- 阀门黏滞
- 外部周期扰动
- 测量噪声
- 回路耦合

### 10.5 输出指标

- 振荡时间占比
- 振荡规律性
- 振荡周期
- 平均振幅
- 最大振幅
- 主频能量占比
- PV-OP 周期一致性
- 振荡严重度
- 振荡原因候选

---

## 11. 重点借鉴八：阀门黏滞诊断

HiaMonitor 强调“强振荡且波形像黏滞”时才给出高黏滞分数，这一思想值得保留。

我方建议综合：

\[
StictionScore=
OscillationEvidence
\times ShapeSimilarity
\times PVOPRelation
\times TravelAbnormality
\]

证据包括：

- PV/OP 规律振荡
- OP 锯齿、阶梯或累积释放
- PV 平顶/平底、非对称三角波
- PV-OP 相位关系
- 阀门行程指数
- 线性/非线性指标
- 阀位反馈与输出偏差

输出不应只是一个分数，而应给出：

- 诊断等级
- 证据趋势
- 可能原因
- 排查顺序
- 是否建议整定 PID
- 是否建议检修阀门/定位器

## 12. 重点借鉴九：仪表故障与数据质量

建立仪表状态：

```text
NORMAL
OUT_OF_RANGE
FROZEN
JUMP
BAD_QUALITY
COMMUNICATION_LOSS
DRIFT_SUSPECTED
```

评价结果必须同时携带质量属性：

```text
VALID
PARTIAL
LOW_CONFIDENCE
INVALID
NOT_EVALUATED
```

数据质量差时，系统不能只给低性能分，而应明确：

> 当前结果可能由仪表或数据质量问题导致，不建议直接进行 PID 整定。

## 13. 重点借鉴十：综合评分采用“加权 + 惩罚因子”

推荐基本形式：

\[
BaseScore=
w_s S+
w_a A+
w_f F+
w_u U
\]

其中：

- \(S\)：稳定性
- \(A\)：准确性
- \(F\)：快速性
- \(U\)：有效自控率

再应用惩罚因子：

\[
FinalScore=
BaseScore
\cdot P_{sat}
\cdot P_{quality}
\cdot P_{manual}
\cdot P_{fault}
\]

其中饱和、仪表故障和数据质量可成为关键否决项。

## 13.1 不建议把所有问题都塞进一个总分

总分用于管理层排序，但工程师还必须看到维度分：

- 控制效果
- 动态响应
- 执行机构
- 数据质量
- 控制投用
- 模型可信度

## 18. 最终建议

对 HiaMonitor，最值得借鉴的是以下五个工程基础：

1. **多厂家 PID 结构模板**
2. **简单与复杂回路资产建模**
3. **指标结果点位化**
4. **评价参数可配置和批量实施**
5. **有效自控率、振荡和黏滞的工程判别**

我方不应止步于复制其评估体系，而应进一步形成差异化：

> **HiaMonitor 式工程化基础  
> + 在线过程辨识  
> + PID 整定与仿真  
> + 问题整改闭环  
> + 报警、工艺和批次关联  
> + AI 诊断解释**

最终形成的不是单纯“控制回路评分软件”，而是一个面向流程工业、特别是精细化工场景的控制回路持续健康管理与优化平台。
