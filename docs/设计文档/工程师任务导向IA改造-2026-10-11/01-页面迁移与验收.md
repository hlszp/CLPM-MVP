## 1. 页面职责与必要交互

| 页面/区域 | 用户来这里做什么 | 输入与首屏 | 输出与接续 |
|---|---|---|---|
| 我的工作 | 决定先处理哪项 | 本人责任、工作日期、当前阶段、为什么处理 | 打开工作详情、回路作业或对应工单；返回保留清单位置 |
| 工作详情侧栏 | 理解一项工作并继续 | 目标、来源、负责人、期限、证据、进度、等待原因 | 继续核查、记录结论、移交或进入原业务操作；按有效权限显示 |
| 系统建议 | 从异常信号发现应核查的问题 | 范围、来源、优先级依据、关联工作、证据时间 | 认领形成核查或关联已有事项；查看全部证据 |
| 我的关注 | 长期跟踪个人选定回路 | 本人关注关系、变化与数据充分性 | 进入 360、就此询问、取消关注 |
| 全回路工作台 | 在授权范围内选择要查看/处理的回路 | 左侧装置—单元—回路树与筛选；右侧选中回路 | 调用共用单回路组件，保留树和选择状态 |
| 单回路工作台 | 处理已经明确的回路/工作 | 传入回路、工作、窗口、指定记录和可用下一步；不显示全回路选择器 | 页面/抽屉共用组件；产生真实记录后回原清单 |
| 工程助手独立页/上下文面板 | 提出问题、解释结果、找到下一步 | 对话和明确的对象/范围/窗口；可见引用来源 | 结构化证据与页面动作；后续才增加受控写入 |
| 驾驶舱 | 观察全局表现与治理进展 | 当前范围、统计窗口、数据截至与来源完整性 | 舱内只读下钻；唯一出口进入工作区 |
| 装置性能 | 判断装置控制表现并找到应处理的回路 | 装置/单元＋精确时间；评分、自控率、平稳率及完整P可评分N/E | 趋势→单元→回路→共用工作台，带原条件返回 |
| 绩效报告 | 周期复盘、形成报告 | 同范围/窗口/profile的指标、评分资格与参考构成 | 按真实能力导出，保留口径和不足说明 |
| 专业概览/记录 | 同类问题比较、批量作业、历史查询 | 专项筛选、榜单、记录身份与有效条件 | 原有抽屉或 360 作业；批量逐项反馈 |
| 配置与管理 | 配置工程对象、规则、权限及系统 | 有效配置、版本、变更对象和影响 | 按现有规则保存/发布、查看结果与审计 |

工作详情是已有业务对象的统一容器：核查用核查表单，建议用审核表单，工单用原工单操作。不得另建一套可绕过原状态检查的通用“完成”按钮。

### 5.1 需要冻结的接口含义

| 接口/记录 | 必须明确的契约 |
|---|---|
| 我的工作查询 | 当前用户、责任范围、授权范围、状态分区、排序、游标/总数、来源完整性和生成时间 |
| 工作项投影 | `kind + sourceId`、回路、目标、实际责任人、原业务状态、期限、等待条件、证据引用、允许动作 |
| 工作认领/移交 | 来源关联、稳定用户 ID、版本冲突、幂等请求身份、审计、失败后的实际结果查询 |
| 个人关注与接续 | 数据库保存账号关注、需跨设备的偏好和最近继续；用户与对象唯一关系、版本冲突、幂等及权限失效；浏览器仅缓存，字段细化见配套 03 号数据设计 |
| 页面动作 | 受支持 route key、有效参数、证据身份、回链；页面和服务端都检查有效性 |
| 助手证据 | 来源/记录/窗口/版本、数据充分性、生成时点；事实/候选解释/未知分别表达 |
| 助手运行 | 会话身份、用户身份、工具输入输出、实际计算/业务引用、失败/取消、重复请求语义 |

不得只在浏览器拼接各来源第一页，再假装形成全量个人队列。服务端可采用统一查询或可证明完整的聚合方案；超出能力时显示部分结果和具体来源状态。

### 5.2 权限与兼容要点

父导航权限取子页面可见角色的并集；当前“权限矩阵”可被所有角色查看，不能因为新父组叫配置与管理就一律限 ADMIN。reports 中不同叶页面、评估计算列表和详情的现行角色集合也并不完全相同，迁移逐项保留/核验，不凭名称归一。

诊断/整定现行可操作角色与处置流转不同；EXPERT 不因进入我的工作获得处置执行权限。新核查的认领、分派、结束权限需明确定义并落到服务端；收藏不授予任何额外动作权限。

模块禁用时仍应解释已有工作的阻塞原因，不能让工作记录无说明消失；如何读取已归档结果依有效模块/数据策略执行。新助手能力未启用时展示未启用说明，不伪造“回答成功”。

存量责任迁移不按模糊姓名自动填 userId；无法唯一核对的记录标待确认。上线可分开开关新导航、我的工作和助手。回退入口布局不能丢弃已产生的关注、核查、对话或业务引用，不直接删除新数据或盲目降级数据库。

## 6. 必须走通的岗位路径

| 案例 | 路径 | 完成证据 |
|---|---|---|
| 日常开始工作 | 登录→分配给我→看待办理由→工作详情→正确作业页 | 找到正常今日计划及历史未完工作，明确下一步 |
| 首次异常核查 | 系统建议→看证据→认领→核查→结论或移交 | 一个负责人、可追踪记录、没有重复创建 |
| 阀门/仪表问题 | 工作项→指定证据→检维修建议/原工单 | 未误导为先整定；沿适用审核和处置链 |
| 参数问题 | 工作项→条件检查→现有辨识/整定→方案 | 同一回路、窗口、参数/模型版本连续 |
| 数据不足 | 工作项→缺口解释→数据处理/等待→复查 | 不显示健康或有效参数建议；定位与修复分别记录 |
| 已实施待观察 | 对应工单→实施证据→等待条件→可比验证 | 未到条件时不催促立即验证；使用正确方案 |
| 无需进一步处置 | 核查→充分证据→结论与理由→结束核查 | 不强制创建工单；结果可追查 |
| 个人关注 | 关注正常回路→另设备登录→查看→取消 | 账号级保存；不制造待办、不修改原回路 |
| 自然语言接续 | 问题→指定事实→页面动作→实际操作→返回 | 对话与页面同对象同证据，真实业务记录可见 |
| 经理观察 | 驾驶舱→统计明细→只读证据 | 数字对账；无越权操作；入口可返回 |
| 装置分析 | 装置/时间→核心指标→单元→问题回路→工作台→返回；驾驶舱经显式出口进入工作区 | 范围/精确窗口/版本连续；N/E与不足说明可见；按同口径和周期报告对账 |

## 7. 验收矩阵

| 编号 | 必须验证的反例 | 预期 |
|---|---|---|
| IAR-A01 | 今日下午计划但尚未超期；逾期但今天没有更新 | 都能按各自理由进入适当工作分区 |
| IAR-A02 | 等待观察期/数据条件；未设期限 | 与当前可行动分开；显示复查责任和条件 |
| IAR-A03 | 同名用户、用户名变更、责任未确认 | 我的工作由稳定身份决定，不错误归属 |
| IAR-A04 | 同异常重复出现；同回路有两个不同问题 | 前者关联已有工作，后者保持独立身份 |
| IAR-A05 | 两人同时认领；移交超时重试 | 只有有效责任变更，没有重复记录或虚假移交 |
| IAR-A06 | 收藏后有异常；取消收藏时已有工单 | 收藏、异常、责任各自保持真实含义 |
| IAR-A07 | 工作来源失败、结果分页、权限范围收缩 | 明确部分/失败/权限变化，不显示虚假无待办 |
| IAR-A08 | 列表总数、状态数和点击明细 | 同范围同规则可对账；分区不重复累计 |
