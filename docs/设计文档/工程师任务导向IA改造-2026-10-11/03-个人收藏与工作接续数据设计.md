## 2. 推荐数据关系

| 逻辑记录/建议表名 | 核心字段 | 约束与用途 |
|---|---|---|
| 回路关注 `user_loop_follow` | user_id、loop_id、is_followed、revision、created_at、updated_at | user_id＋loop_id 唯一；关联 sys_user 和 loop_ledger；状态及版本用于跨设备并发 |
| 账号工作偏好 `user_workspace_preference` | user_id、preference_key、payload、schema_version、revision、updated_at | user_id＋preference_key 唯一；保存默认首页、固定菜单、页面筛选预设等允许项 |
| 最近继续 `user_work_resume` | user_id、resource_kind、resource_id、context、revision、last_visited_at | 用户＋资源类型＋资源 ID 唯一；保存最近一次可恢复的位置和证据引用 |

表名及实际列类型在 P6-05 对照届时模型、API 与迁移目录冻结；若此前已有等价账户设置存储则复用，避免重复建设。以上是最小关系，不创建泛化的个人云盘或知识管理系统。

关注记录保存“谁关注哪条回路”；回路名称、最新评分和状态从回路及分析记录读取，不复制成另一份回路台账。`is_followed=false` 仅表示取消收藏；保留关系版本可防止旧重试覆盖新的操作，不进入收藏列表，不改变任何工单责任。

偏好 payload 按白名单和版本校验：可保存配置项 ID、筛选条件与排序，不接受任意脚本、权限声明、凭据、原始工业数据或任意跳转网址。普通 JSON 容器不能替代独立的收藏关系及其唯一约束。

最近继续只保存业务 ID、页面/剖面标识、回路、时间窗、证据引用和必要筛选；不保存业务结果副本。访问时重新校验对象、权限和证据。未保存的整定输入等草稿不因存在“最近继续”就被宣称已持久化；草稿仍按对应专业功能规则处理。

## 3. 保存、查询与跨设备协议

以下为接口含义，URL 和字段细节在实施前冻结：

- **查我的关注**：登录主体由服务端获取；只返回其个人关系与当前获授权回路，支持分页、搜索和筛选。
- **设置关注状态**：提交指定 loopId、期望状态、expectedRevision 和请求身份。使用“设为已关注/未关注”，不使用重试一次就反转一次的 toggle。
- **保存个人偏好**：按单个 preference_key 更新，校验 revision；不让一台设备把整包旧偏好覆盖其他设备的新设置。
- **保存最近继续**：以服务器接收并成功校验的更新顺序记录，更新需版本检查；进入已获授权的业务对象才允许记入，不用失败访问制造条目。
- **清理个人内容**：取消收藏、删除单条最近记录、清空最近记录、重置指定偏好均经后端处理；不删除业务对象、证据、核查或工单。

两台设备同时修改同一条记录时，过期版本返回冲突和当前有效版本；界面刷新后再明确处理，不静默覆盖。相同请求重试不增加重复收藏、不反转状态。取消收藏的版本记录、最近记录清空后的版本栅栏，必须防止迟到请求恢复旧状态；保留/清理策略在 P6-05 冻结，不能提前删版本后接受旧写入。

只有服务器确认成功才能显示“已保存”。可先显示“保存中”，失败显示未保存并提供重试；本轮不引入离线写入队列，断网时不能把本地操作冒充跨设备保存成功。

## 4. 账号隔离、权限变化与浏览器职责

客户端不通过自由传入 userId 选择数据所有者。登录用户仅操作自己的个人记录；管理员身份也不自动意味着可以查看或修改其他人的私人收藏。共享或代管属于后续独立能力。

查询和打开时分别检查当前权限。失去回路访问权后，不继续显示缓存的名称、状态和证据；可以给出“有部分关注对象当前不可访问”的一般提示，但不泄露对象详情。恢复权限后可重新访问原关注关系。真正删除回路时清理关系或显示不含业务信息的不可用提示，最终删除策略与外键约束一并冻结。

账号停用后拒绝读写个人记录；实际用户删除沿项目既有账户生命周期处理，不在本轮改变其语义。关注不授予权限，不等于预警通知订阅，不自动分派工作。

浏览器可以缓存账号维度的数据，并临时记住未提交的搜索词、滚动位置、抽屉展开状态等。缓存键至少区分部署地址和账号；退出/切换账号/撤权时清理相应状态，不能把上一个人的内容展示给下一个人。服务端失败与确实没有收藏分别显示。

原匿名键 `clpm-preferences` 不能静默导入当前账号：无法证明它属于谁。允许用户显式选择一次性导入可识别的非敏感偏好，经过服务端校验并返回保存结果；未导入的旧值不能在以后登录时继续自动覆盖服务端。

## 5. 首版管理范围

首版支持关注/取消、查看收藏列表、搜索/筛选、跨设备读取；个人默认首页和已有筛选预设按账号保存，最近继续可查看和清除。默认按关注/访问时间排序，不新增拖拽排序要求。

收藏分组、个人标签、团队共享收藏、自动推送订阅仍在后续范围。当前“我的关注”与用户口语中的“我的收藏”指同一项回路快捷管理能力，不同时建立两个重复关系。

## 6. 迁移与验收

P6-05 负责模型、接口、迁移、身份和并发，P6-06 负责页面与跨设备交互，P7 验证升级/回退和资料留存。ORM 与 Alembic 迁移同批，校验新装和存量升级；本轮不执行迁移。核查/工单继续由业务模型保存，与这些个人关系分开。

作为已有 IAR-A03/A05/A06/A07/A16 的持久化子例，至少验证：

1. 设备 A 收藏，设备 B 登录同账号可见；清缓存后仍可恢复。
2. 同浏览器从账号 A 切换到 B，无个人数据串用；修改请求不能越过登录主体。
3. 重复点击、网络重试、两设备同时关注/取消，不产生重复关系或旧请求复活。
4. 默认首页和筛选预设跨设备一致；不同偏好项互不覆盖；同项冲突明确。
5. 最近继续准确恢复回路、窗口和证据；已删除/无权对象不会变成另一条回路。
6. 后端不可用显示未保存/读取失败；不把浏览器缓存标为服务器最新结果。
7. 取消收藏不删回路、不取消工单；收藏正常回路不生成待办或通知订阅。
8. 清空最近记录后迟到请求不恢复旧记录；仅关闭组件不清空持久收藏。
9. 旧无账号 localStorage 不自动归给当前人；用户选择导入后才形成账户记录。

这些是待实施的验收要求，不能以浏览器内演示或本地 mock 代替数据库持久化证据。

## 7. 学习笔记

**持久化**是将数据写入服务器数据库，让页面关闭以后仍然存在；localStorage 虽可能在浏览器重启后保留，但通常不能自动跨设备，也不能代替账号权限校验。**唯一约束**保证同一用户与同一回路只对应一条关系；**版本号**帮助系统识别两台设备谁在修改旧内容；**迁移**是让已有数据库按顺序增加新表或字段的工程步骤。

自测：清理浏览器后收藏消失是否合格？账号 A 的收藏能否通过请求参数切换成 B 来读取？收藏列表能否只保存回路名称？

答案：不合格；不能，所有者取服务端登录主体；不能只存名称，应使用稳定回路 ID，名称可变化或重名。
