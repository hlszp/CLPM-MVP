## 1. R1：待治理 TOP10

- 标题改为「待治理 TOP10」；请求 `limit=10`；同时启用后端已有的 `fitnessFilter=true`（服务端先剔除最新快照为 L0/L1 的回路再排序截断，[performance.py:172](../../backend/app/api/v1/endpoints/performance.py)）。
- 理由：「待治理」语义 = 可采取治理动作的回路；L0/L1（数据不足/手动主导）当前无治理抓手，留在榜内只会挤占名额（客户端展示层已有「不适用」灰标签兜底）。
- 升降序切换、列结构、LoopLink 默认跳诊断均保持不变。

## 2. R2：阀门运行区间异常 TOP10（新增后端聚合端点）

**现状问题**：前端全量翻页拉 `/performance/loops/snapshots?latestOnly=true`（pageSize=100 循环至拉完），客户端按 `valveOpMin<=5 || valveOpMax>=95` 过滤后**全量渲染无上限**。生产 961 回路 = 10 页串行请求，属 0930 事故同型客户端聚合反模式。

**新端点**：`GET /api/v1/performance/valve-alerts`

- 参数：`plantNodeId`（递归子树过滤，可选）、`timeWindow`（today/last_7_days/last_30_days，默认 today）、`limit`（默认 10，≤100）。
- 口径：窗口内每回路最新一条快照（`DISTINCT ON (loop_id) ORDER BY ts_start DESC`，与快照列表 latestOnly 同口径）；`valve_op_min`/`valve_op_max` 非空且（min≤5 或 max≥95）为越限。
- 排序：越限严重度 `severity = max(5-min, max-95, 0)` 降序（贴边越深越靠前），再按位号稳定排序。
- 返回：`{ total（越限回路总数）, items: [{loopId, tagName, loopName, valveOpMin, valveOpMax, severity}] }`。
- 前端：卡片显示「TOP10 + `total` 回路越限」（total>10 时标注「共 N 回路越限，仅列前 10」）；列表项点击跳回路（复用 LoopLink 交互由前端渲染）。
- 阈值 5/95 首版固定（与快照页既有口径一致）；进 sys_config 列为后续可选项。

## 3. R3：装置/单元明细表可折叠（新增节点树聚合端点）

**现状问题**：`board/aggregate` 只返回「当前节点 + 直接子节点」，行数随层级漂移（全厂=根节点数 / 选装置=1+N 单元 / 选单元=1 行），页面无层级语义。

**新端点**：`GET /api/v1/dashboard/board/tree`

- 参数：`plantId`（可选，选中节点时以其子树为根）、`timeWindow`（与 board/aggregate 同取值）。
- 返回：所选范围内 PlantNode 树（嵌套 `children`），每节点带 board/aggregate 明细行同款字段（窗口加权 rate + 最新快照计数）+ `nodeType` + `hasSnapshot`。无快照节点计数字段为 null（前端显示 —，不显示 0，诚实化原则）。
- 实现：节点集合 = 子树内全部节点；聚合复用 `_load_window_items` 的窗口加权逻辑；回路计数用 `batch_collect_descendant_loop_ids`（1 次递归 CTE）避免 N+1。
- 前端：ant Table `expandable`（`children` 嵌套数据自动出展开箭头），默认展开第一层；列结构与现表一致（名称/评级/评分/平稳率/自控率/回路总数）；树形下行序=层级序，不再按评分重排（评分排序在树形下破坏层级）。
- `board/aggregate` 端点保留不动（gauges 卡与环比仍走它）。

## 4. R4：趋势图恒柱状 + 粒度自适应 + 完整小时桶

**现状问题**：
1. `showBar = 桶数<=24`——24h 柱状、7 天/30 天自动变折线（用户裁决禁止的形态漂移）；
2. 末桶 = 当前进行中的小时，而 `unit_kpi_summary` 只写「上一个完整小时」（[kpi_calc.py:3058](../../backend/app/tasks/kpi_calc.py)），**末桶永远无数据**（实测复现：evaluatedLoops=0、三率 null）；
3. 首桶 = 窗口起点所在小时，数据起点晚于窗口起点时为空桶。

**board/trend 改造**：
- 新增 `granularity` 参数：`hour` / `day` / `auto`（默认 auto：窗口 > 48h → day，否则 hour）。日粒度按 `date_trunc('day', snapshot_time)` 聚合（权重、口径与小时聚合相同）；缓存 key 追加 granularity。
- **完整桶对齐**：小时序列 `[ceil_hour(start), floor_hour(now)-1h]`——首桶向上取整；末桶为**最后一个已完结小时**（`floor(now)-1h`）。⚠️ 2026-10-03 修复：首版末桶误取 `floor(now)`，而小时任务在 H+1 整点后才写 H 桶，导致末桶（进行中的小时）恒无评分——现钳到 `-1h`，末桶恒有数据。
- 前端：删除 `showBar` 切换，两个计数系列恒 `bar`（柱宽自适应：`barMaxWidth` 限制 30 天日柱不至于过粗）；日粒度 X 轴标签 `M-D`。三条率值线（评分/自控率/平稳率）仍为折线（双 Y 轴不变）。
- **窗口语义遗留裁决项**：`today` 在 trend = 滚动 24h、在 gauges(board/aggregate) = 北京今日 00:00 起、等级分布 = 前端自拼滚动窗——三处不一致本轮不动（避免牵连口径），已在页面 tooltip 标注统计窗口；统一语义（建议全页滚动窗或全页日历日）待用户裁决后单独改。

### 5.1 现状

- 三模块消费规则**硬编码**：评估 L0/L1 显示「不适用」；诊断 L0 阻断、L1/L2 警告放行（2026-10-01 裁决）；整定 L0/L1 阻断（ERR_TUNING_FITNESS_INSUFFICIENT）、L2 警告、L3 可发起但前置激励提示。

### 5.2 口径提案（核心：一套原子判定，三个维度视图）

维度差异的本质不是判定算法不同，而是**同一组原子标签对不同动作的阻断强度不同**。因此不建三套计算，而是「tag → 各维度档位」的映射配置：

| 原子 tag（默认阈值已可配） | 可评估性 assess | 可诊断性 diagnose | 可整定性 tune |
|---|---|---|---|
| DATA_INSUFFICIENT（L0 数据不足） | L0 阻断 | L0 阻断 | L0 阻断 |
| MANUAL_DOMINANT（手动主导） | L1 不适用 | L1 阻断 | L1 阻断 |
| LOW_AUTO_RATE（自控率极低） | L1 不适用 | L1 阻断 | L1 阻断 |
| OP_SATURATED（OP 饱和） | —（可评估） | L2 警告 | L2 警告 |
| SP_PV_DEVIATION（SP-PV 大偏差） | —（可评估） | L2 警告 | L2 警告 |
| NO_EXCITATION（无激励） | —（可评估） | L3 受限提示 | L3 前置激励提示 |
| WEAK_RESPONSE（响应极弱） | —（可评估） | L3 受限提示 | L3 前置激励提示 |

- 维度等级沿用 L0~L4 语言（L4=全开放），各模块语义：L0/L1=阻断或不适用，L2=警告放行，L3=提示放行，L4=开放。**默认映射与现行三模块行为完全等价（零行为变化的等价迁移）**，分离的价值在于各维度此后可独立调档（例：把 LOW_AUTO_RATE 对可评估性从 L1 调为「不影响」，评估覆盖立即扩大）。
- 保留综合 `fitness_level` 列（= 三维中最保守档），全站既有 L0~L4 徽标（工作台/监视页/TOP 榜）不动。

### 5.3 配置模型（配置模块实现）

- `sys_config` 新增 `fitness.dimension_maps`（JSON）：

```json
{
  "assess":   {"MANUAL_DOMINANT": "L1", "LOW_AUTO_RATE": "L1", "OP_SATURATED": null, "...": "..."},
  "diagnose": {"MANUAL_DOMINANT": "L1", "OP_SATURATED": "L2", "NO_EXCITATION": "L3", "...": "..."},
  "tune":     {"MANUAL_DOMINANT": "L1", "OP_SATURATED": "L2", "NO_EXCITATION": "L3", "...": "..."}
}
```

  `null` = 该 tag 不影响该维度；未配置的维度回落默认映射。DATA_INSUFFICIENT 恒为三维 L0（不可配置降档，数据红线）。
- 配置 UI：`/config/metric` 适用性阈值 Tab 下方新增「维度口径」块：3 维度 × 6 tag 档位矩阵（下拉：不影响/L1/L2/L3），ADMIN 可编辑，保存即生效（下次 KPI 计算任务应用新映射）。
- 现有 7 项数值阈值配置不动（维度映射消费的就是这些阈值产出的 tag）。

### 5.4 数据与消费切换

## 5A. 时间选择改版（2026-10-03 二次裁决，已实施）

裁决：①今日=当日 00:00 → 查询时刻；②日/周/月三选 + 具体日期/周次/月份；③自定义起止（精度小时）。

- **统一窗口真相源**：前端 `resolveWindow()` 计算起止（本地时间），全部接口以 `timeWindow=custom + startTime/endTime` 下发（board/aggregate、board/trend、ranking、grade-distribution 原生支持；board/tree、valve-alerts 本次补齐 custom 参数）。根治本页三处窗口口径不一致（trend 滚动 24h vs gauges 日历今日 vs 等级分布前端拼窗）。
- 周语义：周一起的 7 个日历日（与 locale 无关的周一锚点算法）；月=自然月；end 恒钳制当前时刻（未来不取数）；禁止选择未来日期。
- 趋势粒度自动适配：今日/日（≤48h）=小时柱；周/月=北京日柱（granularity=auto，§4 完整桶口径不变）。
- gauges 卡窗口标注实时跟随：今日 / M月D日 / YYYY年第N周 / YYYY年M月 / 自定义区间。
- 指标分析页深链：其窗口枚举为滚动窗预设，按当前窗口跨度映射最近档（nearestIndicatorWindow）。
- **范围**：本轮仅性能总览页切换新时间选择；其他页面的 timeWindow 控件不受影响。

## 6. R6：1920×1080 一屏布局（参考回路工作台）

参照 `views/loop/workbench360/index.vue` 的固定视口方法：

- 根容器 `height: calc(100vh - 110px); overflow: hidden`（vben 内容区偏移同 workbench360）；`main` 列 flex 布局、`min-height: 0`。
- 行高预算（1080）：工具栏 ~44 + 门禁健康条 ~48 + 顶部 gauge 行 ~96 + 中间行 ~300（趋势图 240 + 卡头）+ 底部行 flex:1（~460，**卡内滚动**）+ 间隙。
- 底部三卡（明细表/待治理 TOP10/阀门 TOP10）表格用固定 `:scroll.y` 预算（≈300，1080 设计基准），卡体 `overflow: hidden`；列表类卡（阀门）内容超高时 `overflow-y: auto`。
- 中间行三卡（状态统计 20% / 趋势 60% / 等级+适用性 20%）：状态统计与等级分布卡内容为行列表，超高内部滚动。
- 小屏（<1080 高）降级：允许底部行按内容溢出滚动（`overflow-y: auto` 兜底），不破坏布局。
