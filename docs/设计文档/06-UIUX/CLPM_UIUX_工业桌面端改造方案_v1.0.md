# CLPM UI/UX 工业桌面端改造基线方案

**文档状态**：基线方案

**适用范围**：CLPM v4.0 已完成代码基础上的 UI/UX 优化改造  
**技术基线**：Vue 3 + TypeScript + vue-vben-admin 5.7 + Ant Design Vue + ECharts

## 0. 文档定位

本文档是 CLPM 后续 UI/UX 优化的基线和指导文件。目标不是推翻 v4.0 已完成实现，也不是重做前后端，而是在现有代码、路由、API、权限和 vue-vben-admin 5.7 框架能力基础上，完成一次面向工业桌面端使用场景的体验升级。

### 0.1 改造边界

| 边界 | 口径 |
|---|---|
| 不重做系统 | 保留 v4.0 已完成的模块、路由、API 与核心业务流程 |
| 不脱离框架 | 基于 vue-vben-admin 5.7 的主题、布局、权限、标签页和偏好配置能力扩展 |
| 不大改后端 | UI/UX 优先复用现有接口，只在关键交互无法支撑时提出兼容型字段或聚合接口补充 |
| 不做普通后台 | 从通用管理后台升级为工业控制回路治理桌面端工作台 |
| 不追求装饰感 | 品质感来自信息层级、数据可视化、状态解释、组件密度和一致性 |

### 0.2 与既有文档关系

| 文档 | 关系 |
|---|---|
| `implementation-contract.md` | IA、路由、API、权限、状态机事实来源。本方案不得与其冲突 |
| `ui-ux-design-guidelines.md` v5.1 | 现行 UI/UX 规范。本方案作为工业桌面端改造补充基线 |
| `DESIGN.md` | 横切设计约束。本方案细化其“稳重、审计化、任务驱动”要求 |
| PRD v3.1 | 产品需求与安全边界上位依据 |

## 1. 改造背景

当前前端已完成 v4.0 重构适配，核心业务链路具备可运行基础。但从产品化、工业软件和日常工程使用角度看，界面仍存在以下问题：

| 问题 | 表现 | 影响 |
|---|---|---|
| 普通后台感偏强 | 大量白色卡片、默认表格、分散操作区 | 产品专业感不足 |
| 页面留白偏多 | 卡片内边距、页面分区和标题区占用较大 | 趋势图、KPI、关键对象展示面积不足 |
| 指标展示单一 | KPI 多以简单卡片数字呈现 | 不像驾驶舱，难以快速判断态势 |
| 操作入口分散 | 筛选、刷新、导出、配置、详情入口各页不一致 | 用户学习成本高 |
| 关键对象不够突出 | 回路、设备/机泵、KPI、趋势图被次要信息挤压 | 用户难以第一眼判断当前关注对象 |
| Tag 关联占用注意力 | 详情页中过多展示关联状态和明细 | 抢占 KPI 与趋势图空间 |
| 任务管理归属模糊 | 任务页面独立存在，但与性能评估引擎配置强相关 | 信息架构割裂 |
| 主题缺少工业感 | 默认白色主题文字、列表、边框层级偏弱 | 缺少专业桌面软件质感 |

---

## 2. 总体目标

CLPM UI/UX 改造目标是：

> 在 vue-vben-admin 5.7 框架基础上，将 CLPM 从通用后台界面升级为工业控制回路治理桌面端工作台。页面优先展示关键对象、KPI、趋势图、异常、任务和处置动作，把空间留给真正关键的信息。

### 2.1 设计关键词

| 关键词 | 含义 |
|---|---|
| 工业桌面端 | 更接近工程软件、监控软件、过程工业分析工具，而非营销化 SaaS 后台 |
| 高密度 | 用紧凑表格、工具条、KPI Strip、面板分区提升信息承载 |
| 数据画布优先 | 趋势图、仪表盘、排行、证据链占据主空间 |
| 任务驱动 | 用户一眼知道当前风险、下一步动作、处理入口 |
| 审计可信 | 配置变更、任务执行、诊断处置有状态、确认和留痕感 |
| 框架友好 | 保留 vben 的主题切换、偏好配置、布局能力，便于后续用户修改 |

### 2.2 验收目标

| 目标 | 验收标准 |
|---|---|
| 首屏关键对象明确 | 不滚动即可看到当前工厂/装置/回路/任务对象 |
| 主数据区域扩大 | 详情页趋势图或核心图表占主体面积 45% 以上 |
| 共性操作统一 | 范围、时间窗、刷新、导出、视图切换进入顶部工具条 |
| KPI 展示升级 | 工作台/驾驶舱不再依赖简单卡片，使用仪表盘、Bullet、趋势、排行组合 |
| Tag 关联降级 | 默认显示关联数量和状态，明细下钻查看 |
| 主题专业化 | 默认浅色主题具备冷灰画布、强表格、明确边框、等宽数字和工业主色 |
| 接口影响可控 | 纯前端改造优先，后端仅做最小字段或聚合接口补充 |

## 3. 核心设计决策

| 编号 | 决策 | 说明 |
|---|---|---|
| D1 | 采用“工业桌面端高密度工作台”作为统一 UI 方向 | 适用于工作台、回路管理、性能评估、诊断中心、回路整定 |
| D2 | 所有核心页面统一使用顶部工具条 | 承载范围、时间窗、刷新、导出、视图和更多操作 |
| D3 | 所有对象详情页统一使用对象摘要条 + KPI Strip + 主数据画布 | 回路、诊断、任务、整定页面均适用 |
| D4 | 回路详情页优先展示设备/机泵信息、KPI、趋势图 | Tag 关联状态降级为数量摘要和下钻弹窗 |
| D5 | 工作台、驾驶舱、KPI 看板引入丰富数据可视化组件 | 仪表盘、Bullet、环形质量图、排行条、趋势图替代简单卡片堆叠 |
| D6 | 任务管理并入性能评估执行体系 | 不作为孤立模块；作为评估任务、任务策略、执行记录管理 |
| D7 | 性能评估“系统配置”改为“指标配置” | 使用 Tab 统一指标定义、权重配置、引擎规则、任务策略、执行记录 |
| D8 | 默认主题为 CLPM Industrial Light | 基于 vben light mode 的工业浅色主题，不另起炉灶 |
| D9 | 保留 vben 主题配置与切换能力 | 用户可调整主色、明暗模式、圆角、布局偏好 |
| D10 | 配置类操作必须有变更摘要、影响范围和确认 | 强化治理平台的审计感和安全感 |
| D11 | 接口改动采用最小兼容原则 | 能前端重组不改接口，能补字段不新增接口，能聚合不破坏旧接口 |

## 4. 基于 vue-vben-admin 5.7 的主题适配策略

### 4.1 总体原则

CLPM 不重写一套脱离框架的主题系统，而是在 vue-vben-admin 5.7 的 `preferences`、Ant Design Vue token、CSS 变量和组件规范上建立工业化扩展。

| 层级 | 职责 |
|---|---|
| vben 框架层 | 明暗主题、主色、圆角、侧栏、头部、标签页、偏好配置 |
| CLPM 语义层 | 工业状态色、KPI 色、PV 质量色、数据线色、业务对象色 |
| 组件规范层 | 工具条、表格、KPI、图表、抽屉、弹窗、状态栏密度与层级 |

### 4.2 当前框架能力吸纳

| vben 能力 | 当前状态 | 改造要求 |
|---|---|---|
| `theme.colorPrimary` | 已配置工业蓝 | 保留为品牌主色入口 |
| `theme.radius` | 已设克制圆角 | 保持 4px 左右工业软件圆角 |
| `theme.mode` | 默认 light | 默认 CLPM Industrial Light |
| `themeToggle` | 已开启 | 保留用户明暗切换 |
| `semiDarkHeader` | 当前 false | 可作为工业半深色预设选项 |
| `semiDarkSidebar` | 当前 false | 推荐作为默认候选或可选预设 |
| `sidebar.width` | 当前 224 | 保持，允许紧凑模式 |
| `tabbar.styleType` | chrome | 保留，符合桌面多标签软件习惯 |
| `navigation.styleType` | plain | 保留，避免装饰化导航 |
| `defaultTableSize` | 已有扩展项 | 用作表格默认页大小和密度偏好入口 |

### 4.3 推荐主题预设

| 预设 | 用途 | 配置倾向 |
|---|---|---|
| CLPM Industrial Light | 默认主题 | 浅色头部 + 半深色侧栏 + 冷灰内容画布 |
| CLPM Light Classic | 兼容当前习惯 | 浅色头部 + 浅色侧栏 |
| CLPM Control Dark | 中控室/夜间值守 | 深色头部 + 深色侧栏 + 深色画布 |

### 4.4 默认主题建议

| 项 | 建议 |
|---|---|
| 页面底色 | 冷灰白，而非纯白 |
| 面板底色 | 白色或极浅灰 |
| 侧栏 | 半深色作为默认候选，增强工业软件感 |
| 头部 | 浅色或半深色，需与侧栏形成稳定层级 |
| 主色 | 工业蓝，保留 vben `colorPrimary` 可配置 |
| 圆角 | 4px 左右，避免大圆角 SaaS 感 |
| 阴影 | 减少阴影，依靠边框、分割线、层级标题 |
| 表格 | 强表头、紧凑行高、明确 hover 和选中态 |

### 4.5 CLPM 语义 Token

| Token | 语义 | 用途 |
|---|---|---|
| `control-primary` | 工业蓝 | 主按钮、当前态、链接、焦点 |
| `control-success` | 正常 | Good、成功、已实施、指标达标 |
| `control-warning` | 注意 | Uncertain、部分有效、待处理 |
| `control-danger` | 风险 | Bad、失败、低效、危险操作 |
| `control-neutral` | 中性 | 忽略、未知、INCONCLUSIVE |
| `surface-canvas` | 页面画布 | 主内容背景 |
| `surface-panel` | 面板 | 表格、图表、配置表单容器 |
| `border-strong` | 强分割 | 表头、工具条、主分区 |
| `text-primary` | 主文本 | 标题、关键数值、对象名称 |
| `text-secondary` | 次文本 | 描述、辅助标签 |
| `data-line-pv` | PV 曲线 | 趋势图主变量 |
| `data-line-sp` | SP 曲线 | 设定值 |
| `data-line-op` | OP 曲线 | 输出 |
| `data-line-mode` | MODE 曲线 | 模式阶梯线 |

## 5. 全局页面骨架

### 5.1 标准页面结构

所有核心业务页面采用统一骨架：

```text
┌──────────────────────────────────────────────────────────────┐
│ PageToolbar：范围 / 时间窗 / 刷新 / 运行 / 导出 / 更多           │
├──────────────────────────────────────────────────────────────┤
│ ObjectSummaryBar：当前对象 / 状态 / KPI / 数据质量 / 更新时间    │
├───────────────┬──────────────────────────────────────────────┤
│ 左侧导航/列表  │ DataCanvas：趋势图 / 仪表盘 / 表格 / 证据 / 仿真  │
│ 可折叠         │                                              │
├───────────────┴──────────────────────────────────────────────┤
│ StatusFooter：任务状态 / 数据延迟 / 可信度 / 最近执行结果        │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 页面类型与布局规则

| 页面类型 | 布局规则 | 示例 |
|---|---|---|
| 运行页 | 工具条 + 摘要条 + 主数据画布 | 工作台、回路监控、KPI 看板 |
| 分析页 | 工具条 + 左对象列表 + 右证据/趋势 | 低效排行、诊断详情、统计分析 |
| 配置页 | 工具条 + Tab/分组表单 + 变更确认 | 回路管理、指标配置、诊断配置 |
| 详情页 | 对象摘要 + KPI Strip + 主图 + 下钻信息 | 回路详情、任务详情、整定详情 |
| 驾驶舱 | 工具条 + 仪表盘/趋势/排行/告警组合 | 工作台、性能驾驶舱 |

### 5.3 顶部工具条规范

| 区域 | 内容 |
|---|---|
| 左侧上下文 | 工厂、装置、单元、回路、任务类型 |
| 中部控制 | 时间窗、粒度、状态筛选、视图切换 |
| 右侧动作 | 刷新、自动刷新、导出、新建、更多 |
| 状态反馈 | 刷新中、导出中、任务执行中、数据延迟 |

工具条建议高度 40 到 48px，控件高度 28 到 32px，复杂页面可 sticky。

### 5.4 对象摘要条规范

| 字段 | 示例 |
|---|---|
| 对象名 | P-101 出口压力控制 |
| 所属层级 | 常减压一单元 / 加热炉区 |
| 设备/机泵 | P-101 / 离心泵 |
| 状态 | 自动 / Good / 运行中 |
| KPI | 综合评分 82.4 |
| 更新时间 | 2026-06-27 14:30 |
| 次级信息 | Tag 关联 7/7 |

## 6. 数据可视化与驾驶舱组件规范

### 6.1 指标展示原则

工作台、驾驶舱、KPI 看板不再以简单卡片堆叠作为主要指标承载。指标展示必须帮助用户判断状态、趋势、风险和下一步动作。

| 原则 | 说明 |
|---|---|
| 指标有形态差异 | 仪表盘、Bullet、趋势、排行、状态灯组合使用 |
| 状态可解释 | 数字 + 阈值 + 趋势 + 状态原因 |
| 生动但克制 | 可用图标、轻动效、仪表盘，但避免装饰性渐变 |
| 支持下钻 | 指标可进入明细、排行、趋势或诊断页面 |
| 不只靠颜色 | 色彩必须配合文本、图标、线型或标签 |

### 6.2 推荐组件映射

| 场景 | 推荐组件 | 用途 |
|---|---|---|
| 综合评分 | 半圆仪表盘 / 健康度 Gauge | 一眼判断总体健康度 |
| 自控投用率 | 仪表盘 + 当前值 | 展示实时运行水平 |
| 稳定率/好值率/快速率 | Bullet Chart | 展示当前值、目标值、阈值区间 |
| 低效回路排行 | 横向条形图 + 表格 | 找到最差对象 |
| KPI 趋势 | 折线图 / 面积图 | 看变化方向 |
| 异常状态 | 状态灯 / 风险徽章 | 快速识别风险 |
| 数据质量 | 环形进度 / 质量条 | 展示 Good/Bad/Uncertain 占比 |
| 任务执行 | 阶段进度条 / 时间线 | 看任务是否卡住 |
| 诊断分布 | 小型堆叠条 / 标签矩阵 | 看异常类型构成 |

### 6.3 视觉品质要求

| 元素 | 要求 |
|---|---|
| 图标 | 使用统一 SVG 图标库，不使用 Emoji |
| 指标图标 | 体现设备、趋势、告警、质量、任务、风险语义 |
| 仪表盘 | 低饱和工业蓝/绿/琥珀/红，不使用炫彩渐变 |
| 动效 | 数值变化、刷新、告警可有轻微动效，150 到 300ms |
| 趋势图 | 弱化网格线，突出关键线和异常区间 |
| 状态灯 | 小而明确，必须配文字 |
| 背景 | 冷灰画布 + 白色/浅灰面板 |
| 数字 | 等宽数字，增强专业感 |

### 6.4 禁止形式

| 禁止 | 原因 |
|---|---|
| 四个白色 KPI 卡片平铺 | 过于普通后台，品质感弱 |
| 大面积彩色渐变卡片 | 不符合工业治理系统 |
| 纯装饰图标 | 占空间但不帮助判断 |
| 只有数字没有阈值 | 用户不知道好坏 |
| 只有颜色没有文字 | 可访问性不足 |
| 花哨动效 | 干扰生产判断 |

## 7. 全局组件规范

### 7.1 PageToolbar

| 项 | 规范 |
|---|---|
| 高度 | 40 到 48px |
| 背景 | 白或浅冷灰 |
| 边界 | 底部 1px 分割线 |
| 控件 | 小尺寸、紧凑、带文字 |
| 分组 | 使用间距或细竖线区分 |
| 操作 | 高频外露，中低频进入“更多” |
| 权限 | 无权限隐藏或禁用并说明原因 |

### 7.2 KpiStrip

用于替代大面积 KPI 卡片：

```text
综合评分 82.4 ↑2.1 | 自控率 91% | 稳定率 76% | 好值率 98% | 可信度 A
```

| 要求 | 说明 |
|---|---|
| 数字等宽 | 便于快速扫读 |
| 趋势可见 | 上升、下降、持平 |
| 状态可解释 | 达标、关注、低效、数据不足 |
| 支持下钻 | 点击进入指标明细或排行 |

### 7.3 TagAssociationBadge

默认只显示摘要：

```text
Tag 关联 7/7 [查看]
```

| 状态 | 显示 |
|---|---|
| 全部关联 | `7/7 已关联` |
| 部分关联 | `5/7 部分关联` |
| 未关联 | `0/7 未关联` |
| 质量异常 | `7/7 已关联，2 个质量异常` |

点击后打开弹窗或抽屉展示 PV/SP/OP/MODE/PID_P/PID_I/PID_D 明细。

### 7.4 DataCanvas

| 内容 | 要求 |
|---|---|
| 趋势图 | 主分析页面中优先占据最大空间 |
| 图例 | 可点击切换系列 |
| Tooltip | 显示精确值、单位、质量码、异常原因 |
| Zoom | 支持时间缩放和区域查看 |
| 状态 | loading、empty、error、partial 均有可见表达 |
| 辅助 | 提供数据表或导出入口 |

### 7.5 StatusFooter

| 字段 | 示例 |
|---|---|
| 数据延迟 | `数据延迟 2m` |
| 最近刷新 | `14:30:21 已刷新` |
| 任务状态 | `评估任务运行中 3/27` |
| 数据质量 | `Good 94.2% / Bad 3.1% / Uncertain 2.7%` |
| 可信度 | `A 级，valid_rate 96.3%` |

## 8. 模块级改造方案

## 8.1 工作台

### 定位

工作台是全厂控制回路治理指挥台，不是统计首页。

### 推荐布局

```text
工具条：工厂范围 / 时间窗 / 自动刷新 / 导出日报 / 更多

摘要条：全厂 | 27 回路 | 综合评分 82.4 | INCONCLUSIVE 3 | 待处理异常 5

主区上：综合健康仪表盘 | 自控率仪表 | 稳定率 Bullet | 数据质量环形图
主区中：KPI 趋势图 | 低效回路 Top10
```

## 10. 前后端接口影响评估

### 10.1 总原则

UI/UX 改造优先复用现有前后端接口。接口变更只在当前接口无法支撑关键页面信息层级、配置确认、状态解释或聚合展示时提出。

| 原则 | 说明 |
|---|---|
| 兼容优先 | 不破坏已有字段和调用方式 |
| 聚合优先 | 一屏展示需要时可补摘要字段或聚合接口 |
| 补字段优先 | 能加字段就不新建接口 |
| 读接口优先 | 先补展示数据，少动写接口 |
| 写接口慎重 | 仅配置确认、备注、审计涉及写接口补充 |
| 状态标准化 | partial、inconclusive、error reason 最好由后端提供原因 |

### 10.2 可纯前端完成

| 改造项 | 说明 |
|---|---|
| 顶部工具条 | 重组现有筛选、刷新、导出、视图操作 |
| 页面留白压缩 | CSS 和组件密度调整 |
| 工业浅色主题 | 基于 vben preferences 和 token 调整 |
| 表格密度优化 | 前端组件配置 |
| KPI 卡片改 KPI Strip | 复用现有 KPI 字段重排 |
| Tag 关联降级展示 | 基于现有 mapping status 计算数量 |
| 抽屉/弹窗/Tab 结构调整 | 页面组织变化 |
| 菜单调整 | 任务管理并入性能评估主要是前端 IA |
| 基础 loading/empty/error | 前端状态组件即可完成 |

### 10.3 可能需要补字段

| 场景 | 字段需求 |
|---|---|
| 回路详情突出设备/机泵 | 设备名称、设备类型、机泵编号、介质、工况、责任单元 |
| KPI Strip | 综合评分、自控率、稳定率、好值率、快速率、可信度、趋势 |
| Tag 关联摘要 | 关联总数、已关联数、缺失角色、质量异常数 |
| 数据质量状态栏 | Good/Bad/Uncertain 占比、valid_rate、数据延迟 |
| 任务执行摘要 | 最近任务状态、失败原因、当前阶段、预计完成时间 |
| 配置确认 | 变更摘要、影响范围、操作备注 |
| 整定风险 | 风险等级、回退方案、适用边界 |

### 10.4 可能新增聚合接口

| 接口方向 | 用途 | 优先级 |
|---|---|---|
| 工作台聚合摘要 | KPI、异常、任务、数据质量一次返回 | P2 |
| 回路详情聚合 | 回路对象、设备信息、KPI、Tag 摘要、趋势摘要 | P1/P2 |
| 配置变更预览 | 保存前返回影响范围和风险 | P1 |
| 批量操作预校验 | 批量配置前返回冲突和影响对象 | P1 |
| 任务执行摘要 | 性能评估页内展示最近任务状态 | P2 |

### 10.5 不建议本轮改动

| 内容 | 原因 |
|---|---|
| 大规模后端接口重构 | 偏离 UI/UX 改造目标 |
| 删除现有任务接口 | 任务归属调整不等于接口废弃 |
| 改数据库模型 | 除非设备/机泵字段确认必须落地且当前缺失 |
| 新建大量聚合接口 | 先确认页面方案，再按缺口补最小接口 |

## 11. 交互状态规范

所有核心表格、图表、抽屉、配置表单必须覆盖以下状态：

| 状态 | 用户看到什么 | 必须动作 |
|---|---|---|
| Loading | 骨架屏、进度、局部 loading | 不显示空白图表或冻结按钮 |
| Empty | 原因说明 + 下一步动作 | 区分无数据、未配置、筛选无结果 |
| Error | 错误原因 + 重试入口 | 不保留误导性的旧数据 |
| Partial | 部分数据有效 + 缺失原因 | 标注可信度和影响范围 |
| Success | 更新完成反馈 | 显示最近刷新时间 |
| Permission | 无权限原因 | 隐藏或禁用操作，并解释 |

## 15. 结论

本次 UI/UX 改造的核心不是“换皮”，而是将 CLPM 已完成的 v4.0 功能基础提升为更专业的工业桌面端产品体验。

最终目标：

```text
关键对象更突出
关键指标更可判断
趋势图和证据画布更大
操作更统一
主题更专业
接口改动更克制
用户仍可基于 vben 配置主题和偏好
```

本文档作为后续 UI/UX 优化、页面重构、主题调整、接口补充评审的基线。
