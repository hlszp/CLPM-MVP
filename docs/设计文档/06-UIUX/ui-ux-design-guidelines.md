# CLPM UI/UX 可视化设计与用户体验规范

**文档状态**: 正式版
**当前版本**: v3.0（完整版，整合 PRD/FDS/ADS/DDS/IDS）
**发布日期**: 2026-06-20
**设计依据**: PRD (v2.2), FDS (v2.0), ADS (v2.0), DDS (v2.0), IDS (v2.0)
**权威声明**: 本文档是后续原型系统开发与正式软件开发的**唯一 UI/UX 输入性文件**。所有视觉、交互、组件、页面设计决策以本文档为准；与历史 v0.1 草稿冲突时以本文档为准。

## 1. 文档概述与定位

### 1.1 文档目的

本文档将 PRD 的产品需求、FDS 的功能规格、ADS 的系统架构、DDS 的数据模型、IDS 的接口契约收敛为一份**面向实现的设计规范**，定义 CLPM 平台所有模块与页面的视觉系统、信息架构、组件标准、交互模式与状态表达。

### 1.2 产品定位

CLPM 是面向流程工业（石油、化工、电力、冶金、造纸、医药中间体等）的**控制回路全生命周期绩效治理与优化闭环平台**。

- **核心价值链**：`可信数据 → 自动性能评估 → 异常自动定位 → 回路诊断 → 建议与整定 → 轻量跟踪与验证 → 规模化交付`
- **安全边界**：平台不直接修改 DCS 的 P/I/D 参数，只输出建议、证据、风险与回退方案；参数由授权人员人工实施并留痕。UI 不得出现任何"下发参数""写入 DCS"类入口。
- **不是**：单机 PID 调参软件、自动下写 DCS 的黑盒自整定系统、APC/RTO/SIS 替代品、繁重审批流的通用工单系统。

### 1.3 分期范围

| 阶段 | 定位 | UI 范围 |
|---|---|---|
| **Phase 1 (MVP/V1.0)** | 跑通"自动评估、自动诊断、轻量跟踪"闭环 | 工厂模型配置、性能看板、诊断中心、Action Tracker、报表中心、系统管理 |
| **Phase 2 (V2.0)** | 深度算法与高级整定 | 回路整定与仿真、AI 辅助波形解读 |
| **Phase 3 (V3.0)** | 规模化与全厂优化 | 多厂区并发、厂级振荡源追踪、批次分析、经济效益折算 |

本文档覆盖 Phase 1 全部页面 + Phase 2 整定模块的结构性规范。Phase 3 页面仅保留结构占位。

## 2. 设计基调与反 AI Slop 原则

### 2.1 视觉语气

**稳重、审计化、任务驱动。** 这是工业治理平台，不是通用 SaaS 控制台，也不是概念展示网站。

- 信息密度高，但层级清晰。
- 优先展示状态、风险、下一步动作。
- 文案以业务动作和结论为中心，避免营销化表达。
- 首屏必须先回答"现在该做什么"，再解释"为什么"。

### 2.2 反 AI Slop 禁忌（强制）

| 禁忌 | 原因 | 替代方案 |
|---|---|---|
| 大面积装饰性渐变（紫/霓虹） | AI 训练语料的"科技感"万能公式，无品牌信息 | 单一工业蓝作 accent，中性底色 |
| Emoji 作功能图标 | 训练语料里每个 bullet 配 emoji，不专业 | 语义化 SVG 图标库（Lucide） |
| 圆角卡片 + 左彩色 border accent | 2020-2024 Material/Tailwind 烂大街组合 | 诚实边框分隔，表格为主 |
| 卡片瀑布流代替工作台 | 消费级模式，不适合工业高密度场景 | 高密度表格 + 侧栏详情 + 时间线 |
| SVG 画人脸/场景/物品 | AI 画 SVG 比例诡异 | 真实数据可视化或诚实 placeholder |
| 装饰性 icon 每处都配 | icon slop，无信息量 | 仅承载差异化信息的密度元素 |
| 编造 stats/quotes 装饰 | data slop | 留白或真实数据 |

### 2.3 信息密度分型

CLPM 属于**高密度型**产品（Dashboard/Tracker/诊断类），核心卖点是"数据驱动治理"。因此：

- 每屏需至少 3 处可见的产品差异化信息（非装饰性数据、状态推断、上下文关联）。
- 装饰性 icon 仍然忌讳——加的是**有内容的**密度，不是装饰。
- 列表和工作台页面优先高密度紧凑布局，不做营销站式大留白。

## 3. 设计系统 (Design Tokens)

### 3.1 色彩系统

所有颜色必须从 CSS 变量引用，不允许页面散落写死 hex。

#### 3.1.1 基础色

| Token | 值 | 用途 |
|---|---|---|
| `--bg-page` | `#F8F9FA` | 页面背景，长时间监控眼部舒适 |
| `--bg-panel` | `#FFFFFF` | 面板背景 |
| `--bg-muted` | `#EEF1F4` | 次级背景/表头底色 |
| `--border-default` | `#E5E7EB` | 默认 1px 边框，区分模块不用重阴影 |
| `--text-primary` | `#1F2937` | 主文本 |
| `--text-secondary` | `#4B5563` | 次文本 |
| `--text-muted` | `#6C757D` | 辅助说明 |

#### 3.1.2 品牌与动作色

| Token | 值 | 用途 |
|---|---|---|
| `--accent-blue` | `#0D6EFD` | 主 CTA、当前态、链接、焦点态（单一蓝色，仅用于主操作） |
| `--accent-blue-bg` | `#E7F1FF` | 主操作浅底色（hover/selected 行） |

#### 3.1.3 风险语义色（严格遵守）

风险色优先用于标签、边线、状态点，**不大面积铺底**。

| Token | 值 | 语义 | 适用场景 |
|---|---|---|---|
| `--status-ok` | `#198754` | 正常/达标 | 评分高、好值率达标、RESOLVED |
| `--status-info` | `#0D6EFD` | 信息/提示 | IN_PROGRESS、Auto 模式 |
| `--status-warning` | `#FFC107` | 警告/需关注 | PARTIAL、评分中、需现场核实 |
| `--status-danger` | `#DC3545` | 危险/故障 | 评分低、PENDING、Manual 模式 |
| `--status-neutral` | `#6C757D` | 中性/数据不足 | INCONCLUSIVE、IGNORED、Bad 质量 |

#### 3.1.4 评分分级配色（动态映射）

综合评分 `score`（0-100）的颜色映射，阈值由算法配置决定，UI 需支持动态读取：

| 区间（默认） | 颜色 | 语义 |
|---|---|---|
| `score >= 80` | `--status-ok` 青绿 | 优良 |
| `60 <= score < 80` | `--status-warning` 琥珀 | 关注 |
| `score < 60` | `--status-danger` 警示红 | 低效（Bad Actor） |
| `status = INCONCLUSIVE` | `--status-neutral` 冷灰 | 数据不足，**严禁显示 0 分** |

### 3.2 字体系统

| Token | 值 | 用途 |
|---|---|---|
| `--font-sans` | `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Noto Sans SC", sans-serif` | 通用界面文字 |
| `--font-mono` | `"Monaco", "Consolas", "SFMono-Regular", monospace` | 数字、规则 ID、设备位号、版本号 |

**等宽强制规则**：所有 `tag_name`、`score`、KPI 数值、时间戳、版本号必须使用 `--font-mono`，确保数值对齐与快速扫视。

### 3.3 字阶与层级

页面的层级由大小、粗细、间距共同表达，不只靠颜色。

| Token | 值 | 用途 |
|---|---|---|
| `--text-h1` | `24px / 700` | 页面主标题 |
| `--text-h2` | `18px / 700` | 模块/分区标题 |
| `--text-h3` | `15px / 600` | 卡片/小节标题 |
| `--text-body` | `14px / 400` | 正文数据（高密度表格可降至 13px） |
| `--text-small` | `12px / 400` | 辅助说明/标签 |

### 3.4 间距系统

采用 4px/8px spacing scale。

| Token | 值 |
|---|---|
| `--space-1` | `4px` |
| `--space-2` | `8px` |
| `--space-3` | `12px` |
| `--space-4` | `16px` |
| `--space-6` | `24px` |
| `--space-8` | `32px` |

规则：一级区块上下间距（`--space-6` 至 `--space-8`）大于区块内元素间距（`--space-2` 至 `--space-4`）。

### 3.5 圆角与阴影

| Token | 值 | 用途 |
|---|---|---|
| `--radius-sm` | `4px` | 控件圆角（克制） |
| `--radius-md` | `8px` | 面板圆角 |
| `--radius-pill` | `999px` | 标签/徽章 |
| `--shadow-sm` | `0 1px 2px rgba(0,0,0,0.05)` | 层级分离 |
| `--shadow-drawer` | `-4px 0 16px rgba(0,0,0,0.08)` | 右侧抽屉 |

**阴影只做层级分离，不做悬浮装饰。** 坚决不使用大面积重阴影。

### 3.6 动效

| 场景 | 动效 | 时长 |
|---|---|---|
| 状态更新反馈 | 全局 Toast fade-in-out | 300ms |
| 抽屉滑出 | `transform: translateX` | 250ms ease-out |
| 表格行 hover | 背景色过渡 | 150ms |
| 页面切换 | 无过渡（生产系统求快） | - |

### 5.3 权限 UI 规则

- **无权限的菜单项**：隐藏（不置灰）。
- **无权限的操作按钮**：隐藏。若因上下文必须保留位置，则置灰 + tooltip 提示"无权限"。

- **Sponsor 下钻限制**：Sponsor 可见看板层级，点击回路时诊断波形入口禁用，提示"当前角色不可查看单回路诊断详情"。
- **状态变更独占**：`action_tracker.action_status` 的修改按钮仅对仪控工程师可见。

## 6. 页面设计规范

### 6.1 模块 A：性能总览首页（工作台）`/`

**目标角色**：仪控工程师（默认首页）、工艺/设备工程师
**页面结构**：工作台页（三栏）

```
+----------------------------------------------------------------------------------------+
| 顶栏：产品名 | 工厂面包屑 | 角色 | 全局状态摘要 | 用户菜单                              |
+----------+----------------------------------------------+--------------------------+
| 左侧导航  | 主内容区                                     | 右侧动作区               |
|          | +------------------+----------------------+  | +--------------------+ |
|          | | 低效回路优先清单  | 当前选中回路证据摘要  |  | 待处理事项         | |
|          | | 排序/过滤/标签    | 小趋势/关键状态       |  | 处理中事项         | |
|          | +------------------+----------------------+  | 已实施待复评       | |
|          | | 全厂KPI摘要：自控率|平稳率|评分|报警|操作  |  | 快捷动作           | |
|          | +-----------------------------------------+  | 进入诊断中心       | |
|          | | Top 差等生趋势图                         |  | 进入Action Tracker | |
|          | +-----------------------------------------+  | +--------------------+ |
+----------+----------------------------------------------+--------------------------+
```

**关键交互**：

| 触发 | 行为 | 结果 |
|---|---|---|
| 点击低效回路 | 选中当前回路 | 中间证据摘要与右侧动作区联动刷新 |
| 点击 KPI 卡片 | 展开详细说明 | 展示趋势、说明和相关低性能回路 |
| 点击"进入诊断" | 跳转 `/diagnosis/:loopId` | 带 `loopId` |
| 点击"进入 Action Tracker" | 跳转 `/tracker` | 带当前回路上下文 |

**数据来源**：`kpi_snapshot_hourly`（最新一小时快照）、`action_tracker`（待办聚合）

### 6.2 模块 B：工厂模型配置 `/plant`

**目标角色**：系统管理员、仪控工程师
**页面结构**：配置页（左树 + 右表单）

**左侧树状视图**：
- 渲染 `plant_node` 层级树（`FACTORY → UNIT → EQUIPMENT`）
- 节点图标按 `type` 差异化（工厂/装置/设备）
- 支持新增、编辑、删除节点（系统管理员独占）
- 同级节点命名重复时提示"该层级下已存在同名节点"

**右侧表单**：
- 选中节点时展示：节点名称、类型、父节点
- 选中 `UNIT` 节点时，下方展示该单元下的回路台账列表（`loop_ledger`）

**回路台账表格字段**：

| 列 | 字段 | 说明 |
|---|---|---|
| 位号 | `tag_name` | 等宽字体，主标识 |
| 所属单元 | `plant_node.name` | — |
| PV 映射 | `mapping_pv` | 缺失标红 |
| SP 映射 | `mapping_sp` | 缺失标红 |
| OP 映射 | `mapping_op` | 缺失标红 |
| MODE 映射 | `mapping_mode` | 缺失标红 |
| 启用状态 | `is_active` | 开关控件 |
| 操作 | — | 编辑映射、查看诊断 |

**位号映射校验**：PV/SP/OP/MODE 四字段任一缺失，该行状态标红，tooltip 提示缺失项（如"历史数据无 MODE 点位"）。

### 6.3 模块 C：性能看板 `/performance`

**目标角色**：全角色可见
**页面结构**：数据表页 + 仪表盘

**顶部 KPI 摘要卡片**（来自 `kpi_snapshot_hourly` 聚合）：

| KPI | 字段 | 说明 |
|---|---|---|
| 自控率 | `auto_mode_rate` | 全厂/装置聚合 |
| 平稳率 | `steady_rate` | 全厂/装置聚合 |
| 综合评分 | `score` | 加权得分 |
| 报警次数 | — | 统计周期内 |
| 操作频次 | — | 统计周期内 |
| 好值率 | `good_value_rate` | 数据质量指标 |

**全局趋势图**：全厂平稳率趋势折线图（ECharts），支持时间窗切换（`today`/`yesterday`/`last_7_days`）。

## 7. 核心组件规范

### 7.1 高密度表格 (Data Table)

工业场景下，所有台账、清单、排行优先使用紧凑型表格，**不允许用卡片代替批量信息浏览**。

**必须具备**：
- 多维联合筛选（顶部筛选栏）
- 列头排序
- 固定表头与首列（位号列固定）
- 状态颜色高亮（行级或单元格级）
- 行级快捷动作（如一键导出）
- 批量选择
- 空状态
- Partial 状态提示

**性能要求**：单页 100 条以上回路表格 FPS ≥ 40。超 500 条启用虚拟滚动。

**筛选栏统一布局**（所有列表页）：
```
[关键词搜索] [装置/单元过滤] [状态过滤] [风险过滤] [排序入口] [批量操作]
```

### 7.2 状态标签 (Status Badge)

统一标签体系，必须是"**颜色 + 文本 + 语义图标**"三维组合，**绝不能仅靠颜色传递信息**。

#### 7.2.1 计算状态标签（`kpi_snapshot_hourly.status`）

| 值 | 颜色 | 文本 | 图标 |
|---|---|---|---|
| `SUCCESS` | `--status-ok` 青绿 | 正常 | ✓ |
| `INCONCLUSIVE` | `--status-neutral` 冷灰 | 数据不足 | ? |
| `PARTIAL` | `--status-warning` 琥珀 | 部分计算 | ⚠ |

#### 7.2.2 处理状态标签（`action_tracker.action_status`）

| 值 | 颜色 | 文本 | 图标 |
|---|---|---|---|
| `PENDING` | `--status-danger` 警示红 | 待处理 | ⏳ |
| `IN_PROGRESS` | `--status-info` 深蓝 | 处理中 | ⟳ |
| `IGNORED` | `--status-neutral` 冷灰 | 已忽略 | — |
| `RESOLVED` | `--status-ok` 青绿 | 已实施 | ✓ |

#### 7.2.3 控制模式标签（`st_loop_data.mode`）

| 值 | 颜色 | 文本 | 波形表现 |
|---|---|---|---|
| `0` Manual | `--status-danger` 红 | 手动 | 红色背景带 |
| `1` Auto | `--status-ok` 绿 | 自动 | 绿色背景带 |
| `2` Cascade | `--status-info` 蓝 | 串级 | 蓝色背景带 |

#### 7.2.4 诊断预诊标签（`diagnosis_label`，自由文本）

| 示例值 | 颜色 | 图标 |
|---|---|---|
| 疑似阀门粘滞 | `--status-warning` 琥珀 | ⚠ |
| 参数过激 | `--status-danger` 警示红 | ✖ |
| 原因不明(需人工介入) | `--status-neutral` 冷灰 | ? |

### 7.3 时序波形 (Time-Series Waveform)

**FDS 强制约束**：诊断中心使用上下分栏，上部为时序波形。

**技术要求**：
- 图表库：ECharts，Canvas/WebGL 渲染
- **降采样**：必须开启 LTTB 降采样，`maxPoints` 默认 2000；超 10 万点强制降采样（`ERR_TS_DOWNSAMPLE_REQ`）
- **多轴联动**：PV、SP 同一 Y 轴（主轴）；OP 独立副 Y 轴（0-100%）
- **MODE 背景带**：按 `mode` 值分段着色（Manual 红/Auto 绿/Cascade 蓝）
- **质量码表达**：`quality=0`（Bad）时段显示灰色虚线断线，悬浮提示"数据质量不可信"，**绝不使用 0 掩盖**
- **交互**：鼠标框选放大 (Zoom)、平移 (Pan)、十字准星联动 (Crosshair Sync)
- **时间窗**：最大跨度 30 天，超限提示 `ERR_TS_001`

### 7.4 PV-OP 散点图

诊断详情页下部，展示 PV-OP 二维散点分布与拟合曲线：
- 散点颜色按 `quality` 区分（Good 实心 / Bad 半透明）
- 拟合图形：椭圆（粘滞特征）/ 平行四边形（振荡特征）
- 命中规则时高亮拟合区域

### 7.5 树形视图

工厂模型配置页使用。要求：
- 支持 `FACTORY → UNIT → EQUIPMENT` 多级展开/折叠
- 节点图标按 `type` 差异化
- 选中节点高亮，右侧表单联动
- 支持拖拽调整层级（系统管理员）
- 大规模节点（>500）启用虚拟滚动

### 7.6 侧边抽屉 (Drawer)

Action Tracker 与低效排行详情使用右侧抽屉。

- 滑出动画：`transform: translateX`，250ms ease-out
- 宽度：Desktop 480px，Tablet 全宽
- 关闭后保留列表滚动位置与筛选条件
- 遮罩层点击关闭

### 7.7 空状态与异常状态

**空状态 (Empty)**：必须说明原因 + 提供动作入口。
- "暂无计算数据，请检查数据接入配置"
- "当前时间窗无低效回路"

**Partial 状态**：明确"缺什么、还能继续做什么、下一步去哪"。
- 批次 Partial：黄色警告横幅，列出 Inconclusive 回路数量与影响

**Inconclusive 状态**（数据不足是一等公民，不是错误）：
- 灰色标签"数据不足"
- 波形区灰色断线
- 评分区显示"—"而非 0
- tooltip"好值率低于 20%，无法计算"

**Error 状态**：
- 计算超时/内存溢出：中断批次，记录日志，触发管理员告警
- 越权操作：全局 Toast"无权限"
- 网络异常：标准错误态 + 重试按钮

## 8. 状态机与状态表达规范

### 8.1 页面状态矩阵

所有列表/详情页统一遵循以下状态表达（整合 prototype-state-spec，对齐 FDS 概念）：

| 页面 | Loading | Empty | Error | Success | Partial/Inconclusive |
|---|---|---|---|---|---|
| 性能总览首页 | 正在加载当前 KPI 与待办 | 当前没有待处理回路 | 当前快照无法读取 | 展示低效清单和动作区 | 部分回路 Inconclusive，只展示可判定部分 |

| 审计日志 | 正在加载日志 | 当前无日志记录 | 读取失败 | 展示日志列表 | — |

### 8.2 核心状态机

#### 8.2.1 回路就绪状态
```
Partial（字段缺失，标红） → 就绪（PV/SP/OP/MODE 完整校验通过）
```

#### 8.2.2 回路评估状态（`kpi_snapshot_hourly.status`）
```
正常计算 → SUCCESS（输出评分）
好值率 < 20% → INCONCLUSIVE（不计算、不聚合、灰色、断线）
部分字段缺失 → PARTIAL（黄色横幅）
```

#### 8.2.3 Action Tracker 处理状态（`action_tracker.action_status`）
```
PENDING → IN_PROGRESS → RESOLVED（触发 A/B 对比采集）
PENDING/IN_PROGRESS → IGNORED
```
- 每次变更记录 `updated_by` + `updated_at`
- 标记 RESOLVED 后截取 `[T-7天,T]` vs `[T,T+7天]` 窗口

#### 8.2.4 诊断预诊标签
- `疑似粘滞`（散点拟合命中椭圆/平行四边形）
- `参数过激`（FFT 检测高频震荡）
- `原因不明(需人工介入)`（算法匹配度低）

#### 8.2.5 报表生成状态
```
生成中 → 已生成（可下载）
生成异常（截图服务失败）→ 支持手动重试
```

## 9. 交互模式规范

### 9.1 全局交互原则

- 任何页面优先服务当前用户要完成的动作，而非展示所有信息。
- `数据不足 / Inconclusive` 是一等状态，不是错误。
- 所有跳转保持当前装置/单元上下文。
- Phase 2/3 页面只允许"查看结构"和"返回"，不做深交互。

### 9.2 动作反馈

- 任何主级按钮点击必须触发明确的状态流转提示。
- 采用轻量级全局 Toast（fade-in-out，300ms），不阻断操作。
- 异步任务（如 PDF 导出）显示"生成中"状态，轮询结果，不阻塞 UI。

### 9.3 上下文保持

- 列表页点击行 → 右侧抽屉，关闭后保留列表滚动位置与筛选条件。
- 跨页跳转携带 `loopId`、`plantNodeId`、`timeWindow` 等上下文参数。

## 11. 响应式与无障碍

### 11.1 响应式断点

| 视口 | 断点 | 规则 |
|---|---|---|
| Desktop | `>= 1440px` | 完整三栏/双栏工作台，高密度多栏 |
| Tablet/HMI | `1024px - 1439px` | 保留两栏，次级详情抽屉化，侧边栏可折叠 |
| Mobile | `< 768px` | 步骤式/抽屉式，仅关键数据查看，不建议波形诊断 |

### 11.2 页面级响应式规则

| 页面 | Desktop | Tablet | Mobile |
|---|---|---|---|
| 性能总览首页 | 三栏工作台 | 清单上、证据中、动作下 | 卡片顺序化，保留主次 |
| 全局看板 | KPI 卡片 + 趋势 + 表格 | 表格优先，趋势折叠 | 摘要优先 |
| 低效排行 | 大表格 + 侧栏 | 表格优先，侧栏抽屉化 | 列表化摘要 |
| 诊断详情 | 趋势 + 散点 + 动作侧栏 | 趋势在上，散点/动作在下 | 趋势摘要 + 可展开证据区 |
| Action Tracker | 表格 + 抽屉 | 表格优先，抽屉全宽 | 列表 + 全宽抽屉 |

### 11.3 无障碍

| 领域 | 规则 |
|---|---|
| 键盘 | 状态变更、导出等操作必须可 Tab 完整操作 |

| 对比度 | 满足 WCAG AA 标准 |
| 等宽 | 数字、位号、ID 等宽字体确保对齐 |

### 11.4 浏览器兼容

Chrome (v90+), Edge (v90+), Safari (v14+)。

## 12. 原型实现指引（huashu-design 对接）

### 12.1 原型技术栈

- **框架**：React 19 + Vite + TypeScript
- **路由**：React Router（SPA）
- **图表**：ECharts（LTTB 降采样、Canvas/WebGL）
- **图标**：Lucide（语义化 SVG）
- **状态**：React Context 承载全局会话（角色、选中回路、时间窗）
- **数据**：本地 mock data，不接真实 DCS

### 12.2 huashu-design 技能对接

后续原型开发使用 `huashu-design` 技能，遵循其设计哲学：

| huashu-design 原则 | CLPM 应用 |
|---|---|
| 反 AI Slop | §2.2 禁忌清单已对齐：禁渐变/Emoji/卡片瀑布/SVG 画物 |
| 高密度信息分型 | CLPM 属高密度型，每屏 ≥3 处差异化信息 |
| 资产 > 规范 | 工业图标用 Lucide 语义库，不手画 SVG |
| Junior Designer 模式 | 先写 assumptions + placeholder，尽早 show |
| 诚实 placeholder | 缺数据留灰色方块+标签，不画烂 SVG |
| 系统优先不填充 | 每元素必须 earn its place，不加 data slop |

### 12.3 原型角色切换模拟

第一阶段不做真实鉴权，用顶部角色切换器模拟：
- 切换影响菜单可见项、默认首页、主 CTA、操作权限
- 不刷新页面数据，但重新计算可见区域和禁用态
- 角色集：仪控工程师、工艺/设备工程师、Sponsor、系统管理员、外部专家

### 12.4 原型验收标准（Phase 1）

- 6 个核心页面可运行（性能总览、工厂模型、低效排行、诊断详情、Action Tracker、报表中心）
- 角色切换器驱动菜单与页面可见态
- 至少 1 条闭环链路可跑通（看板→排行→诊断→标记已实施→A/B 对比）
- 所有主按钮有真实结果
- 所有列表页支持筛选、排序
- `npm run dev` 与 `npm run build` 通过
