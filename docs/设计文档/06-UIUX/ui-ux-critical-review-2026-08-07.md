## 0. 执行摘要

CLPM 前端的**信息架构和页面骨架已经达标**（7 模块双轴导航、单页四区回路工作台、诊断三区、整定 4 锚点均已按契约 v2.7 落地），**设计规范文档也相当完备**（UI/UX v6.1 的 token、五色语义、等宽数字、空状态、高危屏障等规则写得比大多数团队都好）。

**真正的问题在执行层**：规范与实现之间存在系统性落差——色彩纪律、空状态、数字排版、图表基线、品牌身份这五件事，规范里几乎都写对了，代码里几乎都没守住。同时存在 2 个安全叙事级缺陷（死导航、`riskConfirmed:true` 绕过）在持续透支用户信任。（附注：暗色模式经真实开关复测为"可用但未校准"，已从 P0 调整为 SYS-P2-10，见 §10 框架能力盘点。）

**第二轮以流程工业真实岗位（仪控工程师/管理者）工作流复走查（§8）**，结论更尖锐：数据链路与诊断/整定专业深度扎实，但工程师"每天用 50 次"的动线卡在最后三公里（巡检无增量视图、波形 PV 压扁、验证无提醒、交接班零支持）；管理者只接触的 3-4 个页面每个都踩雷（登录即弹"无权限访问"、TOP5 默认显示最优而非最差、**审计日志列表字段映射失效导致全列 "—"**——合规留痕页面形同虚设）。

**总体评分：20/40（Nielsen 启发式，"可接受"下沿）**。骨架 7 分水平，执行 4 分水平。

**最重要的三个数字**：

- **155 行**硬编码 hex 颜色散布在 33 个 `.vue` 文件中（规范 §14 C-01 要求全部走 token）；
- **8+ 个核心页面**空状态只有"暂无数据"四个字（规范 §7.9/§14 E-01 要求"原因 + 动作入口"）；
- **0 处** `aria-label`（全项目），可访问性语义层完全缺失。

**建议路线图**：Phase 0（1 周，修信任）→ Phase 1（2-3 周，收敛视觉系统）→ Phase 2（3-4 周，效率与组件基线）→ Phase 3（持续，暗色/i18n/无障碍正式化）。详见 §9。

## 2. AI-Slop / 模板感判定

**判定：非典型 AI 生成痕迹，但存在明显"框架默认脸"（template-default slop）。**

通过项（无以下 AI slop）：无玻璃拟态、无渐变文字、无紫色霓虹暗色、无 hero-metric 大卡模板、无无意义卡片瀑布。

未通过项（框架默认痕迹，同样损害专业感）：

1. **品牌泄漏**：全站左上角与登录页显示 "Vben Admin"（`index.html:15` 的 `%VITE_APP_TITLE%` 在 `.env.development`/`.env.production` 中均未定义，回退为 vben 默认名；登录页背景甚至直接渲染出 `%VITE_APP_TITLE%` 幽灵文字）。生产构建同样受影响。**这是对"产品化平台"定位伤害最大的一条，修复成本却最低。**
2. **登录页素材**：紫蓝色 SaaS 风 3D 等距插画（通用"数据大屏"素材），与危化工业平台的稳重审计语气（DESIGN.md §2）直接冲突。
3. **Emoji 图标**：回路工作台四区标题用 🛰️📊🔍🔧（loop/workbench.vue:653/677/711/792），而 `preferences.ts:82` 自述设计约束明确写着"反 AI Slop：无 Emoji 图标"——**自己定的规矩自己破**。
4. **彩色标签阵列**：温度=红、压力=蓝、液位=绿、流量=青的类型色矩阵（use-loop-palettes.ts:34-42 硬编码 Tailwind 七色），是 antd 模板的典型默认审美，违反本项目自己的语义色纪律（§3.1.3"严格遵守"）。

## 4. 工业四原则达标度（第一性原理对照）

以 ZL 工业设计规范四大原则 + ISA-101 为基准逐项判定：

### 4.1 Calm UI（99% 时间安静）——**不达标**

规范原文："90% of the screen should use neutral colors"。实际：

- **类别信息彩色化**：回路类型七色（红温度/蓝压力/绿液位/青流量……）、预警规则类型四色（紫组合/蓝阈值/橙可信度/青漂移）、指标类别三色——这些**全部是中性分类信息，不是状态**，却占用了语义色相。ISA-101 的核心纪律是"颜色只留给需要行动的异常"，类别区分应使用文字/图标/灰阶。
- **零值彩色化**：诊断总览"异常回路数 0.0 个"用**红色**大数字——零异常是最优状态，却用了告警色；整定工作台"平均拟合度 0.00%"红色、"已完成 0"绿色。正常/零信息染色的直接后果：用户看到满屏红绿时无法分辨哪些需要行动，且对颜色脱敏（告警疲劳的自我制造）。
- **性能总览六连彩虹 gauge**：每个表盘都带红黄绿蓝弧段，一屏 6 个彩虹 + 1 个绿 donut + 1 个六色饼图，是典型 chartjunk（Stephen Few 仪表盘反模式黑名单第一条）。

### 4.2 Poka-Yoke（防呆）——**框架好，有缺口**

已落地：`ClpmDangerConfirmModal` typed confirmation（8 处）、变更原因留痕、整定"只读建议·人工实施·需留痕"横幅、权重和 100% 校验弹窗。

缺口：

1. **回路工作台快操作绕过风险确认**（loop/workbench.vue:272/314，`riskConfirmed: true` 硬编码）——同一平台，整定详情页要求人工确认，工作台快操作却静默跳过，安全叙事出现裂缝。要么补确认交互，要么在设计文档中明确豁免条款，二者取其一，不能含糊。
2. **危险确认双轨**：8 处 typed confirmation 与 11 页 Popconfirm 并存（规范 §14 明确"禁 Popconfirm"），执行不统一。
3. **无 Undo 窗口**：删除规则/用户等可逆操作全部走确认弹窗，没有"撤销"替代路径——确认疲劳的风险源（行业惯例：可逆操作优先 Undo，不可逆才 Confirm）。
4. **表单约束不足**：预警优先级裸数字输入（无上下限提示）、整定参数输入框未见即时范围校验（需进一步验证）。

### 4.3 Glanceability（1-2 秒一瞥可读）——**不达标**

- **核心波形图失去可读性**：`waveform-chart.vue:530-552` 将 PV/SP/OP 全部放在同一 y 轴（yAxis[1] 只给了 MODE）。OP 是 0-100%，PV 是 0-5 MPa——OP 线飘在 70 高位，PV/SP 被压成底部两条平线，**趋势、波动、偏差全部不可见**。规范 §7.3 明确"PV/SP 同轴、OP 副轴 0-100%"，实现未遵守。这是诊断场景的核心图表，属于 P0 级图表缺陷。
- **数字无上下文**：性能总览 gauge 只有当前值（还全是 --%），无目标刻线、无正常区间、无趋势箭头；ISA-101 要求"当前值+设定点+正常区间带"的条形指示，Stephen Few 要求 bullet graph 替代 gauge。
- **表格数字缺排版纪律**：回路实时表 SP/PV/OP 三列**每格重复单位**（"3.50 MPa"×27 行），单位应进表头；同一回路实时值在工作台显示 4 位小数（3.4642）而监控表显示 2 位（3.48）——ISA-101 §7.2.1.2 精度一致性原则违反；数字列未统一右对齐 + tabular-nums（`ClpmNumeric` 组件存在但覆盖面不足）。
- **截断破坏扫读**：台账/选择器"描述"列普遍 10 字省略号（"自低压蒸汽减温减压器X401…"），而屏幕右侧大量留白；顶栏用户名被裁成"理员"；预警规则代码列断行（"CONFIDENCE_DEGRAD ED"）；数据源页"触发KPI"复选框被面板边缘裁切。

### 4.4 数据墨水比——**中等偏下**

- 优点：1px 细边框、无重阴影、无渐变装饰，底色干净（规范 §3.5.1 执行到位）。
- 问题：空状态大白盒浪费首屏（回路性能页"暂无数据"白盒高约 450px，无原因无动作）；装饰性图表占位（性能总览 donut 只有一个分类"自动"，一个数字就能表达）；统计 chip 条（回路实时 11 个 chip）使用彩色左边条装饰——`border-left` 侧条正是规范与通用设计准则双重禁止的模式。
- 弹窗密度失衡：回路性能页单页挂 2 抽屉 + 2 弹窗（含 90% 宽 4-Tab 诊断弹窗），回路工作台挂 5 弹窗 + 1 抽屉——弹窗套弹窗违背"页面优先服务任务"（DESIGN.md §3），也说明页面信息架构在为"不想离开当前页"付出过高代价。

## 6. 代码级规范扫描（Web Interface Guidelines）

对 9 类目标文件执行规则扫描后的聚合结果（全库 grep 佐证）。**先说通过的**——这些已经是优点，应保持：

- 数字 `tabular-nums` 覆盖良好（industrial-light.css + 10+ 组件）；日期数字本地化走 `toLocaleString('zh-CN')`；无 `<img>` 无尺寸问题；无 `autoFocus` 滥用；渲染中无布局读取；无 `outline-none` 破坏焦点；多数表单有 `confirm-loading`；长文本 `ellipsis/truncate/min-w-0` 处理到位；破坏性操作主流路径有确认。

**命中统计（按类别）**：

| 类别 | 命中 | 代表 |
|---|---|---|
| a11y 可访问性 | 19 | 见下 |
| form 表单 | 6 | 标签未关联、无脏表单守卫 |
| motion 动效 | 5 | `transition: all` ×4、无 reduced-motion |
| antipattern | 4 | `span @click`、原生 `title`、`<a>` 无 href |
| focus | 2 | 行内操作 hover-only 无 `:focus-within` |
| url | 2 | 监控筛选不进 URL、误报无确认 |
| touch/theme/perf | 5 | 无 `color-scheme: dark`、无 theme-color、左栏 100 项无虚拟化 |

**最关键的 8 条（全部有 file:line）**：

1. `index.html:12` — viewport 写死 `maximum-scale=1.0, user-scalable=0`，**禁止用户缩放**，WCAG 1.4.4 硬违规。工业现场平板/大屏用户与低视力用户直接被挡。
2. `toolbar-button.vue:33/166` — 全站工具栏 icon-only 按钮**无 aria-label**（默认 `iconOnly: true`，仅 hover tooltip）。全项目 `aria-label` 零命中。
3. `monitor.vue:1693-1704`、`kpi-strip.vue:138-146`、`loop-performance.vue:1323-1362`、`tuning/detail.vue:265-287`、`workbench.vue:594-602` — "卡片/文字即按钮"模式（`div/span @click`，无 role/tabindex/键盘事件）在 5 处核心交互复制；全 src 零 `@keydown` 处理，自定义交互**全部键盘不可达**。
4. `industrial-light.css:270-332` — 暗色变量块无 `color-scheme: dark`，暗色下原生滚动条/表单控件仍浅色渲染（与 SYS-P0-04 叠加）。

7. `page-toolbar.vue:126-164` — "刷新中…/已刷新/数据延迟"状态区无 `aria-live`，异步反馈读屏不可达。
8. 全站业务页标题均为 `<div>`，仅 4 个文件有 `<h3>`，无页面级 `<h1>` —— 标题层级缺失，读屏与 SEO 双损失（内网系统 SEO 无所谓，但文档结构影响可访问性树）。

## 8. 流程工业角色审查（仪控工程师 / 管理者双重视角）

> 本节以流程工业（危化/化工）企业的真实岗位工作流为标尺，对模块与界面做第二轮走查。证据来自角色实测（sponsor / ic_engineer / admin 三账号登录实测）+ 页面截图 + API 数据比对。与 §1-§7 的"设计实现层"视角互补：本节回答的是**"这套系统放进工厂的真实工作节奏里，卡在哪"**。

### 8.0 角色与节奏设定

- **仪控工程师（IC_ENGINEER）**：全厂 27+ 回路的日常健康责任人。典型一天：班前巡检（15 分钟）→ 异常确认与分级 → 深入诊断 → 处置（整定/联系仪表/工艺协同）→ 24h 后效果验证 → 交接班。
- **管理者（仪控主管 / Sponsor）**：低频、高利害、时间稀缺。典型节奏：早会 3 分钟看板 → 周会 Bad Actor 治理 → 月度考核与汇报 → 合规审计抽查。

## 9. 系统性整改方案与路线图

### 9.1 四条设计宪法（第一性原理推导）

1. **颜色是信息通道，不是装饰材料。** 发布《CLPM 色彩约定表》：语义五色仅服务"状态/异常/需行动"；类别维度（回路类型、规则类型、指标类别）一律中性化（灰阶 tag + 文字/图标区分）；零值/无数据/正常态不着色。全站每处用色必须能回答"这个颜色在告诉我什么"。
2. **空状态是一等公民。** `ClpmEmptyState` 强制三要素——为什么空、下一步做什么、数据统计范围；无数据时不渲染装饰性图表（donut/饼图/gauge 空转比空白更糟，因为它假装有数据）。0 值与"无数据"是两种状态，不得混用。
3. **数字必须可比较。** 全站数值四件套：右对齐、tabular-nums、精度表（同一指标全站同一小数位）、单位进表头；每个关键数字必须有上下文（目标值/正常区间/趋势箭头/数据时间）。`ClpmNumeric` 从"可用组件"升级为"强制基线"。
4. **专家效率与新手引导双通道。** 高频页（监控/工作台/异常跟踪）补齐加速器：筛选入 URL、密度切换、列设置、行内快捷动作、⌘K 位号直达；新手路径（配置、向导）保持渐进披露。两套通道在同一页面共存但互不干扰（默认密度服务专家，引导元素对专家可折叠）。

### 10.2 主题与个性化启用方案（融合 §9 路线图）

- **偏好抽屉策展白名单**：对用户开放=主题模式（亮/暗/跟随系统）、紧凑模式、字号、灰色模式、色弱模式、内容宽度；**隐藏=主色选择器、内置色板、圆角、布局切换**——理由：工业平台色彩语义是纪律（宪法第 1 条），不能被用户级随意改色击穿；布局/圆角是产品设计决策，不交给用户。
- **暗色校准**（Phase 1，SYS-P2-10）：`useClpmTheme` 明暗双板接入 ECharts preset；语义五色暗色对比度重校（亮黄/亮绿在深底需降亮度）；`color-scheme: dark` 补上；industrial-light.css 的 292 补丁随 token 单源化逐步退役。

- **通知铃铛接预警**（Phase 2）：智能预警引擎已有 WebSocket `/api/v1/ws/alerts` 推送通道，接入顶栏 notification widget——这正好落地附录 A 第 28 条"最高优先级未确认预警全局常驻可见"；未接前铃铛置空态说明，不显示假徽标。
- **preferencesExtension 清理**（Phase 1）：补 `preferences.antd.*` 双语 locale 键；删除 `tenantMode` 残留字段；审计 `defaultTableSize`/`reportTitle` 实际消费方，无消费则删除。

### 10.3 锁屏与按钮级权限（评估建议）

- **锁屏**：中控室/办公室共用电脑场景下，锁屏（保留会话、快速恢复）有真实价值，建议 Phase 2 评估开启 `lockScreen`（vben 原生，成本极低）。
- **`v-access`**：当前行内动作（编辑/删除/停用）权限靠页面自行判断或不判。Phase 2 引入 `v-access` 指令统一按钮级权限，配合 RBAC 权限点清单。

### 10.4 系统管理模块完整引用评估（结论：**不完整引用**）

vben playground（演示应用，不在生产构建内）提供 system/{user, role, menu, dept} 完整 CRUD 演示页。评估结论：**不建议完整引用**，理由：

1. **权限模型不匹配**：CLPM 的 RBAC 是契约驱动的**固定 5 角色矩阵**（契约 v2.7 §5，PRD 事实来源），角色与权限点由产品设计固化；vben 的角色/菜单管理面向"动态角色 + 后端菜单表（accessMode: 'backend'）"模型，引入后会产生"界面上可配、契约不支持"的假能力，反而制造权限语义混乱。
2. **后端成本高**：playground 页面基于 mock 数据，接真实后端需要菜单表/角色表/部门表一整套 DDL + API + 权限同步逻辑——与"最小改动、不破坏后端"的整改约束直接冲突。
3. **真实需求已被定制页覆盖**：用户 CRUD/密码重置/启停、审计日志、权限矩阵查看、自动报表、LLM 配置均已存在（当前缺陷是数据映射 bug——修 bug 比换框架页面便宜一个数量级）。
4. **部门管理（dept）无业务对应物**：CLPM 的组织维度是"工厂-装置-单元"工厂模型，不是公司部门树。

**可借鉴（不引用页面，借鉴模式）**：① playground 用户页的"搜索表单 + 抽屉表单 + 状态切换"交互模式，用于 users.vue 修复时顺手对齐；② 角色-菜单树形授权交互设计留档备查（若未来 PRD 开放自定义角色再评估，届时需契约 §5 修订 + 后端菜单/角色表配套）；③ `v-access` 按钮级权限指令（见 §10.3）。
