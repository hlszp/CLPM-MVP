# zcode 执行与交接

当前接续优先使用[12号提示词](12-zcode接续交接提示词-2026-10-11.md)，跨方案依据见[11号复核](11-三方案交叉复核与融入计划-2026-10-11.md)。原P2/G2批次已PASS，不从P0重启；先补本次发现的原G2契约欠项并准备后续任务，保留G2后暂停点。下列通用模板仅在相应阶段获启动后使用，本次文档修订不额外授权业务实施/生产动作。

## 1. 通用执行协议

1. 确认CLPM-MVP仓库、当前分支/SHA/工作区、适用AGENTS、用户本次授权和环境Owner；现有 `.zcode/.codegraph` 不接管清理。
2. 主协调读README、方案§1–3、任务依赖及本阶段；子任务只读指定章节和相邻代码。CodeGraph使用当前checkout的显式projectPath；不运行codegraph install修改AGENTS。
3. 阶段有唯一候选和任务路径Owner；独立子任务用独立worktree。共享文件、DB迁移、真实服务由主协调串行整合，不能多代理共享同一执行树写文件。
4. 本包编制基线不是永远正确：实施前复核变化，登记已修条目与新证据；未经批准不删范围或跳Gate。
5. 用户只启动P0时，保持业务代码只读。P1以后须确认DEC-01具体旧页面白名单，不推断AGENTS禁改自动解除。
6. 按任务卡最小范围实施，复用已有helper/API/类型/组件/测试，不分叉算法和工作台。跨Owner更改先形成具体契约，协调后串行接入。
7. 30分钟或关键步骤完成更新交接；上下文超过约50%收紧，写“已完成/未完成/下一步”。未经提交授权不做WIP commit，以工作区diff及交接保存状态。
8. 不修改ZCode会话数据库来显形、不新建cron、不启动额外Worker/Beat、不借用另一任务环境。后端重启由keeper按授权统一管理。
9. 门禁逐条运行并保存退出码；所有测试/容量命令必须确认隔离环境。真实DB/Worker试验不能以mock替代。
10. 提交/推送/触发CI/合main/部署仅用户明确要求时执行；已有授权可复用，不重复问。唯一推送远端github，origin禁推；禁止force与no-verify。
11. 阶段作者报“待验收”，由未参与编写的验证者固定候选复核；REWORK先修复再复验。没有必要证据的阶段不晋级。

## 4. 任务交接模板

```markdown
# 交接：<阶段/任务ID>
- 状态：未启动/执行中/待非作者验收/REWORK/验收通过/暂停
- 根目录、分支、基点、候选SHA或diff hash：
- 运行环境/keeper、代码Owner：
- 用户授权范围、旧路径白名单、Git/生产授权：
- 文档版本/hash、配置revision、数据manifest/hash：
## 已完成
任务ID → 文件/符号 → 行为差异 → case → 原始证据位置
## 未完成与阻断
明确哪个case/依赖/决定未通过；不能写泛泛“基本完成”。
## 自测与非作者验证
分开列验证者、命令、退出码、passed/failed/skipped/xfail；禁止同一结论混称。
## 影响与回退
schema/历史结果/配置/权限/窗口改变；回退条件和步骤。
## 接续第一步
下一个文件/符号/命令，已完成检查不要无理由重复。
```

## 5. 非作者实施验收提示词

```text
你是指定任务的非作者验证者，未参与该任务实现。业务代码只读，不替作者修代码。
固定候选SHA/diff hash、文档版本、数据/配置与环境Owner；读任务卡和对应case。

输出PASS/REWORK，逐条给文件:行、复现步骤/证据、影响、必要修正及未验边界。
不得提交、推送、合并、部署或操作未授权环境。文档与实现验收分开报告。
```
