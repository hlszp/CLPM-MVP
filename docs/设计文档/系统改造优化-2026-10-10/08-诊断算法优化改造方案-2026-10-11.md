## 1. 决策摘要：先让结论可信，再提高速度

推荐依次完成三件事：

1. **纠正诊断含义与输入错误**：工程参数真正入算；保留真实时间、连续段和质量标记；区分未检查、无法判断、计算失败、有效阴性；保留“有症状但原因未定”。
2. **完善工程判据与证据**：按 SP/MODE/工况事件分析，统一单位和限幅，明确每种方法适用范围及标准依据；候选原因必须有正面证据，支持度不冒充概率。
3. **实施等价性能优化并验证容量**：有限滞后或 FFT 相关、任务内共享特征、批量元信息和队列预算；固定数据、配置和方法后测真实诊断链路。

| 工程师当前可能遇到的问题 | 改造后的行为 | 对业务的影响 |
|---|---|---|
| 配置保存成功，但诊断仍使用默认阈值 | 结果可查看实际生效值、单位、来源和版本 | 参数修改有可核对的效果 |
| 全部跳过或响应事件不足，页面仍显示正常 | 明确未检查/数据不足/缺少事件及补充条件 | 避免漏掉应继续排查的回路 |
| fast 单一粘滞算子阳性，但主分类为空 | 显示粘滞相关症状、原因未定、后续检查项 | 症状不会因未确诊而消失 |
| SP 主动变更被描述为独立外扰 | 标注 SP 响应；其他突变先报告观察事实 | 减少错误的工艺排查和 PID 建议 |
| 同源算法融合后支持度升高，被理解为正确率 | 显示规则支持度、证据依赖、覆盖和校准状态 | 工程师能判断证据强度与局限 |
| 24 小时长窗在粘滞计算中耗时明显增加 | 限定计算范围并复用特征，测量完整落库时间 | 降低批量成本，同时保留诊断覆盖 |

**本轮交付是设计与验收规格。** 未修改业务代码、数据库或运行服务，未运行算法测试、容量基准，未提交或推送。文中“应、验收、目标”描述实施要求，不表示已经实现或通过。

## 3. 工程输入契约

### 3.1 一个可复现的诊断输入包

沿用 P2-03 的 CalculationContext 与不可变输入包，不另建快照体系。具体 schemaVersion 以 P2-03 已验收版本为准；诊断扩展具有自己的版本，不能悄改既有版本的含义。

必须能追溯以下内容：

| 内容 | 最小要求 |
|---|---|
| 原始输入 | PV/SP/OP/MODE、质量码及原始时间戳，窗口采用 UTC 半开区间 [start,end) |
| 数据身份 | datasetSnapshotId、inputHash、原数据来源及绑定版本；保持绑定但改变数值或质量必须改变输入身份 |
| 质量与时间 | OBSERVED/HELD/UNKNOWN、逐信号有效 mask、实际采样间隔、连续段目录、预处理规则及版本 |
| 工程属性 | PV/SP/OP 单位和量程、控制输出上下限、MODE 编码、控制类型；未知有明确标记 |
| 动态事件 | SP/MODE/PID/已知工况切换事件；无法确认工况时记录 unknown，不伪造稳定工况 |
| 配置 | 实际生效参数及来源 DEFAULT/TEMPLATE/NODE/LOOP/TASK、revision、参数 hash |
| 方法身份 | 算子选择、profile/实现版本、融合规则、适用性规则及解释版本 |
| 关联证据 | KPI 来源 recordIds、窗口、方法/单位；实际用作判断的附加输入必须固定身份 |

P2 负责忠实保存行为及来源；P3 负责改变诊断语义。基于已接收的 P2-03，先做接口差异检查，仅补缺少的诊断扩展，不重写已验收载体。D1 必须接入 save_calculation_snapshot(kind=KIND_DIAGNOSIS_RAW)，并把实际输入包 ID 写入 diagnosis_run.dataset_snapshot_id；列存在不等于诊断可复现。

### 3.2 连续段、同步与采样

1. 按实际时间排序、处理重复时间和非法值，保留处理原因。数值信号、可选 SP、质量和逐点 metadata 使用同一时间索引；质量码专项统计保留完整质量时间轴。
2. 动态算子在各自必需信号的公共有效连续段内运行。缺口、MODE 切换、SP 事件和已知工况/PID 变更按算子规则划段；不把不同段拼成一条等距数组。
3. 每个算子注册：目标频带/最小激励、采样前提、最短连续时长/周期数、允许 gap、模式、事件条件和多段归并规则。全局 32 点门禁不能替代这些前提。
4. 首期 FFT、互相关及粘滞波形法采用连续有效等间隔段。输入不足时明确原因；若以后引入重采样或插值，必须有独立预处理版本、抗混叠说明与反例验证。
5. 已有“300 点、30 点、8 点”等参数在历史版本保持原义。新配置优先表达秒/周期数；迁移必须给换算基准和前后差异，不将变采样间隔时的物理持续时间静默改变。
6. 同物理信号不同采样率的对比，只在共同可观察频带、足够周期和满足抗混叠条件时要求结论一致。观察能力不足允许输出不足原因。

**多段归并推荐规则**：每段保留单独特征与状态；某段合格阳性可以保留该时段症状，不自动外推整个窗口；窗口有效阴性要求预先声明范围的必需段/事件覆盖完整。时长类指标按分子、分母汇总；不同模型的 τ、不同频率和支持度不直接平均。

### 3.3 单位、阈值与工程模板

- 修复 recommendations 按 diagCode 的真实消费；任务开始固定快照。无覆盖配置使用已登记默认并保存来源；配置读取异常、非法参数为 ERROR＋具体 reasonCode，不归为缺数据，也不静默退回默认。
- PV/SP 同物理量使用相同换算；OP 归一化与限幅同步换算。单位变化属于仿射变换，阈值、分辨率、量程应同步转换。
- 椭圆法明确传入 PV/OP 实际量程，或消费有证据的归一化信号；取消未经证明的“双轴默认 100”假设。
- expected τ 来自批准模板、设备/工艺设计或已确认正常历史，记录适用工况、来源、版本和维护人。没有来源时只报告测得的动态特征，不判断“比应有速度慢”。
- 仪表冻结幅度应关联仪表分辨率/噪声基线和工程单位；缺少这些属性时保留波形疑似状态，避免确诊仪表故障。
- 饱和率建议与现行 KPI 的时间、MODE、真实限幅和已发布 ε 口径统一；默认零容差的既有裁决继续有效。若保留“距离限位 2 个单位以内”的近限位检查，单列 near-limit 指标、单位和版本，不能继续与严格饱和率混称。
- 新增参数先注册、校验并贯通实际消费后再开放配置。高级统计阈值由有权限的工程人员维护，不把所有内部常数暴露为普通输入项。

## 4. 诊断结果、有效阴性和证据支持度

### 4.1 算子状态与有效阴性

保留既有 executed/detected/confidence/error 字段，并增加版本化 assessmentState、reasonCode、hypothesisId、segmentResults、appliedParameters 等元信息。以下为推荐字段语义，D0 定稿后成为实现依据。

| assessmentState | 含义 | 能否用于排除对应症状 |
|---|---|---|
| POSITIVE | 满足适用条件并命中该方法的异常判据 | 否，保留症状证据 |
| NEGATIVE | 满足输入、工况、观察范围和执行要求，未命中 | 仅限该方法声明的症状假设和观察范围 |
| NOT_APPLICABLE | 方法前提不成立，如无极限环时使用椭圆法 | 否 |
| INSUFFICIENT_DATA | 缺信号、连续时长不足、无合格响应事件或拟合信息不足 | 否 |
| ERROR | 参数解析、内核或依赖异常 | 否；错误不能被空结果吞掉 |
| NOT_RUN | 未选、停用、上游阻断或预算终止；保存不同 reasonCode | 否；资源不足不是数据不足 |
| CANCELLED | 被任务取消，检查未形成有效终态 | 否 |
| LEGACY_UNVERIFIABLE | 历史记录缺少足以证明判断有效性的元信息 | 否；只用于兼容历史 |

有效阴性必须同时满足：目标假设已声明、所需信号和参数可信、模式/事件前提成立、连续时长及激励充分、数值计算成功、阈值实际生效、必需检查完整、未发现越阈证据。一次函数返回或全局门禁通过都不充分。

例如“在这一小时内未检测到满足本方法定义的周期振荡”可以成为有效阴性；“阀门健康、全部故障已排除”不能由椭圆法未命中推出。

### 4.2 诊断运行状态与科学结论分开

沿用数据库 status 的 RUNNING/SUCCESS/PARTIAL/FAILED，不把新科学状态直接塞入该枚举。新增 assessment 元信息建议包含：

~~~json
{
  "schemaVersion": "diagnosis-assessment/1",
  "judgementStatus": "SYMPTOM_DETECTED",
  "causeStatus": "UNRESOLVED",
  "profileId": "<固定的profile身份>",
  "profileVersion": "<固定版本>",
  "scope": {"hypotheses": [], "requiredChecks": [], "excludedChecks": []},
  "coverage": {},
  "supportKind": "RULE_SUPPORT",
  "calibrationStatus": "NOT_CALIBRATED",
  "supportRuleVersion": "<固定规则版本>",
  "evidenceGroups": [],
  "confidenceDefinitionsSnapshot": {},
  "kpiSourceRecordIds": []
}
~~~

此例只展示字段结构，不是 API 已实现样例。判定值域与保存位置建议如下：

- judgementStatus：SYMPTOM_DETECTED / VALID_NEGATIVE / INCONCLUSIVE / NOT_ASSESSED / LEGACY_UNVERIFIABLE。
- causeStatus：CANDIDATE / UNRESOLVED / NOT_ASSESSED。人工复核继续使用现有 review 字段和可追溯证据，算法不写“人工已确认”。
- 建议在 diagnosis_run 增加可空 JSONB assessment_meta，summary/detail 同时输出 assessment；将同份元信息写入既有不可变结果账本。迁移、ORM、生产新装 SQL 同批，D0 核对 P2-03 最新 schema 后实施。
- primary_category 保持现有八类或 NULL；NULL 不再被当成“正常”的充分条件。原因未决可为 NULL 并保留症状、建议和 assessment。
- 有有效阳性但部分算子失败：保留症状，status=PARTIAL，列出未完成范围。全部执行错误：status=FAILED。正常完成的数据不足：可保持 status=SUCCESS，但科学结论为 INCONCLUSIVE，并使用现有 DATA_INSUFFICIENT 类别表达真正的数据不足。
- selected 为空才是零检查，科学结论为 NOT_ASSESSED；L0 全局门禁虽然执行数为零，仍按既有裁决形成正式 DATA_INSUFFICIENT。预算未运行、取消不能改写成数据不足或有效阴性。取消后的未完成对象按任务审计留痕，不发布新正式结论或建议。

推荐组合决定表如下；D0 将其冻结为参数化验收向量。非必需检查失败不扩大或抹去已完整完成的必需范围，仍须显示运行缺项。

| 组合 | run.status | judgementStatus / primary_category | 任务计数与发布 |
|---|---|---|---|
| 所选必需检查全部合格阴性，执行无异常 | SUCCESS | VALID_NEGATIVE / NULL | 已终结；仅声明固定范围内未发现症状 |
| 阳性＋其他必需检查预算未运行或ERROR | PARTIAL | SYMPTOM_DETECTED / 有正面证据才给原因候选，否则NULL | 已终结；保留局部症状和未完成范围，不计全覆盖成功 |
| 仅有阴性＋必需检查ERROR/预算未运行 | PARTIAL | INCONCLUSIVE / NULL | 已终结；不能发布范围有效阴性 |
| 全部NOT_APPLICABLE | SUCCESS | INCONCLUSIVE / NULL | 已终结但不可判定；不得计有效阴性 |
| L0数据门禁，或全部必需检查真正缺数据 | SUCCESS | INCONCLUSIVE / DATA_INSUFFICIENT | 已终结且数据不足；所选检查保存门禁阻断原因 |
| 全部ERROR，或全部因预算NOT_RUN | FAILED | INCONCLUSIVE / NULL | 已终结且失败；配置/资源问题不计缺数据 |
| selected为空 | 优先创建run前拒绝；已有占位则FAILED | NOT_ASSESSED / NULL | 不进入有效诊断成功数；参数/配置原因可追 |
| 取消已有RUNNING占位 | FAILED＋reasonCode=CANCELLED | NOT_ASSESSED / NULL | 任务审计计取消，取消优先避免同时计失败；不发布该占位为正式结论 |

任务终结数是进度，不能冒充有效结论数。对象计数优先级为取消→运行失败→不可判定→可判定，各对象只占一类，另报 PARTIAL 与必需检查覆盖；尚在排队/运行者不计终结。取消前已正式提交的其他对象结果保留，不重复发布。

### 4.3 固定范围和覆盖分母

任务开始固定 profileExpectedOperators、selectedOperators、requiredChecks 和显式排除原因。不得在看到数据不足或未命中后缩小范围。

~~~text
profileExpected = selected + explicitlyExcluded
selected = positive + negative + notApplicable + insufficient + error + cancelled + notRun
validAssessmentCount = positive + negative
~~~

以上计数互斥；notRun 只统计 selected 集合中未运行者。另报数据有效时长、执行覆盖、有效判定覆盖、症状族覆盖，不能用一个百分比混代。

fast 预期 7 项、禁用 3 项、其余 4 项全部完成时，执行覆盖可为 4/4，但 profile 覆盖仍为 4/7。VALID_NEGATIVE 只对事先固定且完整完成的必需检查范围成立；fast/custom 的结果必须写明范围，不宣称全故障排除。

保留旧请求 operators=None 和空数组按 group 执行的语义。明确选择结果与 fast 交集为空时，返回可追溯的参数拒绝或 NOT_ASSESSED；不通过悄改旧空数组含义来表达零检查。

### 4.4 症状、原因与支持度

1. 症状先独立保存，原因分类随后处理。单个粘滞阳性而交叉检查不足，应为 SYMPTOM_DETECTED + UNRESOLVED，不得落“未发现异常”。
2. 删除“未发现粘滞/过激，所以是工艺外扰”的排除式自动归因。原因候选需要正面证据，并列出替代解释；未执行和不适用不能成为反对证据。
3. CUSUM 首先报告偏差突变。SP/MODE 事件已检查时才陈述相应关系；“外扰”“通信故障”“阀门容量不足”“PID 不当”均保留候选语义及确认条件。
4. 支持度、数据质量、覆盖、严重度分别保存和展示。严重度依据幅度相对容差、持续时间和已知工艺影响；未知影响时不根据支持度自动升为 HIGH。
5. 同源关系至少标出同一 PV/OP、共用极限环门控、椭圆特征和相同预处理。方法数不等于独立证据数。
6. 按已采纳的 A 裁决，首期用可审计的保守规则替代未经校准的连乘增强：同依赖组取最大有效阳性支持度；跨组在未校准阶段仍取最大值，保留所有证据和矛盾标记。修改后的值属于新融合 profile，不能与历史 D-S 值无标识混用。
7. 现有“两种粘滞方法命中且达到门槛”最多用于形成阀门排查候选，不解释为两份独立确诊。存在关键反证/前提冲突时保持原因未决；反证不能简单换算为 1−支持度。
8. 已有 confidence 数值字段保留 0—1 兼容域，新结果与新元信息一致；UI 命名“证据支持度”。只有经现场独立校准的方法才能另行发布概率解释。

### 4.5 兼容展示和历史复现

- reader-first：先上线可识别新字段的 API/共享面板/列表/报告/统计，再启用新结果写入。绿色“正常”只在 VALID_NEGATIVE 且范围清楚时显示；其余情况显示准确状态。
- 旧记录缺元信息，展示“历史记录，判定覆盖未验证”，保留原结论供查看；不从 NULL 分类或 SUCCESS 推导历史健康。
- 人工复核保留 NORMAL/OTHER 选项和已保存复核结论。未复核且分类为空时，只有已证实的 VALID_NEGATIVE 可默认选 NORMAL；未决、未检查、失败及历史覆盖未知不得预选正常。详情弹窗与独立复核抽屉采用同一规则。
- 当前详情的 confidenceDefinitions 由运行时代码生成，须改为读取本次结果解释快照。缺快照的旧记录标明旧规则解释不可完整恢复，不能套用新版本解释。
- 原输入包＋原配置＋原算法构建才叫复现；使用新版本为显式重评，追加新 recordId 并关联 sourceRecordId。缺包、损坏或旧构建不存在时明确不可完整复现。
- 自动分类不把症状未决默认派往 PID 整定。复用既有处置体系产生核查/采集建议；仪表、阀门、通信、工艺按候选证据分派，人工复核仍可追加意见。

| output_saturation：AUTO 输出受限 | 时间加权、完整窗口分母、真实限幅与 MODE；严格饱和和近限位分开；覆盖不全时输出贡献边界及不足状态 | AUTO 贴限手算分子/分母；MAN 不进 AUTO 分子但仍在总时长；缺 MODE 不假设 AUTO；未知段可能全饱和时不输出虚低点估计 |

共同要求：段级输出含值、单位、阈值、参数来源、适用性、时间边界、支持/冲突证据和建议复核动作。没有达到工程显著性不等于数学特征不存在，两层信息分别保留。

慢响应首期采用事件前稳定的实测 PV 估计初值 y0，模型 y(t)=y0+A(1−exp(−t/τ))；不能默认 y0=旧 SP、A=新旧 SP 差。A 的估计/固定依据及单位必须保存；初始未稳、终值/增益缺依据且观测不足以辨识、残差不合格或参数触边时，不发布有效 τ 阴性。D0 在独立样本上冻结稳态判据、残差尺度、参数边界与可辨识门槛。

饱和统计设总窗 T、已知 AUTO 饱和时长 Ts、无法确定是否饱和的时长 Tu。完整覆盖才发布 Ts/T 点估计；Tu>0 时保留 Ts、T、Tu 与 [Ts/T,(Ts+Tu)/T] 边界及覆盖，不能把下界当准确饱和率。首期该算子标为 INSUFFICIENT_DATA，保留已知异常事实；是否用边界构造有效阳性须另立已验证判据。

**后续研究范围**：稳健振荡检测/Welch、真实阀位与定位器证据、原 Kano/Choudhury 论文复现、含纯滞后/积分对象的慢响应、跨回路传播与耦合、经标注数据校准融合。新方法必须先证明适用范围和增益，不能以新增算子数量作为完成标准。

## 7. 性能优化设计与容量验收

### 7.1 当前成本与首要改造

N 为有效段点数，L 为最大搜索滞后点数，J 为拟合求值次数，R/W 为突变候选数/确认窗，B 为异常质量段数。

| 算法 | 当前静态复杂度 | 优化动作 |
|---|---|---|
| IAE/Kano/sensor/saturation | O(N) | 保留已有线性实现；减少不必要拷贝和重复特征 |
| FFT 振荡 | O(N log N) | 固定适用段和工作量预算 |
| 椭圆粘滞 | 最坏 O(N²) | full 相关改有限滞后直接法或 FFT 线性相关 |
| Choudhury | 整体最坏 O(N²)，双相干另有分段 FFT | 统一输入后共享椭圆/门控；不把有限频点误称全算法线性 |
| 阶跃过激 | 峰突出程度计算最坏 O(N²) | 先测热点；限制 prominence 窗口会改变定义，若采用须归 P3 方法版本，不能算纯等价提速 |
| 慢响应 | O(JN) | 适用性早判、迭代预算、事件级缓存；不把失败拟合算正常 |
| CUSUM | O(N+RW) | P3 先冻结事件归并语义；P5 仅用前缀和降低相同事件语义下的窗口均值成本 |
| 质量规则 | O(N+B log B) | 只取最长三段时使用稳定 top-k，保留全部异常段计数 |

有限滞后独立参考定义：先按整个有效段去均值；c(l)=Σ x(i+l)y(i)，l=0..L；归一化分母沿固定 profile；保留滞后方向、首个最大峰及显著性门。当前 L=min(floor(300/Δt),floor(N/4))，若 P3 更改物理上限，则以新冻结值作为 P5 基线。

小 N/L 用有限直接法 O(NL)；长窗按固定环境的预校准交叉点和内存预算选择 FFT O(N log N)。FFT 必须补零实现线性相关，记录策略和实现版本。预校准与正式验收分开；测试前冻结近并列峰/阈值的保护带、回退范围和首峰规则，保护带内回退直接参考，确保离散判定一致。P5 等价对照使用 G3 接收 SHA，不拿改判据之前的原始版本作等价目标。

### 7.2 任务内共享特征

缓存生命周期限定到本次任务，不引入跨事件循环的模块级锁或无界全局缓存。缓存键涵盖输入包/时间轴/mask/段/信号角色/单位量程/预处理/特征参数/实现版本。若缓存最终判定，还须包含阈值 revision。

正式测量前冻结缓存最大 bytes/entry 数；当前回路或段消费完即释放，可按容量驱逐。批任务不累计保留所有回路数组；达到缓存上界退化为无缓存计算，并保持相同结论和失败状态。峰值预算应包含 FFT 工作区、原始数组与缓存，而非只计算缓存自身。

去均值 PV 的极限环检查与 PV−SP 的振荡分析不是同一特征。不同 required_signals 的公共 mask 也不同。Choudhury 内部椭圆调用当前默认 1 秒，须先由 P3 统一实际采样契约，再允许共享。缓存开/关结果与失败状态应一致，并测缓存 bytes 和任务结束释放。

### 7.3 真正的端到端基准

计时拆分：接受请求→排队→取元信息→TD 取数→预处理→各算子/共享特征→融合→图快照→commit→回读验证。记录单调墙钟；CPU 微基准单独归属，混合负载报告进程树总 CPU，不把并发期 CPU 差误算成单个算子耗时。

同步记录 RSS 峰值、FFT/缓存内存、查询次数与 bytes、连接池、队列深度、重试、取消延迟、状态分母和漏写/重复写。复用唯一后端生命周期 Worker/Beat，不另起 master。

| 目标 | 采用的验收值与范围 |
|---|---|
| 夜间 fast | 1000 独立回路、固定 24h 窗 ≤1800s，完整结果落库 |
| 夜间 full | 同条件 ≤3600s，单列全部算子覆盖与资源 |
| 事件 fast | 与夜间任务并存：排队 P95≤5s，接受到 commit 完成 P95≤60s |
| 混合负载读 API | 热 P95≤800ms，非预期 5xx=0 |
| 资源 | 无 OOM/连接池耗尽，总 RSS≤冻结内存预算80% |

以上沿已采纳 DEC-05；不是当前性能结果。DEC-08 登记本机 16 核/128GB 与隔离环境，执行前核实际硬件、软件版本、池类型、Owner、数据与缓存定义。

短窗 1h、24h×1s、30d 边界分开报告；fast/full、冷/热分别测，冷/热各至少5批。按 04 增加至少100回路24h动态分析、10回路30d边界。单回路事件 P95 至少50个独立事件样本，保留全部原始时延。场景包含真能进入相关热点的极限环，不能只测常量早退出。

诊断专属 manifest 逐对象固定 expectedAssessmentState、requiredChecks、expectedApplicableOperators 及算子预期状态；至少分为可进入相关热点、可进入响应拟合、混合不足三组。状态与覆盖、耗时同时对账，失败/跳过/不足保留原分母；低覆盖早退组不能代替正常容量组。

数值容差沿 04 已冻结规则，具体量纲特征另有独立 oracle；离散状态、命中、覆盖与原因必须一致。新增更严容差或热点提速门槛只能在正式测试前登记，失败后不放宽。端到端目标优先，不能只报告微基准变快。

### 7.4 工作预算、取消与并发

预算包括窗口/采样、有效段、L、拟合次数、算子数和峰值内存。超预算明确延后、异步执行或拒绝；保持请求范围及未完成原因。图用 LTTB 不进入诊断；减少算子/窗口/分辨率是覆盖变化，须另设 profile。

在取数后、算子/段之间、提交前检查取消；有限 lag 可分块检查。单次 FFT 不可即时中断时如实报告最大不可取消阶段，不承诺立即停止。先减单任务成本，再按 CPU/内存/连接实测决定并发；权限和提交栅栏沿 P4 契约。

## 10. 现场校准、发布和回退

### 10.1 现场证据

在看测试集结果前，按故障类型、工艺类型、采样、控制模式、负荷/工况分层冻结样本协议：正例/正常例/不可判断/争议、每层最低样本数、标注人和仲裁、最低可接受指标。算法输出不能直接充当标注真值；人工复核也需证据与争议状态。

训练/调阈、方法选择、最终测试按回路/设备/时间分离；相邻窗口不随机拆成互相泄漏的训练与测试。报告：

- 召回率：检出的故障样本/全部合格标注故障样本；不可判定故障样本不从分母隐去。
- 误报率：正常样本被报异常的数量/全部合格标注正常样本。
- 有效判定覆盖率与不可判定率：对所有纳入样本报告；另报仅可判定子集的条件指标，不能替代总体指标。
- 各层样本量和置信区间、争议数量、原因确认与症状命中分别统计。
- 支持度校准需独立校准/终验样本；样本不足时继续使用规则支持度，不发布概率解释。

本方案不凭空指定现场“95%正确率”。最低样本量与接受门槛由 P7 协议在取样/揭盲前冻结；缺现场条件时可以完成软件验收，但现场项保持未通过。

2026-10-11 用户裁决 C 延后：本轮不冻结现场范围、指标门槛、样本量或责任人，不把延后解释为免除现场验收；独立软件工作仍按已授权阶段推进。

### 10.2 发布顺序与回退

1. 固定新算法/profile、迁移、契约和候选SHA；部署兼容读路径与正确状态守卫。
2. 在隔离环境使用同一输入包影子比较新旧结果，登记变更原因、变成不足/未决的数量和覆盖差异，不以“数字不变”掩盖旧错误。
3. 在既有发布机制下按受控回路范围启用新 writer；满足 D5/D6 发布门槛后扩展范围。灰度机制若当前不存在，纳入任务实现与验收，不当作已有能力。
4. 发现错误分类、覆盖守恒失败、旧记录解释漂移或容量超预算时，停止新版本发布；恢复上一固定 profile/构建用于后续任务。若旧版本有已知伪正常问题，保留新安全展示和状态保护，或暂停受影响自动诊断，不能以回退为由恢复误导性结论。
5. 已生成历史结果追加保留，错误结果另附勘误/撤回标记和重评关联。回退不删除记录、不修改旧输入，不把数据库降级当作常规回退步骤。

交付必须区分：方案审查、作者自测、非作者软件验收、容量达标、现场验证、已合入/推送/部署。各项分别给证据，不能互相替代。
