### 1.3 强制条款映射（正文规范性要求，本档补齐）

标准原文（第 5 页（PDF 索引 pg-010）+ 视觉核对，正文 §6.3.3，**规范性**）：

> "企业应将数据异常及时段内自控率低于预设百分比的控制回路判定为回路性能最低等级。"

现有实现映射与差距（v2：loop_fitness 行号按 R2 漂移更新，:42,396,:433-437 等已对码复核）：

| 标准要素 | 现有实现（文件:行号） | 映射 | 差距 |
|---|---|---|---|
| "数据异常" | ① 诊断门禁：点数<32 / 可信度 E 级 / 断点比>30% → 门禁不过（gate.py:14-16,61-69）② 评估侧：valid_rate<0.20 → E 级 → INCONCLUSIVE、score=NULL（contracts/data_types.py:77-87；confidence_evaluator.py:404-416 权重和 0 同口径）③ 适用性：gate 不过 → L0 DATA_INSUFFICIENT，三性维度同为 L0（loop_fitness.py:361-374） | 部分实现 | **语义差异**：产品把数据异常处理为"不可评（INCONCLUSIVE，不产分数）"，而非"判为最低等级（产最低档分数）"。与"不可判断不显示为健康或 0 分"的现行产品原则（01§1 可信计算）一致，属**有意偏离**，须在标准差异报告中显式声明，不能默认视为符合 |
| "时段内自控率低于预设百分比" | 阈值 `fitness.low_auto_rate_pct` 默认 20%（sys_config 可调，loop_fitness.py:42,396）；auto_mode_rate<20% → LOW_AUTO_RATE 标签 → L1 仅可监视（loop_fitness.py:435-437；L1 映射 :88-89、落级 :574）；同时手动占比>80%（默认，:41）→ MANUAL_DOMINANT 同判 L1（:430-433） | 已实现（预设百分比=可配置，符合"预设"语义） | 评估放行口径为"仅 L0 阻断"（2026-10-05 三性裁决），L1 回路仍计算评分；自控率低经 R 乘数（effective_auto_rate）压低综合评分自然落入低等级——**间接实现**"最低等级"，无显式"判为最低级"规则 |
| "判定为回路性能最低等级" | 无显式规则 | **未实现** | 需裁决：是否增加"自控率低于阈值 → 强制最低档（或五级）"显式落级规则；推荐默认=维持现状（R 乘数 + INCONCLUSIVE 语义 + 差异声明），备选=增加显式强制落级（数值语义变更，需走 DEC-02 流程并升算法版本）→ 归入 DEC-02⑤ 一并裁决 |

## 3. 不可变输入包（NPZ + JSON manifest）字段级契约

### 3.1 元数据表 `calculation_dataset_snapshot`

| 字段 | 类型 | 语义 |
|---|---|---|
| snapshotId | UUID PK | 输入包身份 |
| datasetRef | string | 绑定身份（≠数值身份；现有 datasetRef 只表示绑定/改绑） |
| inputHash | string | 内容 SHA256（涵盖 NPZ 数组 + manifest 全部内容） |
| tsStart / tsEnd | timestamptz(UTC) | 窗口（半开） |
| schemaVersion | string | manifest 结构版本 |
| createdByRecordId | UUID | 创建引用（result record） |
| retentionClass | enum(NORMAL/FROZEN) | 保留类别 |
| frozenReason / frozenByRecordIds | string / UUID[] | FROZEN 时必填：被哪个方案/实施/审核证据引用 |
| expiresAt | timestamptz | NORMAL 保留期终点（创建 + 90 天，DEC-10） |
| sizeBytes | bigint | 容量审计 |
| cleanedAt | timestamptz 可空 | 清理完成标记 |

NPZ 数组（禁 pickle）：时间轴、各信号值、质量码、逐槽 mask，dtype 显式记录于 manifest。JSON manifest：单位/量程、tag 绑定、窗口、网格与预处理版本。**不变式**：相同绑定但值/质量改变 → 不同 inputHash；重放读原包，不重查当前源。**写入次序**：先原子写文件+核 hash，再提交 DB 引用；未引用残留由隔离清理任务处理。访问/下载继承回路 scope；复现绑定代码 SHA+依赖锁+构建 digest+受控执行配方；损坏/过期/缺构建 → "不可完整复现"。

> v2 注记（R2 §三）：辨识/整定任务落包对预处理链的记录要求见 §6.3 DEC-10 补表述（现状 evidence 无结构化字段、data_hash 不含预处理参数 → 按现行标准"不可完整复现"预处理链）。

### 3.2 存储目录建议（契约级，不写实现）

- 目录：`{CLPM_DATA_ROOT}/calc-snapshots/{yyyymm}/{snapshotId}.npz` 与 `{snapshotId}.manifest.json` 同目录；CLPM_DATA_ROOT 指向**本地持久化共享卷**（与 TDengine 数据卷同级规划），禁止静态目录直接对外暴露（下载走带 scope 校验的 API）。
- 命名只用 snapshotId，不含业务名（避免路径注入与重命名漂移）；原子写 = 同目录临时名 + fsync + rename，rename 成功后才写 DB 行。

### 3.3 清理任务触发方式建议（契约级）

- 触发：复用后端 lifespan 管理的 **Celery Beat 每日低峰调度**（与现有夜间任务同一 Beat，**不新增独立进程**，符合"严禁手工再启动 Worker/Beat"红线）；单 worker 串行执行。
- 清理规则（有序）：① 文件存在但无 DB 引用且创建超过 24h → 删文件（写入失败残留）；② retentionClass=NORMAL 且 expiresAt 已过且**未被任何 record/方案/工单引用** → 先 DB 标 cleanedAt → 删文件；③ FROZEN 永不清理，解除引用 + 过期两条件同时满足才可降级 NORMAL 再进 ②。
- 容量契约（DEC-10 冻结素材，估算口径）：单回路 1h@1s、7 信号 float64 ≈ 3600×7×8B ≈ 200KB/包（含 manifest）；1000 回路每小时全量 ≈ 200MB/h，90 天全量保存 ≈ 432GB。
