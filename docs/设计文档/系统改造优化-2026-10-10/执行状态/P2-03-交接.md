## schemaVersion 策略（P2-03 Owner 定稿，冻结稿 §1 授权）

**主版本 1 + 版本化扩展（次版本递增），当前 "1.1"**。理由：

1. 冻结稿 v1（P0-02 §3）只冻结了 CalculationContext schema 系与元数据表字段，六层语义（07 号文）是其**新增可选节**扩展——语义为"只加不改"，属版本化扩展而非 schema 升级，不破坏已冻结 v1；
2. 读取端按**主版本门禁**：主版本一致即接受，未知**可选**节按显式 null/"未计算"处理；主版本不一致（"2.x"）显式拒绝 `ERR_SNAPSHOT_SCHEMA_UNSUPPORTED`（测试 `test_schema_versioned_extension_and_major_gate`：1.9+未知节接受 / 2.0 拒绝）；
3. 次版本内禁止改字段语义（只加不改）；下次六层字段语义变化时升主版本并保留旧主版本读取配方（环境 keeper 保留责任）。

## 结构决策（冻结稿 §2 授权，单列）

| 决策点 | 定稿 | 理由 |
|---|---|---|
| 包内分段 vs 多包引用 | **单包内多数组前缀**（KPI：`blk{i}__*` 块前缀；辨识：`consumed__*` 整窗 + gap 显式） | 六层语义要求"完整分析输入不只胜出片段"与"来源链单一 inputHash"——单包保证身份原子性（一次哈希涵盖全部数组+manifest），多包引用会在引用完整性上引入部分可用态（某子包过期=整包不可复现），且清理/GC 需处理包间引用，复杂度不合 MVP 量级 |
| gap 表示 | **不拼不删**：辨识包 `consumed__ts_rel` 保留真实时间轴跳变；KPI 包缺口以逐槽 `__null_`/`__valid_` mask 显式（KEEP_ALL_WITH_VALIDITY 同口径） | 07 号文红线"不得跨 gap 连成等距连续曲线"；测试断言 max(ts diff) > 100s |
| created_by_record_id 跨表 | **无硬 FK**（结果账本 record / tuning_record / diagnosis_run 三类宿主） | 引用完整性由 GC 前跨表核查 `find_referencing_records` 保证（清理不可删被引用包） |
| executableBuildDigest | `sha256("clpm-build-v1|"+code_sha+"|"+lock_sha)[:16]`；code_sha=CLPM_BUILD_CODE_SHA env（CI 注入）> git HEAD；lock_sha=uv.lock SHA256 前 16 位；均无 → `UNVERSIONED_BUILD` 显式标记 | 写清口径于 docstring；进程内 lru_cache（无 asyncio 原语，fork worker 各算一次） |
| 旧构建保留 | `{snapshot_root}/retained-builds.json`（环境 keeper 维护；文件缺失=仅当前构建可用，诚实口径不默认放行） | 01§3.2"旧执行环境在隔离环境按保留构建读取"；DEC-10 保留责任主体=环境 keeper |
| DCS 模板 | `loop.dcs_model_id` 有 → `"dcs_model:{id}"`；无 → 显式 `"UNKNOWN_DCS_TEMPLATE"` | 07 号文 §3.3：未知 DCS 型号不得默认标准 kp/ti/td（转换消费在 P3-03） |
