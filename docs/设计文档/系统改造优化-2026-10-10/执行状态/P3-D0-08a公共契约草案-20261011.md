### 1.2 评估业务 assessmentState（三值，字段级）

- 值域（已冻结，11§3/10§3.1）：`COMPLETE / PARTIAL / UNASSESSABLE`。
- 落点：指标证据状态 `MetricResult.details.assessmentState`（10§3.1；`MetricResult` 现行载体 `contracts/data_types.py:314-332`，`value=None` 现语义=INCONCLUSIVE 兼容保留）。**不写入只允许 COMPLETED/FAILED 的账本 status 列**（10§3.1 原文）。
- `PARTIAL` 语义：必要分项存在无法消除的状态区间时，新 profile 的 P 返回不可完整评估，展示可用分项与范围，不对剩余权重重新归一化（10§3.1 例段）。
- 数据可信度 A～E 现行门槛（`contracts/data_types.py:77-87`，E 级 score=NULL→INCONCLUSIVE）继续约束可计算性，不因本次改造放宽（10§3.1）；数据质量与可判定性分开：`NO_DYNAMIC_EVIDENCE` 不得画成数据坏或自动降 L0（10§3.3，INT-02）。

### 1.3 评估名册 E 六类（字段级）

- 互斥守恒等式（已冻结，11§3/10§3.6.2）：`E = scorable + incomplete + failed + cancelled + pending + missing`。原因细分和各指标参考数另作标签，不重复加进该等式；所有已确认结束的批次 pending 应为 0；缺记录不能藏在成功总数中。
- 归类规则：**每回路按选定窗/profile 取唯一归类**（11§3）；`scorable` 只计本窗指定正式版本的 P 为有限数值、必需分项证据完整且通过原有效性门禁的唯一物理回路；真实 0 分算可评分；仅有 F 参考 100 不算（10§3.6.2）。
- 六类语义（10§3.6.2）：incomplete=已完成但 P 证据不足/不可判定；failed/cancelled=已知任务终态；pending=已登记未终结任务；missing=无对应记录/任务。
- 排除规则：停用/主动不参评等既有排除原因另报 `excludedLoopCount`，**不新增以数据不足为由的排除条件**；缺数据、缺动态、失败、取消、尚未计算都不从 E 删去（10§3.6.2，EA-D01）。
- 边界值：N 含合法 0；E=0 → scorableLoopRatio=null 并显示"无参评回路"；E>0 且 N=0 → 显示 0%（11§3；C26-EA2）。
- 契约字段名（10§3.6.2/3.6.3，落库/API 位置由 08d 定稿）：`eligibleLoopCount(E)`、`scorableLoopCount(N)`、`scorableLoopRatio=100×N/E`、`excludedLoopCount`、`membershipRevision`（名册身份：scope/评价窗/profile/配置及组织版本）；API/节点快照必须同时保存并显示 N/E（如"60%，6/10 条"）。
- 名册身份规则：从指定版本、窗口和正式发布身份选代表结果，不能先筛 SUCCESS 再挑旧成功记录，也不能把当前 `evaluated_loops` 直接当 N（10§3.6.2；R07 锚点即此误导路径）。物理回路数和复杂组评分对象数分别返回；用复杂组代表聚合时按现有冻结规则固定代表及成员，另报 `objectCount`/对象覆盖率，禁止"组数作分子、物理回路数作分母"（10§3.6.2）。
- 每指标独立汇总（10§3.6.3）：对每个指标独立保存入选对象、加权分子、权重和、完整/参考/不可用计数与名册身份；零值参与、null 不作 0；权重和为 0 时均分 null；装置到全厂合并分子与权重和，不能平均各装置百分比/均分，不能统一用 evaluated_loops 给所有指标加权。完整 P 比例按物理回路名册合并并去重；24h/30d 合并小时窗时显示"回路小时可评分比例"（分母=回路×小时），另有独立回路统计须单列（11§3 F 参考行+10§3.6.3；C26-EA4）。

### 1.4 F 参考独立统计规则（不填正式 P）

- 参考字段组（10§3.6.1，用户决策"F 也保留参考分"已吸收）：`details.referenceScore=100`、`referenceMethod=STATIC_WINDOW_POLICY`、`referencePolicy=STATIC_BASELINE_100_V1`、`evidenceStatus=INSUFFICIENT_DYNAMIC_EVIDENCE`、`reasonCode=NO_DYNAMIC_EVIDENCE`、规则/参数版本及所用时段。100 沿用现有产品"静稳参考满分"约定，**不是测量值、置信概率或真实响应速度**。
- 正式值：正式动态 `fast_rate.value` 缺动态证据时仍为 null，T 也为 null，不虚构 T=0 秒；正式指标 `assessmentState=UNASSESSABLE`，参考值资格单独记录，**不因 referenceScore 非空变 COMPLETE**；referencePolicy 进入快照和复现比较（10§3.6.1）。
- P 交互：必要 F 权重非零且只有参考值 → P 不完整、不重分配剩余权重；F 权重本来为 0 时按该 profile 实际必需分项判断，不额外强加 F 要求（10§3.6.1；C26-EA3）。
- 参考资格（10§3.6.1）：真实数据质量、连续观测时长/样本、单位量程和时间轴要求；PV 在冻结噪声/趋势范围内；无超门槛 SP 事件/OP 激励/已知模式工况变化；无已确认质量/仪表故障反证。SP/PV 同步爬坡即使误差恒定也不满足；持续恒定偏置若其他条件成立可保留政策参考 100 但同时显示 A/R 及偏差；合法 HELD 可用于状态统计但不足以单独证明持续新观测的静稳资格。缺数据、算法异常、配置失效（含非法 T′）、未收敛、仅有上界或尾段不足不能套用参考 100。
- 互斥与优先：具备完整动态证据时用实际公式得正式 F，不叠加参考 100；两种资格互斥；兼容读取如遇残留参考字段仍以合法正式 F 优先（包括 0 分）（10§3.6.1）。
- 双统计（10§3.6.3，字段名契约、落点 08d+09a）：
  1. 快速性参考均分（主参考展示）：`fastRateReferenceMean`、`referenceWeightedNumerator/referenceWeightSum`、`numericCount/dynamicEstimateCount/policyReferenceCount/unavailableCount`、`policyReferenceWeightShare`；dynamicEstimateCount+policyReferenceCount+unavailableCount=本指标参评对象数；含参考值时名称/徽标必须明确"含 N 条（或 N 个评分对象）动态证据不足"。
  2. 动态证据充分的 F 均分：`fastRateDynamicEstimateMean`、独立分子/权重分母/样本数及 `dynamicEvidenceCoverageRatio`；无完整 F 时为 null，参评数>0 而动态数=0 时动态覆盖为 0%。
  参考汇总与正式字段分别编码，不把混合参考均分回填旧 `fast_rate` 或正式 P。
- 跨小时重复计数必须称**回路小时**（11§3；C26-EA5）。

### 1.6 诊断算子状态（七态＋LEGACY_UNVERIFIABLE，字段级）

值域（已冻结，11§3 一字不差；语义 08§4.1 表）：

| assessmentState | 含义（08§4.1） | 能否用于排除对应症状 |
|---|---|---|
| POSITIVE | 满足适用条件并命中该方法的异常判据 | 否，保留症状证据 |
| NEGATIVE | 满足输入、工况、观察范围和执行要求，未命中 | 仅限该方法声明的症状假设和观察范围 |

| INSUFFICIENT_DATA | 缺信号、连续时长不足、无合格响应事件或拟合信息不足 | 否 |

| NOT_RUN | 未选、停用、上游阻断或预算终止；保存不同 reasonCode | 否；资源不足不是数据不足 |
| CANCELLED | 被任务取消，检查未形成有效终态 | 否 |
