# 协议方法补充 03：节点作用域与进程时间来源

本补充在正式投递前冻结字段来源，补充原《冻结验收协议》与工具 sidecar 契约。原协议和四份初始工具源不改；20 批 × 1000、每批完整九条件与 600s、原 30s 测试门限、历史 6+3、四项用户豁免均不变。本文不构成真实环境 PASS。

## 1. 节点作用域采用有来源的推导字段

冻结候选的 `calculate_node_kpi_hourly` 实际 request 只有 `ts_start/ts_end`，没有 `node_ids`；`_do_calculate_node_kpi` 实际查询 `PlantNode.is_kpi_enabled IS TRUE` 的全部节点。因此保留原始 request 原文，禁止向 kwargs 增补或伪称存在节点 ID。

规范 sidecar 可提供 `nodeIds`，但必须同时标明 `nodeScopeProvenance.kind=derivedFromFrozenEnabledScope`。该字段是以下三组原件交叉限定的推导值，不是 request 原字段：

1. **执行语义证据**：实际运行 M 的完整 `backend/app/tasks/kpi_calc.py`、git blob/文件 SHA-256、`calculate_node_kpi_hourly` 和 `_do_calculate_node_kpi` 原源码及真实级联调用。证明该代码确实查询全部 enabled 节点，并核实际加载版本。最终 protocol 绑定精确 M 和原件，不能只引当前磁盘 HEAD。
2. **冻结作用域证据**：投前 PG 一致性只读事务中的完整 enabled 节点、树、参评 1000 回路、预定各节点后代、无复杂组事实与配置冻结；与执行后的同源配置/身份原件核一致。隔离期间只允许唯一 Keeper 的已记录操作，不允许节点开关/归属或 scope 暗改后复原。推导集合应为原预定 20 节点，不得只用最终有结果的节点倒推 expected 集合。
3. **本批真实执行与产物证据**：该批唯一同窗标准 node 子任务的原始 request、实际 parent/root 链、接收/终态事件与时间、真实 SUCCESS 返回 `total=success=20`、`skipped=failed=cancelled=0`。计数只作交叉核；还须逐节点核这 20 个真实不可变 NODE 记录、窗口/版本、完整 roster 六态守恒、SUCCESS 代表回路的原始 `loopRecordIds`，以及它们与冻结 1000 回路/父批实际 LOOP record 的关系。NODE `logical_run_id` 保留内容寻址语义，不能强行伪装父 Celery UUID。

`nodeScopeProvenance` 至少保留 `actualRequest` 原文/原件引用、`querySourceRef`、`enabledNodesSnapshotRef`、`nodeScopesRef`、唯一子任务与 parent/root/window 证明引用及推导规则。所有引用均含原文件 SHA-256；输出保留原始字段和规范字段的映射。缺任一证据、额外/重复子任务未解释、配置漂移、20/20 不成立或结果输入版本不能对应时为 BLOCKED/REWORK，禁止靠摘要 gate 布尔或“队列空”补真相。

## 2. `startedAtLocal` 仅按明确进程时间来源转换

`capture_capacity_runtime_profile.py` 的 `members[].startedAtLocal` 来自原生 `ps lstart`，例如 `Sat Oct 17 19:00:47 2026`，没有时区。这不是业务提交时间或完成时间，也不参与把 600s 变短/变长。

本轮宿主合同为 `Asia/Shanghai`。正式投前保存原生时区/offset 原件及其 SHA 后，sidecar 可以将该特定字段按 `ZoneInfo('Asia/Shanghai')` 解释，再输出带 `Z`/`+00:00` 的规范 `startedAt`。必须一并保留 `startedAtLocal` 原字符串、`startedAtTimeZone=Asia/Shanghai`、来源原件和转换说明。若实际宿主时区原件不符或无法证明，则 BLOCKED，不能按看到的时差猜测。

不得将全部 naive 时间统一按上海解释：数据库约定的 naive UTC、冻结业务窗口的 naive UTC、显式 UTC 的 collector/事件/命令时间继续分别按其原合同解析。原生 `pid:lstart` 的唯一进程 identity 保留原字节，不用转换后的时间改写原身份。进程真实加载字节、cwd/argv、PPID、Worker/Beat 唯一性仍须独立核实，`loadedSha` 声明本身不是证据。

## 3. 同轮完整载荷与 600s

首次 terminal checkpoint 和首次完整 critical 观察分别保全同一 RR READ ONLY 事务中的四组完整 SELECT *；直接挂该观察的事务起止、PG snapshot、独立 taskObservedAt 与 gzip/原文哈希。post30 的 finalFull 只证明后续持久化，不把该末尾观察时间当业务 SLO witness，也不把较晚 full 伪称为较早事务。

九条件须在真实同轮事实及关联任务终态上独立成立。若 2s 粒度刚跨 600s，只能凭原生完成/持久化时间与事件逐项判断；缺乏足以证明边界时为 BLOCKED，不能自动 PASS，也不能因 post30 采证把原 600s 合同收紧约 30s。
