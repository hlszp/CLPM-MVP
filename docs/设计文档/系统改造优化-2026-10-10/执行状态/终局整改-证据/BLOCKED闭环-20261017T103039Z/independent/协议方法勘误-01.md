1. AUTO_MODE_RATE 的自动模式集合按现行 `app/constants/mode.py` 为 **AUTO=1、CAS=2、REMOTE=3、APC=4**，包括 APC。原协议未列 APC 的文字不完整；本轮 fixture 的 MODE=1 不受影响。
2. 原协议数值表的“3600s”是名义一小时举例。实际 API / `TimeWindow` 的结束时刻按项目契约是**含尾**，`time_axis` 适配为 `[start, end+1s)`。若 F03 当前 fixture 请求 `end=start+1h`，其数值评价分母可能是 **3601s**；须按冻结请求、实际包 `window.tsStart/tsEnd`、NPZ 时间轴和 grid 核对，不能硬套 3600、更不能事后变更输入或分母凑数。F02 的标准小时窗口及其落库键仍依原 standard-hourly 契约核对，不由本勘误改成 custom。
3. `compute` 先只读冻结输入/参数，落盘独立期望及其哈希；`compare` 再另读实际三指标附件。具体 steadyRate 不从实际产物倒推，未知 profile、未固定参数、缺输入或未支持布局明确 BLOCKED。两位小数容差 0.005 个百分点和未取整容差 1e-8 个百分点不变。
4. 当前工具的 NPZ 适配只覆盖本轮预定 FLOW/1s、PV range=[0,100]、单绑定且无登记缺口的隔离合成 fixture。它独立核原始 COV 保持值、QC 与 mask 表达式，并以实际保存的预处理 validity 为数值阶段输入事实；不声称重新实现全部预处理分类器，也不声称通过其它回路/网格/profile 的现场校准。
