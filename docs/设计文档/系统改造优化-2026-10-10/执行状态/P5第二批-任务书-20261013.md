## 批 P5-03【预计算与缓存真实新鲜度】

### 【1 必读】
03 号文 §8 P5-03 卡（验收正本）；04 号文容量基线；批 α 聚合收窄交接（`P5-prep-交接.md` §1.1——**node_performance.py/cockpit_overview.py 已有 unit_ids 收窄+范围 hash 缓存 key，本批在其上做新鲜度/single-flight，不得破坏收窄语义**）；批 β 交接（agg_cache 双层进程内+Redis 已被 β 侧核过 TTL 语义）；现行代码：`workbench_precalc.py`、`workbench_assessment.py`、`node_performance.py`、`agg_cache.py`、既有 MV（prime_agg）/索引及 Beat 任务。

### 【2 范围】
1. **小时可合并统计复用**：跨窗统计优先复用小时级已落库聚合（kpi_node_snapshot_hourly/prime_agg MV），禁止对原始时序任意平均降采样。
2. **最新 scope 行查询统一**：latest 口径查询收口单一实现（评估历史 R02 语义"最新代表后置筛选"不回退）。
3. **缓存绝对有效期**：缓存命中不延寿（TTL 从写入时刻起算，临到期命中立即按过期处理）；Redis 与进程内双层一致性。
4. **single-flight**：同 key 冷请求并发只重建一次（进程内锁+跨进程 Redis 证据二选一或组合，给出分布式合并证据）；失败不缓存。
5. **失效链**：权限（policyRevision）/数据（新窗落库）/配置（sys_config）更新后缓存失效（α 已落 policyRevision 段——补数据/配置两源）。
6. **分块状态与局部重试**：聚合页分块（块=统计块）失败显示 UNAVAILABLE 其余块可用，重试只重失败块。

### 【3 纪律】
唯一 worktree（p503=feat/p5-03-cache-freshness 切自 05e94cab）；不碰 arma/stiction（P5-01 域）与 kpi_calc 任务域；禁新增 Worker/Beat（复用既有 Beat 入口预热）；迁移同批如有；30 分钟交接；不 commit/push。

### 【4 核验】
P1 聚合手算不变（抽 3 块与手算对齐）；20 同 key 并发冷请求重建次数=1（或分布式合并证据）；临到期命中不延寿（时间可控单测）；三源失效各自反例；故障块 UNAVAILABLE 局部可用真库/HTTP 证据；门禁全 0+分母。

### 【5 决策点】
single-flight 进程内/跨进程方案选型→Owner 定稿记录（参照 P4-04 轮询选型登记先例）；分块粒度→按现有统计块天然边界；其他停点报主协调。
