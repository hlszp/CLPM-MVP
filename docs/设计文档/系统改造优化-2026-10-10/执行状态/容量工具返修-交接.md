## 2. R06 · 工具通过条件业务正确性

### 2.1 问题事实（17 号文 R06）

### 2.2 修复点（工具）

**A. 投递前冻结（`_build_freeze`，实投前落盘 `capacity_dataset/run_frees/freeze_<s>_<YYYYMMDDHH>.json`；dry-run 不落盘）**：

- eligible/excluded 清单：前缀范围内全量回路三条件切分，不可参评者单列原因（is_active/status/include_in_evaluation）；
- **manifest 强制**（`--manifest` 缺失即拒绝执行）：generate_capacity_dataset 独立 scenario 文件为 expected 正本；windowStart 必须与被测窗同窗；manifest loopTag 集与前缀 eligible 集**精确相等**（测试身份核对，多/少即拒）；
- 预定节点集：`_PREDICTED_NODES_STRUCTURAL_SQL` **结构推导**（is_kpi_enabled 祖先 × 子树含冻结集回路，`ANY(:ids)`）——不再 join 运行中快照（单测断言 SQL 不含 kpi_snapshot_hourly）；
- expected 业务状态逐回路（manifest expectedStatus → 独立口径映射：EVALUATED*→SUCCESS+score 非空；INCONCLUSIVE(DATA_INSUFFICIENT)→INCONCLUSIVE+fitness_tags 含 DATA_INSUFFICIENT）+ expected 直方图（正常组 1000 EVALUATED；混合组 800/100/50/50）；
- 算法版本：投递时点只读 import `app.tasks.kpi_calc.ALGORITHM_VERSION` 冻结入件 + manifest sha256。

**B. 结果绑定与核验（`_evaluate_run_gate`，纯函数九条件屏障）**：

1. `ledger`：冻结集每回路本窗小时账本行存在（pending/missing 非 0 即未闭合）；
2. `source`：全部行 source ∈ {SCHEDULED, MANUAL_STANDARD}；
3. `run_binding`：每行 `result_record_id → calculation_result_record.logical_run_id == 本批父任务 ID`（Celery 任务重试同 ID=logicalRunId；**旧结果污染/其他 run 的同窗行不得通过**）；
4. `algorithm_version`：小时账本行版本==冻结版本（**错版本不得通过**）；
5. `expected_status`：manifest expectedStatus 逐回路核（**全部 INCONCLUSIVE 正常组不得通过**；EVALUATED 无 score 不得通过；DATA_INSUFFICIENT 标签缺失不得通过）；
6. `latest`：冻结集每回路 latest 行 data_ts_start=本窗+版本一致+绑定本批 logicalRunId；
7. `nodes`：冻结预定节点每节点本窗节点行+版本一致（**缺节点不得通过**）；
8. `task_terminal`：本批 TaskRecord（账本行 source_task_id 唯一值，Redis 只读）=SUCCESS（**父子任务未终结不得通过**）；
9. `parent_terminal`：Celery 父任务终态=SUCCESS（父任务投递完≠完成）。

- 行级条件零行时**不计 vacuous 满足**（ledger 完整是 source/run_binding/version/expected 的前提——防"空结果伪通过"）；
- 节点子任务 ID：`celery inspect active` 尽力取证（not-observed 如实登记）；kpi_calc 级联节点任务不带父 run 标识（2B 域不改动），子任务完成以节点结果行核验为准——**边界如实登记，不冒充绑定**；
- SLO 判定保留，输出完整分母：冻结 eligible/excluded(跳过)/SUCCESS/INCONCLUSIVE/PARTIAL/违约计数/expected 直方图；违约明细逐项 count+sample（上限 20 条采样，计数不截断）；
- `--report-out` JSON 落盘（窗口/父任务 ID/TaskRecord 终态/冻结件路径/九条件/首达时刻/分母/违约明细）。
