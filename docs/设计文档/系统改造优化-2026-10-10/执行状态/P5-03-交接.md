## 1 六项实现要点

### ① 小时可合并统计复用（等价基线不动）

- **问题**：`build_and_upsert` 每 5min 网格对每 scope×窗×(当前+上一窗) 各一次 `_query_window_rows`——26 节点树 ≈156 查询/轮，30d 窗行集全量重扫重聚合。
- **方案**：`Σ(value×w)/Σ(w)` 按行可加——`_query_rows_bulk` 一次装载 60d 最大跨度（30d 当前+30d 环比）全部 UNIT 小时行（轻量列投影），`HourPartials` 按 (unit, hour) 建 Decimal 部分和索引，scope×窗口×环比×趋势全部**内存加法合并**。单测断言整轮 3 scope×3 窗口仅 **1 次批量装载**。
- **等价性（红线）**：权重基仍是 `evaluated_loops`（与 `aggregate_rows` 逐字一致）；每指标独立"非 NULL 分母"语义保留（den 只计 m IS NOT NULL 且 w>0）；Decimal 精确加法。`aggregate_rows`/`build_trend_points` **原样保留**作参考实现（真实行路径 `_query_window_rows` 保留供真库对账）。
- **kpi_node_snapshot_hourly 不作合并数据源（选型登记）**：其 assessment_stats 权重基为重要度权重（score_weight），与 workbench 窗口口径（evaluated_loops）不同——合并会改分值，为保等价不采用。
- **已知数值边界（登记）**：Decimal 精确求和 vs 原 float 逐行累加，在商恰落在 .xxx5 舍入刀口时末位（1e-3）可能翻转——旧 float 路径在刀口上本就依赖求和顺序不可复现；新路径确定性地 ROUND_HALF_EVEN，**与手算对齐以 Decimal 为准**。随机 200 行等价测试断言 ≤0.001（刀口容差），手算 3 块断言精确相等。
- **"禁止原始时序任意平均降采样"**：本模块数据源恒为 unit_kpi_summary（已落库小时聚合），不触碰 TDengine/原始时序——固化为模块不变量注释。

### ③ 缓存绝对有效期（命中不延寿；双层一致）

- 进程层：`_cache[key] = (绝对到期时刻 monotonic, data)`；命中条件 `now < expires`（**临到期即过期**），命中**只读不重写**。
- Redis 层：`setex ceil(ttl)`（≥1s）——原 `int(ttl)+5` 超出 TTL 窗 5s 已移除。
- 晋升路径：Redis GET 命中后补 `TTL` 读剩余秒，进程条目到期 = now+remaining——**不晚于 Redis 层到期**（双层一致性 ±1s，Redis 秒粒度）。
- 时间可控单测（FakeClock/FakeTTLRedis）：t0 写 ttl=100 → t0+99 命中不重写 → t0+100 过期重建；晋升剩余 TTL=1s → 2s 后重建（不按本地 ttl=100 重算）。

### ④ single-flight（选型定稿：进程内 Future 合并 + 跨进程 Redis 锁/轮询合并，组合方案）

- **进程内**：`_inflight: dict[key, (loop, Future)]`——leader 执行 builder、follower `await` leader 的 Future（同 key 并发冷请求只重建一次）。Future 按需在**当前运行循环**创建（非模块级 asyncio 原语——红线规避：跨循环/已完成的陈旧条目直接丢弃不 await，Celery 每任务新循环场景安全退化为无合并）。
- **跨进程**（生产 4 workers）：leader 抢 `SET agg_flight:{key} NX PX 15000`；他 worker 在建时本地**轮询 GET 等值**（100ms 间隔，上限=锁 TTL+宽限；超时兜底自建——极端情况多建一次，正确性不受影响）；锁释放带 token 比对。
- **失败不缓存**：builder 异常 → 两层均不写、锁释放、异常传播给全部合并等待者（leader 被 Cancelled 时 follower 收到可重试 RuntimeError 而非被牵连取消）→ 下一次请求自然重试（⑥ 局部重试的基座）。
- **证据**：20 并发冷请求 builder 执行=1（进程内）；跨进程合并用 FakeTTLRedis 模拟"他 worker 持锁→写值→释放"，本地 builder 全程未执行（`test_跨进程合并_他worker在建时等待其结果`）；死锁超时兜底自建有专测。
- **不做分布式强一致锁/租约队列的取舍**：SETNX+轮询在 redis-py/ fakeredis 兼容面最宽、无 Lua 依赖；等待上限即锁 TTL，leader 崩溃后锁自然过期，等待者兜底自建——不引入无限等待。
