## 6. 缺陷清单（分级）

### D-1【P1｜阻断两个 P6 能力页 + 工程师登录落地】page:my-work 系与 page:config.eng-templates 权限码未随迁移/种子下发
- **事实**：代码侧 `authz_catalog.py` CATALOG/ROLE_SEED 已含（五角色，ADMIN=全码），但 DB `sys_permission` 目录表 124 码 vs 代码 127 码，**恰缺 3 码**：`page:my-work`（组）、`page:my-work.main`、`page:config.eng-templates`；`sys_role_permission` 各角色矩阵同样无（p401/p402 种子为冻结 INSERT，无后续同步迁移；authz_runtime 以 DB 矩阵优先，revision=25≠0 不回退 ROLE_SEED）。
- **后果**：(a) /my-work（P6-G 四视图）全角色菜单隐藏+直达 404；(b) **IC/PE/EXPERT 登录默认首页 /my-work → 直接落 404 fallback**（首页链 P6-06 已切而权限未随批）；(c) /config/eng-templates（P2-04/P6-M 工程模板维护）不可达；(d) 权限配置页「我的工作」列五角色全「—」。
- **影响面**：存量库与全新库皆中（种子迁移本身不含新码）——环境无关的结构性缺口，属 O-INTEGRATE（主协调"权限目录/种子下发"）未收口。
- **建议修复**：补一条 alembic 迁移（目录 3 码 + 五角色矩阵按 ROLE_SEED 增量授权 + revision 推进），迁移种子/引导 SQL/ROLE_SEED 三方一致性测试同批更新。

### D-2【P2】非法 UUID 路径参数 → 500 + 服务端 traceback 裸透，前端原样渲染
- `GET /api/v1/loops/not-a-real-loop-id` → **HTTP 500，响应体为 Python traceback 原文**（asyncpg ValueError→sqlalchemy 链 + 服务器文件路径），非 JSON 错误信封；workbench360 错误块把整段堆栈显示给用户。路径参数未做 UUID 校验（应 422/404 清洁错误）。修复建议：`/loops/{loop_id}` 等路径参数 UUID 校验 + 全局异常处理器兜底清洁信封。

### D-3【P4】术语更名不彻底：「系统建议」页内部仍是「关注队列」
- 菜单/页签/路由 title 已改「系统建议」（P6-H 范围=菜单文案），但 `views/monitor/attention.vue` 页内 h1 工具栏标题（L720）、导出文件名 `关注队列_*.csv`（L359）、导出成功文案、帮助弹窗标题（L594）仍用旧称。与"术语同源/旧称零命中"口径存在页面内部残留。
