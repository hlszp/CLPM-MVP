# 评估、诊断的流式预计算与 TDengine 优化可行性

2026-10-21。审查对象为用户提出的分钟/10 分钟预计算、小时复用及 TDengine 下推方案。生产基线为 `full-1043`；本文件描述目标架构。后续已按用户授权实现[10 分钟影子验证](../过程文档/10分钟影子预计算-实现与验收-2026-10-21.md)：新增默认关闭的影子准备调度，正式计算不消费新缓存。尚未创建 Stream/TSMA 或更改生产配置，持久 dirty/outbox 等仍为后续阶段。读写优化的实现和验证另列于末节。

## 结论与优先顺序

可以做增量预计算，但应缓存**可组合的中间状态和带版本的输入块**，不能平均分钟 KPI、诊断结论或综合分。推荐先继续消除重复 IO，再小范围验证 10 分钟块；需要更细的新鲜度时才增加分钟粒度。不要同时叠加两套全量定时计算。

现场 961 回路两批执行为 1519.281s / 1499.770s，单回路 read 中位数约 16s、compute 约 0.12s、persist 约 3s。read 包含缓存编解码、历史查询和预处理，并非 SQL 的独立耗时。因此优先减少扫描、响应体、重复对象构造和提交往返，不能把更换算术函数当作主要性能收益。详见 [现场基线](../过程文档/961回路小时评估性能排查-2026-10-21.md)。

## 已有实现与复用边界

| 环节 | 当前实现 | 可复用之处 / 尚缺之处 |
|---|---|---|
| 历史数据 | `point_history_repository`、`logical_wide_builder` | TDengine 本地数据唯一事实源；已有批量写、`LAST_ROW` 初值、COV 保持、改绑、锚点、gap、三态质量 |
| 输入与缓存 | `DataPlanner`、L1 DataBlock / L2 Bundle | 已有版本、mask、时间轴、数据血缘；`resolve_data_version` 是布局/策略摘要，不是每个窗口的数据修订号 |
| 预处理 | `preprocessing/pipeline.py`、`outlier_detection.py` | 冻结检测依赖滑动窗口，噪声标记依赖整段 FFT；不可直接复用各分钟独立预处理结论 |
| 自动评估 | `kpi_calc._do_hourly_with_tracking` | 同小时窗口锁；固定发布上下文、配置批量预载、回路有界并发；不同窗口仍可能争抢 IO |
| 手动评估 | 标准评估 / custom 两条入口 | custom 写独立快照，不切换标准 latest；同输入可以复用底层读取，任务身份、权限、账本仍独立 |
| 巡检与优先级 | 巡检续租互斥；事件 0 / 人工 3 / 后台 9；prefetch=1 | 避免巡检重叠和错误分桶，但不能抢占已运行的长任务；并发上限主要在任务/进程内 |
| 导入 | 点表幂等写、覆盖元数据、批次失效、回算分发 | 补数会改变旧窗；现有失效机制没有持久的分钟块 dirty/revision 状态和发布 fencing |
| 结果与展示 | 不可变结果账本、hourly/custom/latest、节点汇总、工作台预计算/MV | 应复用正式结果与批量读 API；工作台预计算不是 KPI 分钟增量计算，不另建同义实现 |

原“55 分钟预热”及整批预热屏障已退役，原因包括窗口错位和等待整批；新方案须按真实闭合块生产，不能恢复旧屏障。参见 [运维说明](../过程文档/ops-runbook.md)。

## 算法能否组合

以下均要求输入的采样网格、归一化、mask、时间/质量策略与全窗基线一致。分钟内不提前舍入，不执行会丢失后续信息的“不足数据”终态门禁。

| 算法 / 数据 | 建议保留的状态 | 小时合成条件 |
|---|---|---|
| 样本均值、总体方差、极值 | `n, mean, M2, min, max` | 用稳定的合并矩公式，最后按 N 或 N−1 取方差；不得平均标准差。当前描述统计用总体标准差，平稳性部分使用样本标准差 |
| 准确率 | PV/SP 同槽有效对数、绝对偏差和 | 合成全窗平均绝对偏差，再应用容限与非线性公式；不能平均分钟准确率 |
| 自控、有效自控、饱和等时长 | 分子/分母/known/unknown 秒数，边界状态与来源时刻 | 按各指标自己的分母、跨信号联合质量和完整请求窗口裁剪；不能共用一个“有效点数”分母 |
| 输出总变化量、过零等边界统计 | 内部累计、首尾值/符号、连续段标识 | 仅在边界确实连续时补首尾项；unknown/gap/改绑不能拼接。过零计数不等于完整振荡率 |
| 平稳率、快速性、振荡、FFT、粘滞、阶跃/整定辨识 | 原始连续片段及算法所需状态 | 不能由分钟评分还原；阶段一继续对完整请求窗运行现有算法 |
| 数据质量 | 原始状态、质量、coverage、边界上下文 | 冻结等需配置对应的左右邻域；整段噪声和窗口级门禁仍在最终请求窗处理 |

例：一分钟有效自控 60/60s，另一分钟 0/10s，合成应为 60/70≈85.71%，不是 `(100+0)/2=50%`。原始 COV 事件 `0@0s, 10@1s, 10@10s` 的事件均值为 6.67，半开区间 [0,10) 的零阶保持时间均值为 9；两者不是同一统计量。

当前 builder 的返回网格可含尾点，指标时长采用半开区间。块拼接要区分“用于右边界的上下文点”和“归属本块的样本”，避免分钟接缝和小时尾点重复计数。任意起点的手动网格也不能未经校验地套用整点块。

## TDengine 原生能力：可用不等于可直接替代

已读取官方 `ver-3.3.6.6` 源码仓库中的版本文档，并在本地真实 **3.3.6.6** 做有限只读查询；没有创建流或 TSMA。

| 能力 | 现状 / 验证 | 建议 |
|---|---|---|
| 批量 INSERT、分点查询、`LAST_ROW`、趋势 `LAST/INTERVAL/FILL` | 项目已使用 | 继续缩减重复查询和返回列，保持因果初值与质量来源，不另拉全表 |
| `COUNT/SUM/AVG/MIN/MAX/STDDEV/VAR_POP` | 本地 20 条事件查询通过；AVG、总体标准差与 Python 对照一致 | 事件量/采集统计可下推；KPI 仅在已证明输入、mask、分母等价的分支下推 |
| `INTERVAL(10m)` | 本地固定 1h 查询产生 6 个统计窗 | 适合趋势/采集统计；不能自动得到 COV 保持、gap 和 PV/SP 联合质量后的 KPI |
| `TWA` | 本地可执行；版本文档规定流中仅支持 FORCE_WINDOW_CLOSE 模式 | 不把它当作当前零阶保持时长均值的替代；须另验插值和窗首尾规则 |
| `STATECOUNT/STATEDURATION` | 分别执行通过；混在同一 SELECT 的探针被版本拒绝 | 可研究状态段辅助统计；它们输出连续记录/时长，不等于有效自控率，且本版本有窗口组合限制 |
| 旧版 Stream | 3.3.6.6 有旧流；当前官网新流从 3.3.7.0 引入 | 先在同版本隔离环境验证旧语法、断流、乱序、重复、历史补入及恢复；本轮不升级数据库 |
| TSMA / recursive TSMA | 原生统计加速的候选 | 普通质量列过滤不满足该版本自动匹配条件；后台计算存在滞后，超出中间状态保留期的补数可能不反映在聚合中，不能无条件用于正式评估 |

3.3.6.6 的旧流默认忽略过期数据，修改数据的处理也有单独选项；FORCE_WINDOW_CLOSE 又要求忽略迟到/更新且不回算。稀疏点在 event-time 不推进时可能不封窗。不能仅设置一个 watermark 就声称解决导入补数。

该版本 TSMA 文档给出的 `maxTsmaCalcDelay` 默认/最小为 600s，`tsmaDataDeleteMark` 默认为 1d；这些是**版本文档值，未查询现场实际设置**。未来若试用，正式手动计算应在修订/新鲜度不可证实时绕过 TSMA，并记录实际数据源路径。开启 TSMA 后仍须对原始查询做独立一致性对照。

原生函数减少响应行数时才有明显 IO 潜力；同一次完整诊断仍需原始波形，再额外扫描一次 SQL 统计可能增加负载。不能因“用了原生函数”就断言整条链路更快。

官方证据（固定版本优先）：[3.3.6.6 函数](https://github.com/taosdata/TDengine/blob/ver-3.3.6.6/docs/en/14-reference/03-taos-sql/10-function.md)、[旧流](https://github.com/taosdata/TDengine/blob/ver-3.3.6.6/docs/en/14-reference/03-taos-sql/14-stream.md)、[TSMA](https://github.com/taosdata/TDengine/blob/ver-3.3.6.6/docs/en/14-reference/03-taos-sql/28-tsma.md)、[新流版本边界](https://docs.tdengine.com/quick-start/stream-processing/)。

## 推荐的数据流（提案）

```text
实时 / 历史导入
  -> TDengine 写入确认 -> PG coverage / source revision + 持久 dirty 记录
  -> 有界低优先级微批（按 dirty 合并，不为每回路每分钟发任务）
  -> 可重建输入块 + 可组合统计状态（OPEN / SEALED / DIRTY / REBUILDING）
       |
自动整点 / 手动请求 -> 固定窗口、参数、策略、数据修订
  -> 块完整且身份匹配？
       YES: 复用可证明等价的输入/中间状态
       NO : 有界读取本地 TDengine；标明回退原因，不等待整批预热
  -> 完整窗口算法、数据门禁和评分
  -> 发布前复核修订与代际 -> 同事务账本 + 快照 + latest
  -> 节点聚合屏障 / BFF 批量读取 / 结果缓存 -> 页面注明实际窗口和新鲜度
```

**输入块与算法特征分层**：源事件/COV 上下文块可按 point + UTC 块边界 + sourceRevision 复用；回路级特征还必须绑定角色历史、工程量程、采样步长与网格相位、质量/预处理版本、指标参数和发布 profile。不把用户权限或任务来源混作“数据相同”的依据；权限仍在每次入口校验。

初期只验证 10 分钟闭合块，原始波形按需保留/压缩，不复制所有指标各一份。961 回路每分钟一行就是 57,660 行/小时；按四个点分别存则更多。预计算会增加写入与存储，须量测净收益，不默认比按需快。块合并先取共同时间轴，保留每点质量和来源，不能把不同采样周期强行复用同一有效性结果。

数据持久化与 dirty 状态需可恢复：TD 与 PG 没有共同事务，应复用现有批次/coverage 确认与幂等重放，再用 outbox 或可重建修订记录闭合故障窗口。Redis 仅作加速，TTL 和 best-effort 删除不足以证明缓存正确。读任务发布前若修订变化，须重试/标记过期；不能继续发布旧块所得的新结果。

## 自动、手动、补数的差别

| 场景 | 复用规则 | 发布规则 |
|---|---|---|
| 自动整点评估 | 已闭合、完整、参数与修订匹配的块；封窗延迟按实测迟到分布确定 | 固定 [start,end)、完整参评分母和 logicalRunId，所有子回路终态可查；不足数据明确结论 |
| 手动标准小时 | 身份完全匹配时复用输入；与自动相同窗口遵循现有互斥 | 重评有自己的任务记录；不把旧“完成”冒充本次执行 |
| 手动任意/滚动窗口 | 只拼完全覆盖的内部块；首尾、不同网格相位或不同配置读原始数据 | 保留请求的精确时间；custom 不更新标准 latest |
| 手动“使用最新数据” | 可用块必须匹配当前修订；未封闭部分直接读取并标记状态 | 明确数据截止时间，不静默读最终一致但尚未更新的聚合 |
| 审计重放 / 固定输入包 | 只用原 datasetSnapshot/inputHash 与当时参数 | 不用今天的预计算块替换历史证据 |
| 导入、断点补数、改绑/量程/策略变更 | 标记受影响块及依赖窗口 DIRTY；按修订重建 | 新算追加新账本版本；不改写旧证据，不让旧代际反向发布 |

迟到 COV 事件可能影响直到下一次事件/held 上限的后续状态，冻结邻域和算法完整窗也会受影响，不能只失效事件落入的那一分钟。持续无事件的慢信号、真实断流、Bad/Unknown 必须分别测试。

## 任务与算法冲突控制

| 冲突 | 现行保护 | 改进的必要条件 |
|---|---|---|
| 自动 / 人工同窗重复读算 | 小时窗锁、同任务幂等、同窗并发读复用 | 输入计算可 single-flight，但不同用户任务仍保留独立进度、权限与账本；不能误合并不同参数/修订 |
| 补数 / 预计算 / 小时发布 | 导入幂等、缓存失效 | 持久 dirty + sourceRevision；发布时比较代际；长补数合并修复范围，禁止每分块触发全厂回算 |
| 历史回算 / 新窗 latest | 业务窗时间规则 | 本轮已把时间规则放到 PG UPSERT 原子条件；**同窗不同配置/发布代际**仍需未来 fencing，不能声称本轮已解决 |
| 预计算 / 诊断 / 评估 / 导入抢 IO | 读写线程池隔离、每任务有界并发、消息优先级 | 跨进程统一预算、短微批与 checkpoint，让后台可退让；优先级不等于抢占。现有 12 并发不是全 Worker 总并发上限 |
| 巡检 / 展示刷新 / 新增预计算 | 巡检互斥；已有工作台缓存/MV | 复用现有调度管理，错峰且负载过高暂停后台；不额外手工启动 Worker/Beat，不制造重复消费者 |
| 任务取消 / 超时 / 重投 | attempt、幂等、失败终态 | 查询收束再重试，租约 token 原子释放；任何未完成块不得标 SEALED，失败可从持久 checkpoint 恢复 |

按窗口分布的小批可降低占用时间，但不能先把 961 回路全部拆成分钟 Celery 任务。先保留 Worker 总预算，优先改善当前任务内 IO；是否拆队列/保留交互执行槽须在混合负载测试后定配置。本轮未调整线程数、并发数或优先级。

## 分阶段实施与验收建议

| 顺序 | 范围 | 进入下一步的证据 |
|---|---|---|
| 1，当前实现 | 合并初值/锚点读取；减少新结果落库 SQL；修复迟到 latest 竞态 | 回归与真实 PG 并发通过，输入/质量字节等价；现场同负载复测 read/groups/cache/commit p50/p95 |
| 2，影子试验 | 固定 24 个代表回路，10 分钟块，仅预备输入和可组合特征，默认关闭正式消费 | 同原始全窗计算对照；常值、跳变、Bad/Unknown、跨块冻结、跨窗振荡、改绑、迟到/重复导入全部一致 |
| 3，资源与恢复 | 有界 dirty 微批、持久修订、checkpoint、跨进程预算；自动/人工混合压测 | 重启/重复消息/失锁/缓存丢失可恢复；人工等待不恶化、实时写入无新增 gap、导入吞吐不下降 |
| 4，小范围正式复用 | 只启用已证明等价的指标/窗口；完整波形算法保留原路径 | 961 个 1h 整批至少重复三次；分开记录排队、执行、提交、页面可见延迟和所有终态分母 |

不得仅比较平均秒数。正确性包括各指标值/状态、confidence、known/unknown 与分母、连续段、任务到结果的关联、重放哈希和卡片窗口一致；统计浮点误差必须预先定义，不能修改 golden 来通过。实际工程秒数目标仍需按生产硬件和混合负载固定，本文件不承诺未经验证的倍率。

未来试验应复用 pytest 与既有隔离 PG/Redis/TDengine 测试，不更换测试框架：

| 必测失败模式 | 预期处理与断言（尚未实施预计算测试） |
|---|---|
| COV 无新事件 / 真断流 / Bad 切换 | 常值有依据，断流和未知不补 Good；联合质量、时长分母与全窗原路径一致 |
| 分钟接缝、跨块冻结、振荡跨界、只有一两个有效点 | 不重复尾点，不在分钟级提前丢弃片段；最终值、状态与质量明细等价 |
| 超过 watermark 或 TSMA 保留期的补数 | dirty 依赖窗重建或原始路径回退；不发布旧聚合，必须可观测 |
| 参数/改绑变化发生在块内或计算期间 | 分段并切换版本，旧代际发布被拒绝；custom 与自动结果独立关联 |
| TD 成功后 PG/Redis 失败、进程重启 | 批次可重放，checkpoint 不越过未确认记录；缓存不是唯一恢复源 |
| 重复消息、失锁、取消、慢 SQL | 唯一计算所有者、收束在途 IO、失败显式终态；不留永久“执行中” |
| 961 回路混合导入/评估/诊断与页面查询 | 完整终态分母、队列及数据库 p95、实时 gap、导入吞吐、页面窗口/新鲜度均核对 |

关闭新开关应立即恢复现行原始计算路径，已发布结果和原始数据保留；脏块重建失败显式告警，不静默替代为零分/成功。数据库升级、Kafka/Flink、新诊断引擎和评分公式变化不属于当前改动。Sequential implementation, no parallelization opportunity：读取与版本/发布身份共享模块，先串行闭合契约，再决定是否拆分。
