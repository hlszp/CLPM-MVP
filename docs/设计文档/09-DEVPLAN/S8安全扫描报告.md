### 1. JWT 安全性

| 用例 ID | 用例名称 | 结果 | 证据 |

## 发现的问题

### 问题 #1：后端配置文件硬编码默认密钥（MEDIUM）
- **位置**：`backend/app/core/config.py:24, 31, 40`
- **现象**：
  - `POSTGRES_PASSWORD: str = "clpm_dev_2026"`
  - `TDENGINE_PASSWORD: str = "taosdata"`
  - `JWT_SECRET_KEY: str = "clpm-dev-secret-key-change-in-production"`
- **风险**：若生产环境未配置 `.env`，将使用源码内公开的默认密钥。`JWT_SECRET_KEY` 默认值已在源码中公开，攻击者可伪造任意 JWT。
- **缓解**：`.env` 已加入 `.gitignore`，`.env.example` 提供模板。
- **修复建议**：
  1. 将 `JWT_SECRET_KEY` 默认值改为空字符串，启动时若为空则抛异常强制配置；
  2. 或在 `Settings` 中加 `@validator` 校验生产环境（`DEBUG=False`）密钥不能为默认值。

### 问题 #2：前端依赖存在 8 个 high 级别漏洞（HIGH）
- **扫描命令**：`pnpm audit --audit-level high --registry https://registry.npmjs.org/`
- **漏洞清单**（仅 high）：

| # | 包 | 漏洞 | 依赖路径 | 影响 |

| 1 | glob | 命令注入（GHSA-5j98-mcp5-4vw2） | `apps/web-antd>@vue/test-utils>js-beautify>glob` | dev 依赖，构建期 |
| 2 | ws | 内存耗尽 DoS（GHSA-96hv-2xvq-fx4p） | `.>happy-dom>ws` | dev 依赖，测试期 |

- **修复建议**：
  1. 优先升级 `axios` 至依赖 `form-data@>=4.0.6` 的版本；
  2. 其余 dev 依赖漏洞通过 `pnpm update` 或在 `package.json` 加 `pnpm.overrides` 强制升级；
  3. 升级后重新执行 `pnpm audit --audit-level high` 验证。

### 问题 #3：TDengine 查询存在 SQL 注入风险（HIGH）
- **位置**：`backend/app/core/tdengine.py:49-54`
- **现象**：
  ```python
  sql = (
      f"SELECT ts, val, quality FROM {settings.TDENGINE_DB}.tag_data "
      f"WHERE tag_name = '{tag_name}' "
      f"AND ts >= '{start_time}' AND ts <= '{end_time}' "
      f"ORDER BY ts ASC"
  )
  result = await conn.query(sql)
  ```
- **数据流**：`tag_name` 来自 `TagRegistry.tag_name`（DB 存储，半可信）；`start_time`/`end_time` 来自 API 查询参数（`GET /diagnosis/analytics?startTime=...&endTime=...`，`api/v1/endpoints/diagnosis.py:119-120`，类型 `str` 无格式校验），经 `services/monitor.py:381`、`services/waveform.py:197`、`tasks/kpi_calc.py:164`、`tasks/diagnosis_engine.py:176` 传入。
- **风险**：攻击者构造 `startTime=' OR 1=1 --` 即可注入 TDengine SQL，导致数据泄露或破坏（TDengine 对 UNION/子查询支持有限，但仍可造成查询异常与信息探测）。
- **修复建议**：
  1. 改用参数化查询：taosws 支持占位符 `conn.query("SELECT ... WHERE tag_name = ? AND ts >= ? AND ts <= ?", [tag_name, start_time, end_time])`；
  2. 或在入口对 `start_time`/`end_time` 强制 ISO 8601 格式校验（`datetime.fromisoformat`），`tag_name` 校验为 `[A-Za-z0-9_\-\.]+`。

## 改进建议

### 短期（本迭代内）
1. **修复 TDengine SQL 注入**（问题 #3）：改为参数化查询或入口严格校验时间格式与 tag_name 字符集。此为 P0 高危。
2. **修复 form-data 漏洞**（问题 #2 #3）：升级 axios 或在 `pnpm-workspace.yaml` 加 `overrides` 强制 `form-data@^4.0.6`。
3. **移除硬编码默认密钥**（问题 #1）：`JWT_SECRET_KEY` 默认值置空，启动时校验非空且非默认值。

### 中期（下个迭代）
4. **补充安全测试用例**：为 5 个 JWT 用例编写自动化测试（伪造签名/过期/黑名单/类型混淆/alg=none），纳入 `backend/tests/test_auth_security.py`。
5. **回路数据范围过滤**：若未来有多装置隔离需求，在 `list_loops`/`get_loop_detail` 增加 `plant_node_id` 范围校验（基于 `ROLE_PERMISSIONS` 中 `plant_node` 维度）。
6. **前端依赖治理**：建立 `pnpm audit` CI 门禁，high 级别漏洞阻断合并。

### 长期
7. **密钥管理**：生产环境引入密钥管理服务（Vault/KMS），避免 `.env` 文件落盘。
8. **CORS 收敛**：生产环境 `CORS_ORIGINS` 应配置为实际前端域名，移除 localhost。
9. **AAS 安全模式**：`config.py:56` `AAS_SECURITY_MODE: str = "None"`，生产环境应升级为 `Sign` 或 `SignAndEncrypt`。

## 结论

本次安全扫描覆盖 18 个用例，**15 通过 / 3 失败**。失败项为：
- SEC-DEP-002（前端依赖 8 个 high 漏洞）
- SEC-DEP-003（后端配置硬编码默认密钥）
- 额外发现 SEC-INJ 类 TDengine SQL 注入（问题 #3，高危）

**P0 阻断项**：问题 #3（TDengine SQL 注入）必须在本迭代修复后方可放行。问题 #1 与 #2 建议本迭代修复，至少在上线前完成。
