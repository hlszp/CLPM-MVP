# 回路工作台多智能体协调机制

> 日期：2026-10-02 ｜ 状态：生效 ｜ 适用于：回路工作台新版开发（`zp` 分支，P1–P4）
> 铁律来源：AGENTS.md「回路工作台新版」节 + 设计方案 v3 + 实施任务书

## 0. 角色与职责

| 角色 | 载体 | 职责 |
|---|---|---|
| **主协调会话** | 用户当前常驻会话（已注册 30 分钟巡检定时器） | 切子任务分支、下达子任务（产出提示词）、每 30 分钟巡检进展、**验收**（门禁+基线+原型对照）、**合并**（子分支→zp；zp→main 须用户显式验收） |
| **子任务会话** | 用户开的新会话 / 其他智能体（Codex 等） | 在自己的子分支上严格按任务书+原型开发；执行 30 分钟检查点纪律；维护自己的移交状态文件；完成后标记"待验收"并停手 |
| **用户** | — | 启动/暂停子任务（"启动 P1"、"停"）、目测额度（<10% 时令子任务暂停）、最终验收与合并决策 |

**额度真相说明（2026-10-02 已可程序化查询）**：额度端点为 `https://open.bigmodel.cn/api/monitor/usage/quota/limit`（Bearer 认证，密钥取 `~/.zcode/v2/provider_config.json` 的 `bigmodel-api` apiKey），返回多窗口额度（当前：5 小时窗 + 周窗，字段 usage=总量/currentValue=已用/remaining=剩余/percentage=已用%/nextResetTime）。封装脚本：`docs/设计文档/回路工作台-任务状态/query-usage.py`（本地工具，gitignored，密钥不回显；退出码 0=剩余>10%，2=任一窗口剩余<10% 应暂停，1=查询失败）。"额度<10% 暂停"为**硬规则**：检查点/巡检跑脚本，exit 2 即暂停子任务。另保留两层兜底：①检查点纪律使硬切损失 ≤30 分钟；②子任务自查上下文水位提前收尾。

## 1. 分支与目录约定

- 主开发分支：`zp`（验收后合 `main`，由主协调会话在用户显式验收后执行）。
- 子任务分支：`zp-p<N>-<英文短slug>`（如 `zp-p1-shell-trend`），**一律从 `zp` 切出**，完成后由主协调会话 `--no-ff` 合回 `zp`；禁止子任务会话自行合并、禁止触碰 `main`。
- 组件目录：`frontend/apps/web-antd/src/views/loop/workbench360/`（D21）。
- 任务状态目录：`docs/设计文档/回路工作台-任务状态/`（**已加入 .gitignore**，本地瞬态协调数据不入库；跨机器移交时把移交文件内容粘贴给接续会话即可）。

## 2. 任务状态文件

- 看板：`docs/设计文档/回路工作台-任务状态/STATE.md`（主协调会话维护）。状态机：
  `未启动 → 执行中 → 待验收 → 验收通过（已合并）`；可进入 `已暂停（待接续）`。
- 每个子任务一个移交文件：`docs/设计文档/回路工作台-任务状态/P<N>-<slug>.md`，**由子任务会话维护**，模板：

```markdown
# 子任务移交：P<N>-<主题>
- 分支：zp-p<N>-<slug>
- 状态：执行中 | 待验收 | 已暂停（待接续）
- 最近检查点：<YYYY-MM-DD HH:MM>
## 目标
（一段话 + 对应任务书任务编号）
## 已完成（每条附证据：提交号 / 文件路径 / 命令输出摘要）
## 未完成（按优先级，注明卡点）
## 下一步（接续者从哪个文件哪一步继续，精确到可执行）
## 移交说明（坑 / 本轮决策 / 未决问题 / 需主会话仲裁事项）
```

## 3. 子任务 30 分钟检查点纪律（写入每个子任务提示词）

子任务会话**连续工作时**，每完成一个子步骤自查：距上次检查点 ≥30 分钟则：
1. **先查额度**：`python3 docs/设计文档/回路工作台-任务状态/query-usage.py`——退出码 2（任一窗口剩余<10%）→ **立即暂停**：提交 WIP、移交文件标记"已暂停（原因=额度）"、报告后停手；
2. 更新移交文件（状态/已完成/未完成/下一步至少刷新到当前真实进度）；
3. 若发现上下文水位已深（长对话自估 >70%），**不再开新子步骤**：把当前改动提交到子分支（WIP 允许）、移交文件标记"已暂停（待接续，原因=上下文水位）"、向用户报告并停手；
4. 收到用户"停"指令：同上收尾流程，标记"已暂停（原因=用户暂停）"。
> 额度耗尽被平台硬切时，最近一次检查点之后的增量丢失上限 = 30 分钟工作量；接续会话凭移交文件 + 子分支提交无损续作。

## 4. 主协调会话 30 分钟巡检（定时器已注册）

每次巡检执行：①读看板与各移交文件；②无活动子任务则一行"跳过"不做任何动作；③`git log` 比对各活动子分支自上次巡检的新提交 vs 移交文件"未完成"清单，识别**停滞**（>40 分钟无检查点更新）与**偏航**（提交内容与任务书范围不符）；④向用户汇报 ≤10 行摘要；停滞/偏航给出建议（催办/接管/暂停）。巡检**禁止**执行开发动作或合并。

## 5. 验收与合并流程（主协调会话职责）

1. 子任务标记"待验收"→ 主协调会话执行验收：`ruff/pytest/check:type/eslint/vitest` 门禁 + v3 §16 验收基线逐项 + 与原型对照抽查；
2. 发现问题 → 退回子任务（状态改回"执行中"，问题清单写入移交文件"未完成"节）；
3. 通过 → 主协调会话 `git checkout zp && git merge --no-ff zp-p<N>-<slug>`，删除子分支（可选），更新看板与实施方案 §17 修订记录；
4. **zp → main 仅在用户对整体阶段成果显式验收后执行**。

## 6. 子任务提示词模板（启动子任务时由主协调会话产出）

```
【角色】你是回路工作台新版开发的子任务执行会话。
【分支纪律】先 `git checkout zp-p<N>-<slug>`（已由主会话切好）；一切提交只进本分支；禁止合并、禁止碰 main/zp。
【必读】AGENTS.md「回路工作台新版」节 → docs/设计文档/回路工作台-协调机制-2026-10-02.md §3 → 实施任务书对应阶段节 → 原型对应区块。
【检查点纪律】按协调机制 §3 执行：每 30 分钟先跑 `python3 docs/设计文档/回路工作台-任务状态/query-usage.py`（退出码 2=剩余<10% → 立即暂停收尾），再更新移交文件 <路径>；上下文水位深或收到"停"立即按 §3 收尾。
【任务】按实施任务书 §<N> 阶段提示词执行（引用，不复制）。
【完成标志】任务书核验清单自检全绿 + 移交文件状态改"待验收" + 向用户报告停止。
```
