> 状态：**P1~P7 全部完成（2026-10-07）**——六页签迁移+弹窗化+总览合并+懒加载+旧工作台退役+菜单十项重排均已落地并验收；实施细节偏差见文末「实施后记」。事实源：本文档 + 用户裁决原文（2026-10-05 会话）。
> 关联：`11-驾驶舱设计方案.md`（驾驶舱初版）、`CLPM工作台改进方案-v2.0.md`（运维工作台 v2.0，将被本方案吸收退役）。

## 1. 背景与裁决记录

现状 `/cockpit`（驾驶舱两页：总览|回路）与 `/workbench`（运维工作台 5 Tab）两个全局概览入口并存冗余。用户裁决（2026-10-05）：

| # | 裁决 |
|---|---|
| D1 | 采用方案 B：驾驶舱吸收运维工作台核心设计，扩为 **6 Tab 满屏驾驶舱**，定位=管理者掌握总体情况 |
| D2 | 「驾驶舱总览」与「运维工作台-系统总览」**合并为一页**，重点显示**当前全厂级各装置、单元的性能情况**；删除驾驶舱的「问题回路 TOP-8」「治理漏斗」 |
| D3 | 性能/诊断/整定/处置 4 个 Tab 沿用当前设计，但**页内所有联动跳转链接全部改为弹窗**（显示摘要性信息），**不得直接跳转到管理后台页面** |
| D4 | 新驾驶舱 Tab 顺序：**总览、回路、性能、诊断、整定、处置**（6 个） |
| D5 | 实施顺序：**先完成新驾驶舱构建+测试，测试通过后再清理原「运维工作台」** |
| D6 | 一级菜单重排改名（十项）；诊断定名「**回路诊断**」（不用故障诊断）；回路工作台改名「**工作台**」 |

## 4. 四业务 Tab 迁移与弹窗化（D3）

### 4.1 迁移方式

- workbench 4 个 tab 内容（`views/workbench/tabs/{assessment,diagnosis,tuning,handling}.vue` + 所需 components）**复制**到 `views/cockpit/tabs/` 与 `views/cockpit/wb-comps/`（并存期旧页面不动，P7 随旧 workbench 一并删除）。
- 主题适配：迁移组件的硬编码色/ant 默认色替换为 `--ck-*` CSS 变量，面板壳统一 `.cockpit-panel`，保证深浅双主题一致。
- store：4 tab 继续消费 Pinia `store/workbench.ts`（scope/timeWindow/plugins 等），驾驶舱侧由 cockpit store 持有 timeWindow——迁移时以 workbench store 为 4 tab 的状态源，cockpit-header 的全局时间窗写入 workbench store（驾驶舱两页原生组件继续读 cockpit store，P6 收口统一）。
- 范围（scope）选择器：原 HeaderBar 的范围下拉不再迁移；4 tab 的 scope 由舱内统一装置树上下文或默认 GLOBAL 提供（P2 起按 tab 落地，默认 GLOBAL 起步）。

### 4.2 跳转点 → 弹窗映射（50 点穷尽）

跳转 4 类处置：真路由 drill（37 处）→ **弹窗**；跨 Tab setActiveTab（3 处）→ **cockpit 页签路由切换**；页内抽屉（5 处）→ 保留原样；死 UI（2 处）→ 清理。HeaderBar 铃铛/驾驶舱按钮（B0#1/2）不迁移（Shell 不迁）。

## 5. 技术方案要点

- 路由：cockpit.ts 扩 4 路由（hideInMenu、noBasicLayout、COCKPIT_ROLES）。
- cockpit-header：tabs 数组扩 6；「管理后台」入口目标由 `/workbench` 改为 `/monitor/loops`（旧 workbench 退役后，管理后台首页=回路监视；P7 落地）。
- 4 tab 首屏性能：沿用懒挂载（首次激活才请求）；驾驶舱页签切换为路由级，keep-alive 由 noBasicLayout 顶层路由 + 组件内 visited 语义等价实现（切页签不重载）。
- 模块热插拔：4 tab 迁移后保留 plugin 4 态感知（TabBar dot + 维护面纱概念转为舱内页签禁用态+面纱）。
- 单测：新增/迁移 workbench tab 相关测试至 cockpit 命名空间；E2E 菜单文案与 /workbench 用例随 P7 更新。
