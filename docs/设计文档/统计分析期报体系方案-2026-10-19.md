# 统计分析期报体系方案（2026-10-19）

> 状态：**方案待裁决**（P0 可启动）
> 关联：`CLPM报告模块优化实施方案-2026-08-28.md`（报告模块诚实化/可插拔，已落地）、`驾驶舱整合方案-2026-10-05.md`（管理者总览，已落地）
> 事实源：2026-10-19 会话用户诉求 + reports/ 七页现状勘察

## 1. 背景与问题

统计分析下现有 7 子模块（绩效 / 数据质量 / 预警统计 / 诊断报告 / 处置报告 / 收益报告 / 订阅配置）本质是 **运维仪表板拼盘**，不是 **仪控部门经理的期报体系**。

### 1.1 用户诉求（2026-10-19）

面向**仪控部门经理**，提供按 **日 / 周 / 月** 的统计报告，覆盖三个维度：

| 维度 | 经理要回答的问题 |
|---|---|
| 装置 | 哪套装置在拖后腿？环比好了还是坏了？ |
| 回路性能 | 自控率/平稳率/评分多少？劣化 TOP 谁？ |
| 诊断-处置工作量与效果 | 本期诊断多少条？处置多少单？有没有用？ |

### 1.2 现状诊断

| 模块 | 形态 | 与目标差距 |
|---|---|---|
| 绩效报告 | 唯一有日/周/月的报表页 | 最接近；缺期报叙事与导出整合 |
| 数据质量 | 仪表板（趋势/可信度/位号体检） | 偏运维技术面，经理不看位号级 |
| 预警统计 | 仪表板（堆叠柱/TOP10） | 无「期」概念，与驾驶舱预警重叠 |
| 诊断报告 | 图表+明细 | 偏运行记录，非「本期工作量」 |
| 处置报告 | 汇总卡+漏斗+人员工作量 | 已有工作量雏形，但是仪表板 |
| 收益报告 | 自控率曲线+前后对比 | 效果叙事弱，难直接进月报 |
| 订阅配置 | 已有日报/周报/月报周期 | 订阅对象不清——没有「报表模板」 |

**结构性缺陷**：能力零件都在（日/周/月、装置树、CSV 导出、订阅周期、PDF 任务），缺的是**组织方式**——用户要的是「一期一份能转发的报告」，系统给的是「七张可下钻的看板」。

### 1.3 明确不做（反堆砌边界）

- 不把 7 页全部改成「报表形式」——位号体检、规则 TOP 等继续做成仪表板更合适
- 不重写数据层——现有 `/reports/*`、`/workbench/*`、`/handling/*` API 已够期报拼装
- 期报页**不做下钻交互**——期报只读、可打印、可导出；钻取走专题页
- 不做经济收益口径——维持技术指标量化决策（沿 2026-08-28 方案）
- 不另建「第 8 个仪表板」

## 3. 期报页面规格（P0 核心）

### 3.1 页面结构（一期一报，只读）

```text
┌─────────────────────────────────────────────┐
│ 期报  [日报|周报|月报]  2026-10-15（周）      │
│ 范围：[全厂 ▾]              [导出PDF][导出Excel][订阅] │
├─────────────────────────────────────────────┤
│ 一、本期结论（3~5 句自动生成）                │
│   · 全厂综合评分 xx（环比 ±x），劣化回路 N    │
│   · 诊断 xx 条 / 处置 xx 单，闭环率 xx%      │
│   · TOP 风险装置：xxx；TOP 劣化回路：xxx      │
├─────────────────────────────────────────────┤
│ 二、装置维度                                  │
│   · 装置排名表（评分/环比/参评/劣化）          │
│   · 环比上升/下降 TOP3                        │
├─────────────────────────────────────────────┤
│ 三、回路性能维度                              │
│   · 自控率 / 平稳率 / 评分 走势（期粒度）      │
│   · 劣化回路 TOP10（含原因标签）              │
├─────────────────────────────────────────────┤
│ 四、诊断-处置工作量与效果                      │
│   · 工作量：诊断次数、处置单、人均负荷          │
│   · 效果：闭环率、平均处置时长、无效/驳回率     │
│   · 收益：典型回路 before×after（评分/自控率）  │
├─────────────────────────────────────────────┤
│ 五、附：数据质量与预警（简表）                 │
│   · INCONCLUSIVE 率、预警量/确认率            │
└─────────────────────────────────────────────┘
```

### 3.2 时间口径

| 期型 | 窗口 | 环比基准 |
|---|---|---|
| 日报 | 当日 00:00–24:00（Asia/Shanghai） | 前一日 |
| 周报 | 本周一 00:00 – 下周一 00:00（isoWeek） | 上一周 |
| 月报 | 自然月 | 上一月 |

与绩效报告现有日/周/月口径对齐（isoWeek 周一起始，本地日界→UTC 转换已有实现可复用）。

### 3.3 数据拼装（复用现有 API，不新建大数据接口优先）

| 章节 | 数据源（现有） | 备注 |
|---|---|---|
| 本期结论 | 由各章节结果本地拼装 | 纯前端/轻 BFF |
| 装置维度 | `/reports/performance` 综合视图 或 `/workbench/assessment` ranking | 复用参评/环比/失分 |
| 回路性能 | `/reports/performance` 回路视图 + `/performance/nodes/*/snapshot` | 走势取期粒度点 |
| 诊断-处置 | `/reports/diagnosis-statistics`、`/handling/statistics`、`/reports/benefit` | 工作量+效果 |
| 数据质量与预警 | `/reports/data-quality`、`/reports/alert-statistics` | 简表 2~4 行 |

**可选 P2**：新增 BFF `GET /reports/period` 一次返回整期 payload（减少前端 6 次串行、便于 PDF 任务复用）。

### 3.4 导出与订阅

- **导出 PDF**：复用既有 `overview_pdf_export` / 报告生成任务骨架；期报单文件
- **导出 Excel**：多 sheet（结论/装置/回路/治理/附）
- **订阅**：订阅配置项从「报表配置」改为「期报模板」——周期（日/周/月）+ 范围（全厂/装置）+ 接收人 + 启用；Beat 生成后推送（沿用 P3 订阅做实路径）

## 4. 专题重组（P1）

| 专题 | 吸收 | 保留能力 |
|---|---|---|
| 绩效专题 | 现绩效报告 | 日/周/月、综合+回路、CSV、列配置 |
| 诊断与处置专题 | 诊断报告 + 处置报告 + 收益报告 | 分类饼图、漏斗、人员工作量、before×after、TOP 回路 |
| 数据质量与预警 | 数据质量 + 预警统计 | 趋势、可信度、位号体检（折叠）、预警 TOP、导出 |

诊断/处置/收益合并理由：**「干了什么、干得怎样」是一条故事线**，拆三页强制经理跳转。  
数据质量/预警合并理由：**「数据与风险底座」**，一页看清底座是否可信。

## 7. 风险与依赖

| 风险 | 缓解 |
|---|---|
| 现有 `/reports/*` 各页口径不一致（参评/窗口） | 期报统一只消费已对齐的 ranking/workbench 口径 |
| PDF 任务已知限制（内存任务表，多副本不共享） | 沿 2026-08-28 已知限制登记；单副本部署可接受 |
| 处置/诊断依赖闭环模块 | 模块禁用时期报相应章节显示「模块未启用」横幅，不崩页（沿可插拔口径） |
| 空数据期 | 诚实空态（「本期无数据」），不造假图表 |
