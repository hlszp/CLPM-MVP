## 0. 现状诊断（为什么现在这个页面"不好"）

当前工作台为"左侧回路列表 + 右侧四区垂直均分"（概览 10% / 评估 30% / 诊断 30% / 整定 30%，外加后加的闭环验证区）：

1. **主画布缺位**：页面唯一的大图是"评分趋势"——一个派生指标的历史；工业用户真正要看的 **PV/SP/OP 过程趋势被塞进弹窗**（`LoopTrendModal`，要点"趋势"按钮才出现）。工业用户用趋势思考，把趋势藏起来等于把工作台的灵魂藏起来。
2. **四区均分 = 没有重点**：评估/诊断/整定三个 30% 高的区块各自再做 50/50 切分，一屏出现 6+ 个同权重视觉块，无单一视觉锚点。
3. **主动作失效**：后端 `workbench_summary.py:936-1146` 已经算好 `nextAction`（含 `_disabled()` 禁用原因），前端 9 类动作 5 类空 `break`（FP-P0-01）；闭环时间线事件未绑定（FP-P0-02）——**后端已经对了，前端没接上**。
4. **概览区是字段表**：label-value 网格（位号/装置/单元/模式……）占据首屏，是"数据库视图"而非"状态判断"。

好消息：后端 summary（runtime/freshness/评估/诊断/整摘要/tracker 时间线/A/B 对比/活跃关注/生命周期/nextAction）数据已经足够丰富，**这次重构主要是前端信息架构问题，不是数据缺口问题**。

## 1. 一页纸契约（Page Contract）

| 条目 | 约定 |
|---|---|
| 页面名称 / 路由 | 回路工作台 `/monitor/loop-workbench`（保留 legacy `/loop/workbench` 重定向） |
| 主对象 | **一条回路 × 时间窗 × 证据版本**（不是"评估/诊断/整定三个功能"） |
| 主任务 | 30 秒内回答三个问题：这条回路现在好不好 → 为什么 → 下一步做什么 |

| 上下文 | 进入/离开保留 loopId + timeWindow + 来源路由；跨页跳转用受控 route ID，业务判断按 ID 从服务端重载 |

| 角色 | IC 全功能；PE 可补充证据无整定动作；EXPERT 只读+升级；SPONSOR 不出现工程动作按钮；可见即有权 |

| 持久结果（Q-16） | 本页可产生：评估/诊断/整定任务、Tracker 案例、验证记录、审计事件；纯浏览不算完成任务 |

### 2.3 关键设计规则

1. **趋势即主页**：过程趋势从弹窗升格为常驻主画布；评分趋势降级为 R5 评估卡内迷你 sparkline，不再独占 30% 区块。
2. **概览字段网格取消**：位号/装置/模式进 R1 页头，评分/可信度/有效率进 R2 状态条——信息相同，但按"身份 / 状态 / 证据"分层，不再是数据库视图。
3. **评估/诊断/整定从"三个 30% 区块"降级为"三张证据卡"**：每张卡只回答"结论是什么、什么时候算的、可不可信、去哪看全部"。这是工作台作为**编排器**的本分（文档 10 §5.2）。
4. **Decision Dock 是右侧栏的第一公民**：9 类 nextAction 全部接通（FP-P0-01 修复是本设计的前置），禁用态显示后端给出的原因。
5. **左脊柱升级（v1.2 修订，千级回路口径）**：装置树**只到装置/单元级**（范围轴，节点带异常数/最低分聚合），**回路不作为树叶出现**——树下方为独立回路列表区（当前选中单元的回路：状态点+位号+评分）；**搜索框同时支持装置/单元名与回路位号/描述**（搜装置=圈定树范围，搜位号=直达回路，loops.py:86）；服务端分页/虚拟滚动（loops.py:103-104）；保留深链接不在筛选结果中的提示（现有 MW-P0-03）。千级回路规模化以"圈范围→找例外→搜具体"三场景为设计目标，不以"全量浏览"为目标；500+/1000 回路压测列入验收前置（IA 复盘 P2-D）。
6. **面→点关系（v1.1 新增）**：本页（页型 C，点）与回路列表页（页型 B，面）构成两级结构——列表支持列表/卡片双视图（后端 `/loops/monitor` 已支持 `view=list/card`，loops.py:273；卡片视图定位筛选后小集合，非全量浏览）；列表点行带完整上下文进入本页，本页返回保留列表筛选与时间窗（现有 `handleFleetLoopClick` 模式契约化）。
7. **页面文字三级来源原则（v1.8 新增，数据诚实红线）**：页面上的所有文字必须属于三级之一——①**结构化字段**（算法/数据库输出，必有 §2.5 端点来源，是卡片主体）；②**规则模板短句**（来自诊断规则配置的预制文案，标注"规则模板"）；③**LLM 生成叙述**（可选增强，受 `use-ai-insight-gate` 门控，**未接入 LLM 时不渲染该区域且不留空白**）。禁止出现无来源的"看起来像分析结论"的静态文字——它会被用户误认为系统判断。

### 2.4 性能证据增强（v1.1 增补，2026-08-12 用户评审新增需求）

**需求**：工作台上不仅看 PV/SP/OP 过程趋势，还要看本回路 ①当前主要性能指标 ②综合性能雷达/棒图 ③历史变化（8h/24h/72h 自由切换）。

**评估结论**：需求成立（对应主任务"好不好→为什么"，HiaMonitor 回路详情同构），数据基本现成；吸收方式必须保证页面区块数不增加、单视觉锚点不破。三条设计决策：

1. **雷达与棒图分工（v1.4 用户拍板）**：**六轴雷达**——平稳率/准确率/快速率/自控率/好值率/饱和率六个"率"类指标（同为 0~100 达成度量纲，形状可比），**雷达中心显示综合评分+等级**；其余 6 项（振荡率/仪表故障率/有效自控率/调节时间/卡涩指数/行程指数）走**达标率横向棒图**，按 `get_threshold(control_type)` 阈值归一化，带阈值标线。不复用现有 3 轴 `radar-chart.vue`（轴数与中心读数需求不同，新绘轻量组件，沉淀为共享候选）。
2. **历史折线与过程趋势共享主画布（v1.9 混合图修订）**：R4 主画布顶部加 `过程变量 | 性能指标` 分段切换，**共用画布头部同一时间窗选择器**；性能指标模式为**折线+棒图混合图**——综合评分折线为主线（趋势走向），平稳率/准确率/快速率分组棒图为支撑（逐时点对比），量纲同为 0-100 共轴，ECharts 原生支持、数据不变；**棒图粒度自适应**：8h/24h 按小时、72h 按 2h 桶、168h 聚合为日粒度 7 组，防止密集成糊；告警线图层必须在棒图之上。
3. **时间窗全局统一（v1.6 选项扩展）**：时间窗选择器位于**画布头部第一行右侧**，档位为 `[8h | 24h | 72h | 168h | 自定义]`——168h 对应后端已有 `last_7_days` 档位；**自定义起止时间组件（datetime-local，精确到分钟）**，KPI 快照接口已支持 `startTime/endTime`（performance.py:377），**过程趋势接口的自定义起止为待扩展项**（实施时确认，当前仅有固定档位）。画布头部两行制：第一行＝模式切换 + 标题 + 时间窗，第二行＝图例。粒度核对：KPI 快照为小时级，8h=8 点 / 24h=24 点 / 72h=72 点 / 168h=168 点；自定义窗口小时快照按实际跨度取点；过程趋势 LTTB 降采样 maxPoints=2000 覆盖全部档位。
4. **趋势图告警线来源（v1.3 明确）**：KPI 历史图上的告警线取**定级阈值中"合格/警告"边界**（默认 60 分），数据源 `GET /configs/grading-thresholds`（配置·指标配置·定级阈值 tab），随配置动态变化，**禁止硬编码**；阈值项自带颜色时优先使用配置色。

### 2.6 时间窗联动规范（v1.4 新增，用户评审提出）

**问题**：时间窗 `[8h | 24h | 72h]` 除驱动曲线外，还联动哪些取数？不规范则实施时各自猜测、用户切换时困惑（"切到 72h 评分怎么没变？"）。（v1.5：时间窗选择器已移至画布头部，物理位置与 A 类联动语义一致。）

**接口事实**（只读核查）：KPI 快照接口支持 `startTime/endTime`（`performance.py:377`，可联动）；工作台 summary 接口**无时间窗参数**（`monitor.py:81`，评分/雷达/横道只能取最新快照，不重算）。

**三层语义**（必须全站一致执行）：

| 层 | 元素 | 联动行为 | 口径与标注要求 |
|---|---|---|---|
| **A 窗口联动（趋势类）** | R4 过程趋势（PV/SP/OP） | 随窗口重取数（`trendWindow`） | 标题栏显示当前窗口 |
| | R4 KPI 历史折线 | 随窗口重取数（`startTime/endTime`） | 同上 |
| | R4 事件标记（▼◆▐▓） | **只显示落在窗口内的标记**，窗口外的隐藏 | 图例不变 |
| | R4 缺口▓与趋势内有效率 | 按窗口内数据计算 | — |
| **B 快照口径（评估类）** | R2 综合评分/等级/可信度/有效率 | **固定取最新评估快照，不随窗口变化** | 状态条加 ⓘ tooltip："最近评估快照（计算窗口 24h · 08-12 06:00），不随页面时间窗变化" |
| | R2 日 delta | 固定日环比 | tooltip 说明"与昨日同时段快照比较" |
| | R5 雷达图/指标横道 | **固定取最新快照，不随窗口变化** | 卡内 meta 必须显式标注计算窗口与时间（已有："24h 窗口 · 08-12 06:00"） |
| **C 窗口无关（状态与事件类）** | R2 生命周期条、决策栏下一步/活跃关注/闭环时间线、R5 诊断卡/整定卡、R6 验证对比 | 不联动 | 诊断/整定卡 meta 标注事件时间（已有） |

**配套规则**：

1. 凡 B 类元素，**计算窗口与计算时间必须可见**（meta 行或 tooltip），这是防混淆的硬要求；
2. 用户需要"按 72h 重新评估"时，走主动作：评估卡"完整证据 →"或发起评估弹窗带窗口参数——**不做隐式联动重算**（重算是昂贵的算法任务，不是查询）；
3. 未来扩展（不进本期标杆）：summary 接口增加 `window` 参数，使 B 类可选择联动；届时本规范修订；
4. 窗口切换时 A 类元素显示局部 loading，**不得清空重绘导致闪烁**（keep-alive 旧数据 + 加载遮罩）。

### 2.7 关注与收藏：方案讨论（v1.10，本期不实施）

**背景**：左脊柱快捷筛选已有"我的关注 3 / 收藏"两个 chip（当前为占位）。用户提问：关注和收藏应在哪里操作？本节仅作方案讨论，**不在本页面实现该功能**。

**① 概念决策（建议先拍板）**：关注（watchlist，订阅语义——回路状态变化时进入"我的关注"集合，未来可接通知）与收藏（favorite，书签语义——快速访问）在工业产品上极易混淆（HiaMonitor 也只有 watchlist 一个概念）。**建议第一版只实现"关注"一个概念**，UI 上"收藏"chip 可作为关注的别名或撤掉；若坚持两个并存，必须各自有一句话语义说明并长期维护。

**② 操作入口（在哪里加/减关注）**：按自然度排序——a. **回路工作台页头**位号旁的星标切换（用户看着回路时决定关注，最自然）；b. **回路列表行内**星标列（悬停可见，批量标记）；c. **关注队列**条目悬停操作。**不新增一级页面**。

**③ 管理入口（在哪看和取消）**：左脊柱"我的关注"chip 本身就是管理视图——筛选出集合后点星标即取消；批量管理放进回路列表页的筛选态或个人偏好抽屉，不单独建管理页面。

**④ 数据模型（需新建 1 张表）**：`user_loop_mark`（`id` / `user_id` / `loop_id` / `mark_type`[follow|favorite] / `created_at`），唯一约束 `(user_id, loop_id, mark_type)`，索引 `(user_id, mark_type)`。数据量极小（用户数 × 每人关注数十条），无分区需求。

**⑤ API（需新增 3 个端点）**：`GET /users/me/marks?type=`、`POST /users/me/marks`、`DELETE /users/me/marks/{markId}`；回路列表接口（loops.py:81）与工作台 summary 联查返回 `marked` 标志位。权限：仅本人可读写（`/users/me` 作用域），**不需要新角色、不进 RBAC 矩阵**。

**⑥ 与现有设计的衔接**：左脊柱 chips 的计数（"我的关注 3"）实现后来自 marks 表联查；页头星标状态来自 summary 的 `marked` 字段。

**⑦ 演进路径（不进本期）**：第二阶段可将"关注"接入通知语义（绩效预警只推送关注回路）；第三阶段再评估是否拆出独立收藏。实施立项时应单开任务，不与本标杆页改造混合。
