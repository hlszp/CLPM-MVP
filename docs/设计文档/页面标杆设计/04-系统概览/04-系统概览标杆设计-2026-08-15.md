## 0. 方向检讨：为什么 v3.1 不适用于 MVP

| 版本 | 方向 | 不适用于 MVP 的原因 |
|---|---|---|
| v1.0 | 装置健康矩阵 × 今日例外双联 | 例外是关注队列的职责 |
| v2.0 | 三级跳视图 | 下钻逻辑对但形态错 |
| v3.0/3.1 | 一屏总览 + 左树联动 | **MVP 核心矛盾**：① 左树驱动排名联动，排名随选择变化——用户无法同时看到"全厂所有装置排名"和"全厂所有单元排名"；② 系统健康面板（链路/订阅/网络/Tailscale）占据内容区，不属于"装置绩效"范畴；③ 关注点偏离 MVP 核心场景（运维快照 vs 深度分析） |
| **v4.0（当前）** | **三列仪表盘 + 排名即导航** | 解决 v3.1 三个核心矛盾：排名全量展示不联动、去掉左树用排名做导航、系统健康降级为状态条 |

**v4.0 核心决策**：

1. **排名全量展示，不随选择联动**——装置排名和单元排名始终展示全厂层级的数据，用户一眼看遍所有装置和单元的绩效排名
2. **去掉左侧工厂树**——排名即导航，点击排名中的装置/单元行即为选中，驱动趋势和重点回路联动
3. **三列布局**——装置排名（左）+ 单元排名（中）+ 重点回路（右）并齐，底部全宽趋势图
4. **1920×1080 无滚动**——页面整体不滚动，组件内部可滚动
5. **图表形式差异化**——装置数量少（3~8个）用横道图，单元数量多（10~50个）用帕累托柱状图
6. **系统健康降级**——仅保留 `● 实时在线` 状态点，网络模式/Tailscale 迁移至配置-链路配置

## 1. 一页纸契约（Page Contract）

| 项 | 内容 |
|---|---|
| 页面名称 / 路由 | 系统概览 `/dashboard/workbench`（保持 canonical 与 affixTab） |
| 页型 | B 仪表盘：全厂控制回路绩效运维快照 |
| 主对象 | **全厂 → 装置 → 单元三级的回路绩效排名与趋势** |
| 主任务 | 10 秒回答：① 全厂整体绩效如何？② 哪些装置/单元最差？③ 最近趋势在变好还是变坏？④ 哪 10 个回路最需要关注？ |
| 主用户 | **SPONSOR（厂长/调度/管理者）为主**，IC/PE/ADMIN 同页使用 |
| 主动作 | **排名选中**（点击装置/单元行 → 趋势与重点回路联动）；**回路下钻**（点击重点回路行 → 跳转回路工作台） |
| 信息所有权 | 本页 = 全厂级 KPI 快照 + 全量排名（装置+单元）+ 选中节点趋势 + 选中节点重点回路 Top10；回路完整详情在回路工作台，深度分析在评估总览 |
| 上下文 | 无左侧导航树；排名区即导航入口；选中态驱动趋势和重点回路联动 |
| 空态 | 数据加载中骨架屏；无数据空态；组件内部空态不影响其他区域 |
| 时间窗 | 五档：近 8h / 今日 / 昨日 / 近 7 天 / 近 30 天（**对齐现有 API 支持**）；默认"近 30 天"；趋势区时间窗切换仅影响趋势图 |
| 布局 | **1920×1080 一屏无滚动**；四区域：卡片区（全宽）+ 三列（装置排名/单元排名/重点回路）+ 趋势区（全宽） |
| 持久结果 | 纯浏览/导航页，不产生持久结果 |
| 禁止项 | ① 不出现左侧工厂树；② 不出现系统健康面板（链路/订阅/网络/Tailscale）；③ 不出现关注事项 chips（关注队列已有独立页面）；④ 不出现微型扇形图；⑤ 排名数据不随选择变化（始终全厂层级）；⑥ 阈值禁硬编码 |

### 2.2 区域规格与数据来源

#### §1 全厂卡片区（~110px）

**定位**：全厂绩效快照，始终展示全厂数据，不随选中项变化。

| 元素 | 规格 | 数据来源 |
|---|---|---|
| 综合评分卡 | 大字号分值 + 等级标签（优秀/良好/合格/警告/不合格），~180px 宽 | `GET /dashboard/board/aggregate?timeWindow=` |
| 平稳率卡 | 百分比 + 迷你色条（8px 高），~120px 宽 | 同上 `stabilityRate` |
| 快速率卡 | 百分比 + 迷你色条，~120px 宽 | 同上 `fastRate` |
| 准确率卡 | 百分比 + 迷你色条，~120px 宽 | 同上 `accuracyRate` |
| 自动投用率卡 | 百分比，~100px 宽 | `GET /dashboard/auto-rate-rt` |
| 回路统计卡 | `已评估/总数`，~100px 宽 | `board/aggregate` `evaluatedLoops/totalLoops` |
| 评分等级分布 Pie | 全厂回路在 5 个等级的占比，~180×90px 缩略图 | `GET /nodes/overview` `statusDistribution` |
| 状态指示 | `● 实时在线` 小状态点 | 数据源健康检查 |
| 口径标注 | `B 类口径 · 近30天` | 随时间窗联动 |

**API 汇总**：5 个接口并行——`board/aggregate`、`auto-rate-rt`、`nodes/overview`、`datasource/health` + 时间窗切换触发重新加载。

#### §2 装置排名区（左列 ~28% 宽，~560px 高）

**定位**：全厂所有装置的绩效排名，兼做下钻导航入口。

| 规格 | 说明 |
|---|---|
| 图表类型 | **水平条形图（横道图）** |
| 每行高度 | ~38px |
| 条长 | 综合评分 0-100 映射 |
| 条色 | 等级色阶（优秀绿/良好蓝/合格橙/警告红/不合格深红） |
| 标签 | 左侧：装置名（如 `1#装置`），右侧：分值 |
| 选中态 | 选中行背景高亮 + 左侧 3px 色条 + 底部"清除选择"按钮 |
| 溢出 | 装置多时组件内部**上下滚动** |
| 叠加 | 条内可叠加三率分段（平稳/快速/准确按比例着色） |
| 数据范围 | **始终全厂层级**，不随选中项变化 |
| 交互 | 点击行 → 选中该装置 → §4 重点回路 + §5 趋势联动切换 |

**数据来源**：`GET /dashboard/board/aggregate?timeWindow=` → `items`（装置级聚合，按 `avgScore` 降序排列）

#### §3 单元排名区（中列 ~42% 宽，~560px 高）

**定位**：全厂所有单元的绩效排名，帕累托分析。

| 规格 | 说明 |
|---|---|
| 图表类型 | **帕累托柱状图**（垂直柱 + 累计百分比折线） |
| 柱高 | 综合评分 0-100 映射 |
| 柱色 | 等级色阶（同装置排名） |
| 排序 | 按评分降序排列（帕累托核心） |
| 累计线 | 右侧 Y 轴 0-100%，折线标识"前 N 单元覆盖 80% 低分问题" |
| 柱宽 | ~32px |
| 间距 | ~8px |
| 溢出 | 单元多时组件内部**横向滚动**（固定柱宽，不压缩） |
| 选中态 | 选中柱高亮 + 下方标签色变 + 底部"清除选择"按钮 |
| 数据范围 | **始终全厂层级**，不随选中项变化 |
| 交互 | 点击柱 → 选中该单元 → §4 重点回路 + §5 趋势联动切换 |

**数据来源**：`GET /dashboard/board/aggregate?timeWindow=` → `items`（单元级聚合，按 `avgScore` 降序排列）

#### §4 重点回路区（右列 ~30% 宽，~560px 高）

**定位**：选中节点（默认全厂）下评分最低/最高的 10 个回路，提供跳转出口。

| 规格 | 说明 |
|---|---|
| 每行 | `#排名` `回路名` `所属装置·单元` `评分` `等级标签` `→` 跳转按钮 |
| 行高 | ~48px（紧凑） |
| 切换 | 标题栏右侧 `[评分最低10 ▼]` / `[评分最高10]` dropdown |
| 默认 | 全厂评分最低 10 个回路 |
| 溢出 | 列表多时组件内部**上下滚动** |
| 联动 | 选中装置/单元后，切换为该节点下的 Top 10 |
| 底部 | 显示当前选中范围（如"选中: 1#装置"）+ "清除选择"按钮 |

**数据来源**：`GET /performance/ranking?plantNodeId=&timeWindow=&limit=10&sortBy=score&sortOrder=asc`（`plantNodeId` 随选中项变化，全厂时为 `undefined`）

#### §5 趋势区（底部全宽，~340px）

**定位**：选中节点（默认全厂）的综合评分与三率时间趋势。

| 规格 | 说明 |
|---|---|
| 时间窗切换 | `近8h` `今日` `昨日` `近7天` `近30天` segmented 按钮（对齐现有 API 支持） |
| 主系列 | 综合评分（实线，2px 粗） |
| 辅系列 | 平稳率/快速率/准确率（虚线，1px 细），图例可点击 toggle 显隐 |
| Y 轴 | 0-100 |
| X 轴 | 日期（按日聚合） |
| 默认 | 全厂综合评分趋势（近 30 天） |
| 联动 | 选中装置/单元后切换为该节点数据 |
| 底部 | 显示当前选中范围（如"选中: 1#装置 · 近30天"） |

**数据来源**：`GET /nodes/{nodeId}/trend?start=&end=`（装置/单元级）；全厂级用 `GET /dashboard/board/trend?timeWindow=`

### 2.3 布局尺寸分配（1920×1080，精确像素预算）

| 区 | 宽度 | 高度 | 像素 | 说明 |
|---|---|---|---|---|
| 浏览器页头 | 100% | ~60px | — | 应用导航（固定） |
| §1 卡片区 | 100% | ~100px | 100 | 7 卡片横排 + Pie 缩略图 + 状态指示 |
| 区域间距 | — | ~8px | 8 | §1 与三列之间 |
| §2 装置排名 | ~28%（~520px） | ~540px | 540 | 左列 |
| §3 单元排名 | ~42%（~806px） | ~540px | 540 | 中列（最宽，给帕累托图） |
| §4 重点回路 | ~30%（~574px） | ~540px | 540 | 右列 |
| 区域间距 | — | ~8px | 8 | 三列与趋势区之间 |
| §5 趋势区 | 100% | ~330px | 330 | 底部全宽 |
| 页面底部内边距 | — | ~12px | 12 | 确保不溢出 |
| **合计** | — | **~1058px** | **1058** | + 60px 页头 = 1118px → 超出 1080px 约 38px |

> **精确调整策略**：三列高度 540px + 趋势区 330px + 卡片区 100px + 间距 16px + 页头 60px = 1046px（不含底部内边距）。剩余 34px 分配给底部内边距和组件内部 padding。**如果实际渲染后仍超出**，可通过以下策略调整：① 三列内部行高从 38px 压缩至 34px（-4px × N 行）；② 趋势区 Y 轴 padding 从 40px 压缩至 24px；③ 卡片区内部 padding 压缩。

## 3. 交互流程

### 3.1 页面加载（默认全厂）

```
页面加载
  → §1: 全厂 KPI + Pie 分布 + 状态指示
  → §2: 全厂装置排名（按评分降序）
  → §3: 全厂单元排名（帕累托，按评分降序）
  → §4: 全厂评分最低 10 回路
  → §5: 全厂综合评分趋势（近 30 天）
```

### 3.2 选中装置

```
点击 §2 某装置行
  → §2: 该装置行高亮（背景色 + 左侧色条）
  → §3: 无变化（单元排名始终全厂层级）
  → §4: 切换为该装置下评分最低 10 回路
  → §5: 切换为该装置的综合评分趋势
  → §2/§4/§5 底部显示"选中: X#装置"
```

### 3.3 选中单元

```
点击 §3 某单元柱
  → §3: 该柱高亮
  → §2: 无变化（装置排名始终全厂层级）
  → §4: 切换为该单元下评分最低 10 回路
  → §5: 切换为该单元的综合评分趋势
  → §3/§4/§5 底部显示"选中: 单元X"
```

### 3.4 清除选择

```
点击"清除选择"按钮（§2/§3/§4/§5 底部）
  → §2/§3: 取消高亮
  → §4: 恢复为全厂评分最低 10 回路
  → §5: 恢复为全厂综合评分趋势
```

### 3.5 时间窗切换

```
点击 §5 时间窗按钮（近8h/今日/昨日/近7天/近30天）
  → §5: 趋势图按新时间窗重新加载
  → §1 卡片区不变化（卡片区时间窗独立于趋势区）
```

### 3.6 重点回路切换

```
点击 §4 dropdown（评分最低10 ↔ 评分最高10）
  → §4: 列表刷新为选中范围下评分最高/最低 10 个回路
```

### 3.7 回路下钻

```
点击 §4 某回路行
  → 跳转回路工作台 /monitor/loop-workbench?loopId=xxx&from=overview
```

## 4. 与评估总览的分工边界

| 维度 | 系统概览（本页） | 评估总览（评估模块） |
|---|---|---|
| 模块归属 | 监控 | 评估 |
| 视角 | 运维快照 | 深度分析 |
| 核心问题 | "好不好？哪里差？" | "为什么？怎么改？" |
| 评分呈现 | 一个快照值 + 排名对比 | 评分构成分解 + 逐指标评价 |
| 趋势 | 近期演变（8h/今日/昨日/7天/30天） | 多周期对比（月环比/同比） |

## 7. API 数据端口清单

| # | 页面元素 | API 端点 | 说明 |
|---|---|---|---|
| 1 | §1 综合评分/三率/回路统计 | `GET /dashboard/board/aggregate?timeWindow=` | 全厂级聚合（不传 plantId 时返回全厂根节点聚合） |
| 2 | §1 自动投用率 | `GET /dashboard/auto-rate-rt` | 实时口径 |
| 3 | §1 等级分布 Pie | `GET /nodes/overview` → `statusDistribution` | 全厂五档计数 |
| 4 | §1 状态指示 | `GET /datasource/health` | 数据源健康检查 |
| 5 | §2 装置排名 | `GET /nodes/ranking?nodeType=FACTORY&sortBy=score&sortOrder=desc&limit=50&timeWindow=` | **一次调用返回所有装置排名**（含 score/steadyRate/accuracyRate/fastResponseRate/loopCount） |
| 6 | §3 单元排名 | `GET /nodes/ranking?nodeType=UNIT&sortBy=score&sortOrder=desc&limit=200&timeWindow=` | **一次调用返回所有单元排名**（同上字段） |
| 7 | §4 重点回路 | `GET /performance/ranking?plantNodeId=&timeWindow=&limit=10&sortBy=score&sortOrder=[asc/desc]` | `plantNodeId` 随选中项变化；全厂时不传 |
| 8 | §5 趋势图 | 装置/单元：`GET /nodes/{nodeId}/trend?start=&end=`；全厂：`GET /dashboard/board/trend?timeWindow=` | 选中节点趋势 |

> **API 可行性验证结论**：§2 和 §3 使用 `nodes/ranking?nodeType=` 可一次返回全装置/全单元排名，无需多次 `board/aggregate` 调用。`nodes/ranking` 返回字段包含 `score`、`steadyRate`、`accuracyRate`、`fastResponseRate`、`autoModeRate`、`loopCount`、`status`，满足图表需求。**时间窗限制**：`nodes/ranking` 支持 `last_8_hours`/`today`/`yesterday`/`last_7_days`/`last_30_days`，不支持 `last_10_days`/`last_90_days`（如需扩展需改 `_parse_time_window` 函数）。
