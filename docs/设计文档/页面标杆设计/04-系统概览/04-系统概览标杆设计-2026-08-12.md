## 0. 现状诊断（"待办门户"不是"概览"）

现有页面 441 行，由 5 个接口的待办计数 + 预测卡 + 链路健康卡 + 两个聚合卡 + 一个入口卡拼成。对照 IA 体检 §3.1 与验证形态表，问题：

1. **回答错了问题**：页面回答"各模块积压了多少待办"（面向系统模块），而不是"全厂装置哪里有问题、今天先干什么"（面向生产对象）。KpiStrip 的五个计数（诊断/跟踪/验证/评估/整定）把用户引向五个模块页面——**这是导航，不是概览；导航是菜单的职责**（IA 体检 §3.1 降格条款）。
2. **没有"面"**：全厂装置健康矩阵完全缺失。工业产品的首页即"对象 + 状态热度"，用户 3 秒内应看到热点装置；现在首屏没有任何装置/单元维度信息。
3. **没有"例外"**：03 关注队列已经建成统一例外分诊台，但概览页没有它的投影——用户必须自己想到去点关注队列。"今日例外 Top-N"应主动出现在首屏右联。
4. **运维状态占据首屏**：数据链路健康（实时订阅/网络模式/Tailscale）是运维视角，正常运行时占据首屏一整卡片是浪费；异常才需要展开（降格为页头指示灯）。
5. **入口卡占位**："装置性能"入口卡只有一个按钮和一段说明文字——no-op 级别的内容占位，取消。
6. **保留项**：待办计数并非全无价值——它回答"我的工作积压"，但应降格为次要区域（R3 横向窄条），不再是首屏主角；ClpmPredictionCard（异常预测 Top10）与右联"今日例外"语义重叠，**合并进右联**（预测=未来的例外，例外=当下的例外，同一队列不同时间轴，统一由关注队列口径承载，避免两个"需关注"清单互相打架）。

### 2.3 关键设计决策

1. **双联是本页的第一决策**：左联回答"哪里有问题"（面，对象维度），右联回答"先干什么"（例外，行动维度）——这是 IA 体检 §3.1 的原话，也是 HiaMonitor/Loop Scout 类产品的收敛形态。现有"待办门户"把两个问题都答错了：它按系统模块组织，而仪控工程师按生产对象思考。
2. **右联不新建任何接口**：`/monitor/attention?pageSize=10` 的服务端分诊排序（优先级→阶段→时间）天然就是 Top-N 语义；03 刚完成的标杆使本联成为"投影"而非"新功能"。**例外只有一个权威来源**——这避免了两处清单口径漂移（IA 体检 §3.1：右联是"派生投影"）。
3. **左联复用节点级聚合体系**：`kpi_node_snapshot_hourly`（GB/T 44693.2-2024 §6.4 递归加权聚合）+ `/nodes/overview` 已提供全部所需字段，**这是后端已建好、前端没用上的典型**（与 01 的 FP-P0 教训同类：后端已对、前端没接）。
4. **热度排序即观点**：左联按评分升序（最差在前），与 02 默认排序同一产品观点；右联按服务端分诊规则。本页不提供任何排序/筛选控件——概览的职责是"已经替你排好"。
5. **运维状态降格**：链路健康四格卡 → 页头指示灯。正常运行时一个绿点；异常时红点 + 点击展开原详情（现有 ClpmDataCanvas 内容移入展开面板，组件逻辑保留）。SPONSOR 不需要知道 Tailscale 是什么。
6. **待办计数降格不降功能**：五个计数 + 角色差异 + 零值中性 + 失败容忍（P1-023）全部保留，但从首屏主角降为 R3 窄条——它回答"我的工作积压"，是第三优先级问题（面 → 例外 → 我的积压）。
7. **角色化通过密度表达**：SPONSOR 默认只看双联（R3 整定 chip 不可见、例外主动作只读化——03 服务端已按角色生成动作，本页直渲染即可）；工程师角色看到完整 R3。**不做两套页面**。
8. **两联口径分别标注**：左联=KPI 快照口径（B 类，时间窗四档），右联=实时聚合口径（03 同口径）——R-A 要求口径差异显性，防止用户以为右联也受时间窗影响。

## 4. 走查剧本（验收依据）

**S1 厂长晨会（SPONSOR，主场景）**

**S2 工程师下钻（IC）**
