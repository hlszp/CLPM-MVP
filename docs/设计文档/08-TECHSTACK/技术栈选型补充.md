## 1. 文档信息

### 1.1 文档目的

本文档对 ADS v3.0 中的关键技术选型进行补充说明，明确原型阶段与正式开发阶段的技术栈差异，定义前后端、数据库、工具链的最终选型与版本要求，作为开发团队技术实施的统一依据。

### 1.2 设计依据

| 文档 | 版本 | 用途 |
|---|---|---|
| PRD | v3.0 | 产品需求与功能边界 |
| ADS | v3.0 | 架构分层、服务划分、技术选型基线 |

### 1.3 适用范围

本文档适用于 CLPM 系统 Phase 1（MVP）及后续版本的正式开发阶段。原型阶段（React 19 验证）的技术选型仅作为参考对照。

## 2. 技术栈总览

### 2.1 原型阶段 vs 正式开发阶段对比

| 技术领域 | 原型阶段 | 正式开发阶段 | 变更说明 |
|---|---|---|---|

| 后端框架 | （原型无后端） | Python FastAPI | 对齐 ADS v3.0 |
| ORM | - | SQLAlchemy 2.0 + Alembic | |
| 认证方案 | Mock | JWT + bcrypt | |
| 时序数据访问 | Mock 数据 | taospy（TDengine Python 客户端） | |
| 缓存 | - | Redis + aioredis | |

### 2.2 选型变更核心理由

原型阶段使用 React 19 验证交互逻辑与界面设计，正式开发阶段切换至 vue-vben-admin 的核心理由：

1. **企业级开箱即用**：vue-vben-admin 内置权限管理、路由守卫、布局系统、菜单配置，省去大量基础架构开发工作
2. **活跃社区与维护**：GitHub 18k+ Star，持续更新，问题响应及时
3. **技术栈对齐**：Vue 3 + Vite + TypeScript + Ant Design Vue + Pinia 是当前企业级后台管理系统的主流技术栈
4. **原型可复用**：原型的交互逻辑、页面结构、Mock 数据结构可直接迁移，仅组件语法从 React 转为 Vue

### 3.4 HTTP 客户端：Axios

| 项目 | 说明 |
|---|---|
| HTTP 客户端 | Axios 1.x |
| 选型理由 | 拦截器机制成熟；请求/响应统一处理；取消请求；并发请求支持；对齐 IDS 统一响应规范 |

**统一拦截器配置**：

```typescript
// 请求拦截器：统一注入 Token
axiosInstance.interceptors.request.use((config) => {
  const token = useUserStore().token;
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// 响应拦截器：对齐 IDS 统一响应规范
axiosInstance.interceptors.response.use(
  (response) => {
    const { code, data, message } = response.data;
    if (code === 0) {
      return data;  // 业务成功，直接返回 data
    }
    // 业务错误，统一提示
    message.error(message);
    return Promise.reject(new Error(message));
  },
  (error) => {
    if (error.response?.status === 401) {
      // Token 过期，跳转登录
      useUserStore().logout();
    }
    return Promise.reject(error);
  }
);
```

**对齐 IDS 统一响应规范**：

```typescript
interface ApiResponse<T> {
  code: number;       // 0 表示成功，非 0 表示业务错误
  message: string;    // 提示信息
  data: T;            // 业务数据
  timestamp: number;  // 服务器时间戳
}
```

### 4.2 ORM：SQLAlchemy 2.0 + Alembic

| 项目 | 说明 |
|---|---|
| ORM | SQLAlchemy 2.0 |
| 迁移工具 | Alembic 1.13+ |
| 选型理由 | SQLAlchemy 2.0 提供类型安全的全新 API；Alembic 支持自动生成迁移脚本；Python 生态最成熟的 ORM 方案 |

**SQLAlchemy 2.0 使用要点**：

- 采用 `Declarative Base` + `Mapped` 类型注解
- 异步引擎 `create_async_engine` + `AsyncSession`
- 连接池配置：`pool_size`、`max_overflow`、`pool_pre_ping`

**Alembic 迁移规范**：

- 每次模型变更生成独立迁移脚本
- 迁移脚本必须包含 `upgrade` 与 `downgrade`
- 生产环境迁移前必须备份数据库
- 大表 DDL 拆分执行，避免锁表

### 4.3 认证：JWT + bcrypt

| 项目 | 说明 |
|---|---|
| JWT 库 | python-jose 3.x |
| 密码哈希 | bcrypt 4.x |
| 选型理由 | python-jose 支持多种算法；bcrypt 是工业级密码哈希方案；FastAPI 官方文档推荐组合 |

**认证流程**：

```text
1. 用户登录 → 校验账号密码（bcrypt 验证）
2. 签发 Access Token（JWT，有效期 1 小时）+ Refresh Token（有效期 7 天）
3. 前端存储 Token（localStorage），后续请求注入 Authorization: Bearer <token>
4. Token 过期 → 使用 Refresh Token 换取新 Access Token
5. Refresh Token 过期 → 重新登录
```

**JWT Payload 规范**：

```json
{
  "sub": "user_id",           // 用户 ID
  "roles": ["admin"],         // 角色列表
  "exp": 1718985600,          // 过期时间
  "iat": 1718982000,          // 签发时间
  "jti": "unique_token_id"    // Token 唯一标识（用于黑名单）
}
```

### 4.6 任务调度：Celery + Redis

| 项目 | 说明 |
|---|---|
| 任务队列 | Celery 5.x |
| Broker / Backend | Redis 7.x |
| 选型理由 | Python 生态最成熟的异步任务队列；支持定时任务（Celery Beat）；任务重试与幂等；监控工具完善（Flower） |

**任务规划**：

| 任务类型 | 队列 | 触发方式 | 并发数 | 说明 |
|---|---|---|---|---|
| 性能指标计算 | `metric` | Celery Beat 定时（每小时） | 10 | 1200+ 回路 KPI 计算 |
| 诊断任务 | `diagnosis` | 事件触发（评分跌破阈值） | 5 | FFT 分析、模型拟合 |
| 报表生成 | `report` | Celery Beat 定时（班/日/周/月） | 2 | PDF 报表渲染 |
| AAS 同步 | `aas_sync` | Celery Beat 定时（5 分钟） | 1 | Tag 位号同步 |
| 数据回补 | `backfill` | 手动触发 | 5 | 历史数据补算 |

**幂等性设计**：
- 每个任务携带 `task_id` + `loop_id` + `time_window` 作为幂等键
- 任务执行前检查 Redis 是否已存在相同幂等键的结果
- 任务失败自动重试（最多 3 次），重试间隔指数退避

## 5. 数据库环境

### 5.1 本地开发环境：Orbstack 虚拟化

本地开发强制使用 Orbstack 作为容器运行环境，部署 PostgreSQL、TDengine、Redis 三类基础设施容器。

#### 5.1.1 容器配置

| 容器 | 镜像 | 端口映射 | 数据卷 | 说明 |
|---|---|---|---|---|
| PostgreSQL | `postgres:16` | 5432:5432 | `pg_data:/var/lib/postgresql/data` | 关系型业务数据 |
| TDengine | `tdengine/tdengine:3.x` | 6030:6030, 6041:6041 | `td_data:/var/lib/taos` | 时序数据 |
| Redis | `redis:7` | 6379:6379 | `redis_data:/data` | 缓存与队列 |

#### 5.1.2 docker-compose.yml 示例配置

```yaml
version: '3.8'

services:
  postgresql:
    image: postgres:16
    container_name: clpm-postgresql
    restart: unless-stopped
    environment:
      POSTGRES_DB: clpm_db
      POSTGRES_USER: clpm_user
      POSTGRES_PASSWORD: clpm_dev_password
      TZ: Asia/Shanghai
    ports:
      - "5432:5432"
    volumes:
      - pg_data:/var/lib/postgresql/data
      - ./deploy/sql/postgresql:/docker-entrypoint-initdb.d:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U clpm_user -d clpm_db"]
      interval: 10s
      timeout: 5s
      retries: 5

  tdengine:
    image: tdengine/tdengine:3.3.0.0
    container_name: clpm-tdengine
    restart: unless-stopped
    environment:
      TZ: Asia/Shanghai
    ports:
      - "6030:6030"
      - "6041:6041"
    volumes:
      - td_data:/var/lib/taos
      - ./deploy/sql/tdengine:/init-scripts:ro
    healthcheck:
      test: ["CMD", "taos", "-s", "SELECT server_version()"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7
    container_name: clpm-redis
    restart: unless-stopped
    command: redis-server --requirepass clpm_dev_password --appendonly yes
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "clpm_dev_password", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  pg_data:
  td_data:
  redis_data:
```

### 6.3 Git 工作流

采用 Git Flow 分支模型，规范团队协作。

#### 6.3.1 分支模型

| 分支 | 命名规范 | 来源 | 合并目标 | 说明 |
|---|---|---|---|---|
| `main` | - | - | - | 生产环境稳定版本，受保护 |
| `develop` | - | `main` | - | 开发集成分支，最新功能 |
| `feature/*` | `feature/<issue-id>-<short-desc>` | `develop` | `develop` | 功能开发分支 |
| `release/*` | `release/<version>` | `develop` | `main` + `develop` | 发布准备分支 |
| `hotfix/*` | `hotfix/<issue-id>-<short-desc>` | `main` | `main` + `develop` | 生产紧急修复 |

#### 6.3.2 分支流转示例

```text
main ──────────────────────────────────────────────●─────────●─── (生产)
      │                                             ↑         ↑
      │                                             │         │
      │                                          release/*  hotfix/*
      │                                             │         │
      └─●─────────────●─────────────●───────────────●─────────develop (集成)
                     │             │
                     │             │
                  feature/A     feature/B
```

#### 6.3.3 Commit 规范

采用 Conventional Commits 规范：

```text
<type>(<scope>): <subject>

<body>

<footer>
```

**Type 清单**：

| Type | 说明 |
|---|---|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档变更 |
| `style` | 代码格式（不影响功能） |
| `refactor` | 重构（非新增功能、非修复 Bug） |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具/依赖变更 |

**示例**：

```text
feat(loop): 支持回路 Tag 关联批量导入

- 新增批量导入 API
- 支持 Excel 模板下载
- 导入失败行号定位

Closes #123
```

#### 6.3.4 Code Review 规范

- 所有 PR 必须至少 1 名团队成员 Review 通过方可合并
- PR 必须通过 CI 检查（lint + test + build）
- PR 描述需包含：变更说明、测试方式、影响范围
- 禁止直接推送至 `main` 与 `develop` 分支

### 6.4 CI/CD：GitHub Actions

使用 GitHub Actions 实现 lint + test + build + deploy 全流程自动化。

#### 6.4.1 CI 流程

```yaml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

jobs:
  frontend-ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm run lint
      - run: pnpm run typecheck
      - run: pnpm run build

  backend-ci:
    runs-on: ubuntu-latest
    services:
      postgresql:
        image: postgres:16
        env:
          POSTGRES_PASSWORD: test
        ports: [5432:5432]
      redis:
        image: redis:7
        ports: [6379:6379]
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v3
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: uv sync --frozen
      - run: uv run ruff check .
      - run: uv run ruff format --check .
      - run: uv run pytest
```

#### 6.4.2 CD 流程

| 环境 | 触发条件 | 部署方式 | 审批 |
|---|---|---|---|
| 开发环境 | 推送至 `develop` | 自动部署 Docker Compose | 否 |
| 测试环境 | 推送至 `release/*` | 自动部署 Docker Compose | 否 |
| 生产环境 | 推送至 `main` + 打 Tag | Helm 部署 K8s | 是（人工审批） |

#### 6.4.3 镜像构建与推送

```yaml
- name: Build and push Docker image
  uses: docker/build-push-action@v5
  with:
    context: .
    file: ./deploy/docker/backend.Dockerfile
    push: true
    tags: |
      ghcr.io/${{ github.repository }}/backend:${{ github.sha }}
      ghcr.io/${{ github.repository }}/backend:latest
```
