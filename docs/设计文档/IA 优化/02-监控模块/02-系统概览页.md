## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

仪控工程师上班第一件事是**"今天有什么需要关注的？"**。系统概览页应回答：

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 有多少待处理诊断？ | KpiStrip "诊断待处理" 卡片 | ✅ |
| 有多少异常跟踪待办？ | KpiStrip "异常跟踪待办" 卡片 | ✅ |
| 有多少验证超期？ | KpiStrip "验证超期" 卡片（C1-3） | ✅ |
| 有多少评估待执行？ | KpiStrip "评估待执行" 卡片 | ✅ |
| 有多少整定任务？ | KpiStrip "整定任务" 卡片（角色化） | ✅ |
| 数据链路是否正常？ | 链路健康卡（SignalR/网络模式/最近同步） | ✅ |
| 哪些回路可能出问题？ | PredictionCard Top10 异常预测 | ✅ |
| 整改效果怎么样？ | TrackerEffectivenessCard 整改有效率 | ✅ |

### 3.2 范式级评估

**优点**：
- 待办门户定位准确，回答了"今天有什么需要关注的"核心问题
- 非零优先排序（A-12）符合"异常优先"原则——有待办时待办在前，无待办时全部中性
- 零值中性（A-03）符合工业设计"零待办是好状态"语义

**不足**：
- 概览页是"跨回路总览"视角，但缺少"单回路深度"入口——用户看到"诊断待处理 5 条"后，需点击跳转到诊断任务页，不能在概览页直接看到是哪 5 条
- PredictionCard 展示 Top10 异常预测回路，但回路位号是否接入 LoopLink 快捷跳转待确认（F-CTX-003 相关）

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-OVW-001 | **概览页缺少待办项的快速预览（Top 3）** | P2 | KpiStrip 只显示计数，用户需点击跳转才能看到具体待办。可在卡片下方增加 Top 3 待办预览（位号+标签），减少一次跳转。 |
| F-OVW-002 | **PredictionCard 回路位号未接入 LoopLink** | P3 | 异常预测回路位号应支持快捷跳转诊断/整定（F-CTX-003 相关） |

## 10. 结论

系统概览页是 CLPM **设计最成熟的页面之一**（3.39/4.0），跨模块待办门户定位准确、KpiStrip 跳转链路清晰、角色化适配到位、非零优先排序 + 零值中性符合工业设计原则。A-03/A-12/P1-023/BL-3 等整改项均闭环。

**核心建议**：
1. **短期**：KpiStrip 增加 Top3 待办预览（2 天，减少跳转成本最高）
2. **中期**：随双架构路径 B，概览页作为驾驶舱模式核心页面，增加 AI 结论卡片（前台给结论）
3. 系统概览页是**驾驶舱模式的最佳起点**——已有待办门户基础，只需增加模式切换和简化视图
