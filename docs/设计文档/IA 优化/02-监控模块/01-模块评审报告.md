## 1. 执行摘要

监控模块是 CLPM 的**运行驾驶舱与单回路处置入口**，承担跨回路扫视、预警结果与单回路闭环处置三大职能。经过 MW-P0~P5 闭环整改，该模块在**技术实现与交互完整度上已达全站最高水平**——统一关注队列五来源聚合、回路工作台单页四区重构、区级延迟加载、五角色冒烟全绿。但从第一性原理看，**4 页面认知层次不同却归入同一菜单**，且关注队列与回路工作台的职能边界需进一步显式化。

**模块评分：3.0 / 4.0 — 良好（实现优秀，范式有优化空间）**

## 3. 模块架构分析

### 3.1 当前结构

```
监控（order:1，实体轴 + 运行驾驶舱）
├─ 系统概览 /dashboard/workbench        — 跨模块待办门户（KpiStrip + 链路健康 + 诊断/跟踪卡）
├─ 回路工作台 /monitor/loop-workbench    — 单回路四区闭环（监控/评估/诊断/整定概况）
├─ 关注队列 /monitor/attention           — 五来源聚合待办（ALERT/DEGRADATION/DATA_QUALITY/TRACKER/VERIFICATION）
├─ 预警事件 /monitor/alerts              — 预警结果列表（历史/审计/导出）
├─ [隐藏] 回路实时表格 /loop/monitor      — 重定向到工作台 table 模式
└─ [隐藏] 旧版实时表格 /loop/monitor/legacy — 旧组件保留兼容
```

### 3.2 四页面认知层次分析

| 页面 | 认知层次 | 视角 | 用户任务 |
|---|---|---|---|
| 系统概览 | 全厂视角 | 跨回路总览 | "今天有什么需要关注的？" |
| 回路工作台 | 单回路视角 | 单回路深度处置 | "这个回路怎么了？怎么处置？" |
| 关注队列 | 行动视角 | 跨回路优先级排序 | "先处理哪个？下一步做什么？" |
| 预警事件 | 结果视角 | 历史异常追溯 | "之前发生了什么？已处理了什么？" |

**范式级发现**：4 页面认知层次不同（全厂/单回路/行动/结果），归入同一"监控"菜单是**按数据流向归类**。系统概览和关注队列更偏"驾驶舱"（跨回路总览+行动），回路工作台更偏"工作站"（单回路深度），预警事件偏"审计"（历史追溯）。

## 4. 第一性原理评估（视角一）

### 4.1 监控模块的本质职能

从第一性原理看，监控模块应解决**"早发现"** 这一核心问题：

| 本质要求 | 当前覆盖 | 覆盖方式 | 范式评估 |
|---|---|---|---|
| 实时状态可见 | ✅ | 回路工作台 PV/SP/OP 实时趋势 + WS 指示 | 良好 |
| 异常早期发现 | ✅ | 关注队列五来源聚合 + DayDeltaBadge 增量徽标 | 良好 |
| 优先级排序 | ✅ | 关注队列四级优先级（URGENT/HIGH/MEDIUM/LOW） | 良好 |
| 跨回路扫视 | ✅ | 系统概览 KpiStrip + 回路工作台左栏列表 | 良好 |
| 单回路深度 | ✅ | 回路工作台单页四区 | 良好 |
| 预警实时推送 | ✅ | 通知铃铛接 /ws/alerts + 预警事件页 | 良好 |

### 4.2 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-MON-001 | **4 页面认知层次不同却归入同一菜单** | 范式级 P2 | 系统概览/关注队列=驾驶舱（跨回路），回路工作台=工作站（单回路），预警事件=审计。双架构路径 B 可分层。 |
| F-MON-002 | **关注队列与回路工作台职能边界需显式化** | P2 | 关注队列=跨回路优先级排序（先做哪个），工作台=单回路深度处置（怎么做）。当前两者都有"回路"维度，用户可能困惑。 |
| F-MON-003 | **预警事件与关注队列的预警来源有重叠** | P3 | 关注队列 ALERT 来源 = 活跃预警，预警事件页也展示活跃预警。需明确：关注队列=待办行动，预警事件=全量历史。 |

## 10. 结论

监控模块是 CLPM **实现完整度最高的模块**（3.0/4.0），MW-P0~P5 闭环整改后，统一关注队列、回路工作台单页四区、区级延迟加载、五角色冒烟全绿、性能压测达标、视觉走查 WCAG AA 100%——**技术实现层面已达优秀水平**。

但从第一性原理看，**4 页面认知层次不同却归入同一菜单**（F-MON-001），系统概览和关注队列偏"驾驶舱"（跨回路总览+行动），回路工作台偏"工作站"（单回路深度），预警事件偏"审计"（历史追溯）。双架构路径 B 可根本解决——驾驶舱模式承载概览+关注队列+预警，工作站模式承载回路工作台。

**核心建议**：
1. **短期**：显式化关注队列与工作台职责边界（3 天）、W-8/9/10 遗留修复（2 天）
2. **中期**：随双架构路径 B 实现监控模块分层
3. 监控模块是双架构路径 B 的**最佳试点模块**——4 页面天然适合驾驶舱/工作站分层，可先行验证
