## 1. 页面定位与核心价值

### 1.1 定位

回路工作台是 CLPM **实体轴的核心页面**——单回路 360° 一站式处置入口。采用 master-detail 布局（左侧回路列表 + 右侧单页四区），在同一页面内聚合监控、评估、诊断、整定四个模块的概况，用户无需跨模块跳转即可完成 80% 的单回路处置任务。

### 1.2 核心价值

| 价值 | 实现 | 评估 |
|---|---|---|
| 单回路全景 | 四区垂直布局（概览/评估/诊断/整定） | ✅ |
| 减少跨模块跳转 | 一页内一览概况 + 直接发起任务 | ✅ |
| 实时反写 | 任务完成后区内容即时更新 | ✅ |
| 详情走弹窗 | 趋势/诊断详情/整定详情弹窗化 | ✅ |
| 跨回路扫视 | 左栏回路列表 + 增量徽标 | ✅ |

### 1.3 四区布局

```
┌──────────┬──────────────────────────────────────────┐
│ 左栏      │ ① 回路概览（自适应高度）                    │
│ 回路列表  │   位号/名称/量程/控制方式/设定值/实时值/健康度│
│ +增量徽标 │ ├──────────────────────────────────────────┤
│ +排序     │ ② 性能评估（30%）                          │
│          │   12 大指标卡片（50%）+ 评分趋势图（50%）    │

│          │ ③ 回路诊断（30%）                          │
│          │   诊断标签+置信度卡片（50%）+ PV/OP·FFT（50%）│
│          │ ├──────────────────────────────────────────┤
│          │ ④ 回路整定（30%）                          │
```

## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

IC_ENGINEER 处置单个回路时的核心需求：

| 需求 | 回答方式 | 当前实现 |
|---|---|---|
| 这个回路现在状态怎么样？ | ① 概览区：实时值 + 数据健康度 | ✅ |
| 性能评估结果如何？ | ② 评估区：12 指标 + 评分趋势 | ✅ |
| 有什么诊断问题？ | ③ 诊断区：标签 + 置信度 + FFT | ✅ |
| 需要整定吗？当前 PID 是什么？ | ④ 整定区：当前 PID + 推荐 PID | ✅ |
| 怎么发起处置？ | 四区内联按钮（辨识/整定/仿真/诊断） | ✅ |
| 切换回路查看？ | 左栏列表 + 增量徽标 + 搜索 | ✅ |

### 3.2 范式级评估

**优点（范式级最佳实践）**：
1. **实体轴聚合度高**——四区聚合监控/评估/诊断/整定概况，80% 处置任务在页内完成，减少跨模块跳转
2. **master-detail + fullPathKey=false**——切换回路仅 router.replace 更新 query，不新增 tab/面包屑，是全站范本级最佳实践
3. **区级延迟加载**——MW-P4-04 实现，切换回路时按区独立加载，避免全屏 spinner
4. **workspace/table 双模式**——workspace 模式（单回路四区）vs table 模式（高密度回路表），EXPERT 强制 workspace（canUseTableView 守卫）

**不足**：
1. **深度操作仍需跳转**——四区只展示概况，深度操作（诊断详情、整定详情）需弹窗或跳转。F-IA-003 建议提升聚合度，深度操作弹窗化
2. **W-10 回路切换请求风暴**——每次切换触发 4 路并行 + 72h 快照分页全量拉取，27 回路巡检连点时请求风暴

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-WB-001 | **实体轴聚合度高但深度操作仍需跳转** | 范式级 P2 | 四区聚合概况有效，但诊断详情/整定详情仍需弹窗或跳转。可进一步提升聚合度——深度操作弹窗化，减少跳转。对应 F-IA-003。 |
| F-WB-002 | **回路切换请求风暴未根治** | P2 | W-10 遗留：每次切换 4 路并行 + 72h 快照分页全量拉取。快照接口应加 limit/降采样参数。 |
| F-WB-003 | **当前 PID vs 推荐 PID 对比呈现偏弱** | P3 | 整定区左右分栏但无并排 diff 感，Phase 3 可考虑双列对照表。已有评估已记录。 |

## 9. 双架构归属标注

| 元素 | 驾驶舱模式 | 工作站模式 | 理由 |
|---|---|---|---|
| 左栏回路列表 | ✅ 简化（仅异常+增量徽标） | ✅ 完整（全回路+搜索+排序） | 驾驶舱看异常，工作站看全量 |
| ① 概览区 | ✅ 简化（5 字段：位号/名称/实时值/健康度/模式） | ✅ 完整（7 字段） | 驾驶舱低密度，工作站高密度 |
| ② 评估区 | 🔶 只读趋势 + AI 结论 | ✅ 完整（12 指标 + 趋势 + 发起评估） | 驾驶舱看结论，工作站看过程 |
| ③ 诊断区 | 🔶 只读标签 + AI 解读 | ✅ 完整（标签 + FFT + 发起诊断） | 驾驶舱看结论，工作站看证据 |
| ④ 整定区 | ❌ 隐藏（驾驶舱无整定） | ✅ 完整（当前 PID + 推荐 + 辨识/整定/仿真） | 整定是工作站专属高危操作 |
| workspace/table 双模式 | ❌ 驾驶舱仅 workspace | ✅ 工作站双模式 | EXPERT 强制 workspace 是雏形 |

**关键洞察**：回路工作台是**双架构路径 B 的最佳试点页面**——四区天然适合驾驶舱/工作站分层：
- 驾驶舱模式：概览（简化）+ 评估（只读+AI结论）+ 诊断（只读+AI解读），隐藏整定区
- 工作站模式：四区完整 + table 模式 + 深度操作弹窗

当前 EXPERT 强制 workspace 模式（canUseTableView = false）已是这一分层的雏形——**权限 → 认知匹配**的初步尝试。

## 10. 结论

回路工作台是 CLPM **实体轴的核心页面**（3.27/4.0），单页四区聚合监控/评估/诊断/整定概况，80% 处置任务在页内完成。master-detail + fullPathKey=false + router.replace 是全站范本级最佳实践，区级延迟加载、虚拟滚动、workspace/table 双模式均达标。W-1~W-7 已闭环，W-8/9/10 为遗留体验债。

**核心建议**：
1. **短期**：W-10 请求风暴根治（1 天）、W-8/9 遗留修复（1 天）
2. **中期**：深度操作弹窗化（2 周，减少跳转进一步提升聚合度）
3. **范式级**：回路工作台是双架构路径 B 的最佳试点——四区天然适合驾驶舱/工作站分层，EXPERT 强制 workspace 已是雏形，可扩展为完整的模式切换
4. 该页面是**实体轴聚合度的标杆**，其他模块的实体轴页面（如诊断详情、整定详情）应参考其 master-detail + 单页多区设计模式
