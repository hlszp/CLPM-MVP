## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 有哪些整定案例？ | 知识库条目表格 | ✅ |
| 按控制类型筛选？ | Select 下拉（FLOW/PRESSURE/TEMPERATURE/LEVEL/COMPOSITION） | ✅ |
| 按问题类型筛选？ | Select 下拉 | ✅ |
| 按算法筛选？ | Select 下拉（IMC/Lambda/ZN/SIMC/Cohen-Coon） | ✅ |
| 按效果筛选？ | Select 下拉 | ✅ |
| PID 参数怎么变的？ | PID 变化对比表（变更前/变更后） | ✅ |
| 效果改善了吗？ | KPI 改善明细（绿勾/红叉） | ✅ |

### 3.2 范式级评估

**优点**：
- 列设置持久化：usePagePreference('tuning-knowledge-base') 保存列配置到本地
- PID 变化对比表：变更前/变更后两列清晰展示，P/I/D 参数变化一目了然
- KPI 改善明细：绿勾/红叉图标直观展示每个指标的改善/恶化
- 控制类型选项对齐：FLOW/PRESSURE/TEMPERATURE/LEVEL/COMPOSITION 与 loopType 枚举一致
- 表格→抽屉的查看模式高效，不离开列表即可查看详情

**不足**：
- KPI 条计算范围：KPI 条基于当前页数据计算（recordList.value），而非全局统计。当翻页时 KPI 条会变化，可能误导用户
- 筛选条件布局：4 个 Select 横排（控制类型 120px + 问题类型 140px + 算法 120px + 效果 100px = 480px），在窄屏上可能折行
- 关联方式显示：matchSource 字段用 h() 自定义渲染，但模板中也有 matchSourceLabel 函数，存在重复
- 详情抽屉分区：4 个分区用 `<h3>` 标题分隔，但缺少视觉分隔线

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-KB-001 | **KPI 条计算范围** | P2 | KPI 条基于当前页 recordList 计算，翻页时变化，可能误导用户 |
| F-KB-002 | **筛选条件布局** | P2 | 4 个 Select 横排，窄屏折行 |
| F-KB-003 | **关联方式显示重复** | P3 | h() 自定义渲染 + matchSourceLabel 函数重复 |
| F-KB-004 | **详情抽屉视觉分隔** | P3 | 4 个分区缺 Card/Border 组件视觉分隔 |

## 10. 结论

整定知识库是**整定模块的经验沉淀中心**（3.24/4.0，B+），案例沉淀 + 多维度筛选 + PID 变化对比 + KPI 改善明细 + 列设置持久化的结构覆盖了整定经验复用的核心需求，技术实现专业。

**核心问题**是 KPI 条基于当前页数据而非全局统计（F-KB-001），翻页时 KPI 条变化可能误导用户；筛选条件布局在窄屏折行（F-KB-002）。

**核心建议**：
1. **短期**：KPI 条范围修正（0.5 天）+ 筛选条件 flex-wrap（0.5 天）
2. **中期**：随双架构路径 B，知识库的 KPI 统计和筛选适合驾驶舱/工作站分层——驾驶舱看全局统计和常用筛选，工作站做深度检索和案例查看
3. 整定知识库是**双架构路径 B 的经验层**——已有统计和检索基础，适合驾驶舱快速参考与工作站深度沉淀
