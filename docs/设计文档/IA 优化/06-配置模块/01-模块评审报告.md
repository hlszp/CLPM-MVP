## 1. 执行摘要

配置模块是 CLPM 的**架构基础设施**——回答"系统怎么连接、数据怎么组织、指标怎么计算、诊断怎么配置、预警怎么触发"。该模块以工程/操作分离为设计原则，将结构性配置（链路、指标、诊断、预警）集中管理，操作性调参保留在各业务页面。经过 IA 重构 Phase A（指标配置从各业务页迁入），该模块在**信息架构集中度与权限分层**上已有显著改善。

模块包含 7 个主页面，覆盖数据接入层（链路配置、数据源管理）、实体管理层（测点配置、回路配置）、算法配置层（指标配置、诊断配置、预警规则）三个维度。整体实现质量良好（3.47/4.0），其中预警规则页以 3.62 分成为最高分页面。但从第一性原理看，**Token 安全语义理解成本高**、**指标配置 Tab 数量过多**、**规则优先级缺少说明**等问题影响配置效率。

**模块评分：3.47 / 4.0 — 良好**

## 3. 模块架构分析

### 3.1 当前结构

```
/config (配置)
├── /config/link (链路配置)         ← ADMIN 独占
├── /config/tag (测点配置)          ← ADMIN/IC_ENGINEER/PE_ENGINEER
├── /config/loop (回路配置)         ← ADMIN/IC_ENGINEER/PE_ENGINEER
├── /config/datasource (数据源管理)  ← ADMIN/IC_ENGINEER/PE_ENGINEER
├── /config/metric (指标配置)       ← ADMIN 独占
├── /config/diagnosis (诊断配置)    ← ADMIN 独占
└── /config/alert-rules (预警规则)  ← ADMIN 独占
```

| 层级 | 页面 | 职能 | 权限 |

## 8. 结论

配置模块是 CLPM **架构基础设施模块**（3.47/4.0），以工程/操作分离为设计原则，7 个页面覆盖数据接入、实体管理、算法配置三个维度，ClpmDangerConfirmModal 统一危险操作、子组件独立拆分、权限分层设计等实现质量良好。**预警规则页以 3.62 分成为模块最高分页面**，其 ClpmAlertDslEditor 专用 DSL 可视化编辑器为亮点。

**核心短板**：
1. **Token 安全语义复杂**：用户理解成本高，影响配置效率
2. **指标配置 Tab 数量过多**：7 个 Tab 在中等屏幕上可能折行
3. **规则优先级缺少说明**：数值含义不明确

**核心建议**：
1. **短期**：Token 增加 Tooltip 说明（C-1）+ Tab 分组（C-4）+ 优先级 Tooltip（C-5）
2. **中期**：随双架构路径 B，配置模块整体偏向工作站模式，仅测点/回路/预警在驾驶舱有简化版需求
3. 配置模块是**双架构路径 B 的基础设施支撑**——所有驾驶舱/工作站的数据、指标、规则均依赖配置模块
