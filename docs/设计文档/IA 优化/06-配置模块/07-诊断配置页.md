## 1. 页面定位与核心价值

### 1.1 定位

诊断配置页是配置模块的**算法配置层——诊断标签管理**——管理 CLPM 智能诊断的诊断指标、算法参数和阈值。以表格→Modal 的经典 CRUD 模式，支持诊断指标的创建、编辑、启用/禁用、删除。

### 1.2 核心价值

| 价值 | 实现 | 评估 |
|---|---|---|
| 诊断指标管理 | 8 类诊断标签（振荡/阀门卡涩/积分饱和/异常响应等） | ✅ |
| 算法参数配置 | 算法类型 + 参数 + 阈值 + 启用开关 | ✅ |
| 标签颜色映射 | DIAGNOSIS_LABEL_COLOR_MAP 统一管理诊断标签颜色 | ✅ |
| 安全操作 | Switch 切换启用有 loading 态 + 危险操作二次确认 | ✅ |
| 密度切换 | useTableDensity 支持三档密度 | ✅ |

## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 有哪些诊断指标？ | 诊断指标列表表格 | ✅ |
| 诊断指标怎么配置？ | Modal 表单：算法类型/参数/阈值/启用开关 | ✅ |
| 怎么启用/禁用？ | Switch 切换 + loading 态 + 危险确认 | ✅ |
| 标签颜色？ | DIAGNOSIS_LABEL_COLOR_MAP 统一管理 | ✅ |
| 参数/阈值怎么编辑？ | 键值对数组编辑 | ✅ |

### 3.2 范式级评估

**优点**：
- 诊断指标是智能诊断的配置基础，8 类诊断标签覆盖主要故障模式
- DIAGNOSIS_LABEL_COLOR_MAP 统一管理诊断标签颜色，语义清晰（OSCILLATION 橙/VALVE_STICTION 红/INTEGRAL_WINDUP 紫/ABNORMAL_RESPONSE 黄等）
- Switch 切换启用有 `togglingId` 追踪当前正在切换的指标 ID，避免重复操作
- ClpmDangerConfirmModal 替代 Modal.confirm，危险操作二次确认
- 密度切换：`useTableDensity('diagnosis-config')` 支持三档密度

**不足**：
- 缺少创建入口：代码中未见"新增诊断指标"按钮，可能诊断指标由种子数据预置
- 参数/阈值编辑使用键值对数组，当条目多时操作繁琐
- 建议支持 JSON 批量导入导出参数和阈值

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-DIAG-001 | **缺少创建入口** | P3 | 诊断指标可能由种子数据预置，建议明确展示预置状态 |
| F-DIAG-002 | **参数/阈值编辑效率低** | P3 | 键值对数组编辑，建议支持 JSON 批量导入导出 |

## 10. 结论

诊断配置页是 CLPM **算法配置层的诊断标签管理页**（3.46/4.0），DIAGNOSIS_LABEL_COLOR_MAP 统一颜色映射、Switch loading 态防重复操作、ClpmDangerConfirmModal 统一危险确认、useTableDensity 密度切换等实现质量良好。

**核心问题**是缺少创建入口（F-DIAG-001）和参数/阈值编辑效率低（F-DIAG-002）。建议明确展示预置状态并支持 JSON 批量导入导出。

**核心建议**：
1. **短期**：明确展示预置/创建入口（0.5 天）
2. **中期**：参数/阈值支持 JSON 批量导入导出（1 天）
3. 诊断配置页是**纯管理配置页**，仅在工作站模式完整展示，驾驶舱模式不需要
