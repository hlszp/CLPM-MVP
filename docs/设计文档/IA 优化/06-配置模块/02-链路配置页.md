## 1. 页面定位与核心价值

### 1.1 定位

链路配置页是配置模块的**数据接入层核心**——管理 CLPM 与现场控制系统的连接链路。包括历史 API 配置、实时 SignalR 配置、网络模式切换（局域网/公网/Tailscale）、DCS 系统品牌型号管理、MODE 矩阵映射。

### 1.2 核心价值

| 价值 | 实现 | 评估 |
|---|---|---|
| 历史数据接入 | 历史 API URL + Token + 断点续传配置 | ✅ |
| 实时数据接入 | SignalR Hub URL + Token + 重连策略 | ✅ |
| 网络模式切换 | 局域网 / 公网 / Tailscale 三种模式 | ✅ |
| DCS 品牌管理 | 多品牌/型号 CRUD + 配置导入 | ✅ |
| MODE 矩阵 | MODE 映射矩阵 + MODE 定义编辑 | ✅ |
| 连接测试 | 历史 API 测试 + SignalR 测试 | ✅ |

## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 历史数据从哪来？ | 历史 API URL + Token 配置 | ✅ |
| 实时数据怎么传？ | SignalR Hub URL + 重连策略 | ✅ |
| 网络模式怎么选？ | 局域网/公网/Tailscale 切换 | ✅ |
| 多 DCS 品牌怎么管？ | 品牌/型号 CRUD + 配置导入 | ✅ |
| MODE 怎么映射？ | MODE 矩阵 + MODE 定义编辑 | ✅ |
| 连接通不通？ | 历史 API 测试 + SignalR 测试 | ✅ |

### 3.2 范式级评估

**优点**：
- 数据接入是系统基础，链路配置覆盖了历史数据和实时数据两条链路
- 网络模式切换支持局域网/公网/Tailscale 三种部署场景，灵活性高
- ClpmDangerConfirmModal 统一危险操作确认（网络切换、测试连接）
- Token 打码处理安全，GET 返回打码值不回填表单
- v-permission 守卫写操作按钮，对齐后端权限

**不足**：
- Token 安全语义复杂：GET 返回打码值不回填；留空=不变；输入新值=覆盖；勾选清空=传空串。用户理解成本高
- 网络模式切换是高危操作（瞬断实时链路），但缺少预检查（当前是否有实时订阅在运行）
- 默认 URL 硬编码为内网地址，建议移到环境变量

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-LINK-001 | **Token 安全语义理解成本高** | P2 | 四种状态（打码/不变/覆盖/清空）的组合策略复杂，建议增加 Tooltip 或帮助气泡 |
| F-LINK-002 | **网络模式切换缺预检查** | P2 | 切换网络模式可能瞬断实时链路，需预检查实时订阅状态 |
| F-LINK-003 | **默认 URL 硬编码** | P3 | `DEFAULT_HISTORY_API_URL` 硬编码内网地址，建议移到环境变量 |

## 10. 结论

链路配置页是 CLPM **数据接入层的基础设施**（3.40/4.0），3 Tab 结构（数据源/DCS系统/MODE矩阵）覆盖了数据接入的完整链路，ClpmDangerConfirmModal 统一危险操作、Token 打码安全处理、v-permission 权限守卫等实现质量良好。

**核心问题**是 Token 安全语义理解成本高（F-LINK-001）和网络模式切换缺少预检查（F-LINK-002）。建议增加 Tooltip 说明和实时订阅状态预检查。

**核心建议**：
1. **短期**：Token 增加帮助说明（1 天）+ 网络切换预检查（0.5 天）
2. **中期**：默认 URL 迁移到环境变量 + 断点续传独立区域
3. 链路配置页是**纯管理配置页**，仅在工作站模式完整展示，驾驶舱模式仅需展示网络模式状态
