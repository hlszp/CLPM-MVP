## 1. 页面定位与核心价值

### 1.1 定位

数据源管理页是配置模块的**数据接入层核心**——管理 CLPM 历史数据的导入、完整性检查和回算。以导入表单为入口，支持回路选择、时间范围、冲突策略、完整性检查，任务列表展示导入进度和状态。

### 1.2 核心价值

| 价值 | 实现 | 评估 |
|---|---|---|
| 历史数据导入 | 回路选择 + 时间范围 + 冲突策略 + 触发回算 | ✅ |
| 完整性检查 | 检查完整性 + 结果可视化 + IntegrityReportDrawer | ✅ |
| 断点续传 | 支持 gap backfill，导入缺失数据 | ✅ |
| 任务管理 | 导入任务列表（进度/状态/操作）+ 批量回算/取消 | ✅ |
| 并发控制 | runWithConcurrency 并发控制导入任务 | ✅ |
| 轮询状态 | usePolling 轮询任务状态，实时更新进度 | ✅ |

## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 怎么导入历史数据？ | 导入表单：回路选择 + 时间范围 + 冲突策略 + 触发回算 | ✅ |
| 数据完整吗？ | 完整性检查 + IntegrityReportDrawer | ✅ |
| 导入进度？ | 任务列表 + 进度条实时更新 | ✅ |
| 断点续传？ | gap backfill 配置，导入缺失数据 | ✅ |
| 批量操作？ | 批量回算 + 批量取消 | ✅ |
| 并发控制？ | runWithConcurrency 控制并发导入数 | ✅ |

### 3.2 范式级评估

**优点**：
- 历史数据导入是数据架构核心，完整性检查保障数据质量
- usePolling 轮询导入任务状态，实时更新进度
- runWithConcurrency 并发控制，避免同时发起过多导入
- IntegrityReportDrawer 独立抽屉展示完整性检查结果
- ClpmDangerConfirmModal 用于取消/删除操作
- 服务端分页：回路列表改为服务端分页，解决 >100 回路丢失问题

**不足**：
- 回路单选限制：TreeSelect 为单选模式，用户想导入多个回路时需重复操作
- 完整性检查结果缺少一键触发导入的快捷按钮
- 表单控件过多：回路选择 + 时间范围 + 冲突策略 + 触发回算 + 完整性检查共 5 组控件
- 任务列表列宽：包含多个状态列（status/progress/errorMessage），建议调整

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-DATASRC-001 | **回路单选限制** | P2 | 批量导入需求下单选效率低，建议支持多选 |
| F-DATASRC-002 | **完整性检查结果缺快捷按钮** | P2 | 检查完成后需关闭抽屉再手动触发导入，建议增加一键导入 |
| F-DATASRC-003 | **表单控件密度过高** | P3 | 5 组控件拥挤，建议分区展示 |

## 10. 结论

数据源管理页是 CLPM **数据接入层的导入工具**（3.36/4.0），usePolling 轮询、runWithConcurrency 并发控制、IntegrityReportDrawer 独立拆分、服务端分页等实现质量良好。

**核心问题**是回路单选限制（F-DATASRC-001）影响批量导入效率，以及完整性检查结果缺少快捷导入按钮（F-DATASRC-002）。

**核心建议**：
1. **短期**：回路选择支持多选（2 天）+ 完整性检查增加一键导入（0.5 天）
2. **中期**：表单控件分区展示 + 任务列表列宽优化
3. 数据源管理页是**纯管理操作页**，仅在工作站模式完整展示，驾驶舱模式仅需展示活跃导入任务
