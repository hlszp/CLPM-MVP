## 1. 页面定位与核心价值

### 1.1 定位

指标配置页是配置模块的**算法配置层核心**——管理 CLPM 的 KPI 指标体系、权重、定级阈值、数据可信度、异常值检测、KPI 算法参数、诊断阈值模板。以 7 Tab 结构覆盖指标配置全链路。

### 1.2 核心价值

| 价值 | 实现 | 评估 |
|---|---|---|
| 指标定义 | KPI 指标元数据与公式 | ✅ |
| 权重配置 | 综合评分各指标权重 | ✅ |
| 定级阈值 | 性能等级分档（GB/T 44693.2 五级） | ✅ |
| 数据可信度 | valid_rate 阈值 A/B/C/D/E | ✅ |
| 异常值检测 | 异常值检测算法参数 | ✅ |
| KPI 算法参数 | KPI 计算算法参数 | ✅ |
| 诊断阈值模板 | 诊断指标阈值模板 | ✅ |

## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| KPI 指标有哪些？ | 指标定义 Tab：3+1+8 KPI 体系元数据与公式 | ✅ |
| 权重怎么分配？ | 权重配置 Tab：综合评分各指标权重 | ✅ |
| 等级怎么定？ | 定级阈值 Tab：GB/T 44693.2 五级分档 | ✅ |
| 可信度怎么评？ | 数据可信度 Tab：valid_rate 阈值 A/B/C/D/E | ✅ |
| 异常值怎么检？ | 异常值检测参数 Tab：算法参数配置 | ✅ |
| KPI 怎么算？ | KPI 算法参数 Tab：计算算法参数 | ✅ |
| 诊断阈值？ | 诊断阈值模板 Tab：诊断指标阈值模板 | ✅ |

### 3.2 范式级评估

**优点**：
- 指标体系是 KPI 计算的核心，7 Tab 完整覆盖指标定义→权重→定级→可信度→异常值→算法参数→诊断模板全链路
- 7 个 Tab 各自独立文件，职责单一
- `defineAsyncComponent` 按需加载，减少初始加载
- tabKey 自增触发组件重建，简化子组件刷新逻辑
- 结构配置从各业务页迁移到配置模块，符合 IA 重构 Phase A 方案

**不足**：
- 7 个 Tab 横向排列在中等屏幕上可能折行或截断
- 刷新通过 tabKey 自增强制重载当前 Tab，会触发组件完整重建
- Tab 标题缺少 Tooltip 或描述说明
- Tab 顺序不可自定义

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-METRIC-001 | **Tab 数量过多** | P2 | 7 个 Tab 横向排列可能折行，建议分组 |
| F-METRIC-002 | **刷新交互通过组件重建** | P2 | tabKey 自增触发组件重建，建议暴露 refresh 方法 |
| F-METRIC-003 | **Tab 无描述** | P3 | Tab 标题缺少 Tooltip 或帮助说明 |

## 10. 结论

指标配置页是 CLPM **算法配置层的核心页面**（3.46/4.0），7 Tab 独立子组件、defineAsyncComponent 异步加载、tabKey 强制重载等实现架构清晰，结构配置从各业务页迁移到配置模块的 IA 重构落地良好。

**核心问题**是 Tab 数量过多（F-METRIC-001）影响导航效率，以及刷新通过组件重建实现（F-METRIC-002）不够优雅。建议将 7 Tab 分组为"KPI 配置"和"诊断配置"两个主 Tab。

**核心建议**：
1. **短期**：Tab 分组为 KPI/诊断（1 天）+ 子组件暴露 refresh 方法（1 天）
2. **中期**：Tab 增加 Tooltip 描述 + Tab 顺序可自定义
3. 指标配置页是**纯管理配置页**，仅在工作站模式完整展示，驾驶舱模式不需要
