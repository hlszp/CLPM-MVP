## 1. 页面定位与核心价值

### 1.1 定位

回路配置页是配置模块的**实体管理核心**——管理 CLPM 系统中所有回路（Loop）的定义、属性和关联测点。以工厂树→回路表格的主从布局，支持回路 CRUD、批量配置、批量分组、视图切换（紧凑/Tag 详情）、变更摘要确认。

### 1.2 核心价值

| 价值 | 实现 | 评估 |
|---|---|---|
| 回路实体管理 | 工厂树→回路的主从布局 + CRUD（Drawer 内联） | ✅ |
| 双视图切换 | 紧凑视图（高效浏览）/ Tag 详情视图（7 个 Tag 关联详情列） | ✅ |
| 批量配置 | 批量设置 isMonitored/isStatEnabled/importanceLevel/includeInEvaluation | ✅ |
| 批量分组 | 批量分组操作 | ✅ |
| 变更安全 | 编辑保存/Tag 关联/批量配置变更摘要弹窗 | ✅ |
| 导入导出 | Excel 导入/导出回路配置 | ✅ |

## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 有哪些回路？ | 工厂树→回路表格（主从布局） | ✅ |
| 回路详细属性？ | LoopEditDrawer 内联编辑 | ✅ |
| 回路关联了哪些测点？ | Tag 详情视图：PV/SP/OP/MODE/PID_P/PID_I/PID_D | ✅ |
| 批量配置怎么弄？ | 批量配置（监控/统计/重要度/纳入评估） | ✅ |
| 分组管理？ | 批量分组操作 | ✅ |
| 变更安全吗？ | 变更摘要弹窗（字段变更前后对比） | ✅ |

### 3.2 范式级评估

**优点**：
- 回路是系统核心实体，工厂树→回路的主从布局符合工业场景
- LoopEditDrawer（编辑/查看抽屉）、use-loop-changes.ts（变更对比逻辑）、PlantNodeTree（工厂树组件）**独立拆分**，职责单一
- 变更摘要弹窗：编辑保存时显示变更摘要，包含字段变更前后对比
- 批量操作：支持批量配置和批量分组，规模化配置效率高
- Tag 详情视图：增加 7 个 Tag 关联详情列（PV/SP/OP/MODE/PID_P/PID_I/PID_D）
- 列设置持久化：通过 usePagePreference 保存列配置
- Segment 视图切换：紧凑视图/Tag 详情视图

**不足**：
- 回路数加载性能：`loadLoopCounts` 采用分页循环（pageSize=100）加载全量回路统计，当回路数多时可能较慢
- 视图切换记忆：视图切换（compact/tags）状态未持久化，刷新后恢复默认 compact

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-LOOP-001 | **回路数加载性能风险** | P3 | 分页循环加载全量统计，建议后端提供聚合接口 |
| F-LOOP-002 | **视图切换未持久化** | P3 | 刷新后恢复默认，建议 usePagePreference |

## 10. 结论

回路配置页是 CLPM **实体管理的核心页面**（3.56/4.0，模块最高分），LoopEditDrawer + use-loop-changes.ts + PlantNodeTree **独立拆分**架构、变更摘要弹窗 Poka-Yoke、双视图切换、批量配置/分组等实现质量突出。

**核心亮点**是组件独立拆分和变更摘要弹窗。LoopEditDrawer 分离编辑/查看逻辑，use-loop-changes.ts 封装变更对比，PlantNodeTree 自定义工厂树组件，三者职责单一、复用性强。

**核心建议**：
1. **短期**：视图切换状态持久化（0.5 天）
2. **中期**：后端提供回路数聚合接口（1 天）
3. 回路配置页是**双架构的核心页面**——驾驶舱看关键回路状态，工作站做全量管理和批量操作
