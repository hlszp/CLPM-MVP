## 1. 页面定位与核心价值

### 1.1 定位

KPI 报表页是评估模块的**报表导出页面**——提供综合报表（装置级 KPI 聚合）与回路报表（回路级 KPI 快照）两种视图，支持日/周/月时间维度切换，按工厂模型层级筛选，并支持 CSV 导出。是 PE_ENGINEER 周报/月报的主要工具页面。

### 1.2 核心价值

| 价值 | 实现 | 评估 |
|---|---|---|
| 综合报表 | `getBoardAggregateApi` 装置级聚合 | ✅ |
| 回路报表 | `getLoopSnapshotsApi` 回路级快照 | ✅ |
| 日/周/月维度 | DatePicker/WeekPicker/MonthPicker | ✅ |
| 工厂模型筛选 | Select + collectDescendantIds 递归 | ✅ |
| CSV 导出 | 前端 CSV 生成 + Blob 下载 | ✅ |
| 性能等级映射 | `getGradingThresholdsApi` 动态阈值 | ✅ |
| UTC 时区处理 | getTimeRange 本地→UTC 转换 | ✅ |
| 回路报表聚合 | 前端 computed 按 loopId 分组求均值 | ✅ |

## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

PE_ENGINEER 做周报/月报时，核心需求是**"按时间维度和装置层级导出 KPI 报表"**。KPI 报表页应回答：

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 装置级 KPI 聚合如何？ | 综合报表（boardAggregate） | ✅ |
| 回路级 KPI 快照如何？ | 回路报表（loopSnapshots） | ✅ |
| 按日/周/月维度？ | 三档时间维度切换 | ✅ |
| 按装置筛选？ | 工厂模型 Select + 递归收集子孙 | ✅ |
| 性能等级分布？ | getRating + ratingDistribution | ✅ |
| 如何导出？ | CSV 导出（前端生成 Blob） | ✅ |
| 回路报表多快照聚合？ | 前端 computed 按 loopId 分组求均值 | ✅ |

### 3.2 范式级评估

**优点**：
- 双报表（综合/回路）覆盖装置级+回路级两个层次
- 三档时间维度（日/周/月）覆盖巡检/周报/月报场景
- 工厂模型筛选递归收集子孙节点 ID，解决非末级节点精确匹配返回空结果的问题
- UTC 时区处理：本地选中的日/周/月边界转 UTC ISO，避免窗口偏移 8 小时
- 动态阈值定级：`getGradingThresholdsApi` + `getRating` 按评分映射 5 级
- 回路报表前端聚合：按 loopId 分组求均值 + 可信度取最差值（worstConfidence）

**不足**：
- **前端聚合性能风险**：回路报表按 loopId 分组求均值在前端 computed 中完成，大数据量时（数百回路×数十天快照）可能卡顿
- **无 URL 深链**：筛选条件不持久化到 URL，刷新丢失
- **CSV 导出仅前端**：大数据量 CSV 前端生成可能卡顿，后端导出更可靠

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-KR-001 | **前端聚合性能风险** | P3 | [kpi-report.vue:L192-L234](file:///Users/zhangping/DEV/CLPM/frontend/apps/web-antd/src/views/metric/kpi-report.vue#L192-L234) 大数据量时前端 computed 聚合可能卡顿。建议评估后端聚合可行性 |
| F-KR-002 | **无 URL 深链** | P3 | 筛选条件不持久化到 URL，刷新丢失 |
| F-KR-003 | **CSV 导出仅前端** | P3 | 大数据量 CSV 前端生成可能卡顿。后端已有 `GET /diagnosis/statistics/export`，评估 KPI 报表后端导出可行性 |

## 10. 结论

KPI 报表页是**评估模块的报表导出工具**（3.10/4.0），双报表（综合/回路）+ 三维度（日/周/月）+ 工厂模型筛选 + CSV 导出 + UTC 时区处理 + 动态阈值定级的功能完整，**报表导出能力达到良好水平**。

**核心问题**是前端聚合性能风险（F-KR-001）+ 无 URL 深链（F-KR-002），大数据量时前端 computed 聚合可能卡顿，筛选条件刷新丢失。

**核心建议**：
1. **短期**：增加 URL 深链（1 天）
2. **中期**：评估前端聚合→后端聚合 + 后端 CSV 导出（参考诊断统计导出）
3. KPI 报表页是**PE_ENGINEER 周报/月报的核心工具**——双报表+三维度+CSV 导出覆盖报表场景
