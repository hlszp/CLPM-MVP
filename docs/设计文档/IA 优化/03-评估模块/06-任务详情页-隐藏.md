## 1. 页面定位与核心价值

### 1.1 定位

任务详情页是 CLPM 的**跨模块隐藏页面**——从评估任务列表或诊断任务列表跳转进入，展示单个任务的全生命周期详情。页面以 4 阶段时间线（取数→预处理→指标计算→可信度判定）为信息骨架，支持活跃任务自动轮询、失败错误展示、任务通知管理。

### 1.2 核心价值

| 价值 | 实现 | 评估 |
|---|---|---|
| 任务全生命周期可视 | 4 阶段时间线（取数/预处理/指标计算/可信度） | ✅ |
| 活跃任务实时跟踪 | usePolling 每 5s 轮询 | ✅ |
| 失败原因可追溯 | 错误信息卡片 | ✅ |
| 任务通知管理 | 通知列表 + 标记已读 | ✅ |
| 耗时实时计算 | duration computed | ✅ |
| 时区正确处理 | normalizeUtcTimestamp（naive datetime 视为 UTC） | ✅ |

## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 任务跑到哪一步了？ | 4 阶段时间线（取数/预处理/指标计算/可信度） | ✅ |
| 任务成功还是失败？ | 状态+进度+错误信息卡片 | ✅ |
| 任务耗时多少？ | duration computed 实时计算 | ✅ |
| 失败原因是什么？ | 错误信息卡片展示错误详情 | ✅ |
| 任务通知有哪些？ | 通知列表 + 标记已读 | ✅ |
| 能否取消活跃任务？ | 取消按钮 + Popconfirm | ✅ |

### 3.2 范式级评估

**优点**：
- 4 阶段时间线覆盖完整的任务生命周期（取数→预处理→指标计算→可信度判定）
- 活跃任务自动轮询（usePolling 每 5s），无需手动刷新
- 失败时错误信息卡片醒目展示，支持快速定位失败原因
- normalizeUtcTimestamp 正确处理 naive datetime（视为 UTC），避免时区错误
- 任务通知列表支持标记已读，通知管理闭环

**不足**：
- **缺少返回入口**：页面缺少返回任务列表的按钮或面包屑，用户需通过浏览器后退或重新导航
- **轮询间隔硬编码**：活跃任务每 5s 轮询，间隔硬编码，无法按任务类型调整
- **通知列表前端筛选**：通过 `filter((n) => n.taskId === taskId.value)` 前端筛选，通知量大时性能不佳

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-TASK-001 | **缺少返回入口** | P2 | 隐藏页面无返回按钮，用户需浏览器后退。建议工具栏增加"返回"按钮 |
| F-TASK-002 | **轮询间隔硬编码** | P3 | 5s 间隔硬编码，无法按任务类型调整。建议可配置或按任务类型差异化 |
| F-TASK-003 | **通知列表前端筛选** | P3 | 通知量大时前端筛选性能不佳。建议后端按 taskId 过滤 |

## 10. 结论

任务详情页是**跨模块隐藏页面**（3.38/4.0），4 阶段时间线 + usePolling 自动轮询 + normalizeUtcTimestamp 时区处理 + 错误信息卡片 + 通知列表的技术实现完整，**任务全生命周期可视能力达到良好水平**。

**核心问题**是缺少返回入口（F-TASK-001），用户从任务列表跳转后无法一键返回。建议工具栏增加"返回"按钮，根据来源页（评估任务/诊断任务）智能返回。

**核心建议**：
1. **短期**：工具栏增加"返回"按钮（0.5 天）
2. **中期**：轮询间隔可配置（1 天）+ 通知列表后端过滤（1 天）
3. 任务详情页是**跨模块隐藏页面的典型代表**——服务评估和诊断两个模块，路由独立但功能共享
