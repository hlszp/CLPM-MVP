## 3. 第一性原理评估（视角一）

### 3.1 用户核心需求

| 问题 | 回答方式 | 当前实现 |
|---|---|---|
| 全厂性能怎么样？ | 子弹图（6 大 KPI 装置级聚合） | ✅ |
| 哪个装置最差？ | 工厂模型树切换 + 装置级聚合 | ✅ |
| 回路等级分布如何？ | 等级分布饼图（服务端聚合） | ✅ |
| 实时自控率多少？ | 实时自控率卡片 + 新鲜度标注 | ✅ |
| 最该关注哪些回路？ | TOP5 治理台账（按评分升序） | ✅ |
| 诊断情况如何？ | DiagnosisSummaryCard | ✅ |
| 整改效果如何？ | TrackerEffectivenessCard | ✅ |
| 数据是否新鲜？ | rtReadAtText + rtStale 检测 | ✅ |

### 3.2 范式级评估

**优点**：
- 全厂性能驾驶舱定位准确，子弹图直观展示 6 大 KPI 装置级聚合值 vs 目标值
- 工厂模型树抽屉化（A-13）释放主区 15% 宽度，默认收起，按需展开
- 实时数据新鲜度检测（RT_STALE_MINUTES=10），超过 10 分钟标灰/警示
- 时间窗 4 档切换（8h/24h/168h/30d），覆盖巡检/日报/周报/月报场景
- 诊断汇总卡+整改有效率卡嵌入，跨模块信息聚合

**不足**：
- **TOP5 治理台账与回路性能页功能重叠**：总览页展示回路级 TOP5，回路性能页也展示回路级表格。总览应聚焦装置级聚合，TOP5 应改为装置级排名或精简为 Top3
- **TOP5 无诊断跳转入口**：看到低分回路后无法一键跳转诊断分析（F-EVAL-001 相关）
- **等级分布饼图是环形图**：用户偏好饼图而非环形图（user_profile），但此处环形图含中心汇总数字，信息密度更高

### 3.3 范式级发现

| 编号 | 发现 | 级别 | 理由 |
|---|---|---|---|
| F-PID-001 | **TOP5 与回路性能页功能重叠** | P2 | 总览 TOP5 回路级 + 回路性能表格回路级。建议：TOP5 改为装置级排名或精简为 Top3 + 跳转回路性能 |
| F-PID-002 | **TOP5 无诊断跳转入口** | P1 | rankingList 表格操作列无"诊断"按钮。F-EVAL-001 相关 |
| F-PID-003 | **环形图 vs 饼图偏好冲突** | P3 | 用户偏好饼图（user_profile），但环形图含中心汇总数字。建议：保留环形图但确认用户最新偏好 |

## 10. 结论

性能总览页是**评估模块的门户页面 + SPONSOR 默认首页**（3.09/4.0），子弹图 + 等级分布 + 实时自控率 + TOP5 + 诊断/整改嵌入的结构覆盖了全厂性能概览的核心需求，A-13 工厂树抽屉化 + 实时新鲜度检测 + 动态阈值的技术实现到位。

**核心问题**是 TOP5 与回路性能页功能重叠（F-PID-001）+ 无诊断跳转入口（F-PID-002），用户看到低分回路后无法一键跳转诊断分析。建议 TOP5 增加诊断跳转按钮，并考虑改为装置级排名或精简为 Top3。

**核心建议**：
1. **短期**：TOP5 增加诊断跳转按钮（0.5 天）+ TOP5 改装置级或精简（1 天）+ 优先级色编码（0.5 天）
2. **中期**：随双架构路径 B，性能总览作为驾驶舱模式核心页面
3. 性能总览页是**驾驶舱模式的评估入口**——已有子弹图+等级分布+实时数据基础，适合驾驶舱快速概览
