## 1. 先认识系统面对的对象：一个控制回路

可以把一个控制回路理解成“测量—比较—调整—再次测量”的小系统。

**教学例子：用蒸汽加热一只罐，目标温度 80°C。**

| 名称 | 白话解释 | 例子 |
|---|---|---|
| PV，Process Variable | 仪表测得的当前过程值 | 当前罐温 75°C |
| SP，Set Point | 希望达到的目标 | 目标 80°C |
| OP，Output | 控制器发给执行机构的输出命令 | 蒸汽阀控制命令 60% |
| MODE | 当前控制模式 | AUTO 自动，或 MAN 手动 |
| PID | 根据偏差及其变化产生 OP 的控制方法 | 温度偏低时调整蒸汽命令 |
| 控制回路 | 上述测量、控制器、阀门和过程形成的反馈链 | 温度控制回路 |

OP=60% 不保证实际阀门已经开到 60%；命令与真实阀位之间可能存在摩擦、限位、气源或定位器问题。阀门也可能是反作用配置，不能对所有回路都假设“OP 越大，温度越高”。

**控制器负责调节，CLPM 负责观察和诊断。** CLPM 分析历史趋势，帮助工程师发现波动、迟缓、输出受限等现象，提供候选原因、证据和处置建议。项目安全边界是：DCS 参数由授权人员人工实施，平台不直接修改 DCS 的 P/I/D。

## 3. 一起读最值得理解的一段代码

下面摘自 [metric_calculator/stiction.py 的 `_estimate_lag`](/Users/zhangping/DEV/CLPM-MVP/backend/app/services/metric_calculator/stiction.py:254)。这是粘滞分析的辅助步骤：尝试找到 PV 与 OP 波动之间的时间偏移，再用于相图配对。它本身不会确诊阀门粘滞。

```python
x = pv - float(np.mean(pv))
y = op - float(np.mean(op))
denom = math.sqrt(float(np.sum(x**2) * np.sum(y**2)))
if denom <= 0:
    return 0, 0.0
n = len(x)
corr = np.correlate(x, y, mode="full")
window = corr[n - 1 : n + max_lag]
lag = int(np.argmax(window))
peak = float(window[lag]) / denom
if peak < MIN_CORR_PEAK:
    return 0, peak
return lag, peak
```

### 每一步在做什么

1. **减均值**：`np.mean` 求平均值。PV 从 75°C 附近上下波动，减掉平均值后就只看“高了多少、低了多少”，降低基线数值对比较的影响。
2. **计算归一化分母**：`denom` 用两条波形的整体幅度，把相关结果缩放成便于判断的量。如果没有波动，相关判断缺乏基础，函数返回零补偿。
3. **数清点数**：`n = len(x)` 表示共有多少个采样点。
4. **互相关**：`np.correlate` 将两条波形按不同时间偏移配对，计算每种配对的相关程度。可以想成拿两张透明波形图左右移动，比较它们在哪个位置最一致。
5. **只取允许搜索的范围**：`window` 保留 0 到 `max_lag` 的非负滞后结果。`full` 结果中的 `n-1` 是零滞后位置；Python 切片右端不包含，所以这里保留 `max_lag+1` 项。
6. **找最大位置**：`np.argmax` 返回最大值所在的位置，作为候选滞后点数。
7. **检查相关峰够不够强**：`peak` 达不到门槛时，不进行时间补偿。
8. **返回结果**：`lag` 是采样点数。若每点间隔 2 秒、lag=3，则候选偏移为 6 秒。

闭环中 OP 受 PV 反馈影响，也可能共同受外部因素影响。因此互相关得到的偏移是用于配对的候选信息，不能直接证明因果，也不能自动等同已辨识的真实过程纯时滞。

### 为什么这里可能慢

当前先计算 `full` 的全部偏移，再扔掉绝大多数，只留下很小的搜索范围。输入越长，被丢弃的计算越多。

N 表示输入点数。完整直接互相关的计算量约随 N² 增长；点数翻倍，主计算量约变成四倍。只计算所需的 L 个左右滞后时，计算量约随 N×L 增长。如果 L 固定，N 翻倍就约增加一倍工作量。

例如 **教学估算**：N=10,000、最大滞后 L=100。完整相关的乘加项数量量级约为一亿；所需有界相关约为一百万。这里比较的是理论计算量，不能据此声称软件实际快了一百倍。

还有一种 FFT 相关方法，能将长序列相关的复杂度降到约 O(N log N)。它需要正确处理补零、滞后方向、归一化和浮点误差。

推荐优化方向是保持同一输入、同一搜索范围、同一阈值及结果语义，减少无用计算。验证时需比较相关数值、最大峰位置和最终诊断结论，尤其关注门槛附近及并列峰。

## 4. “未发现异常”为什么需要检查前提

当前 [classification.py](/Users/zhangping/DEV/CLPM-MVP/backend/app/services/diagnosis_operators/classification.py:358) 有这样的兜底逻辑：没有候选分类时，生成 `NO_SYMPTOM`，即“未发现异常症状”。

```python
if not candidates:
    result.primary = CategoryJudgement(
        category=NO_SYMPTOM,
        confidence=0.0,
        basis=["数据门禁通过、各算子置信度均低于判定门槛：未发现异常症状"],
    )
```

`candidates` 是候选分类列表。`if not candidates` 只说明列表为空；列表为空还可能来自未执行、不适用、覆盖不足或未形成分类资格，不能单靠这个条件证明已经有效排除了问题。

**有效阴性**指：针对某项明确检查，所需数据和工况条件满足，检查实际完成且没有命中。结论只覆盖该窗口、工况和已检验的假设。

| 情形 | 应怎样理解 |
|---|---|
| 连续、适用数据中完成振荡检查，没有越过门槛 | 对该类振荡的有效阴性 |
| 算法被停用或 fast 不包含 | 未检查 |
| SP 一直不变，无法观察阶跃响应 | 对阶跃速度检查不适用／不足以判断 |
| 数据中断，连续段不足 | 数据不足以判断 |
| 拟合报错或响应估计退化 | 失败／不可判定，需说明原因 |

这类修改会改变部分诊断记录的分类与建议：以前可能显示“未发现异常”，之后会明确显示“未检查”“缺少有效响应”等。有效阴性与充分证据的阳性需要继续保持各自语义。改变汇总结果还需要检查前端展示、筛选、统计和处置建议链。

## 5. 支持度为什么不能直接读成正确概率

当前 `confidence` 多由特征公式或固定档位产生。例如 FFT 主峰占比被放大后封顶，冻结命中可以给固定 0.85。

**支持度**表达现行规则对该证据的支持强弱；**校准后的概率**则需要现场样本证明：“在这类回路和工况中，给出某个数值的结果，实际有多少被独立确认”。目前不能直接完成后一种解释。

两个算子支持度均为 0.8，现行融合公式会得到约 0.941。但它们可能用了同一份 PV/OP、同一个前提门禁，甚至重复了同一个椭圆特征。类似两个人重复转述同一个消息，不能当作两份独立确认。

工程师应同时看四项：

| 维度 | 回答的问题 |
|---|---|
| 数据质量 | 数据是否可靠、完整？ |
| 检查覆盖 | 计划检查哪些，哪些真正得到有效结果？ |
| 诊断支持度 | 现行规则对该候选有多强的支持？ |
| 严重度 | 波动或偏差造成多大影响、持续多久？ |

很小的周期波动可能获得很强的振荡支持，但工艺影响很小；很严重的异常也可能因为数据不足而无法确定原因。

## 6. 11 个算子分别在找什么

算子就是执行一项专项分析的计算程序。以下应先按“观察到的症状”理解，再看可能原因和复核方法。

| 算子 | 小白可以先这样理解 | 关键边界 |
|---|---|---|
| IAE 振荡 | 偏差是否反复、规律地正负摆动 | 噪声、SP 动作和缺口可影响过零分析 |
| FFT 振荡 | 波动是否有突出周期，周期和振幅是多少 | 有周期不能直接证明 PID 问题 |
| 椭圆粘滞 | PV 与 OP 的相图是否呈现候选粘滞特征 | 轴比不能直接解释成阀门死区百分比 |
| Choudhury NGI/NLI | OP 增量是否有明显非高斯、非线性特征 | 限幅、工况切换等也可造成这些特征 |
| Kano 粘滞 | 某些段里 OP 变化小、PV 却变化大 | 尚需阀位和工艺信息区分原因 |
| 阶跃过激 | SP 改变后是否冲过目标、反复摆动 | 需要有效响应、适用模式与足够观察时间 |
| 响应迟缓 | 目标改变后，响应是否比工程期望慢 | 期望必须有来源；当前拟合的闭环尺度与过程模型参数不同 |
| 偏差突变 | PV−SP 是否反复发生明显跳变 | 当前需进一步排除 SP/MODE 变化后才能支持外扰判断 |
| 传感器波形 | 数据是否疑似冻结、噪声改变或漂移 | 稳定生产、量化、采集保持也可能像冻结 |
| 质量码规则 | 数据源报告多少 Bad/Uncertain，持续多久 | Bad 可能来自设备、组态或通信，需看子码 |
| 输出饱和 | 自动时 OP 是否经常靠近控制限位 | 可能是负荷、限幅、容量或积分问题，需排查 |

指标“工程化”就是把一个数学结果变成工程师可使用、可复核的信息：明确单位、分母、时间窗、模式、量程、阈值来源、适用条件和下一步复核动作。

例子：`frozen_window=300` 是 300 点。1 秒一采样时约对应 5 分钟的窗口尺度，10 秒一采样时约对应 50 分钟；不能一律把它显示为“5分钟冻结”。`frozen_eps=1e-4` 当前是 PV 原始单位的阈值，单位变化会影响解释。

## 7. 建议修改会影响什么

| 建议 | 预期影响 | 需要怎样证明没有误改 |
|---|---|---|
| 拆开未检查、不可判定、失败、有效阴性 | 部分“未发现异常”会变为更准确的状态；影响展示、统计与处置建议 | 为各状态构造独立例子，核对分类与端到端展示 |
| 保留时间轴、mask 并按适用连续段分析 | 振荡、冻结、滞后等结果可能变化；有些窗口会明确不足 | 缺口反例不能产生虚构的连续波形或跨缺口周期 |
| 排除 SP/MODE 事件再判断外扰 | 某些原“外扰”可能变成正常响应或未决 | 已知事件边界与独立预期对照 |
| 统一量程、单位和阈值真实消费 | 工程单位变化与配置修改能得到一致、可解释结果 | 同物理曲线换单位应保持约定的归一化结论；改阈值验证边界 |
| 支持度明确含义与证据依赖 | 工程师更容易判断应信到什么程度；修改融合规则会影响分类 | 先验证语义，再用现场独立标注做校准 |
| 完整相关改有界相关或 FFT | 主要目标是减少 CPU 和延迟、保持算法结论 | 同输入与独立参考比较，检查数值容差和边界命中 |
| 缩短窗口、降采样、减少算子 | 可减少计算，但可能漏掉小幅、快速或慢周期问题 | 属于覆盖和算法语义调整，需单独验收 |

| 误报率／召回率 | 正常标注样本中错报异常的比例／异常标注样本中被检出的比例；都需真实、可追溯分母 |

## 9. 自测题：先写决定和理由，再看答案

以下均为教学情景。每题给出你的判断，并用一句话解释证据或缺失条件。题目从基础概念逐渐到代码和工程判断。

1. **基础：命令与测量。** SP=80°C、PV=75°C、OP=60%。小李说“OP=60% 已经证明阀门开度是60%”。你接受这个判断吗？如果不接受，还要看什么？
2. **基础：未检查。** 一次任务正常结束，但所有专项算法都被停用。报告应显示“回路健康”还是“未检查”？为什么任务成功仍不够？
3. **基础：滞后单位。** `_estimate_lag` 返回 lag=3，采样间隔2秒。你会把候选偏移标成3秒还是6秒？是否同时写“已证明真实纯时滞”？
4. **典型：没有激励。** SP 在两小时内一直保持80°C，慢响应算子没有命中。你会签字确认“响应速度正常”吗？缺了什么证据？
5. **典型：支持度。** 系统给“疑似仪表问题，支持度0.85”，没有现场标签校准。你向同事说“85%概率仪表坏了”是否合适？请改写一句解释。
6. **边界：数据缺口。** 原始时间是0、1、2、100、101秒，删掉缺口后保留5个数。开发者直接当成0、1、2、3、4秒做FFT。你允许这样处理吗？应保留什么信息？
7. **反例：复杂度。** N翻倍。完整直接互相关是O(N²)，有界相关是O(NL)，且L不变。两者工作量大约怎样增长？这能否直接推出实际耗时倍率？
8. **实际代码：优化与改算法。** 当前先算full相关再只取0…L。方案A只算0…L并保持归一化等规则；方案B先把采样点降到原来的十分之一。哪个优先作为保持结论的优化候选？分别怎样验收？
