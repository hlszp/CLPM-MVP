# 驾驶舱回路详情的评估窗口

回路卡片与右侧单回路面板的综合评分、六维雷达和可信度，统一使用最近一个有综合评分的小时 `kpiSummary`。驾驶舱列表请求 `latestScoredHour=true`，后端跳过较新的无分值快照及非 1h 窗口，零分仍有效；筛选、排序、分页定位与聚合使用同一取数口径。退出参评的回路继续不展示历史评分。其他调用方默认保持“最新快照”的原有口径。

卡片和详情标明服务端返回的实际 `tsStart` / `tsEnd`，例如 `10-21 09:00–10:00`；跨日保留两端日期。后端无时区后缀的 UTC 时间通过 `formatLocalTime` 转换显示。旧接口只给截止时间时，显式注明“区间未提供”，不推算起点。

`getLoopMonitorDetailApi(loopId, 'last_24_hours')` 仍用于实时值、PID 参数及近 24 小时趋势。该响应中的 KPI 是窗口汇总，不能覆盖小时快照的雷达或可信度。同一回路刷新列表快照时，面板同步更新评分与分项，无须重复请求详情；详情读取失败也保留已有小时评估。缺少小时快照时，雷达保持缺数据并显示“暂无小时快照”，卡片不显示“六维正常”。节点聚合视图保持原有口径。

回归测试：`src/__tests__/cockpit-loop-snapshot.test.ts` 与 `cockpit-p5-04-server-filtering.test.ts`。本机 PostgreSQL 事务回滚测试见 `backend/tests/integration/test_cockpit_scored_hour.py`，覆盖快照选择、零分、实际区间、非小时窗口、退出参评、筛选/排序/定位及统计分母。此次不修改评分公式、阈值或历史结果，不重算已有小时快照，也无数据库迁移。本次修复不在已部署的 full-1043 中，尚待后续发布与现场验收。
