## 五、TDengine 口令与初始化（**2026-09-27 现场事故根因**，务必先读）

### 5.1 不要手敲 `docker compose`——缺参数会导致"应用连不上 TDengine"

手敲 `docker compose -f docker-compose.prod.yml ...` 会丢掉两个必需参数：

- `--env-file .env.prod`：compose 层插值 `TDENGINE_PASSWORD` 取不到值（它只读同目录 `.env`）→ 容器内 `TAOS_ROOT_PASSWORD` 为空，而后端经 `env_file` 拿到的是非空口令 → **两边不一致**；
- `--profile tdengine`：TDengine 是 **profile 门控服务**，不带它则本次操作不会纳入 TDengine。

症状（TDengine 日志）：`failed to login ... since invalid pass` / `err:[0x357] Authentication failure`；
后果：应用建不出 `clpm_ts` → 点表不存在 → **趋势 / 评估 / 诊断全部无数据**。
正确做法：**统一用 `./deploy.sh <子命令>`**（`deploy/deploy.sh:174/177` 恒带这两个参数）。

### 5.2 口令三处必须一致

`.env.prod` 的 `TDENGINE_PASSWORD` == 容器环境 `TAOS_ROOT_PASSWORD`（由 `--env-file` 传入）== TDengine 内 root 的实际口令。
任何一处为空或不同，都会复现 5.1 的认证失败。

### 5.3 `.td-password-changed` 标记文件的首次/非首次差异

| 场景 | 标记文件 | 原因 |
|---|---|---|
| **首次部署（全新卷）** | **必须删除**：`rm -f .td-password-changed` | entrypoint 需用 `TAOS_ROOT_PASSWORD` 设定口令 |
| **非首次部署（卷已存在且改过密码）** | **必须存在**：`touch .td-password-changed` | 否则 entrypoint 用默认口令 `taosdata` 去 `ALTER USER` 失败 → `exit 255` **崩溃循环**（现象：容器反复 `Up N seconds`，其它容器是 `Up N hours`） |

### 5.4 五闸门诊断的判读顺序

`scripts/diag_realtime_pipeline.py` 的 FAIL 文案"表不存在→writer 建表失败或从未写入"在**连接层/认证层失败**时同样会出现（**属误导，待修**）。请按四层由外向内判读：

```bash
# ① 连接层：容器在不在、健康不健康（profile 服务，ps 要带 profile）
docker compose -f docker-compose.prod.yml --profile tdengine ps
# ② 认证层：日志有无 Authentication failure + CLI 能否登录
docker compose -f docker-compose.prod.yml --profile tdengine logs --tail=60 tdengine
docker exec -i clpm-tdengine taos -u root -p"<口令>" -s "SHOW DATABASES;"
# ③ 库表存在性：应看到 clpm_ts
docker exec -i clpm-tdengine taos -s "SHOW DATABASES;"
# ④ 数据新鲜度（同第 4 节 ③）
```
