## 二、这就是虚拟机部署包吗？—— 是

- 目标环境：**Windows VM + Docker Desktop（Linux 容器）+ `docker-compose.prod.yml`**；
- 交付包内镜像**按 `linux/amd64` 构建**（`deploy/package.sh` 的 `BUILD_PLATFORM="linux/amd64"`），与本机 arm64 无关，**可直接用于 x86_64 虚拟机**；
- 包结构：`deploy.sh`（含自动回滚）+ `deploy/`（备份/回滚/迁移）+ `docker-compose.prod.yml` + `.env.prod.example` + `db/`（初始化 SQL）+ `images/` + `README.md`。

## 三、部署团队要手动做的事（按顺序）

**1) 传输与校验**
```powershell
Get-FileHash .\clpm-delivery-20260926-145041.tar.gz -Algorithm SHA256
# 期望：3a4c542d909a11f1093f44af5ecfa3fcd1a90453398d1175071e0b7becc5aa79
tar -xzf clpm-delivery-20260926-145041.tar.gz ; cd clpm-delivery-20260926-145041
```

**2) 配置环境变量（必须人工填写，包内只有模板）**
```powershell
copy .env.prod.example .env.prod ; notepad .env.prod   # 数据库口令 / JWT 密钥 / AAS·SignalR 地址与凭证 / 网络模式
```

**3) 部署**
```powershell
docker load -i images/clpm-images-20260926-145041.tar.gz   # 或由 ./deploy.sh 自动加载
./deploy.sh                                                 # 备份 + 自动回滚 + 排查清单
# 覆盖升级时强制重建四个服务（backend 与 celery-worker/beat 共用镜像）：
docker compose -f docker-compose.prod.yml up -d --force-recreate backend celery-worker celery-beat frontend
```

**4) 部署后三项验证（必做）**
```powershell
# ① 落库形态自检：期望 writeMode=point / readLayout=point / consistent=true
docker compose -f docker-compose.prod.yml exec -T backend python scripts/register_layout_manifest.py --layout point
# ② 日志：应见 PointHistoryWriter 已启动；不应见"保持待命"
docker compose -f docker-compose.prod.yml logs --tail=200 backend | Select-String "PointHistoryWriter|实时落库自检|已接管实时数据订阅|保持待命"
# ③ 点表持续增长；宽表不再新增（本版起属预期，不是故障）
docker compose -f docker-compose.prod.yml exec -T tdengine taos -s "SELECT COUNT(*) FROM clpm_ts.st_point_data_v1;"
```

**5) 生产库删除宽表（独立步骤，代码已不读写它）**
⚠️ **必须先备份并确认导出目录非空再删**（开发环境漏掉此步曾致数据不可恢复）：
```bash
docker exec clpm-tdengine sh -c "mkdir -p /tmp/wide_backup && taosdump -o /tmp/wide_backup clpm_ts st_loop_data"
docker cp clpm-tdengine:/tmp/wide_backup ./wide_backup-$(date +%F)
ls -lh ./wide_backup-*/                    # ★ 非空才继续
docker exec -i clpm-tdengine taos -s "DROP STABLE clpm_ts.st_loop_data;"
docker exec -i clpm-tdengine taos -s "SHOW clpm_ts.STABLES;"   # 应只剩 st_point_data_v1
```

**6) 部署后需观察两件事（开发机无法替你排除）**
1. **位号级体检性能**：先在服务器用 CLI 试（开发机仅 222 位号，生产数千）：
   `docker compose -f docker-compose.prod.yml exec -T backend python scripts/audit_data_quality.py --last-hours 24`；720 档若明显卡顿请反馈，需加接口保护；
2. **首次重连后的日志**：确认真实环境下"点表有数据即跳过缺口登记"生效（该逻辑目前仅经单测验证）。

1. **不要启用 `kpi.min_observed_ratio`**：代码就绪，但 24h/7d 影响量化报告未出，启用前需先评估；
