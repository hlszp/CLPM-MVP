# full-1056：工作台搜索"渐进加载期假报无匹配"修复（仅前端）

日期：2026-10-24。源码基线：`macbook`（1055 之后工作区）。**仅前端镜像**，后端/数据库不动。

## 0. 修复内容

工作台回路清单是渐进加载（首页 100 条先渲染、余页分批并入，1209 回路全量到齐需数秒）。此前首页到达后 loading 遮罩即消失，此时跨装置搜索（如 41FIC…，回路还在未到达的页里）过滤为空，空态显示**「无匹配回路」假结论**——即"首次进入搜不到、刷新后正常"的根因。

修复（诚实化）：

- 清单未完整时，搜索空态显示**「清单同步中（N/1209），跨装置搜索请稍候…」**（进度实时），不再报"无匹配"；
- 左脊柱底部计数同步追加**「（清单同步中 N/M）」**，渐进过程可感知；
- 清单加载完成后行为与原先完全一致（空=真无匹配）。

注：命中结果随余页到达自动补全（computed 响应式），此前行为不变——本次只是把"还在加载"如实说出来。

## 3. Linux root：校验、解包、构建、更新（整块）

前置校验：前端容器应为 `clpm-frontend:full-1055`（本包基底写死 full-1055），不符先停。

```bash
bash -euo pipefail <<'CLPM_1056_FE'
cd /tmp
[ "$(sha256sum clpm-src-1056.tar.gz | cut -d' ' -f1)" = "a79f89fb551178348ae8bf06e47c8d41b21786c0cd1a4d6b027df9bd06a665ae" ] || { echo "包哈希不符"; exit 1; }
test ! -e /opt/clpm-src-1056
mkdir /opt/clpm-src-1056
tar -xzf /tmp/clpm-src-1056.tar.gz -C /opt/clpm-src-1056
docker inspect --format '{{.Name}} {{.Config.Image}}' clpm-frontend | tee /opt/clpm-src-1056/before.log
cd /opt/clpm-src-1056
docker build --pull=false -f Dockerfile.frontend --build-arg SOURCE_REVISION=1056-spine-search -t clpm-frontend:full-1056 .
cd /opt/clpm-delivery-20261005-full
docker compose --env-file .env.prod -f docker-compose.prod.yml -f docker-compose.shadow-1046.yml -f /opt/clpm-src-1056/compose.image-1056.yml -f /opt/clpm-src-1055/compose.image-1055.yml --profile tdengine up -d --no-deps --force-recreate --wait --wait-timeout 180 frontend
docker exec clpm-frontend nginx -t && docker exec clpm-frontend nginx -s reload

CLPM_1056_FE
```

> 注：compose 命令同时携带 1055 与 1056 两个覆盖文件——1056 只覆盖 frontend；1055 覆盖文件继续锁定后端三容器为 full-1055，缺它后端会回到旧镜像。后续管理保持这组文件组合（或把两份合并后再用）。

1. 全新进入回路工作台，清单出现后**立即**在搜索框输入跨装置回路名（如 `41FIC30048`）：空态应显示**「清单同步中（N/1209），跨装置搜索请稍候…」**且 N 递增，数秒后命中自动出现——**不应再出现"无匹配回路"**；
