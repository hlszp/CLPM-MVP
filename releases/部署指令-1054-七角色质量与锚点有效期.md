# full-1054：七角色质量码全链 + 锚点有效期 + UNKNOWN 口径对齐

日期：2026-10-23。源码基线：`macbook`（提交 SHA 见 manifest-1054.json），
基底镜像**写死** `FROM clpm-backend:full-1053`。

## 0. 本包是什么、不是什么

- **是**：1053 之上的评估算法修复批（R1~R8，见
  `docs/过程文档/评估算法-COV全面检查-审查报告-2026-10-23.md` §三）。
  核心变化：`{role}_quality` 七角色质量码全链透传；锚点 `coverage_until`
  半开有效期；accuracy/stability/好值率剔除覆盖 UNKNOWN 槽；QUALITY_HF 伪
  角色块可信度由质量码+覆盖给出；ideal_settling_time 可信度修正；backfill
  失败计数修正。缓存版本 `pre_v5 / tqpv5`，部署后旧 L1/L2 自然失效。
- **不是**：本轮**未部署**。源码与自动化验证通过 ≠ 已上线；生产现运行
  full-1053。部署由用户择机执行，本指令不含新一轮现场取证环节；部署后
  通用巡检沿用 `部署指令-1053-COV-ZOH.md` §4A 的只读命令。
- 无数据库迁移；前端不变。

## 3. Linux root：校验、解包、构建（整块）

新目录必须不存在；存在则停止。构建前先确认三容器当前镜像为 full-1053
（若不是，先核对现场状态，不盲目继续）。

```bash
bash -euo pipefail <<'CLPM_1054_STEP'
cd /tmp
sha256sum -c clpm-src-1054.tar.gz.sha256
test ! -e /opt/clpm-src-1054
mkdir /opt/clpm-src-1054
tar -xzf /tmp/clpm-src-1054.tar.gz -C /opt/clpm-src-1054
docker inspect --format '{{.Name}} {{.Config.Image}} {{.State.StartedAt}}' clpm-backend clpm-celery-worker clpm-celery-beat | tee /opt/clpm-src-1054/before-containers.log
docker image inspect clpm-backend:full-1053 --format '{{.Id}}' | tee /opt/clpm-src-1054/base-image-id.log
cd /opt/clpm-src-1054
docker build --pull=false -f Dockerfile.backend --build-arg SOURCE_REVISION=58ed6212cc26ac98594d554c1cfcd683adda3615 -t clpm-backend:full-1054 .
CLPM_1054_STEP
```

## 4. Linux root：更新三个后端进程（整块）

```bash
bash -euo pipefail <<'CLPM_1054_STEP'
cd /opt/clpm-delivery-20261005-full
test -f docker-compose.prod.yml
test -f docker-compose.shadow-1046.yml
docker exec clpm-backend python -m scripts.ten_minute_shadow status
docker compose --env-file .env.prod -f docker-compose.prod.yml -f docker-compose.shadow-1046.yml -f /opt/clpm-src-1054/compose.image-1054.yml --profile tdengine up -d --no-deps --force-recreate --wait --wait-timeout 180 backend celery-worker celery-beat
docker exec clpm-frontend nginx -t
docker exec clpm-frontend nginx -s reload
docker inspect --format '{{.Name}} {{.Config.Image}} {{.State.StartedAt}}' clpm-backend clpm-celery-worker clpm-celery-beat | tee /opt/clpm-src-1054/after-containers.log
docker exec clpm-backend python -m scripts.ten_minute_shadow status
docker exec clpm-backend printenv APP_VERSION
CLPM_1054_STEP
```

前后影子状态均须为 `enabled=false`；本包不运行任何 enable 命令。`--wait`
健康确认后才重载 nginx。后续 Compose 管理这三个服务须继续携带
`/opt/clpm-src-1054/compose.image-1054.yml`，省略会按原文件回到旧镜像。

## 5. 部署后生效方式

- 无需清 Redis：缓存键含 `tqpv5:pre_v5`，1053 时期的键自然不命中。
- 生效节奏：下个整点 hourly 快照起；历史窗口以页面「整点回算」或评估
  任务页回算覆盖。
- 通用巡检（容器健康 / health / 台账 1209/961/248 / UNIT 有分）沿用
  `部署指令-1053-COV-ZOH.md` §4A 命令原文执行。
