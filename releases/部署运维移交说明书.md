## 1. 系统形态概述

- **架构**：前后端分离 + 时序/关系双库 + 任务队列，全容器化交付
  - 前端：Vue 3 + Vite（Nginx 托管，对外唯一端口 **7141**）
  - 后端：FastAPI（uvicorn 4 worker，容器内 7101，不暴露宿主机）
  - 任务：Celery Worker + Celery Beat（独立容器）
  - 存储：PostgreSQL 16（业务库）、TDengine 3.3.6.6（时序库）、Redis 7（缓存/队列）
  - 反向代理：Nginx（前端容器内），后端/数据库端口均不出容器网络
- **部署单元**：单一离线交付包（含全部镜像、编排、脚本、数据库初始化 SQL），目标环境**无需联网**
- **运行环境**：Linux x86_64 + Docker 24+（物理机或 Windows 宿主机上的 Linux 虚拟机均可，见手册 §1）
- **数据源**：厂内 AAS 服务（SignalR 实时 + 历史数据接口 + OPC UA），通常与应用同机（地址写法规则见手册 §3"同机 AAS 地址规则"）

## 4. 部署与升级

**现场部署的唯一操作依据是《客户现场部署手册》**（`releases/客户现场部署手册.md`，随本说明书一并移交）。要点摘录：

- **部署**：解压 → 配置 `.env.prod`（重点：JWT 用 `openssl rand -hex 32` 生成；TDengine 密码须 8~16 字符且四类字符至少三类）→ `./deploy.sh`（约 1~2 分钟，失败自动回滚并生成 `/tmp/clpm-deploy-troubleshooting-*.md`）
- **升级**：新包解压 → 复制旧 `.env.prod` → `./deploy.sh`（自动备份 → 迁移 → 健康检查，失败回滚）
- **回滚**：`./deploy/rollback.sh`（镜像多 tag + 自动备份保障，数据库回退需交互确认）
- **验证**：`curl http://<IP>:7141/health`（注意是 `/health`）、7 容器 healthy、admin/admin123 登录

## 5. 运行维护

### 5.1 日常命令（部署目录内执行）

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml ps          # 状态
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f backend   # 日志
./deploy/backup.sh                                                          # 备份（PG+TDengine）
docker compose --env-file .env.prod -f docker-compose.prod.yml --profile tdengine down   # 停止（⚠️ 必须带 --profile tdengine）
```

### 5.2 备份策略

- `./deploy/backup.sh`：PostgreSQL（pg_dump）+ TDengine（taosdump），输出到 `~/backups/clpm/<时间戳>/`，自动保留 30 天
- 升级部署时脚本自动执行一次备份；建议运维侧再加 cron 每日备份
- Windows VM 方案下可叠加虚拟机快照作为整机级兜底

### 5.3 监控（可选）

- compose 含 monitoring profile（Prometheus + Grafana + node-exporter + 4 条告警规则）：`docker compose --env-file .env.prod -f docker-compose.prod.yml --profile tdengine --profile monitoring up -d`
- 监控端口不暴露宿主机，需 SSH 隧道访问；Grafana 默认密码需用 `GRAFANA_ADMIN_PASSWORD` 环境变量覆盖

### 5.4 安全口径

- 敏感配置全部经 `.env.prod`（`chmod 600`）注入，仓库与镜像不含任何真实密码
- 生产启动强制校验：JWT 密钥 ≥32 字符、禁止开发默认密码、TDengine 密码复杂度
- 对外仅 7141 端口；登录接口限流（10 次/分/IP+账号）；`/metrics` 内网白名单
- **默认账号**：admin / ic_engineer / pe_engineer / sponsor / expert，密码统一 `admin123`（产品决策：无强制改密机制，个人中心可自愿改密；如客户安全基线要求改密，由现场人工执行）

## 6. 数据库与迁移

- 迁移工具：Alembic，当前 head `g7b8c9d0e1f2`，迁移链单 head 受 CI/本地门禁守护
- 首次部署：`01_schema.sql` initdb 建表（已与迁移链列级对齐）+ `alembic stamp head` + 种子数据幂等导入
- 升级部署：`alembic upgrade head` + 种子数据幂等重载（ON CONFLICT，可安全重复）
- 模型变更纪律：ORM 改动与迁移同批提交（开发侧遵守，运维知悉即可）
