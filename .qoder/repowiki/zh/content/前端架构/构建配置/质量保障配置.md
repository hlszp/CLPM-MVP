## 简介
本文件面向前端工程化质量保障体系，系统性说明 ESLint、Stylelint、Git Hooks（Lefthook）、Commitlint、OxLint/OxFmt 以及 **Hex 基线安全扫描** 等工具在仓库中的职责边界、规则策略与集成方式。目标是帮助开发者快速理解并正确配置本地与 CI 的检查流程，确保 JavaScript/TypeScript、Vue 模板、CSS/SCSS 的规范统一，并通过提交前检查与自动化流程降低代码缺陷率，同时防止未注册的安全隐患代码被推送到仓库。

## 核心组件
- ESLint：基于 @vben/eslint-config 的统一 JS/TS/Vue 语义检查；针对 Vue 模板布局交由 OxFmt 处理，ESLint 专注语义规则。

- Lefthook：在 pre-commit 阶段并行执行 lint 与类型检查；在 commit-msg 阶段执行 commitlint；在 pre-push 阶段执行更严格的全量门禁（含后端与前端及 hex 安全扫描）。

### Hex 基线安全扫描（新增）
**更新** 新增 Hex 基线安全扫描机制，用于管控 Vue 组件中的十六进制颜色硬编码，防止新增安全债务。

- **白名单机制**：定义颜色定义型文件（token/色板/图表预设）允许 hex 使用，不参与计数
- **基线管控**：通过 hex-baseline.json 记录每个文件的 hex 数量基线，采用棘轮策略只减不增
- **新增拦截**：不在白名单且不在基线中的文件出现 hex → 直接失败，阻止未注册代码推送
- **收敛支持**：支持 `--update-baseline` 参数在收敛完成后更新基线

```mermaid
flowchart TD
HStart(["Hex 安全扫描"]) --> Scan["扫描 frontend/apps/web-antd/src<br/>下的 .vue/.ts/.css 文件"]
Scan --> Filter{"是否在白名单?"}
Filter --> |是| Skip["跳过计数<br/>styles/, preferences.ts 等"]
Filter --> |否| Count["统计 hex 数量<br/>忽略注释中的 hex"]
Count --> Baseline["读取 hex-baseline.json<br/>获取基线配置"]
Baseline --> Compare{"对比当前与基线"}
Compare --> |超出基线| Fail["✗ hex 棘轮超限<br/>阻止推送"]
Compare --> |新增文件| NewFail["✗ 新增 hex 债务<br/>阻止推送"]
Compare --> |通过| Success["✓ 安全检查通过"]
Skip --> Success
NewFail --> Exit["exit 1"]
Fail --> Exit

```

## 性能与可维护性建议
- 分层检查：提交前只做增量检查（staged files），推送前再执行全量检查，兼顾速度与质量。
- 规则渐进收紧：对历史债务采用"先放开、后治理"的策略（如 no-non-null-assertion、no-explicit-any），逐步推进。
- 格式化与检查解耦：OxFmt 负责排版，ESLint/OxLint 专注语义，避免重复与冲突。
- 忽略无关文件：OxFmt 明确忽略构建产物与锁文件，减少无效扫描。
- **Hex 债务治理：通过白名单机制区分真正的颜色定义文件与业务代码中的硬编码，采用棘轮策略确保债务只减不增。**

## 故障排查指南
- 提交被拦截（pre-commit）：
  - 查看 pnpm lint 与 pnpm check:type 的输出，定位 ESLint/OxLint/Stylelint/类型错误。
  - 若为 Vue 模板换行或闭合括号问题，优先使用 OxFmt 格式化后再提交。
- 提交信息被拒绝（commit-msg）：
  - 根据 commitlint 提示修正提交信息格式（如 feat/fix 前缀等）。
- 推送失败（pre-push）：
  - 按顺序检查后端 ruff、pytest、前端类型检查与 **hex 白名单守护** 结果，逐项修复。
  - **Hex 扫描失败时，查看具体是哪个文件新增了 hex 债务或超出了基线限制。**
- 规则误报：
  - 确认是否在对应配置文件中有覆盖（如 stylelint 的 selector-class-pattern、eslint 的 Vue 模板规则、oxlint 的非空断言）。
  - **对于 Hex 扫描，确认文件是否在白名单中，或是否需要更新基线配置。**

## 结论
本项目通过 Lefthook 将 ESLint、Stylelint、OxLint/OxFmt、TypeScript 类型检查、Commitlint 以及 **Hex 基线安全扫描** 串联成完整的本地与远程质量门禁。遵循"提交前快速反馈、推送前全量把关"的原则，既保证了开发体验，又确保了代码质量、安全性与一致性。新增的 Hex 安全扫描机制有效防止了未注册的颜色硬编码被推送到仓库，建立了代码质量的新防线。建议在后续迭代中持续收敛规则、完善忽略策略，并配合自动化脚本进一步缩短反馈周期。

## 附录：工作流集成示例
- 本地开发
  - 安装依赖后会自动安装 Lefthook 钩子。
  - 提交前：pnpm lint + pnpm check:type + commitlint。
  - 推送前：触发仓库根 lefthook.yml 的后端与前端全量检查，包括 Hex 安全扫描。
- Hex 安全扫描使用
  - 首次运行：node scripts/check-hex-whitelist.mjs --update-baseline 生成基线文件
  - 日常检查：node scripts/check-hex-whitelist.mjs 验证当前状态
  - 收敛完成后：再次运行 --update-baseline 更新基线
- 推荐实践
  - 修改代码后先运行 pnpm format 进行格式化，再提交。
