模块以 shell 脚本为核心编排层，围绕 `docker-compose.prod.yml`（由 `package.sh`/`build-and-deploy.sh` 同步到目标服务器）组织多容器服务：backend/frontend/postgres/redis/tdengine/celery-worker/celery-beat。
- 构建与交付：`package.sh` 在本地通过 `docker buildx --platform linux/amd64` 构建自有镜像并拉取第三方镜像（postgres:16-alpine、redis:7-alpine、tdengine:3.3.6.6、可选 prometheus/grafana/node-exporter），导出为 `releases/images/clpm-images-<version>.tar.gz`，再组装成自包含的 `clpm-delivery-<version>` 目录并打包；`build-and-deploy.sh` 在此基础上增加 SSH 远程传输与部署流程，支持 `--build-only/--deploy-only/--backend-only/--frontend-only/--skip-gate` 参数。
- 部署执行：`deploy.sh`（本地服务器直跑）与 `build-and-deploy.sh`（macOS→zpdev 远程）两条路径共享 `lib-migrate.sh` 提供的 `alembic_sync_head` / `load_seed_data` / `tdengine_ensure_schema` 函数，要求调用方定义 `backend_exec()` / `postgres_exec()` / `tdengine_exec()` 三种命令执行器以适配本地 compose exec 或远程 ssh+docker exec。
- 版本与回滚：每次构建生成 `latest` + `<git-commit>` + `<YYYYMMDD-HHMMSS>` 三标签镜像，`rollback.sh` 自动选取非 latest 的最旧 tag 作为回滚目标，并可选择性执行 `alembic downgrade -1`；`releases/manifest.json` 记录每个版本的 commit、appVersion、镜像大小与 tar 包名，作为可审计的发布清单。
- 数据保护：`backup.sh` 通过 `pg_dump` 与 `taosdump` 分别备份 PostgreSQL 与 TDengine，按时间戳分目录保存并清理 30 天前备份；部署前自动检测运行中容器并触发备份。
- 监控与配置：`prometheus/prometheus.yml`、`alerts.yml` 与 `grafana/provisioning/datasources/dashboards.yml`、`dashboards/clpm-overview.json` 提供 Prometheus 指标采集、告警规则与 Grafana 仪表盘预配置；`nginx.conf` 反向代理前端至后端 API；`sudoers.d/` 提供 Tailscale 免密访问权限模板。
- 依赖方向：所有脚本单向依赖 `lib-migrate.sh` 暴露的函数接口，不直接耦合具体容器名称以外的实现细节；环境变量统一从 `.env.prod` 读取（通过 `grep` 解析而非 source，避免执行任意代码）。
