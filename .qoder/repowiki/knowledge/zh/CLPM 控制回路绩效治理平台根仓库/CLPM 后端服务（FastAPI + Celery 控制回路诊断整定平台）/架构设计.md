应用以 `app/main.py` 的 `create_app()` 为唯一装配点：在 lifespan 中启动日志、CORS、限流、幂等、指标采集、请求 ID 中间件链，并自动拉起 Celery Beat（定时任务）和 Worker（默认+dead_letter 队列），通过 pgrep + pidfile 实现多实例隔离与看门狗自愈；业务路由按模块启用状态（`core.modules.is_module_enabled`）条件挂载到 `/api/v1` 前缀。

分层协作关系：
- `app/core/*` 提供配置、SQLAlchemy/Redis/TDengine 连接、安全认证、全局异常与 Prometheus 指标，被所有上层模块共享。
- `app/models/` 定义 SQLAlchemy ORM 模型并由 Alembic 版本化迁移（`alembic/versions/`），是持久化契约的唯一来源。
- `app/schemas/` 用 Pydantic 描述请求/响应结构，作为 API 契约由 `app/api/v1/endpoints/*` 消费。
- `app/services/*` 按领域拆分（loop/diagnosis/tuning/alerting/preprocessing/metric_calculator/cache/data_source 等），仅依赖 core 与 models，不直接操作数据库会话，由 endpoints 注入。
- `app/tasks/celery_app.py` 集中注册 Celery 任务，由 main lifespan 自动启动 worker/beat，生产环境由独立容器接管。
- `app/contracts/` 与 `app/constants/` 提供跨服务共享的数据类型与控制模式常量，避免各服务重复定义协议。

运行时通过 `sys_config` 预载数据源配置、算法参数、异常值阈值与可信度阈值到进程缓存，配合 Redis pub/sub 实时同步；实时数据经 `data_source.realtime_subscriber` 订阅后写入 TDengine，再经三层缓存（DataBlock/MetricDataBundle/特征）供计算与查询使用。
