根目录作为 CLPM-MVP 的单一可交付仓库，通过 docker-compose.prod.yml 在 clpm-net 网络上把 backend_service（FastAPI + Celery）、frontend_app（Nginx 反代）、celery-worker/beat、postgres、tdengine、redis 以及可选 prometheus/grafana/node-exporter 串联，依赖顺序由 healthcheck + depends_on condition: service_healthy 保证；TDengine 通过 profiles=["tdengine"] 强制启用，monitoring 通过 profiles=["monitoring"] 按需挂载。Dockerfile.backend 与 Dockerfile.frontend 由根级 Makefile 调用，并通过 APP_VERSION 注入版本标签供 deploy.sh 统一打 tag。Makefile 暴露 dev/dev-all/test/lint/format/build/deploy/migrate/seed/clean 等顶层命令，分别转发到 backend（uv+pytest+ruff+mypy）与 frontend（pnpm workspace+Turbo），屏蔽各子模块工具链差异。数据契约约定：计算类历史数据统一走本地 TDengine，实时值经 SignalR → Redis 缓存，AAS 同步仅用于导入，该约定由 README 数据链路章节与 docker-compose 中 tdengine profile 共同约束前后端行为。e2e_tests 与 performance_tests 复用同一套容器化基础设施，通过环境变量切换真实或 mock_data_server 数据源。DESIGN.md 与 docs_and_design 提供产品基线，实现契约 v2.11 作为当前路由/API/权限/状态机的权威来源，被前后端共同遵循。
