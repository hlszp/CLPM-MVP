模块以 Playwright Test 为执行框架，`playwright.config.ts` 定义单一 chromium 项目（1440×900 视口），通过 `webServer` 自动拉起 `../frontend/apps/web-antd` 的 dev 服务（端口 5666），后端 API（localhost:7101）需手动启动。

- 共享 fixture：`fixtures/auth.ts` 通过 `base.extend` 扩展出 `loginAs(role)` 和 `logout()` 两个 fixture，封装了三种登录路径——纯 UI 登录、API 预取 token + 浏览器 route mock 的混合登录（解决连续测试中后端 SignalR/Celery 导致的慢响应）、以及带 429 重试与 25 分钟 JWT 缓存的 `loginViaApi`；同时提供 `clearAccessToken` 清理 localStorage/sessionStorage 并重置 token 缓存。
- 用例组织：`tests/` 下按业务域拆分 spec 文件（login、roles、diagnosis、tuning、metric、performance、visual-contrast-check 等），每个 spec 通过 `import { test, expect } from '../fixtures/auth.js'` 复用认证 fixture，并在 `beforeEach` 中调用 `clearAccessToken` 保证用例隔离。
- 视觉回归：`scripts/capture-visual-baseline.mjs` 是独立 Node 脚本，直接 require `@playwright/test` 中的 chromium，遍历 21 个关键路由（含 `[LOOP]` 占位符由后端 API 动态解析 loopId），输出到 `visual-baseline/baseline/` 或 `current/`；`tests/visual-inspection.spec.ts` 在三种分辨率（desktop/laptop/tablet）+ 亮/暗模式下截图至 `visual-inspection/`；`screenshots/` 存放失败时自动捕获的断点截图。
- 依赖方向：spec → fixtures/auth → @playwright/test；脚本不依赖 fixtures，直接操作 Chromium；配置集中管理 baseURL、超时、locale、timezone、trace/screenshot/video 策略。
