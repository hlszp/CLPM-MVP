- API 文件按业务域拆分（auth/dashboard/loop/diagnosis 等），统一通过 `api/request.ts` 导出的 `requestClient` 发起请求，并遵循后端统一响应码 code === 0/'0' 为成功、data 字段为数据的规范。
- 路由采用模块化声明：每个业务域在 `router/routes/modules/` 下提供独立 `.ts` 文件，通过 `import.meta.glob` 自动聚合，并通过 `meta.module` 标记实现运行时模块开关过滤。
- 跨组件 UI 状态优先以 `composables/use-*` 形式组织（如 use-loop-realtime、use-polling、use-monitor-context），仅在需要跨页面共享时才放入 Pinia store。
- 组件按领域分组到 `components/<domain>/`（clpm/loop/monitor/plant-node/metric），公共基础组件放在 `clpm/` 下并通过 `index.ts` 统一 re-export。
- 页面视图按业务域分目录存放于 `views/<domain>/`，复杂页面内部再拆 `components/`、`composables/`、`constants.ts` 保持单一职责。
- 全局行为通过 `bootstrap.ts` 集中装配（指令、i18n、store、路由、插件），业务代码不直接调用 `createApp`，保证应用生命周期可控。
