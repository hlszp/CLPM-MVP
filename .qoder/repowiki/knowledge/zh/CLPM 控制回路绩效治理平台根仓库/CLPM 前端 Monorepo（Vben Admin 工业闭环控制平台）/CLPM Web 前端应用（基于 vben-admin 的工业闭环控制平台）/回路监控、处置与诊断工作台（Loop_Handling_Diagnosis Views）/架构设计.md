模块按业务域划分为三个并列的 views 子目录：`loop/`、`handling/`、`diagnosis/`，每个域遵循“根页面 + `components/` 子组件 + 可选 `composables/` 组合式函数”的自包含结构。
- `loop/workbench.vue` 是核心入口，采用左侧装置树+回路清单、右侧单页两区（概览+评估）的 master-detail 布局，通过 `provide/inject` 向子组件共享 assessmentDetail/scoreHistory，并通过 `useMonitorContext`、`useLoopRealtime`、`useVirtualList`、`useLatestRequest` 等跨域 composables 复用实时数据、虚拟滚动与请求代次保护；路由状态以 URL query（plantNodeId/loopId/loopType）为真相源，由 `monitorCtx.update` 驱动。
- `handling/workbench.vue` 以双 Tab（建议审核 / 工单执行）组织，使用 `ClpmDataCanvas` + antd Table 承载列表，抽屉（`order-detail-drawer`、`handling-archive-drawer`、`handling-detail-drawer`）承载详情；状态机（PENDING→ACCEPTED→CONVERTED 等）与角色权限（IC_ENGINEER/PE_ENGINEER/ADMIN vs SPONSOR/EXPERT）在常量 `constants.ts` 中集中声明。
- `diagnosis/workbench.vue` 采用左脊柱（装置树+勾选式回路多选，上限 10 个）+ 右主区（配置时间窗/算子 + 结果面板）布局，批量诊断逻辑封装在 `composables/use-diagnosis-runner.ts`，结果详情通过 `DiagnosisDetailModal`、证据/历史/复核通过独立 Drawer 组件呈现。
依赖方向单向向下：views → `#/api/*` 接口层 → 后端；组件之间仅通过 props/emits 或 provide/inject 通信，无跨域耦合。
