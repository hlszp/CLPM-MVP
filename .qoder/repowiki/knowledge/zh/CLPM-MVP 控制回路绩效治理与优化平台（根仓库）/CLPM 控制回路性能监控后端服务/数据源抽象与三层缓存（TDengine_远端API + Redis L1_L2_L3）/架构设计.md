模块分为两大子域，依赖方向单向：计算任务 → data_source → cache → Redis/TDengine。

- 数据源层（`services/data_source/`）：以 `base.HistoryDataProvider` Protocol 定义 `make_query_fn` / `query_trend_data` / `close` 三方法契约；`tdengine_provider.TDengineProvider` 通过宽表一次查 7 列并叠加 Redis 1 小时实时缓存探测（历史窗口直接跳过），`remote_api_provider.RemoteApiProvider` 对接外部 HistoryDataAppService HTTP API，内置限流信号量与熔断器（429/5xx 计数打开，半开探测后闭合）；`factory.get_provider()` 强制所有计算任务走本地 TDengine Provider（远端仅用于导入任务），通过全局单例避免重复初始化。
- 缓存层（`services/cache/`）：按 ADS §10.7.x 分三层——L1 `L1DataBlockCache`（`pdb:` Key，按 tagGroup 分层 TTL 1h/5min）、L2 `L2BundleCache`（`pdb_l2:` Key，600s TTL，缓存组装后的 Bundle 列表）、L3 `L3FeatureCache`（`pdb_l3:` Key，1800s TTL，缓存 ARMA/IAE 等中间特征）。三者共享同一序列化链路：对象→JSON→zstd(level=3)→base64→Redis SETEX，反序列化失败时主动 DEL 脏键；批量写入均通过 Redis Pipeline 合并 RTT。`invalidation.CacheInvalidator` 基于 SCAN+DEL 实现回路/指标/tagGroup/全量四级失效策略。
- 模型层（`models/dcs_*.py` + `engine.py`）：`DcsVendor`→`DcsModel`→`DcsModeMapping`/`DcsPidStructure` 构成 DCS 品牌/型号/模式映射的 ORM 实体；`EngineRule` 管理计算周期/取数/调度规则。所有模型继承 `Base`，主键为字符串化 UUID，使用 PostgreSQL JSON/UUID 方言与 CHECK/UNIQUE 约束。

依赖方向：cache 不依赖 data_source；data_source 通过 `app.core.tdengine*` 访问 TDengine，通过 httpx 访问远端 API；models 仅被上层服务引用，本模块内无循环依赖。
