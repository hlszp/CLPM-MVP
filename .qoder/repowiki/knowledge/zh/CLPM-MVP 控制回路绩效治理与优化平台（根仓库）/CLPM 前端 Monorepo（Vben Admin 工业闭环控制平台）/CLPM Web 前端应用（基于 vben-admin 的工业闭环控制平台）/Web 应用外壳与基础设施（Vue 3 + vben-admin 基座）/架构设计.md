应用入口 `main.ts` 通过 `initPreferences` 初始化命名空间化的用户偏好，并在启动前读取本地缓存的主题模式以兼容新用户默认浅色；随后懒加载 `bootstrap.ts` 完成 Vue 实例创建、Sentry 错误上报（仅生产且配置 DSN）、v-loading/权限指令注册、i18n、Pinia store 初始化、tippy/Motion 插件安装、路由挂载与动态标题监听。

- 路由层：`router/index.ts` 根据环境变量选择 hash/history 模式并挂载守卫；`router/routes/index.ts` 使用 `import.meta.glob('./modules/**/*.ts', { eager: true })` 自动发现各业务模块路由文件（`alert/loop/diagnosis/handling/metric/reports/system/tuning/task` 等），并通过 `filterTreeByModules` 按 `meta.module` 启用集合过滤生成 `accessRoutes`，未启用模块路径走 `isKnownRoutePath` 返回 404 而非 403。
- API 层：`api/request.ts` 封装 `@vben/request` 的 `RequestClient`，统一注入 Authorization/Accept-Language 请求头，并以响应拦截器链实现：统一响应体解包（code/dataField）、Refresh Token 自动续期（对齐 IDS v3.2 §5.2，防死锁标记 `__isRetryRequest`）、401 重认证/登出、403/5xx/业务错误提示；每个业务域文件（auth/dashboard/loop/diagnosis 等）导出独立函数式 API。
- 状态层：`store/` 仅暴露 auth 相关 Pinia store，其余状态由 `composables/` 中的组合式函数（如 `use-loop-realtime`、`use-polling`、`use-monitor-context`、`use-operational-context`）管理，遵循“轻量 UI 状态用 composables、跨页面共享数据用 Pinia”的分层约定。
- 组件层：按领域划分 `components/clpm`（通用工业组件）、`components/loop`、`components/monitor`、`components/plant-node`、`components/metric`；页面级视图位于 `views/`，按业务域分目录（dashboard/diagnosis/handling/loop/metric/reports/system/tag/task/tuning），子模块内再拆 `components/`、`composables/`、`constants.ts`。
- 适配与扩展：`adapter/` 提供 Ant Design Vue 表单与 vxe-table 的 vben 适配器；`directives/permission.ts` 实现按钮级 `v-permission` 通配符指令；`locales/` 提供中英文 i18n 资源。
- 测试：`src/__tests__/` 为 Vitest 单元测试（覆盖 composables、store、utils、routes-authority 等），`__tests__/e2e/smoke.spec.ts` 为 Playwright 冒烟测试，验证应用启动与登录页渲染。
