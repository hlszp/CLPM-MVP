模块采用 Nitropack 文件系统路由约定：`api/` 下按资源域（auth、menu、timezone、user）组织 RESTful 处理器文件（如 `login.post.ts`），通过文件名与 HTTP 方法映射到 H3 `defineEventHandler`；全局中间件位于 `middleware/1.api.ts`，统一处理 CORS 预检并对 `/api/system/` 的写操作返回 403 演示限制；`nitro.config.ts` 集中配置 `/api/**` 的跨域响应头与错误处理器（`error.ts`）。业务逻辑下沉至 `utils/`：`jwt-utils.ts` 使用 jsonwebtoken 签发/校验 Access Token 与 Refresh Token（密钥从环境变量或默认值读取），`cookie-utils.ts` 管理刷新令牌 Cookie，`response.ts` 提供统一的 `{code,data,error,message}` 成功/失败包装及分页辅助，`mock-data.ts` 维护用户、菜单、权限码与时区选项等静态数据。依赖方向单向：route handler → utils → 静态 mock data，无持久化存储。
