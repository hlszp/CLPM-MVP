根目录作为 CLPM-MVP 的编排中枢，将 backend_service、frontend_app、deployment_infra、e2e_tests、performance_tests、mock_data_server、docs_and_design、demo_and_clpm_engine、root_scripts 等子模块聚合为单一可交付仓库：
- 运行时编排：`docker-compose.prod.yml` 通过 `clpm-net` 网络把 backend（7101）、frontend（Nginx 7141）、celery-worker、celery-beat、postgres、tdengine、redis 以及可选的 prometheus/grafana/node-exporter 串联，依赖顺序由 healthcheck + depends_on 保证；TDengine 通过 profiles=["tdengine"] 强制启用，monitoring 通过 profiles=["monitoring"] 按需挂载。
- 镜像构建：`Dockerfile.backend` 与 `Dockerfile.frontend` 由 Makefile 的 `build-docker` 调用，并通过 `APP_VERSION` 参数注入版本标签，供 deploy.sh 统一打 tag。
- 开发入口：`Makefile` 暴露 `dev/dev-all/test/lint/format/build/deploy/migrate/seed/clean` 等顶层命令，分别转发到 backend（uv+pytest+ruff+mypy）与 frontend（pnpm workspace+Turbo），屏蔽各子模块工具链差异。
- 数据契约：所有计算类历史数据统一走本地 TDengine，实时值经 SignalR → Redis 缓存，AAS 同步仅用于导入，这一约定由 README 数据链路章节与 docker-compose 中 tdengine profile 共同约束前后端行为。
- 测试与压测：e2e_tests 与 performance_tests 复用同一套容器化基础设施（Postgres/TDengine/Redis/Celery），通过环境变量切换真实或 mock 数据源。
- 文档基线：DESIGN.md 与 docs_and_design 提供产品基线，实现契约 v2.11 作为当前路由/API/权限/状态机的权威来源，被前后端共同遵循。
